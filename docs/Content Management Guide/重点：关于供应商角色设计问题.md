补充关于供应商角色问题设计：当前系统设计

**1. 注册用户/供应商的定义**

当前系统采用 **产品中心模型**，没有"供应商"角色。具体结构如下：

- **User**（用户）：注册用户，可关联到 `Organization`（组织）
- **Organization**（组织）：通过 `type` 字段区分不同类型的组织（如制造商、经销商等），一个组织可以同时是"供应方"和"需求方"
- **Product**（产品）：属于全局产品目录，通过 `createdById` 关联到创建者，但**不直接属于某个组织**
- **Offer**（报价）：关联 `Organization` + `Product`，表示某个组织对某个产品提供报价

**2. 专属Officer的挂接**

当前系统**没有"专属Officer"的概念**。用户通过 `Organization` 关联，但系统中没有定义某个组织有专属的客户经理/商务代表。如果需要这个功能，需要新增模型和对应的前端展示。

**3. 供应商品牌产品展示的限制**

根据项目架构约束：

- **禁止供应商店铺化**（无独立供应商页面、无店铺/排名/评分/关注）
- **禁止 `/suppliers` 和 `/suppliers/[slug]` 路由**
- 供应商信息仅在**产品详情页**内展示，不设独立入口

### 当前产品展示方式

| 展示内容 | 当前实现                   | 说明                          |
| :------- | :------------------------- | :---------------------------- |
| 产品列表 | ✅ 全局产品目录 `/products` | 通过分类、搜索筛选            |
| 产品图片 | ✅ ProductMedia + FileAsset | 支持多图、主图设置            |
| 产品参数 | ✅ ProductParameterValue    | 关联 ParameterDefinition 定义 |

### 如果要实现品牌展示，建议方案

由于 V1.0 已冻结（M13.9 Release），这些需要在后续版本中实现：

1. **品牌信息展示**：在 Product 模型中增加 `brand`、`manufacturer` 字段，或关联到 Organization 的扩展信息
2. **专属Officer**：新增 `AccountManager` 模型，关联 Organization ↔ User，并开放 API 查询
3. **产品详情页品牌区**：在 `/products/[slug]` 页面增加组织信息和联系方式区域（当前已通过 InquiryForm 支持询价联系）
