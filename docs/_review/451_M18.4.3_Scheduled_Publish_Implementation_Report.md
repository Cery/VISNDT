## 5. Scheduler Implementation

- **扫描规则**：`ContentSchedulerService.scan()` 仅查询 `status=REVIEW AND scheduledPublishAt <= now()`。
- **执行流程**：`onModuleInit` 启动 `setInterval`（60s，`unref` 不阻塞进程退出），`running` 标志防重入；逐条复用 `ContentService.publish(id, systemUser, { scheduled: true, scheduledAt })`（不复制发布逻辑）。
- **幂等设计**：
  - `ContentService.transition()` 改为原子条件更新 `updateMany({ where: { id, status: from }, data })`，`count === 0` 视为状态已变更并抛错——并发/重复扫描下仅一次成功，保证只产生一次 `OPENED` 与一次 `STATUS_CHANGE`。
  - 发布成功自动清除 `scheduledPublishAt`，避免二次扫描命中。
- **系统身份**：`ensureSystemUser()` 幂等创建 `system@visndt.com` 系统用户（无组织关联）作为执行主体，WorkflowEvent / AuditLog 可追溯执行来源。
- **失败处理**：单条发布失败 catch 记录错误日志，不阻塞其他内容；下一轮扫描自动重试；不修改 `scheduledPublishAt`。
