## 4. Search UX Current State Assessment

### 4.1 Search Entry UX

| Dimension | Score | Detail |
|-----------|-------|--------|
| GlobalSearchBar visibility | ✅ Good | Desktop header (inline) + mobile menu + /search page |
| Type selector usability | ✅ Good | Dropdown with 5 domain types, clean visual design |
| Submit interaction | ✅ Good | Enter key + button click, navigates to /search |
| Clear button | ✅ Good | X button when input has value |
| Placeholder guidance | ✅ Good | "搜索工业检测设备、知识、方案..." |
| Real-time suggestions | ❌ Missing | SearchSuggestionDropdown exists but NOT wired to GlobalSearchBar |
| Keyboard shortcuts | ❌ Missing | No `/` key binding, no arrow key navigation in suggestions |
| Search history | ❌ Missing | No recent searches, no localStorage persistence |

**Key Finding #1**: The `SearchSuggestionDropdown` component is fully implemented (300ms debounce, 5 suggestions, loading/empty states, outside-click + Escape close) but is **never integrated** with `GlobalSearchBar`. The `GlobalSearchBar` component does not import or render `SearchSuggestionDropdown`. This is a critical gap — the user types in the search bar but receives zero real-time feedback.

### 4.2 Search Result Layout

| Dimension | Score | Detail |
|-----------|-------|--------|
| Result count summary | ✅ Good | "搜索 'keyword' 共找到 N 条结果" |
| Sectioned results | ⚠️ Partial | All 4 sections shown in "全部" mode, including 0-result sections |
| Pagination | ❌ Missing | Only page 1 (20 results), no load more or pagination |
| Sorting | ❌ Missing | No sort by relevance, date, name |
| Filtering | ❌ Missing | No category filter, content type filter within results |
| Grid/List toggle | ❌ Missing | Always list view |
| Scroll behavior | ⚠️ Partial | Tab switch uses `scroll: false`, no scroll-to-section |

**Key Finding #2**: In "全部" (type=all) mode, sections with zero results still render with their header and "(0 条结果)" count. This creates visual noise and wastes vertical space. The `SearchResultSection` component should be conditionally hidden when count is 0 and type is 'all'.

**Key Finding #3**: No pagination mechanism. The `unifiedSearch` function hardcodes `page: 1, pageSize: 20`. Users cannot view more than 20 results per domain. This is a core search usability gap.

**Key Finding #4**: Tab switching from 'all' to a specific type and back triggers a full re-fetch of all 4 domains. The results from the initial 'all' search are discarded and re-fetched. For a pure frontend optimization, results could be cached in component state.

### 5.2 Gap Detail Analysis

#### G1: SearchSuggestionDropdown Not Integrated (P0)

**Current State**: `SearchSuggestionDropdown.tsx` is fully implemented with:
- 300ms debounce
- `GET /products?keyword=` for suggestions
- Max 5 results
- Loading/empty/error states
- Outside-click and Escape key dismiss

But `GlobalSearchBar.tsx` does NOT import or use it.

**Required Fix**: Import `SearchSuggestionDropdown` into `GlobalSearchBar`, wire `keyword` state, `visible` on focus, `onSelect` to set keyword, `onClose` on blur.

**Architecture Impact**: None. Pure frontend integration.

#### G2: Zero-Result Sections Visible in "全部" Mode (P0)

**Current State**: `SearchPageContent` renders all 4 `SearchResultSection` components when `type === 'all'`, regardless of whether each domain has results.

**Required Fix**: Add conditional rendering — hide `SearchResultSection` when `count === 0` and `type === 'all'`.

**Architecture Impact**: None. Pure frontend conditional rendering.

#### G3: No Pagination (P0)

**Current State**: `unifiedSearch()` hardcodes `page: 1, pageSize: 20`. `SearchPageContent` has no pagination UI.

**Required Fix**: Add page state, "Load More" button or pagination controls, update `unifiedSearch` call with dynamic page. Since backend APIs support pagination (page/pageSize params), this is a frontend-only change.

**Architecture Impact**: None. Existing APIs already support pagination.

#### G4: No Retry Button (P1)

**Current State**: Error state shows "搜索服务暂不可用" with a link to browse products, but no retry button.

**Required Fix**: Add "重试" button that re-triggers `unifiedSearch()`.

**Architecture Impact**: None. Pure frontend addition.

#### G5: No Product Images (P1)

**Current State**: `ProductResultCard` shows only text (name, model, description, category, status). No product thumbnail.

**Required Fix**: Add product image thumbnail from `Product.media` or `Product.images`. Requires checking if Product API response includes media URLs.

**Architecture Impact**: Requires verifying Product type includes media/image fields. If available, pure frontend addition. If not, requires backend API investigation (may be blocked).

#### G6: Tab Switching Re-fetches (P1)

**Current State**: When switching from 'all' to 'product' and back, all 4 domains are re-fetched.

**Required Fix**: Cache `UnifiedSearchResults` in component state. When switching tabs, reuse cached results. Only re-fetch when query changes.

**Architecture Impact**: None. Pure frontend state management optimization.

#### G7: highlightText Duplicated (P1)

**Current State**: `highlightText` function is copy-pasted in `ProductResultCard`, `KnowledgeResultCard`, `SolutionResultCard`, `SupplierResultCard`. `formatDate` duplicated in `KnowledgeResultCard` and `SolutionResultCard`.

**Required Fix**: Extract to `@/lib/search-utils.ts` as `highlightText(text, keyword)` and `formatDate(value)`. Import in all card components.

**Architecture Impact**: None. Pure frontend refactoring.

#### G8: No Partial Error Handling (P1)

**Current State**: `unifiedSearch()` uses `Promise.all` — if any domain fails, the entire search fails. Individual `search*` functions have try/catch, but `unifiedSearch` doesn't use `Promise.allSettled`.

**Required Fix**: Replace `Promise.all` with `Promise.allSettled` in `search.service.ts`. Show partial results with error indicators for failed domains.

**Architecture Impact**: None. Service layer change only.

#### G9: No Sticky Search Bar on Scroll (P1)

**Current State**: On `/search` page, the search bar scrolls away with the page header.

**Required Fix**: Make search bar sticky within the result page using `position: sticky` on the header container.

**Architecture Impact**: None. Pure CSS change.
