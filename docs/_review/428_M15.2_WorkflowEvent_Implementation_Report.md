## 4. WorkflowEvent Changes

### 4.1 Match Event Subject Normalization (3.1)

**Status**: ✅ 已实现

**Location**: `apps/api/src/matching/matching.service.ts`

所有 Match 生命周期事件均已使用 `WorkflowEntityType.MATCH`：

| Match Event | entityType | action | 
|-------------|-----------|--------|
| Match Created | `MATCH` | `CREATED` |
| Match Reviewed | `MATCH` | `REVIEWED` |
| Match Accepted | `MATCH` | `ACCEPTED` |
| Match Rejected | `MATCH` | `REJECTED` |

Demand 关联信息通过 `metadata.demandId` 保留。

### 4.2 WorkflowAction Strategy (3.2)

**Status**: ✅ 已合规

未新增任何 WorkflowAction 枚举值，全部复用现有值：
- `CREATED`, `SUBMITTED`, `OPENED`, `RESPONDED`, `ACCEPTED`, `REJECTED`, `CLOSED`, `WITHDRAWN`, `REVIEWED`

### 4.3 Demand Lifecycle Boundary (3.3)

**Status**: ✅ 已收敛

**Location**: `apps/api/src/demands/demands.service.ts`

- `update()` 方法区分生命周期变化和普通字段更新：
  - 状态变化（PUBLISHED/CLOSED）→ `publish()` / `close()` → 产生 WorkflowEvent
  - 普通字段变化（title, description, parameters 等）→ 不产生 WorkflowEvent
- `batchStatus()` 使用 `applyDemandStatusTransition()` → 每个状态变化均有事件记录

### 4.4 RFQ Lifecycle Boundary (3.4)

**Status**: ✅ 已收敛

**Location**: `apps/api/src/rfqs/rfqs.service.ts`

| RFQ Operation | WorkflowEvent | Status |
|--------------|---------------|--------|
| `create()` | `RFQ + CREATED` | ✅ |
| `createFromMatch()` | `RFQ + CREATED` | ✅ |
| `update()` → status change | `transitionRfqStatus()` → 自动产生事件 | ✅ |
| `batchStatus()` | `transitionRfqStatus()` → 每个对象均有事件 | ✅ |
| `publish()` | `RFQ + OPENED` | ✅ |
| `close()` | `RFQ + CLOSED` | ✅ |

### 4.5 RFQ Response Event (3.5)

**Status**: ✅ 已补齐

**Location**: `apps/api/src/rfq-responses/rfq-responses.service.ts`

| Response Operation | WorkflowEvent | Status |
|-------------------|---------------|--------|
| `create()` | `RFQ_RESPONSE + CREATED` (metadata: rfqId, demandId, organizationId) | ✅ |
| `view()` | `RFQ_RESPONSE + REVIEWED` | ✅ |
| `accept()` | `RFQ_RESPONSE + ACCEPTED` | ✅ |
| `reject()` | `RFQ_RESPONSE + REJECTED` | ✅ |

### 4.6 Rematch Event Handling (3.6)

**Status**: ✅ 已规范

**Location**: `apps/api/src/matching/matching.service.ts`

- 使用 `MATCH + CREATED + metadata.trigger=rematch`
- 未新增 `REMATCHED` action
- `MATCH_CREATED_TRIGGER` 常量定义 `{ publish: 'publish', rematch: 'rematch' }`
