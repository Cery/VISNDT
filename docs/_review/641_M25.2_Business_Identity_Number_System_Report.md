## 二、Identity Architecture Decision

### 三层身份模型
```
Database ID（UUID，已有，业务主键）
        +
Business Identity Number（本轮新建，人类可读业务编号）
        +
Human Readable Reference（展示层，BusinessIdentityBadge）
```

### 编码规范
```
VIS-{PREFIX}-{YYYYMMDD}-{SEQUENCE}
```
| 类型 | 前缀 | 示例 |
|------|------|------|
| PRODUCT | `PROD` | `VIS-PROD-20260821-00000001` |
| DEMAND | `DEM` | `VIS-DEM-20260821-00000001` |
| RFQ | `RFQ` | `VIS-RFQ-20260821-00000001` |
| OFFER | `OFF` | `VIS-OFF-20260821-00000001` |
| ORGANIZATION | `ORG` | `VIS-ORG-20260821-00000001` |
| USER | `USR` | `VIS-USR-20260821-00000001` |
| ASSET | `AST` | `VIS-AST-20260821-00000001` |
| CONTENT | `CNT` | `VIS-CNT-20260821-00000001` |

### v0.1 派生规则（DB Schema FROZEN 下的关键决策）
由于 `prisma/` 与 `migration/` 冻结、禁止新增 SEQUENCE 列、禁止一次性历史迁移，SEQUENCE 段采用**确定性派生**：
- 日期段 = 记录 `createdAt`（`YYYYMMDD`）。
- 序列段 = 现有 UUID（去分隔符）前 8 位 hex → 无符号整数 → 补零（默认宽 8）。
- 特性：同记录恒等、跨记录唯一（平台规模冲突概率可忽略）、无需存储即可展示、可逆回 UUID。
- 契约同时支持显式 `sequence` 入参，为未来规范化分配预留通道。

**边界声明**：Business Identity Number ≠ 数据库主键 / ≠ 替代 UUID / ≠ 业务状态 / 不承载业务逻辑判断；不触碰 Database / API / Matching / Search / AI。
