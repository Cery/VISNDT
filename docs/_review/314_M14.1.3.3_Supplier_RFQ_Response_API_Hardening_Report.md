## 3. API 行为变化

加固位置：

- [rfq-responses.service.ts:L91-L230](file:///F:/Desktop/VISNDT/VISNDT/apps/api/src/rfq-responses/rfq-responses.service.ts#L91-L230)

`POST /rfqs/:id/responses` 现在新增以下业务校验：

1. RFQ 存在性检查
   - RFQ 不存在时返回 `NotFoundException`

2. RFQ 发布状态检查
   - 当前代码库 `RFQStatus` 不存在 `PUBLISHED`
   - 现有工作流中“已发布 RFQ”实际对应 `status = OPEN` 且 `publishedAt != null`
   - 非已发布 RFQ 返回 `BadRequestException`

3. 当前用户组织检查
   - 无 `organizationId` 时拒绝创建

4. OrganizationMember 有效性检查
   - 校验当前用户在当前组织存在 `OrganizationMember`
   - 同时要求 `User.status = ACTIVE`
   - 同时要求 `Organization.status = ACTIVE`
   - 由于现有 `OrganizationMember` 模型无 `status` 字段，本次按代码事实采用上述“有效成员”判定

5. 可选 `offerId` 校验
   - `offerId` 存在时校验 Offer 是否存在
   - `offer.organizationId` 必须等于当前用户 `organizationId`

6. 重复响应友好错误
   - 创建前预查 `rfqId + organizationId`
   - 已存在时返回明确 `ConflictException`
   - 同时保留 Prisma `P2002` 兜底，避免并发下退回底层通用错误

保持不变：

- `offerId` 仍为 optional
- `message` 仍为 optional
- 创建成功后的通知逻辑保持存在
- 返回结构仍由 `ApiResponse.ok()` 包装
