## 数据兼容性分析

结论：**当前 Schema 设计对历史数据兼容。**

原因：

1. `RFQ.sourceMatchId`、`RFQ.targetOrganizationId` 为可空字段，对既有 RFQ 记录兼容
2. `RFQResponse.reviewedBy`、`reviewedAt`、`decisionNote` 为可空字段，对既有 Response 记录兼容
3. 将 `RFQ.demandId` 从唯一约束改为普通外键，只会放宽约束，不会破坏既有单 RFQ 数据
4. 本次未删除业务字段、未修改枚举、未改动已有主键和现有唯一键 `@@unique([rfqId, organizationId])`

## Backfill 准备情况

结论：**本阶段无需数据回填即可上线 Schema。**

说明：

1. 新增字段均允许为空
2. 历史 RFQ 可继续保持“一条 Demand 对应一条 RFQ”的旧数据形态
3. 历史 RFQResponse 在 Buyer Review 前可保持 `reviewedBy/reviewedAt/decisionNote = NULL`
4. 后续若业务侧要求将既有 RFQ 显式映射到 `sourceMatchId` 或 `targetOrganizationId`，应在后续非冻结任务中单独定义 backfill 规则；本次未扩展该范围
