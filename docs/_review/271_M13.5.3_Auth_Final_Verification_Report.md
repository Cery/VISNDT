## 4. RefreshToken Verification

### Token Lifecycle

```
┌─────────────────────────────────────────────────────────────────┐
│                     REFRESH TOKEN LIFECYCLE                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  CREATE:                                                         │
│    crypto.randomBytes(64) → raw token (128 hex)                  │
│    SHA-256(raw) → tokenHash stored in DB                         │
│    expiresAt = now + JWT_REFRESH_EXPIRES_IN (default 7d)         │
│                                                                  │
│  VALIDATE:                                                       │
│    SHA-256(raw) → lookup tokenHash in DB                         │
│    Check: revokedAt === null                                     │
│    Check: expiresAt > now                                        │
│                                                                  │
│  ROTATE (refresh):                                                │
│    1. Validate old token                                         │
│    2. revokeRefreshToken(old) → revokedAt = now                  │
│    3. createRefreshToken(userId) → new token                     │
│    4. Set new refresh_token cookie                               │
│    → Old token is immediately invalid (rotation) ✅              │
│                                                                  │
│  REVOKE (logout):                                                │
│    revokeRefreshToken(raw) → revokedAt = now                     │
│    clearCookie('refresh_token')                                  │
│    → Token cannot be reused ✅                                   │
│                                                                  │
│  CLEANUP:                                                        │
│    cleanupExpiredTokens() → DELETE WHERE expiresAt < now         │
│    → Cron job can call periodically ✅                           │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Rotation Verification

| Aspect | Result |
|--------|--------|
| Old token revoked before new created | ✅ (Line 133: revoke → Line 144: create) |
| Atomic operation | ⚠️ Not wrapped in transaction — potential race condition |
| Recovery from failure | ⚠️ If create fails after revoke, user logged out |

### 10.7 🔴 Finding: API_BASE_URL Fallback Port

**File:** `apps/web/src/lib/constants.ts:2`  
**File:** `apps/web/src/lib/auth.ts:23`

```typescript
// Current (wrong):
export const API_BASE_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3001';

// Should be:
export const API_BASE_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:4000';
```

**Impact:** If `NEXT_PUBLIC_API_URL` is not set, the frontend will try to connect to port 3001 instead of 4000 (where the API backend runs). In dev, `.env` has `NEXT_PUBLIC_API_URL=http://localhost:4000`, so this works. But if the env var is missing, all API calls will fail.

**Severity:** 🟡 Medium — functional in dev, broken in env-var-less deployment.

## 11. Security Flow Verification

### 11.1 Login Flow

```
Browser
  │
  │ POST /auth/login
  │ { email, password }
  ▼
  ┌──────────────────────────────────────┐
  │ Backend                               │
  │ 1. Validate credentials (bcrypt)      │
  │ 2. Generate JWT accessToken (24h)     │
  │ 3. Generate refreshToken (7d)         │
  │ 4. Store refreshToken hash in DB      │
  │ 5. Set-Cookie: access_token (HttpOnly) │
  │ 6. Set-Cookie: refresh_token (HttpOnly)│
  │ 7. Return { user }                    │
  └──────────────────────────────────────┘
  │
  ▼
  Browser receives HttpOnly cookies
  → access_token used for all subsequent API calls
  → refresh_token used for silent renewal
```

**Status:** ✅

### 11.2 Refresh Flow

```
  API Call → 401
  │
  │ POST /auth/refresh
  │ Cookie: refresh_token=xxx
  ▼
  ┌──────────────────────────────────────┐
  │ Backend                               │
  │ 1. Read refresh_token from cookie     │
  │ 2. SHA-256 hash → lookup in DB       │
  │ 3. Check: not revoked, not expired    │
  │ 4. Revoke OLD refresh_token 🔄        │
  │ 5. Create NEW refresh_token          │
  │ 6. Generate NEW accessToken          │
  │ 7. Set-Cookie: new access_token       │
  │ 8. Set-Cookie: new refresh_token      │
  └──────────────────────────────────────┘
  │
  ▼
  Retry original request with new cookies
```

**Status:** ✅ (Token Rotation verified)

### 11.3 Logout Flow

```
  POST /auth/logout
  Cookie: refresh_token=xxx
  │
  ▼
  ┌──────────────────────────────────────┐
  │ Backend                               │
  │ 1. Read refresh_token from cookie     │
  │ 2. SHA-256 hash → lookup in DB       │
  │ 3. Set revokedAt = now (DB)          │
  │ 4. clearCookie('access_token')       │
  │ 5. clearCookie('refresh_token')       │
  └──────────────────────────────────────┘
  │
  ▼
  Browser: cookies cleared, user state null
```

**Status:** ✅

### 11.4 CSRF Flow

```
  GET /auth/csrf
  │
  ▼
  ┌──────────────────────────────────────┐
  │ Backend                               │
  │ 1. crypto.randomBytes(32) → token    │
  │ 2. Set-Cookie: csrf_token (httpOnly: false)│
  │ 3. Return { csrfToken }              │
  └──────────────────────────────────────┘
  │
  ▼
  Browser stores token in memory
  │
  │ POST /rfq

  │ Cookie: csrf_token={token}

  │ Backend (CSRF Middleware)             │

  │ 2. Check: Auth endpoint? → skip      │
  │ 3. Verify: X-CSRF-Token header exists│
  │ 4. Verify: csrf_token cookie exists  │
  │ 5. timingSafeEqual(header, cookie)   │
  │ 6. Pass → proceed to controller       │
  └──────────────────────────────────────┘
```
