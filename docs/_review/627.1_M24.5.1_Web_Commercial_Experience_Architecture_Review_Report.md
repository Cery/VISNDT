## 5. Component Architecture Assessment

| 目录 | 定位 | 审计结论 |
|---|---|---|
| `components/relation/` | 跨内容商业关联展示 | PASS — `RelatedContentSection` 为共享底座，`RelatedProducts`/`RelatedSolutions`/`RelatedKnowledge` 为瘦包装，无重复逻辑 |
| `components/conversion/` | 转化 CTA | PASS — `DemandCTA`/`InquiryCTA` 为 client 组件（analytics），复用既有 Demand/询价流程 |
| `components/commercial/` | 供应商能力画像 | PASS — `SupplierCapability` 纯展示，按 Offer 去重展示能力，无商城语义 |

审查点：

- **重复逻辑**：无。方案/知识关联复用同一 `RelatedContentSection`，产品关联独立但结构与共享底座一致。
- **过度耦合**：无。relation 组件为受控（props）展示组件，数据由 Server Page 注入；conversion 组件通过 `contextType` 解耦来源。
- **Next.js App Router 边界**：符合。Server Component 页面负责取数；Client Component 负责交互/Analytics。`RelatedProducts` 等被 Server Components 直接渲染，无"client 内嵌 async"坏味道。
- **未来商业化扩展**：支持。relation 层以 props 契约存在，后续可扩展映射数据源而不改展示层。

```
Component Architecture:
PASS

## 6. Relation Strategy Assessment

当前策略：**Latest Published Priority**（最新发布优先）。

审计确认：

- `getProducts({ sortBy:'createdAt', sortOrder:'desc' })` 与 `getContentList({ sort:'publishedAt', order:'desc' })` 均为**确定性排序**，无 AI/语义关键词推断。
- 「相关」为页面级数据组合，非后端模糊匹配；空态与 API 失败均显式降级。
- 明确属于 **MVP Deterministic Relation**（确定性关联），符合既有"确定性映射/禁 AI 猜测"的架构冻结要求。

未来演进方向（未引入 AI Semantic Matching）：

```
Category Mapping
Parameter Mapping
Tag Mapping
Manual Curated Relation
```

这些方向可在不改变组件展示契约的前提下，替换 relation 数据源实现，具备平滑迁移能力。

```
Relation Strategy:
PASS
