## 2. 修改原因

Phase 1 Schema Migration 已将 `Demand.rfq` 单关系迁移为 `Demand.rfqs` 数组关系，但 `apps/api/src/demands/demands.service.ts` 中仍残留旧 relation shape，导致 `@visndt/api` 构建失败。

本次任务仅在冻结允许范围内，对旧引用进行 relation shape cleanup，不改变既有业务入口、权限模型或领域语义。

## 3. Prisma relation 迁移影响

### 3.1 关闭需求时的关联 RFQ 处理

- 原实现：
  - `include: { rfq: ... }`
  - `demand.rfq`
- 迁移后：
  - `include: { rfqs: ... }`
  - `demand.rfqs`

为保持原逻辑语义，需求关闭时会对该 Demand 下仍处于 `OPEN` 状态的关联 RFQ 执行关闭，并逐条写入既有 `WorkflowEvent` 留痕。

### 3.2 删除需求时的依赖检查

- 原实现依赖：
  - `demand.rfq`
- 迁移后依赖：
  - `demand._count.rfqs`

该调整仅将单对象存在性判断替换为数组关系计数判断，未改变“存在 RFQ 依赖时禁止删除 Demand”的业务规则。
