## 4. Database Capability Assessment

### 4.1 Existing Capability

| 模型 | 现有字段 | Supplier Display 可用字段 |
| --- | --- | --- |
| Organization | id, name, type, status, createdAt, updatedAt | name, type, status |
| Offer | id, organizationId, productId, title, description, price, currency, status | title, description, status, organization (via relation) |
| Product | id, categoryId, name, model, description, status | offers[] (via relation) |

### 4.2 Missing Capability

| 缺失能力 | 说明 | 影响 |
| --- | --- | --- |
| Organization 丰富展示字段 | 无 logo、description、location、website、capabilities | Supplier Profile 展示信息不足 |
| Supplier 专属标识 | 无 isSupplier / supplierType 字段 | 无法区分 Supplier 与其他类型 Organization |
| Offer Supplier Display 字段 | 无 capability 描述、supplierNote 等 | Offer 仅承载报价信息，非 Supplier 能力展示 |
| Supplier 产品目录 | 无独立 Supplier Product List | 需通过 Offer 反查 Product |

### 4.3 Schema Decision

**结论：M19.2 保持 Zero Schema Change** ✅

理由：
1. 当前 Product → Offer → Organization 关系链已满足基础 Supplier Display 需求（name + type + status + title + description）
2. 前端已有 [SupplierCapabilityList](file:///f:/Desktop/VISNDT/VISNDT/apps/web/src/components/products/SupplierCapabilityList.tsx)、[ManufacturerInfo](file:///f:/Desktop/VISNDT/VISNDT/apps/web/src/components/products/ManufacturerInfo.tsx) 组件，可直接消费现有 API 数据
3. Organization 丰富字段（logo/description/location）可在 M19.2 通过前端展示优化实现（利用现有字段），如需新增字段则进入 M19.3+ 评估
4. 架构冻结原则：**Backend Capability First，前端消费现有能力，零 Schema 变更优先**
