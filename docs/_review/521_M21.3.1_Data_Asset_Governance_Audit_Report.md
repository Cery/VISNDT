### 5.2 Domain Quality Detail

#### Product Domain — B+

**Strengths**:
- ProductCategory 有 slug 唯一约束，支持 SEO 友好 URL
- ProductParameterValue 有 (productId, definitionId) 唯一约束，防止重复参数
- 参数体系完整：Group → Definition → Option → Value 四层结构
- 所有 Model 都有 createdAt/updatedAt

**Weaknesses**:
- Product 无 slug 字段（路由使用 slug 但 Schema 无此字段，依赖前端转换）
- Product 无 seoTitle/seoDescription/seoKeywords
- Product.status 为 String 类型（非 Enum），缺乏类型安全
- ProductMedia 的 fileAssetId 为 optional（nullable），允许无文件引用的媒体记录

#### Content Domain — A-（最高质量域）

**Strengths**:
- Content 有 slug 唯一约束
- Content 有完整 SEO 字段（seoTitle, seoDescription, seoKeywords）
- Content 有完整生命周期字段（publishedAt, archivedAt, scheduledPublishAt）
- ContentRevision 独立版本快照（12 字段），版本历史与主数据分离
- ContentTag + ContentTagRelation 建立标签体系，支持多对多关系
- Content.status 为 Enum 类型（ContentStatus），类型安全

**Weaknesses**:
- ContentTag 无 Index（除 slug unique 外），tag 查询性能可能不足
- ContentRevision 无 (contentId, version) unique 约束（仅 Index）

#### Offer Domain — B

**Strengths**:
- (organizationId, productId) 唯一约束，防止重复 Offer
- OfferStatus 为 Enum，类型安全
- 有完整的 price/currency 字段（虽平台不展示）

**Weaknesses**:
- 无 offer 生命周期时间字段（如 activatedAt, withdrawnAt）
- Offer 与 RFQResponse 的关联为 optional（offerId nullable）

#### Buyer Domain — B+

**Strengths**:
- Demand 18 字段，为全 Schema 最丰富模型，含联系人/预算/数量/交付日期
- DemandMatch 有 matchScore 量化匹配度
- RFQ 有完整的 targetOrganizationId 定向机制
- RFQResponse 有 (rfqId, orgId) 唯一约束 + reviewedBy 审核人

**Weaknesses**:
- Demand.status 为 Enum 但缺少 MATCHED 状态（MATCHED 仅在 DemandMatch 中）
- RFQResponse 无独立的 response 内容字段（仅有 message），缺少结构化报价数据
- DemandMatch 的 offerId 为 optional，匹配可能不关联具体 Offer

#### Inquiry Domain — B

**Strengths**:
- InquiryStatus 为 Enum，生命周期完整：NEW → PROCESSING → REPLIED → CLOSED
- 有 contactName/contactEmail/contactPhone 联系人信息
- 5 个 Index 覆盖 organizationId/productId/createdById/status/createdAt

**Weaknesses**:
- productId 和 organizationId 均为 optional，允许无关联的咨询记录
- 无 replyContent/repliedAt 字段，无法追踪回复内容

#### Identity Domain — B-

**Strengths**:
- User.email 唯一约束
- OrganizationMember 有 (orgId, userId) 唯一约束
- UserInvitation 有 token 唯一约束 + expiresAt 过期机制

**Weaknesses**:
- Organization 仅 5 字段（id/name/type/status/timestamps），无 logo/description/website/industry
- Organization.type 为 String 而非 Enum，缺乏类型约束
- User 无 role 字段，角色信息仅存在于 OrganizationMember
- User 无 lastLoginAt/emailVerified 等安全字段

#### System Domain — B+

**Strengths**:
- WorkflowEvent 有 entityType+entityId 复合索引，支持高效查询
- AuditLog 有 oldValue/newValue JsonB 字段，支持完整变更追踪
- FileAsset 通过 entityType+entityId 关联任意实体，统一资源管理

**Weaknesses**:
- AuditLog.entityType 为 String 而非 Enum，与 WorkflowEvent.entityType（Enum）不一致
- FileAsset 无 fileSize 单位说明（假设为 bytes）
- Notification 的 referenceType 为 String 而非 Enum
- 缺少 ConversionEvent 持久化模型（520 报告 P0 缺口）

## 6. Lifecycle Assessment

### 6.1 Status Lifecycle Maps

#### Inquiry Lifecycle（完整）

```
NEW ──→ PROCESSING ──→ REPLIED ──→ CLOSED
  │                                      ▲
  └──────────────────────────────────────┘
         (可直接关闭，跳过处理)
```

**评估**: 生命周期完整，4 状态覆盖创建→处理→回复→关闭全流程。CLOSED 为终态。

#### Demand Lifecycle（丰富但缺 MATCHED 状态）

```
DRAFT ──→ PUBLISHED ──→ SUBMITTED ──→ PROCESSING ──→ CLOSED
  │                        │
  └──→ CANCELLED           └──→ CANCELLED
```

**评估**: 6 状态覆盖草稿→发布→提交→处理→关闭/取消。但 Demand 自身无 MATCHED 状态（匹配状态仅在 DemandMatch 中），导致 Demand 状态与 Match 状态脱节。

#### Offer Lifecycle（复杂但可简化）

```
DRAFT ──→ ACTIVE ──→ SUBMITTED ──→ ACCEPTED
  │         │            │            │
  │         └──→ INACTIVE │            └──→ REJECTED
  └──→ WITHDRAWN         └──→ WITHDRAWN
```

**评估**: 7 状态，但 ACTIVE/INACTIVE/SUBMITTED 三态语义重叠。INACTIVE 和 WITHDRAWN 功能相似。

#### RFQ Lifecycle（标准）

```
DRAFT ──→ OPEN ──→ RESPONDING ──→ CLOSED
  │         │                       │
  └──→ CANCELLED                    └──→ CANCELLED
```

**评估**: 5 状态，流程清晰。RESPONDING 为中间态（等待供应商响应）。

#### RFQResponse Lifecycle（简洁）

```
SUBMITTED ──→ VIEWED ──→ ACCEPTED
                │            │
                └──→ REJECTED
```

**评估**: 4 状态，覆盖提交→查看→接受/拒绝。终态明确（ACCEPTED/REJECTED）。

#### Content Lifecycle（最成熟）

```
DRAFT ──→ REVIEW ──→ PUBLISHED ──→ ARCHIVED
  │                    │
  └──→ ARCHIVED        └──→ ARCHIVED
```

**评估**: 4 状态，支持 scheduledPublishAt 定时发布。ARCHIVED 为终态。生命周期最完整，配合 ContentRevision 版本历史 + WorkflowEvent 审核时间线。
