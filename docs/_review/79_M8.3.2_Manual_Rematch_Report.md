## 1. Phase Overview

**目标：** 增加 Demand 手动重新匹配能力，允许用户在修改 Demand 参数或产品数据变更后，手动触发重新匹配。

**流程：**
```
POST /api/v1/demands/:id/rematch
  → 权限检查 (owner/org ADMIN)
  → 删除旧 DemandMatch 记录
  → MatchingService.match(demandId)
  → 返回匹配结果统计
```

## 3. API Impact

### 3.1 新增端点

| 属性 | 值 |
|------|-----|
| Method | `POST` |
| Path | `/api/v1/demands/:id/rematch` |
| Auth | `@UseGuards(JwtAuthGuard)` + `@ApiBearerAuth()` |
| Permission | Demand owner 或同一 Organization 用户 |

### 3.2 请求

```
POST /api/v1/demands/{id}/rematch
Authorization: Bearer <token>
```

### 3.3 响应

```json
{
  "success": true,
  "message": "Rematch completed",
  "data": {
    "demandId": "uuid",
    "matched": 5,
    "skipped": 2,
    "totalCandidates": 10,
    "elapsedMs": 150
  }
}
```

### 3.4 错误响应

| 场景 | HTTP Code | 说明 |
|------|-----------|------|
| Demand 不存在 | 404 | `Demand {id} not found` |
| 无权限 (不同组织) | 400 | `You do not have permission...` |
| 无组织绑定 | 400 | `User must belong to an organization` |
