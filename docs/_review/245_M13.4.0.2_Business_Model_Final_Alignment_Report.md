## 3. 审查 2: 供应商合作入口设计

### 3.1 问题分析

244 规划中，供应商的公开入口被完全删除。这带来一个问题：**企业如何发现 VISNDT 平台并入驻？**

当前 244 的隐式合作路径：
```
企业 → 在 VISNDT 上看到自己产品 → 发现产品已有 Offer → 联系平台管理员 → 获得邀请码 → 注册
```

这个路径过于隐式，需要补充一个**明确的合作入口页面**。

### 3.2 方案评估

| 方案 | URL | 定位 | 评估 |
|------|-----|------|------|
| A: 无入口 | — | 仅靠邀请制 | ❌ 过于封闭，企业无法自主发现入驻渠道 |
| B: `/join` | /join | 企业入驻 | ⚠️ 名称暗示"加入我们"，可能被理解为供应商注册 |
| C: `/partner` | /partner | 合作伙伴 | ⚠️ 名称暗示"合作伙伴关系"，过于对等 |
| D: `/business` | /business | 商业合作 | ✅ 中性表达，涵盖企业入驻、产品合作、采购需求 |

### 3.3 推荐方案: `/business`

```
推荐: /business

定位: 商业合作入口页 (不是供应商目录!)

目的:
  ✅ 企业入驻申请 (如何成为 VISNDT 上的产品提供方)
  ✅ 产品合作 (如何让产品出现在 VISNDT 产品中心)
```

## 5. 审查 4: 产品详情页商业闭环检查

### 5.1 当前闭环路径

244 的产品详情页闭环路径：

```
产品详情页:
  ├── 产品信息 (名称, 型号, 描述)               ✅
  ├── 技术参数 (参数表)                          ✅
  ├── 图片 Gallery                              ✅
  ├── 应用场景                                   ✅
  ├── 制造商信息 (名称, 资质, 联系按钮)           ✅
  ├── "Request Quotation" 按钮                  ✅
  │     → 跳转 /demands/new?productId=xxx        ✅
  └── "Contact Manufacturer" 按钮                ✅
        → 弹出联系表单                            ✅
```

### 5.2 缺失环节分析

当前闭环有一个缺陷：**"Request Quotation" 和 "Contact Manufacturer" 都是重量级操作**。

- "Request Quotation" → 创建完整需求 (4 步骤表单)
- "Contact Manufacturer" → 直接联系

**缺少一个轻量级的"第一次接触"机制** — 用户可能只是想了解产品信息、询问交货期、确认价格范围，而不是立即创建正式采购需求。

### 5.3 推荐: 新增 Inquiry 机制

在产品详情页增加一个**轻量级的 Inquiry (咨询)** 按钮，作为 "产品 → 用户 → 企业" 的第一次连接：

```
产品详情页 CTA 层级:
  ┌──────────────────────────────────────────────────────┐
  │ 🏭 Acme NDT Solutions                                │
  │ ISO 9001:2015, CE Certified                          │
  │                                                      │
  │ [💬 Quick Inquiry]  [📋 Request Quotation]           │
  │       ↑ 新增               ↑ 已有                    │
  └──────────────────────────────────────────────────────┘

Quick Inquiry (轻量咨询):
  - 用户点击 → 弹出简单表单 (姓名, 邮箱, 消息, 可选电话)
  - 不需要登录 (Visitor 也可发起)
  - 提交后 → 创建 Inquiry 记录 → 通知企业联系人
  - 目的: 降低首次接触门槛

Request Quotation (正式询盘):
  - 需要登录
  - 创建完整 Demand
  - 触发匹配流程
  - 目的: 正式采购流程
```

### 5.4 完整商业闭环

```
Visitor 浏览产品
  ↓
点击 "Quick Inquiry"
  ↓
填写简单表单 (姓名, 邮箱, 消息)
  ↓
提交 → Inquiry 记录创建
  ↓
企业收到通知
  ↓
企业回复 → 建立联系
  ↓
Visitor 注册 → 成为 Buyer
  ↓
创建正式 Demand → 触发匹配
  ↓
RFQ → 报价 → 成交
```

### 5.5 判定

```
✅ 通过 — 产品详情页商业闭环基本完整

调整项:
  1. 新增 "Quick Inquiry" 轻量咨询按钮
  2. 与 "Request Quotation" 形成两级 CTA:
     - Quick Inquiry: 轻量, 无需登录, 降低门槛
     - Request Quotation: 正式, 需要登录, 完整流程
  3. 新增 Inquiry 数据模型 (M13.4 可暂用 Notification 替代)
```

## 9. 供应商角色定义 (冻结版)

### 9.1 角色定位

```
Supplier ≠ 独立平台角色
Supplier = Organization.type='supplier' 的企业组织成员

在 VISNDT 中:
  - 供应商不是卖家/店铺主
  - 供应商是产品提供方 (Product Provider)
  - 供应商是需求响应方 (Demand Responder)
  - 供应商是合作参与方 (Cooperation Participant)
```

### 9.2 供应商权限边界

```
✅ 供应商可以:
  - 在产品详情页中作为产品来源企业被展示
  - 查看本组织关联的产品 (参与产品)
  - 接收与产品匹配的采购需求 (合作机会)
  - 查看撮合记录和匹配分数
  - 接收和响应 RFQ
  - 提交报价
  - 查看报价历史
  - 管理联系人信息
  - 查看收到的 Quick Inquiry
  - 接收通知

❌ 供应商不可以:
  - 拥有独立主页/SEO 页面
  - 创建/编辑产品 (产品由 Admin 管理)
  - 自主上架/下架产品
  - 拥有产品目录
  - 被评分/排名
  - 被关注/收藏
  - 自定义店铺页面
  - 浏览其他供应商
```

### 9.3 供应商入驻流程

```
企业访问 /business
  ↓
了解 VISNDT 合作模式
  ↓
提交入驻申请 (POST /business/applications)
  ↓
平台审核 (1-3 工作日)
  ↓
审核通过 → 管理员创建 Organization + 发送邀请码
  ↓
企业联系人注册 (POST /auth/register)
  ↓
关联到 Organization
  ↓
管理员创建 Offer (关联 Product → Organization)
  ↓
产品出现在产品中心 (制造商信息区块)
  ↓
开始接收需求匹配和 RFQ
```
