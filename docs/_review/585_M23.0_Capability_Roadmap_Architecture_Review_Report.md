## 4. Capability Deep-Dive Assessment

### 4.1 Product Capability

**Current State:** Product model is frozen and stable. Supports Category → ParameterDefinition → ProductParameterValue hierarchy. Device-agnostic design supports all NDT equipment types (Ultrasonic, Radiographic, Magnetic Particle, etc.) without code changes.

**Assessment:**
- Product Center = Industrial Equipment Asset Catalog ✓
- Parameter system = Extensible, data-driven ✓
- Category system = Data-driven, NDT-expandable ✓
- No marketplace/store/price drift ✓

**M23 Direction:** Maintain. No expansion needed. Product model is complete for current scope.

### 4.2 Supplier Capability

**Current State:** M22.1 delivered Supplier Workspace with Dashboard, Profile, Offer Management, RFQ Response, Business Opportunity Center. Self-service profile editing through PATCH /organizations/:id.

**Capability Gaps:**
- Supplier public profile page is basic
- No supplier capability portfolio view
- No supplier content/knowledge association
- RFQ response workflow is manual

**Assessment:**
- Core supplier workflow = Complete ✓
- Self-service maturity = Partial (M22.1 scope)
- Supplier discovery = via Unified Search ✓

**M23 Direction:** P2 Evaluate. Supplier Experience maturity improvement is dependent on business demand. Not a P0/P1 priority for M23.0.

### 4.3 Knowledge Capability

**Current State:** M22.3 delivered complete Knowledge Base: 5 models (Domain, Category, Entry, ContentRef, Relation), 3 enums, 22 Admin API + 5 Public API, 9 Admin pages + 3 Web pages. KnowledgeEntry SEO fields fully utilized. Knowledge Relation network operational.

**Capability Gaps:**
- Knowledge Context Adapter not implemented (M23.0 deliverable)
- Knowledge-to-Product association not established
- Knowledge-to-Scenario mapping not established
- No knowledge recommendation in matching/demand flow

**Assessment:**
- Knowledge Base core = Complete ✓
- Knowledge Context = Designed (584), not implemented
- Knowledge Application = Future

**M23 Direction:** **P0 Foundation.** Knowledge Context is the highest priority M23.0 deliverable. Without it, Knowledge Base remains an isolated asset without application integration.

### 4.4 Matching Capability

**Current State:** `weighted_v1` algorithm is stable and deterministic. Demand Parameter → Product Parameter → Score → DemandMatch pipeline proven. 3 match strategies (NUMBER range, ENUM exact, STRING exact). Hard fail for required parameters. Match lifecycle (PENDING → REVIEWED → ACCEPTED/REJECTED) complete.

**Capability Gaps:**
- Match explanation is raw parameter scores only
- No human-readable match reasoning
- No knowledge context alongside match results
- No scenario-based matching guidance

**Assessment:**
- Matching core = Frozen, stable ✓
- Match explainability = Basic (raw scores)
- Knowledge integration = Designed (584), not implemented

**M23 Direction:** **P2 Explainability.** Matching algorithm is frozen. Enhancement focus is on match detail UX and knowledge context display — not on scoring changes.

### 4.5 Search Capability

**Current State:** M22.4.1 delivered unified `GET /search` with 5 entity adapters. M22.4.2 delivered unified discovery UX (Desktop + Mobile). M22.4.3 delivered SEO asset architecture (sitemap + JSON-LD + metadata). KnowledgeEntry replaces Content(KNOWLEDGE) as primary knowledge source.

**Capability Gaps:**
- Multi-entity pagination is per-entity (not unified page)
- Content type filter is client-side only (on loaded results)
- Parameter-related filter not implemented
- No search analytics
- No search relevance tuning

**Assessment:**
- Unified Search API = Complete ✓
- Discovery Experience = Complete ✓
- SEO Asset = Complete ✓
- Search optimization = P2 items deferred

**M23 Direction:** **P1 Optimize.** Search foundation is solid. M23 focus is on incremental optimization: analytics, filter enhancement, and relevance monitoring.

### 4.6 AI Capability

**Current State:** M21.7 delivered 7-layer AI Foundation (Gateway, Semantic, Tool Registry, Adapter, Assistant, RAG, Context). All layers are interface/contract only — zero runtime implementation. AI remains FROZEN by architecture decision.

**Assessment:**
- AI Foundation = Interfaces complete, runtime frozen ✓
- AI boundary = Clearly defined (AI ≠ Matching Engine, AI ≠ Auto Decision) ✓
- AI readiness = Contract-only, not operational

**M23 Direction:** FROZEN. AI remains at interface/contract level. ADR-018 (AI ≠ Matching Engine) and ADR-017 (Knowledge ≠ Score Input) remain in effect. M23.3 may explore AI Decision Support interface design (no runtime).

### 4.7 Content Capability

**Current State:** M22.2 delivered complete Content Center: 4 types (ARTICLE, KNOWLEDGE, INSIGHT, SOLUTION), 4 statuses (DRAFT, REVIEW, PUBLISHED, ARCHIVED), ContentMedia, ContentRevision, ContentTag, ContentChunk. 10 API endpoints. Admin CRUD complete. Web experience complete.

**Assessment:**
- Content publishing = Complete ✓
- Content SEO = Complete ✓

**M23 Direction:** Maintain. Content system is stable. No new content types. No content model changes.

## 7. Architecture Decision Register (M23)

| ADR | Decision | Status | Rationale |
|-----|----------|--------|-----------|
| ADR-M23-001 | M23.0 Focus = Knowledge Context Foundation | ACTIVE | Knowledge Base is complete but isolated. Knowledge Context bridges the gap between Knowledge and Matching/Search without modifying either. |

| ADR-M23-004 | Matching Enhancement = UX Only, No Algorithm Change | ACTIVE | weighted_v1 is frozen. Enhancement is human-readable explanation and knowledge context display — not scoring changes. |
| ADR-M23-005 | Supplier Maturity = Business-Driven, Not Roadmap-Driven | ACTIVE | M22.1 delivered core workflow. Further investment depends on business demand, not technical roadmap. |
| ADR-M23-006 | Scenario Understanding = M23.1+, Not M23.0 | ACTIVE | Interface designed (584 ADR-019). Implementation requires Knowledge Context as prerequisite. |
| ADR-M23-007 | AI = FROZEN Through M23.0 | ACTIVE | AI interfaces remain as contracts. ADR-018 in effect. No AI runtime, no auto-decision, no auto-match. |
| ADR-M23-008 | M23 Zero-Drift Principle | ACTIVE | No new model, no new API pattern, no marketplace expansion, no AI activation. M23 = optimize existing, don't create new. |
