## Unfreeze Reason

### Why Frontend-Only is Insufficient

| Capability | Frontend Only | Backend Required |
|------|:---:|:---:|
| Recent Activities (last 5 users, demands, matches) | ❌ No API exists | ✅ Read-only Prisma queries |
| Pending Items (counts by status) | ❌ No API exists | ✅ Prisma count queries |
| System Summary (health + freshness) | ❌ No API exists | ✅ Simple status check |

**Conclusion**: Dashboard operational awareness requires Backend extension. The data already exists in PostgreSQL — only read-only API endpoints are needed.

## Proposed API Design

### 1. GET /admin/dashboard/activities

**Purpose**: Recent platform activities — last N events across all entities.

**Query Parameters**:

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `limit` | `number` | `5` | Max results per category |

**Response**:

```typescript
{
  users: User[];        // Last N registered users
  demands: Demand[];    // Last N created demands
  matches: DemandMatch[]; // Last N matches
  notifications: Notification[]; // Last N unread notifications
}
```

**Implementation**: Prisma `findMany` with `orderBy: { createdAt: 'desc' }`, `take: limit`.

### 2. GET /admin/dashboard/pending

**Purpose**: Pending items requiring admin attention.

**Response**:

```typescript
{
  usersPending: number;           // Users with INACTIVE or SUSPENDED status
  demandsPending: number;         // Demands not yet published
  rfqPending: number;             // RFQs awaiting response
  unreadNotifications: number;    // Total unread notifications
}
```

**Implementation**: Prisma `count` with `where` filters.

### 3. GET /admin/dashboard/status

**Purpose**: System health summary.

**Response**:

```typescript
{
  database: 'connected';          // Prisma connection check
  api: 'healthy';                 // API status
  lastUpdated: string;            // ISO timestamp of most recent activity
  entityCounts: {
    users: number;
    organizations: number;
    products: number;
    demands: number;
    matches: number;
  };
}
```

**Implementation**: Simple Prisma checks + `findFirst` with `orderBy: { createdAt: 'desc' }` across entities.

## Security Design

### Authentication & Authorization

```typescript
@ApiTags('Admin Dashboard')
@Controller('admin/dashboard')
@UseGuards(JwtAuthGuard, RolesGuard)   // ← Same as existing
@Roles(Role.ADMIN)                      // ← Same as existing
@ApiBearerAuth()                        // ← Same as existing
```

**All 3 new endpoints must use the existing class-level guards.**

### Data Safety

| Rule | Implementation |
|------|---------------|
| Only aggregate/recent data | No individual user details |
| No password fields | Prisma `select` excludes `passwordHash` |
| No cross-org business data | Counts only, no org-specific breakdown |
| ADMIN role only | `@Roles(Role.ADMIN)` class-level guard |
