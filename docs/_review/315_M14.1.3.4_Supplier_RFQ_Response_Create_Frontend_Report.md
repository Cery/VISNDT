
分层说明：

- 页面组件层：[page.tsx:L120-L144](file:///F:/Desktop/VISNDT/VISNDT/apps/web/src/app/workspace/supplier/rfqs/%5Bid%5D/page.tsx#L120-L144) 负责 UI 状态、输入 trim、空值过滤、loading/success/error 三态维护；**不直接调用 api lib**

HTTP 请求特征：

- Method: `POST`

## 4. 页面流程

页面路由：`/workspace/supplier/rfqs/[id]`

### 4.1 进入页面

1. `AuthGuard` 强制登录
2. `RoleGuard roles={['SUPPLIER']}` 限定仅 Supplier 角色可见
3. `loadRfq()` 调用 `getRfq(id)`，维护 `isLoading / error / rfq` 三态（既有逻辑未改动）

### 4.2 初始信息区

- 原禁用按钮「响应此RFQ（开发中）」替换为可点击的 indigo 主题按钮：
  - 行为：平滑滚动到 id=`rfq-response-form` 的响应表单区块（不强制要求用户滚到页面底部）
  - 样式：沿用现有 Tailwind / 圆角 / shadow-sm / focus:ring-2 风格，与 Buyer RFQ 页面按钮一致

### 4.3 响应表单区块（新增）

区块位置：组织信息卡片之后、`</>` 之前，新增独立 `<section>`。

字段：

| 字段 | DOM | 必选 | 说明 |
|------|-----|------|------|
| Offer ID | `<input type="text">` | 否 | 自由文本输入；placeholder 示例 `off_xxxxxx`；提交前 trim；空则不发送字段 |
| Message | `<textarea rows="5">` | 否 | 自由文本；resize-y；提交前 trim；空则不发送字段 |

操作按钮：

- 「清空」：重置 `responseMessage / responseOfferId / submitError / submitSuccess`；loading 期间禁用
- 「提交响应」：调用 `handleSubmitResponse()`；loading 期间禁用并显示 spinner 文案「提交中...」

### 4.4 提交状态机

- **Loading (`isSubmitting = true`)**：两输入框 + 两按钮 disabled；提交按钮显示 inline SVG 旋转动画
- **Success (`submitSuccess = true`)**：隐藏表单与错误区；展示 emerald 主题成功卡片，内容：
  - 标题：响应提交成功
  - 说明：已成功提交；同一组织对同一 RFQ 仅允许一次响应；**不做任何自动跳转或 router.push**
  - 成功卡片持续保留，用户可自行导航离开
- **Error (`submitError !== ''`)**：保留表单当前值不丢，上方展示 rose 主题错误卡片，含语义化标题「提交失败」与具体原因文案；用户可修改后重试

### 4.5 错误语义映射（对齐 314 报告）

错误映射函数：[page.tsx:L54-L84](file:///F:/Desktop/VISNDT/VISNDT/apps/web/src/app/workspace/supplier/rfqs/%5Bid%5D/page.tsx#L54-L84)

| 后端异常（314 已硬化） | HTTP 状态 | 前端提示文案 |
|----------------------|-----------|-------------|
| RFQ 不存在（NotFoundException） | 404 | RFQ 不存在，可能已被删除。 |
| RFQ 未开放（OPEN + publishedAt 校验失败 / BadRequestException） | 400 | 当前 RFQ 未开放响应，请等待发布后再试。 |
| offerId 不存在 / 不属于当前组织（BadRequestException，message 含 offer） | 400 | 所选 Offer 非法或不属于您的组织，请检查后重试。 |
| 无 organizationId / 非有效 OrganizationMember / 用户或组织非 ACTIVE（BadRequestException 或 Forbidden，message 含 organization/member/组织/成员） | 400/403 | 您不是有效组织成员，无法提交 RFQ 响应。 |
| 重复响应预查冲突（ConflictException 或 P2002 兜底） | 409 | 您已对此 RFQ 提交过响应，请勿重复提交。 |
| 会话过期 / 401 | 401 | 登录状态已过期，请重新登录。 |
| 其他状态码 | N/A | 优先使用后端 `errorBody.message`，否则「提交失败（N），请稍后重试。」 |
| 非 ApiError（fetch 网络层失败） | N/A | 提交失败，网络异常或服务暂时不可用。 |

## 9. 已知限制

本实现严格按任务清单收敛，存在以下**已知但刻意保留**的限制：

1. **offerId 采用自由文本输入，未提供下拉选择**
   - 原因：任务要求「禁止修改 RFQ 类型体系 / 禁止新增 API」，前端当前无 `getOffersByOrg` 等可复用的 Offer 列表封装；引入选择器需要额外扩展 offers API
   - 提示：已在 placeholder 中给出 `off_xxxxxx` 示例

2. **message 与 offerId 在前端均为可选**
   - 原因：严格对齐 313/314 后端 DTO 契约（二者都是 optional）；不自行追加前端必选校验

3. **提交成功后未自动刷新详情 / 未刷新我的响应列表**
   - 原因：任务要求「不要自动跳转 / 不要开发响应列表」；保持成功提示即可

4. **错误映射依赖状态码 + message 关键字双重启发式**
   - 原因：314 后端抛出的 Nest 异常未使用结构化错误码；若后端异常消息措辞大改，前端提示可能退化到通用文案
   - 兜底：`default` 分支始终优先回显 `err.message`，不会丢失后端真实信息

5. **未对 Supplier 角色再追加服务端组件级限制**
   - 原因：保持与现有页面一致的 `RoleGuard roles={['SUPPLIER']}` 客户端守卫；未改动权限体系

6. **未加表单长度限制 / XSS 防护额外 sanitize**
   - 原因：页面本身提交后只读展示后端 message（后端当前创建接口未 include offer 等），不自行拼接原始 HTML；沿用既有 api-client JSON.stringify 路径；未越界修改公共安全策略
