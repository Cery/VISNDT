## 3. Why Context Handoff Is Required

### 3.1 Problem Statement

The VISNDT project has accumulated:
- **130+ review reports** across 11 major phases
- **24 backend modules** with complex interdependencies
- **40+ admin pages** with 48 routes
- **24 Prisma models** with 14 enums
- **6 remaining technical debt items**
- **Strict freeze rules** that vary by phase

Without centralized context documentation, each new chat session must:
1. Read project memory (cached)
2. Read multiple review reports to understand current state
3. Re-discover freeze rules and constraints
4. Re-understand module dependencies
5. Waste ~5-10 turns on context recovery

### 3.2 Solution

The `docs/context/` directory provides a single, version-controlled source of truth for project context. Each file serves a specific purpose:

| File | Purpose | Audience |
|---|---|---|
| `PROJECT_CONTEXT_MASTER.md` | Complete project overview | New chat sessions |
| `CURRENT_STATUS.md` | Current phase + recent changes | New chat sessions |
| `ARCHITECTURE_FREEZE.md` | What can/cannot be modified | Implementation phases |
| `DATABASE_CONTEXT.md` | Prisma models, relations, constraints | Backend development |
| `API_CONTEXT.md` | API endpoints, modules, conventions | Backend development |
| `FRONTEND_CONTEXT.md` | Admin UI, router, components | Frontend development |
| `ROADMAP_CONTEXT.md` | Historical + future phase planning | Planning sessions |
| `HANDOFF_TEMPLATE.md` | Standardized phase report format | All phases |

## 7. Future Workflow Rules

### 7.1 New Chat Session Workflow

```
1. Read docs/context/PROJECT_CONTEXT_MASTER.md     (5 min)
2. Read docs/context/CURRENT_STATUS.md              (2 min)
3. Read docs/context/ARCHITECTURE_FREEZE.md         (3 min)
4. Read relevant phase report from docs/_review/    (2 min)
5. Proceed with task
```

**Total context recovery:** ~12 minutes (vs. ~30+ minutes without context docs)

### 7.2 Phase Execution Workflow

```
1. Read CURRENT_STATUS.md → understand current state
2. Check ARCHITECTURE_FREEZE.md → verify constraints
3. Execute phase → modify files
4. Generate report → use HANDOFF_TEMPLATE.md
5. Update CURRENT_STATUS.md → reflect new state
6. (Optional) Update PROJECT_CONTEXT_MASTER.md → reflect major changes
```

### 7.3 Context Maintenance Rules

| Event | Files to Update |
|---|---|
| Phase completed | `CURRENT_STATUS.md`, `ROADMAP_CONTEXT.md` |
| New API endpoint | `API_CONTEXT.md` |
| New admin page | `FRONTEND_CONTEXT.md` |
| Freeze rule change | `ARCHITECTURE_FREEZE.md` |
| Database migration | `DATABASE_CONTEXT.md` |
| Major architecture change | `PROJECT_CONTEXT_MASTER.md` |
