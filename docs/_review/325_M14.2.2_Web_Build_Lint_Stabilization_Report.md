## 4. 每个 lint 问题修复说明

### 4.1 `apps/web/src/lib/api/rfqs.ts`

问题：

- 规则：`@typescript-eslint/no-empty-object-type`
- 原因：`RfqDetailItem` 以空接口形式继承 `RfqItem`，语义上等价于父类型，触发规则报错。

修复：

- 将空接口继承改为类型别名：
  - `export interface RfqDetailItem extends RfqItem {}`
  - 改为 `export type RfqDetailItem = RfqItem;`

修复理由：

- 保持 `RfqDetailItem` 仍然表示与 `RfqItem` 相同的数据语义。
- 不改变任何调用方的导入方式与使用方式。
- 不涉及 API 请求结构或响应结构改造。

### 4.2 `apps/web/src/services/inquiry.service.ts`

问题：

- 规则：`@typescript-eslint/no-explicit-any`
- 原因：`getMyInquiries` 返回类型写成 `Promise<{ data: any[]; total: number }>`，使用了显式 `any`。

修复：

- 将返回类型改为 `ReturnType<typeof fetchMyInquiries>`。

修复理由：

- 直接复用 API 层 `fetchMyInquiries` 的真实返回类型。
- 保持服务层函数签名与函数调用方式不变。
- 避免人工重复声明类型，降低后续类型漂移风险。
