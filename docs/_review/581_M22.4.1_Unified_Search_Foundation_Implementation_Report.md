## 3. Unified Search Verification

### Search Adapter Architecture

```
GET /search?q={keyword}
        │
        ▼
  SearchService.search()
        │
        ├── searchProducts()      → Product Discovery
        ├── searchKnowledgeEntries() → KnowledgeEntry Discovery (ADR-003)
        ├── searchContent()       → Content Discovery (ARTICLE, INSIGHT)
        ├── searchContent()       → Solution Discovery (SOLUTION)
        └── searchSuppliers()     → Supplier Capability Discovery
        │
        ▼
  UnifiedDiscoveryResponse
```

### Response Contract

```typescript
interface UnifiedDiscoveryResponse {
  query: string;
  products: EntitySearchGroup<ProductDiscoveryItem>;
  knowledge: EntitySearchGroup<KnowledgeDiscoveryItem>;
  content: EntitySearchGroup<ContentDiscoveryItem>;
  solutions: EntitySearchGroup<ContentDiscoveryItem>;
  suppliers: EntitySearchGroup<SupplierDiscoveryItem>;
}
```

| Entity Type | Search Fields | Status |
|-------------|--------------|--------|
| Product | name, model, description | ACTIVE |
| KnowledgeEntry | title, summary | ACTIVE (replaces Content KNOWLEDGE) |
| Content (ARTICLE, INSIGHT) | title, summary | ACTIVE |
| Content (SOLUTION) | title, summary | ACTIVE |
| Content (KNOWLEDGE) | EXCLUDED | KNOWLEDGE excluded per ADR-003 |
| Supplier | offer title, description (aggregated by org) | ACTIVE |

### Frontend Migration

| Before (M22.3) | After (M22.4.1) |
|----------------|-----------------|
| Client-side `Promise.allSettled` across 4 endpoints | Single `GET /search` call |
| Separate response types per entity | Unified `UnifiedDiscoveryResponse` |
| Content(KNOWLEDGE) as knowledge source | KnowledgeEntry as primary knowledge source |
| Manual aggregation in frontend | Server-side aggregation in `SearchService` |
