## 3. Current Product Center Architecture

### 3.1 现有路由

| Route | 文件 | 现状 |
| --- | --- | --- |
| `/products` | `app/products/page.tsx` | 客户端组件，React Query，`useSearchParams` |
| `/products/[slug]` | `app/products/[slug]/page.tsx` | 详情页（参数/供应商/相关产品/相关知识 Tab） |
| `/products/compare` | `app/products/compare/page.tsx` | 比较页（`?ids=`） |

### 3.2 现有数据流

```
GET /products  → ProductsService.findAll()
                 include: { category, createdBy.organization }   ← 无 media / parameterValues
                 where: keyword OR / categoryId / parameterFilters(AND) / status=ACTIVE

GET /product-categories → ProductCategoriesService.findAll()
                 include: { children: true }                     ← 仅一层 children，平铺分页返回

GET /parameter-definitions → ParameterDefinitionsService.findAll()
                 include: { group: true }                        ← 全站参数定义，无分类上下文
```

### 3.3 现有组件

`components/products/`：`ProductFilter`（分类平铺 + 排序 + 参数面板）、`ParameterFilterPanel`（动态渲染 def.dataType 的 NUMBER/ENUM/BOOLEAN/STRING 控件）、`ProductCard`（占位图 + name/model/category/描述/比较复选框）、`SearchBar`、`ProductGrid`、`CompareBar`、`CompareTable` 等。

### 3.4 关键结论

- Schema 已建模 `ProductCategory.parentId/children`（树能力存在），但 API 只返回一层 `children`、UI 平铺渲染。
- 参数筛选能力（精确 + 数值范围 + AND）已完备，但面板拉全站参数，无分类上下文。
- Product Center 与 Search 在「关键词 + 分类 + 参数」上重叠，缺乏明确目录化身份。

## 5. Category Navigation Architecture

### 5.1 数据契约（不做变更）

基于既有 `ProductCategory` 模型（`parentId` + `children` 自引用，任意深度已支持），**不创建** `NewCategoryTree` / `CatalogCategory` / 任何新表。

### 5.2 树展示模型

目标导航（示例）：

```
Product Center 工业检测设备目录
├── 工业视频内窥镜
│   ├── 电子内窥镜
│   │   ├── 超细径电子内窥镜
│   │   ├── 高清工业内窥镜
│   │   └── 摆动探头内窥镜
│   ├── 光学内窥镜
│   │   └── 光纤内窥镜
│   └── 管道检测设备
```

展示规则：
- 侧边栏树，根分类在顶层，可展开/折叠子分类（支持 2–3 级，Schema 支持更深）。
- 「全部产品」为默认根节点（无筛选状态）。
- 选中分类在 URL 以 `categoryId` 呈现，保持可分享、可前进/后退。

### 5.3 分类→产品聚合规则（关键决策）

当前 API `GET /products` 的 `categoryId` 为**精确匹配**。若选择父分类（如「电子内窥镜」），工业采购期望看到**其子树全部产品**（含「超细径/高清/摆动探头」）。

**设计决策（Directory 语义）**：选择分类 = 返回该分类及其所有后代分类的产品（subtree aggregation）。

实现契约（供任务 601 使用）：
- 前端可基于树解析后代分类 id，向 `GET /products` 传递**多分类条件**（`categoryIds` 或 `categoryId` + `includeDescendants`）—— 具体参数形态由 601 实施时决定，本次仅冻结「子树聚合」这一语义。
- 服务端需支持「分类子树内 ACTIVE 产品」的确定性查询，**不做 AI/语义猜测**。

### 5.4 数据获取策略（供 601 选择）

| 方案 | 说明 | 评价 |
| --- | --- | --- |
| A 前端组装 | 拉取全量分类（parentId），前端构建树 | 无 API 变更，分类量大时有分页/深度问题 |
| B 只读树端点 | 新增 `GET /product-categories/tree`（递归返回树） | 语义清晰，属只读 API 设计（本次仅定义） |

**推荐**：优先 B（递归树端点），将其作为 601 的实施契约；A 作为无 API 变更的降级路径。两者均复用既有 `ProductCategory`，无 Schema 变更。

## 6. Parameter Context Architecture

### 6.1 强制约束

必须遵循：

```
Category Context
  ↓
Relevant Parameters
  ↓
Filter Products
```

**禁止**：

```
All Parameters → Global Filter Panel
```

### 6.2 分类驱动参数规则

- 当选中分类（子树）时，参数面板只展示「该分类子树内 ACTIVE 产品实际使用的参数定义」（Relevant Parameters），而非全站参数。
- Relevance 推导是**确定性**的：`Product(categoryId, status=ACTIVE) → ProductParameterValue → ParameterDefinition`，对子树内去重、按使用频次/展示序排序。
- 无分类选择时，显示全量产品实际使用的参数（或保持「全部」语义）。

### 6.3 与 Search 边界（共享思想，不共享实现）

| 维度 | Search | Product Center |
| --- | --- | --- |
| 语义 | Search Context Facet | 分类驱动参数（Category-Driven） |
| 触发 | 搜索上下文 / 关键词 | 选中分类（子树） |
| 实现 | `search-context.service` | **独立实现，不复用 Search 服务/端点** |

两者共享「分类→相关参数」的思想，但**实现层彻底分离**，禁止 Product Center 调用 Search 的参数上下文逻辑。

### 6.4 实现契约（供 602 使用）

- 新增只读端点（示例）：`GET /products/parameters?categoryId=xxx` 或 `GET /product-categories/:id/parameters`，返回该分类子树内 ACTIVE 产品的去重参数定义（含 `group` / `options`）。
- 返回排序：使用频次 desc → `displayOrder` → `name`（确定性，无 AI）。
- 无 Schema 变更；属只读 API 设计，本次仅定义契约。

### 7.2 设计字段

### 7.3 强制禁止

```
Supplier Store Card      ✗
Price Card               ✗
Marketplace Card         ✗
```

### 7.4 实现契约（供 603 使用）

当前 `GET /products` 列表 `include` 不含 `media` / `parameterValues`。为支撑 Capability Discovery Card，需在列表 API **最小化**补充：
- `media`：仅 `isPrimary=true` 的首图（或 `where isPrimary`）。
- `parameterValues`：仅关键参数（按 `ProductParameterDefinition.displayOrder` 或定义 `key` 标记取前 2–3 条）。

以上为只读 API 设计契约，本次不实现。

## 8. Product Center vs Search Boundary

| 维度 | Search（Unified Discovery） | Product Center（Catalog Discovery） |
| --- | --- | --- |
| 实体范围 | 多实体（Product + Knowledge + Solution + Content + Supplier） | **Product Only** |
| 触发方式 | 关键词 + 主动检索 | 分类浏览 + 参数探索 |
| 分类能力 | 分类 Tab + Facet | 树形目录导航 |
| 参数能力 | Search Context Facet | 分类驱动参数 |
| 比较 | ❌ | ✅ 专有 |
| 询价转化 | - | ✅ 专有（详情页） |
| 跨实体/语义/推荐 | ✅ | ❌（禁止复制） |

**红线**：Product Center 不得复制 Search 的跨实体搜索、知识检索、供应商搜索、智能推荐能力。
