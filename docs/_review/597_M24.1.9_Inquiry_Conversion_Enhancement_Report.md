## 4. Existing Inquiry / RFQ Architecture Audit

- **Inquiry 语义**：`Inquiry` 关联 `Product`（productId）+ `Organization`（organizationId，即接收询价的供应商组织）。`CreateInquiryDto` 强制 `productId` + `offerId` + `organizationId` 三键，确保询价必须明确指向「某个产品的某个供应商 Offer」。
- **Product → Offer → Organization 关系**：`Offer` 携带 `productId` + `organizationId`，构成当前产品 → 供应商能力的确定性链路（Product-Centric，非 Supplier Store）。询价正是复用这条链。
- **Demand / RFQ / RFQResponse 体系**：已有完整模型与 API（`Demand` → `RFQ`（可从 Demand/Match 创建）→ `RFQResponse` → 供应商响应决策），作为下游商业沟通流程存在。
- **Inquiry 边界**：Inquiry = 需求表达（Demand Expression），是买家的商业需求入口，非订单/支付/交易，非 Marketplace，非 Supplier Store。
- **Supplier 定义**：Capability Provider（能力提供者），非 Store Owner / Seller / Transaction Party。
- Result: PASS。Inquiry 与 RFQ 架构已清晰分离且边界正确；Inquiry 为入口，RFQ 为既有沟通流程，二者不混淆。

## 5. Product Discovery → Inquiry Flow Audit

产品详情页 `ProductDetailContent` 的 `suppliers` 标签页集成 `SupplierInquirySection`，形成完整链路：

```
SupplierCapabilityList（展示 Active/Submitted Offer，用户显式选择）
    ↓
Selected Supplier Banner（确认选择 + 切换供应商）
    ↓
ProductInquiryContext（产品名称/型号/分类上下文）
    ↓
InquiryForm（productId + offerId + organizationId 提交）
    ↓
POST /inquiries（校验 Product → Offer → Organization，持久化 + 通知供应商组织成员）
```

- 用户必须**显式选择**供应商后才展示询价表单（`selectedOffer` 为 null 时仅显示供应商列表）。
- **无自动选择首个 Offer**（禁止 AI/随机/排名选择，供应商选择为用户驱动）。
- 无 Active Offer 时展示引导性空态（"暂无其他可询价的供应商"）。
- Result: PASS。Discovery → Inquiry 闭环完整。

## 8. Inquiry Contract Verification

`apps/api/src/inquiries/inquiries.controller.ts`：

| Endpoint | Method | Access | 说明 |
| --- | --- | --- | --- |
| `/inquiries` | POST | PUBLIC（Throttle 10/min） | 创建产品询价，返回 inquiry + notificationsSent |
| `/inquiries/mine` | GET | JWT | 查询我的组织询价（分页 page/pageSize） |
| `/inquiries/:id` | GET | JWT | 按 ID 查询询价 |

`CreateInquiryDto`（`apps/api/src/inquiries/dto/create-inquiry.dto.ts`）：

| 字段 | 约束 |
| --- | --- |
| productId | UUID，必填 |
| offerId | UUID，必填 |
| organizationId | UUID，必填 |
| name | string，必填，max 100 |
| email | email，必填 |
| phone | string，可选，max 30 |
| message | string，必填，max 2000 |

`inquiries.service.ts` create 五步校验：

1. Product 存在校验
2. Offer 存在且 `offer.productId === dto.productId`（Offer 属于该产品）
3. `offer.organizationId === dto.organizationId`（组织与 Offer 匹配）
4. Organization 存在校验
5. 持久化 Inquiry + 通知该组织所有成员（SYSTEM 通知，referenceType=INQUIRY）

Result: Inquiry Contract = PASS。当前产品被明确关联；供应商为 User-selected（非 AI-selected）；无 AI/随机/排名选择。
