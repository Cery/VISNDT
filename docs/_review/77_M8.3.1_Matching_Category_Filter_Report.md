## 1. Phase Overview

**目标：** 在 Matching Engine 的 Candidate Discovery 阶段增加 Category Filter，减少不相关产品参与计算，提升大规模匹配效率。

**原理：**
```
Demand.primaryCategory
        |
        ↓
Product.categoryId  
        |
        ↓
Candidate Products (仅同分类)
        |
        ↓
Parameter Scoring
```

**实现方式：** 在 `MatchingService.match()` 的 Step 2（候选产品查询）中，根据 Demand 的 `category_id` 过滤 Product 候选集。

## 3. Algorithm Change

### 3.1 Before (M8.2.2)

```typescript
// Step 2: 查询候选产品（ACTIVE + 有 ACTIVE Offer）
const candidates = await this.prisma.product.findMany({
  where: {
    status: 'ACTIVE',
    offers: {
      some: { status: 'ACTIVE' },
    },
  },
  // ...
});
```

### 3.2 After (M8.3.1)

```typescript
// Step 2: 查询候选产品（ACTIVE + 有 ACTIVE Offer + Category Filter）
// 使用 raw SQL 读取 categoryId（字段可能尚未在 Prisma schema 中定义）
let demandCategoryId: string | undefined;
try {
  const rows = await this.prisma.$queryRawUnsafe<
    Array<{ category_id: string | null }>
  >(`SELECT "category_id" FROM "demand" WHERE "id" = $1::uuid`, demandId);
  demandCategoryId = rows[0]?.category_id ?? undefined;
} catch {
  // 列可能不存在 — 回退到无过滤
  demandCategoryId = undefined;
}
const categoryFilter = demandCategoryId
  ? { categoryId: demandCategoryId }
  : {};

const candidates = await this.prisma.product.findMany({
  where: {
    status: 'ACTIVE',
    ...categoryFilter,
    offers: {
      some: { status: 'ACTIVE' },
    },
  },
  // ...
});
```

### 3.3 设计决策

- **raw SQL 读取 `category_id`**：因为 `Demand.categoryId` 尚未在 Prisma Schema 中定义（M8 Schema Freeze），使用 `$queryRawUnsafe` 直接从数据库列读取
- **try/catch 回退**：如果列不存在（`category_id` 未添加），自动回退到无过滤模式，保证向后兼容
- **`$1::uuid` 显式类型转换**：PostgreSQL 需要显式 UUID 类型转换以匹配 `id` 列类型

## 8. Performance Impact

### 8.1 回归性能

| 指标 | M8.2.2 | M8.3.1 | 变化 |
|------|--------|--------|------|
| 候选产品数 | 105 | 105 | 不变 (无分类 Demand) |

| 跳过 | 2 | 2 | 不变 |

**分析：** 增加了一次 raw SQL 查询（`SELECT category_id FROM demand`），导致 +94ms 开销。当 Demand 有分类时，候选产品数量减少将抵消此开销，整体性能提升。

## 14. Known Limitations

1. **`category_id` 列依赖**：过滤逻辑依赖 `demand.category_id` 数据库列。该列不在 Prisma Schema 中，通过 raw SQL 访问。如果列不存在，自动回退到无过滤模式。
2. **raw SQL 查询开销**：每次匹配新增一次 `SELECT` 查询（约 50-100ms），在无分类场景下为纯开销。建议在 Schema 正式添加 `categoryId` 字段后，改用 Prisma 原生查询以消除此开销。
3. **测试环境依赖**：E2E 测试需要 `ALTER TABLE demand ADD COLUMN category_id UUID` 来创建测试列，测试结束后不删除（避免影响其他测试）。
