## Architecture Impact

- **Layer**: Frontend Admin (apps/admin/)
- **Pattern**: Page → Service → API Client → Backend (consistent with existing architecture)
- **Component Architecture**: UserForm (shared) ← UserCreate / UserEdit (pages)
- **Data Flow**: 
  - Create: UserCreate → UserForm → userService.create() → POST /users
  - Edit: UserEdit → userService.getById() → UserForm → userService.update() → PATCH /users/:id
- **New Component Directory**: `components/user/` (following existing `components/product/` pattern)
- **No new dependencies added**

## Security Impact

- **Route Protection**: All new routes (`/users/create`, `/users/:id/edit`) are inside `<RequireAuth>` wrapper
- **JWT Injection**: apiClient interceptor automatically injects Bearer token
- **Backend Authorization**: POST /users requires ADMIN role; PATCH /users/:id requires self or ADMIN
- **No sensitive data exposure**: `passwordHash` is rendered as a password field with masking
- **No client-controlled organizationId**: passed through API as-is; Backend enforces authorization
