## 3. 安全问题修复说明

355 审计指出的问题：

1. Controller 未接收当前用户
2. Service 直接依据传入 `ids` 执行 `deleteMany`
3. 已登录用户若获得他人通知 ID，存在跨用户删除风险

本次修复后：

1. Controller 层已将当前用户注入 `batchDelete()` 调用链，见 [notifications.controller.ts:L37-L41](file:///F:/Desktop/VISNDT/VISNDT/apps/api/src/notifications/notifications.controller.ts#L37-L41)
2. Service 层先对 `ids` 去重，再查询目标通知及其归属用户组织信息，见 [notifications.service.ts:L234-L239](file:///F:/Desktop/VISNDT/VISNDT/apps/api/src/notifications/notifications.service.ts#L234-L239)
3. 若存在不存在的通知 ID，会先中断并抛出 `NotFoundException`，见 [notifications.service.ts:L241-L245](file:///F:/Desktop/VISNDT/VISNDT/apps/api/src/notifications/notifications.service.ts#L241-L245)
4. 对每条目标通知执行既有 `validateAccess()` 校验，只有通过校验后才进入 `deleteMany`，见 [notifications.service.ts:L247-L253](file:///F:/Desktop/VISNDT/VISNDT/apps/api/src/notifications/notifications.service.ts#L247-L253)

修复效果：

1. 删除操作不再是“只要知道 ID 就能删”
2. `batch-delete` 的访问约束已与单条通知访问逻辑保持一致
3. 本次修复没有扩展通知权限模型，只是把既有访问规则补齐到批量删除接口
