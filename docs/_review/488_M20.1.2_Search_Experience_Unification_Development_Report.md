## 5. Search Architecture Verification

### 5.1 Data Flow

```
SearchPage (Server Component + Suspense)
  └── SearchPageContent (Client Component)
        ├── GlobalSearchBar (input + type selector)
        ├── SearchTypeTabs (domain navigation)
        └── useEffect → unifiedSearch() → search.service.ts
              ├── searchProducts() → GET /products?keyword=
              ├── searchKnowledge() → GET /content/public?type=KNOWLEDGE + client-side filter
              ├── searchSolutions() → GET /content/public?type=SOLUTION + client-side filter
              └── searchSuppliers() → GET /offers?keyword= + organization aggregation
```

### 5.2 API Usage

| API | Usage | Status |
|-----|-------|--------|
| `GET /products` | Keyword search, suggestions | ✅ Reused |
| `GET /content/public` | Knowledge + Solution fetch | ✅ Reused (client-side keyword filter) |
| `GET /offers` | Supplier discovery via keyword | ✅ Reused (organization aggregation) |

### 5.3 State Management

- URL-controlled via `useSearchParams` + `useRouter`
- No Zustand, Context, or global search store
- Parallel API requests via `search.service.ts`
