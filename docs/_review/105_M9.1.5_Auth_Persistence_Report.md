# M9.1.5 Auth Persistence Report

## Phase Overview

| Item | Value |
|---|---|
| Phase | M9.1.5 Auth Persistence |
| Date | 2026-07-21 |
| Status | Complete |
| Scope | Admin Frontend login state lifecycle |
| Target | Zustand persist middleware, localStorage persistence, token expiry |

**Goal**: Replace in-memory-only auth state with persistent auth state that survives page refresh, and add automatic token expiry detection.

**Approach**: 
- Add Zustand `persist` middleware with `localStorage` storage
- Decode JWT `exp` claim to track token expiration
- Auto-clear expired tokens on rehydration and on access
- Maintain full backward compatibility with existing RequireAuth, axios interceptors, and login flow

## Auth Lifecycle Before/After

### Before (In-Memory Only)

```
Login → setAuth(token, user) → state in memory
Page Refresh → state lost → isAuthenticated=false → redirect to /login
Logout → clearAuth() → state cleared
401 from API → clearAuth() → redirect to /login
```

### After (Persisted + Expiry)

```
Login → setAuth(token, user) → state persisted to localStorage + decoded tokenExpiresAt
Page Refresh → persist rehydrates from localStorage
  ├─ Token valid → isAuthenticated=true → RequireAuth passes → useEffect checks expiry → stays
  └─ Token expired → onRehydrateStorage clears auth → isAuthenticated=false → redirect to /login
Logout → clearAuth() → state cleared in memory + localStorage
401 from API → clearAuth() → state cleared in memory + localStorage
Periodic → checkTokenExpiry() → if expired, auto clearAuth
```

## Token Expiry Strategy

### JWT Decode (No Dependencies)
```typescript
function decodeTokenExpiry(token: string): number | null {
  try {
    const payload = JSON.parse(atob(token.split('.')[1]));
    return payload.exp ? payload.exp * 1000 : null; // JWT exp is in seconds
  } catch {
    return null;
  }
}
```

### Three-Layer Expiry Defense

| Layer | Trigger | Action |
|---|---|---|
| **Rehydration** | Page refresh / first load | `onRehydrateStorage` checks `tokenExpiresAt`, clears auth if expired |
| **Route Guard** | Accessing protected route | `RequireAuth.useEffect` calls `checkTokenExpiry()`, redirects to `/login` if expired |
| **API Interceptor** | Any authenticated API call | Backend returns 401 → `client.ts` interceptor calls `clearAuth()` → redirect to `/login` |

### Expiry Flow
```
Token stored in localStorage (tokenExpiresAt: 1711152000000)
  │
  ├─ User refreshes page at 1711152001000 (1s after expiry)
  │   └─ onRehydrateStorage: Date.now() >= tokenExpiresAt → clearAuth()
  │       └─ isAuthenticated=false → RequireAuth redirects to /login
  │
  ├─ User is on page, token expires silently
  │   └─ Next API call → 401 from backend → clearAuth() → redirect to /login
  │
  └─ User navigates to protected route with expired token
      └─ RequireAuth useEffect → checkTokenExpiry() → clearAuth() → redirect to /login
```

## Security Impact

| Aspect | Before | After | Impact |
|---|---|---|---|
| Token storage | Memory only (lost on refresh) | localStorage (survives refresh) | Improved UX, no re-login on refresh |
| Token exposure | XSS: memory only (safe) | XSS: localStorage readable (risk) | Acceptable risk — admin SPA, no third-party scripts |
| Expired token usage | Backend rejects (401) only | Client-side pre-check + backend 401 | Earlier detection, fewer failed API calls |
| Logout completeness | Clears memory only | Clears memory + localStorage | Full cleanup |
| Token in localStorage | N/A | JWT access token stored | Standard SPA pattern; no refresh token, so exposure window limited to JWT lifetime |

**Security Note**: localStorage is accessible to any JavaScript running on the same origin. This is the standard trade-off for SPA auth persistence. The admin frontend is not intended to embed third-party scripts, and the JWT has a limited lifetime, mitigating the risk.
