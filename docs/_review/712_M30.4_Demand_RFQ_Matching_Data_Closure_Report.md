## 3. 问题闭合（711 D-1~D-4）

### D-1 ｜P1 · Defect ｜需求参数录入能力前端完全缺失 — CLOSED
- **经分析**：前端（Web/Admin）原是「能力侧参数完备、需求侧缺失」；后端 `POST/GET/PATCH/DELETE /demands/:id/parameters` 已存在但未被消费。
- **修复**：新建 `DemandParameterEditor.tsx` 复用组件（按 ParameterGroup 分组，支持 STRING/NUMBER/ENUM/BOOLEAN + 数值区间 + 单位 + 必填 + 优先级）；Web create 页面新增参数录入区并在提交时逐条写入；Web edit 页面回显原始参数 + 增量 diff（新增/修改/删除）；Admin DemandEdit 复用参数管理（service + 页面，适配 antd）。
- **验证链路**：`POST /demands` → `POST /demands/:id/parameters`（STR/NUM/ENUM）= 201/201/201。

### D-2 ｜P1 · Defect ｜RFQ 详情接口不返回需求参数 — CLOSED
- **经分析**：`rfqs.service.ts findOne` 仅 `include: { demand: true }`，未含 `demand.parameters`；前端补调公开 `/demands/:id` 会绕过 synthetic RFQ 的角色可见性边界（供应商凭 demandId 可读任意需求上下文）。
- **修复（最小投影扩展，不改 schema/不复制参数/不改匹配）**：`findOne` 在 `demand` 下 include `parameters`（嵌套 `parameterDefinition.options`）；`demands.service.ts` 的 `findOne`/`getParameters` 同步增加 `parameterDefinition.options` 关联，保证 ENUM 标签可回显。
- **验证链路**：`GET /rfqs/:id` 返回 `demand.parameters` 3 项，含 ENUM options 2 项 + organization。

### D-3 ｜P2 · Defect ｜需求参数展示缺失 — CLOSED
- **修复**：Buyer RFQ 详情（`RFQDetail.tsx`）与 Supplier RFQ 详情（`workspace/supplier/rfqs/[id]`）复用 `DemandParameters` 组件展示真实参数；修复 Supplier 端空态文案错误与参数格式化。
- **验证链路**：`GET /demands/:id` 回显 `parameters` count=3（含 options）；`GET /rfqs/:id` `demand.parameters` count=3。

### D-4 ｜P2 · UX Issue ｜前后端 DemandParameter 结构不匹配 — CLOSED
- **经分析**：原前端为平铺 `{name, value, unit}`，后端为 `value/valueMin/valueMax + 嵌套 parameterDefinition`；`valueMin/valueMax` 数值区间无法表达为单个 `value`，ENUM 需经 `parameterDefinition.options` 取标签。
- **修复**：Web `demands.ts` 与 Admin `demand.types.ts` 统一为后端嵌套结构；`DemandParameters` 按 `dataType` 分支渲染——NUMBER 区间（`min ~ max + unit`）、ENUM 取 option.label、BOOLEAN 中文「是/否」、STRING 原值+单位，并标注必填/优先级。
- **验证链路**：详情与 RFQ 均正确返回 `parameterDefinition{dataType,unit,options}`，前端格式化命中预期。
