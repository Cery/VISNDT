| `PATCH /products/:productId/media/:id` | ✅ JWT | ADMIN |
| `DELETE /products/:productId/media/:id` | ✅ JWT | ADMIN |

### 6.2 Security Improvements from M13.2.7

| Improvement | Description |
|---|---|
| **Delete cascade** | ProductMedia deletion now removes FileAsset (DB + S3), preventing orphan files from remaining accessible via public download URL |
| **Create rollback** | If ProductMedia creation fails, the uploaded FileAsset is cleaned up (DB + S3) |
| **Orphan detection** | `GET /files/orphans` allows admin to audit and identify security gaps |
| **Orphan cleanup** | `POST /files/orphans/cleanup` allows safe, re-validated deletion of orphan files |
| **No mass delete** | Cleanup requires explicit ID list, no "delete all" vulnerability |
| **No auto-delete** | No cron or scheduled task — human review always required |

### 6.3 Remaining Security Notes

| Note | Detail |
|---|---|
| Public download endpoint | `GET /files/:id/download` is still public — files accessible to anyone who knows the FileAsset ID. This is by design for product media. |
| M13.2.7.2 mitigates this | After ProductMedia deletion, FileAsset is also deleted, so the download URL returns 404. |
