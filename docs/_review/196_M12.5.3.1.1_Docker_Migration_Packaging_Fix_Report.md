# M12.5.3.1.1 Docker Migration Packaging Fix Report

**Date**: 2026-07-27  
**Phase**: M12.5.3.1.1 - Docker Migration Packaging Fix  
**Status**: ✅ PASS

---

## 1. Phase Overview

This phase addresses a critical infrastructure issue discovered during M12.5.3.1 API Core Endpoint Smoke Test: the API Docker image was missing the Prisma migrations directory, making `prisma migrate deploy` impossible in production deployments.

The fix adds a single `COPY` instruction to the Dockerfile to include the `database/prisma/migrations/` directory in the production image.

---

## 2. Problem Description

| Attribute | Detail |
|-----------|--------|
| **Discovery** | M12.5.3.1 API Core Endpoint Smoke Test |
| **Symptom** | `prisma migrate deploy` reports "No migration found in prisma/migrations" |
| **Impact** | Fresh production deployments would have no database tables; all API calls fail with `Database error: P2021` (table not found) |
| **Workaround Used** | Manually copied `database/prisma/migrations/` into the container via `docker cp` |

---

## 3. Root Cause

The Dockerfile at `apps/api/Dockerfile` copied `database/prisma/schema.prisma` (line 67) into the production stage but did not copy the `database/prisma/migrations/` directory. The `.dockerignore` file does not exclude migrations, so the only issue was the missing `COPY` instruction.

**Before (line 66-67)**:
```dockerfile
# Copy Prisma schema (for migrations)
COPY database/prisma/schema.prisma database/prisma/
```

**After (line 66-68)**:
```dockerfile
# Copy Prisma schema and migrations (for migrate deploy)
COPY database/prisma/schema.prisma database/prisma/
COPY database/prisma/migrations/ database/prisma/migrations/
```
