  createdAt   DateTime       @default(now()) @map("created_at")

### 6.2 Future Risk Assessment (After Implementation)

| Risk | Severity | Mitigation |
|------|:---:|------------|
| Malicious file upload (virus, script) | 🔴 High | MIME type validation, file extension whitelist, virus scanning |
| DoS via large uploads | 🟡 Medium | File size limit (e.g., 10MB), rate limiting |
| Unauthorized file access | 🟡 Medium | Signed URLs, permission checks per entityType |
| Storage key exposure | 🟡 Medium | Never expose storageKey in API responses |
| File type bypass | 🟡 Medium | Server-side MIME detection (not just extension) |
| Orphaned files | 🟢 Low | Cascade delete or garbage collection |

### 6.3 Recommended Security Controls

| Control | Implementation |
|---------|---------------|
| **File size limit** | 10MB default, configurable per entityType |
| **MIME whitelist** | IMAGE: image/png, image/jpeg, image/webp, image/gif |
| | DOCUMENT: application/pdf, application/msword, application/vnd.openxmlformats-officedocument.* |
| | CERTIFICATE: application/pdf |
| **File extension whitelist** | .png, .jpg, .jpeg, .webp, .gif, .pdf, .doc, .docx, .xls, .xlsx |
| **Access control** | Download: entity-scoped. Delete: ADMIN or uploader |
| **Signed URLs** | S3 pre-signed URLs for download (expires in 15 min) |
| **Cascade delete** | Delete FileAsset → delete S3 object + ProductMedia records |

## 9. Recommendation

### 9.1 Decision Matrix

| Option | Pros | Cons |
|--------|------|------|
| **A. Full Implementation** | Complete file management, production-ready | 12-15h, High complexity, Backend Unfreeze |
| **B. MinIO Only + Metadata API** | S3-compatible, works locally, lower cost | Still 10-12h, Backend Unfreeze |
| **C. Metadata-Only (Status Quo)** | 0 effort, 0 risk | No file upload, manual FileAsset ID entry |
| **D. Skip** | 0 effort | Missing core feature |

### 9.2 Recommended Approach: Phased Implementation

| Phase | Content | Effort | Dependencies |
|-------|---------|:---:|--------------|
| **M13.2.4.1** | MinIO Docker service + env config | 1h | docker-compose.yml |
| **M13.2.4.2** | FileAsset Backend Module (upload/download/delete) | 5-6h | @aws-sdk/client-s3, multer |
| **M13.2.4.3** | FileAsset Admin Page (list/upload/delete) | 4-5h | M13.2.4.2 |
| **M13.2.4.4** | ProductMediaCreate integration (upload → create) | 1-2h | M13.2.4.3 |
| **M13.2.4.5** | Security hardening (MIME check, size limit, scan) | 2-3h | M13.2.4.2 |

### 9.3 MVP Recommendation

**Implement M13.2.4.1 + M13.2.4.2 + M13.2.4.4 (skip standalone FileAsset admin page)**

This delivers:
- ✅ File upload via ProductMediaCreate page
- ✅ File download via signed URL
- ✅ File delete
- ✅ MinIO local storage (S3-compatible, production-ready)
- ❌ Standalone FileAsset management page (can be added later)

**Rationale**: The primary user need is uploading product images/documents. Standalone FileAsset management is a secondary concern. Integrating upload directly into ProductMediaCreate eliminates the manual FileAsset ID entry pain point.
