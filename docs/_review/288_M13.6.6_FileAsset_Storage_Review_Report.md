### 7.4 Current Limitations

| Limitation | Detail |
|------------|--------|
| Hardcoded entityType | `upload()` always sets `entityType: 'PRODUCT'` (line 84 of file-asset.service.ts) |
| Placeholder pattern | Uses `00000000-0000-0000-0000-000000000000` as placeholder entityId |
| No multi-entity support | FileAsset only links to Product via ProductMedia; no direct Product/Org/Demand/RFQ linkage |
| No public upload endpoint | All uploads require ADMIN role |
| No file listing API | No paginated list of all FileAssets (only orphans) |
| No direct file download URL | Download endpoint redirects to S3 signed URL (no proxy) |

## 8. Risk Assessment

| Risk | Level | Detail |
|------|-------|--------|
| Orphan accumulation | 🟡 Medium | Uploads without subsequent ProductMedia.create() leave orphan records + S3 objects |
| Hardcoded entityType | 🟡 Medium | `FileEntityType` enum has 5 values but only `PRODUCT` is implemented |
| Placeholder UUID | 🟢 Low | `00000000-...` is a well-known sentinel, but `findOrphans()` checks both media count and placeholder |
| No rate limiting on upload | 🟡 Medium | `POST /files/upload` has no `@Throttle()` decorator |
| Download endpoint public | 🟢 Low | Anyone with a valid FileAsset UUID can download (by design for signed URLs) |
| No image optimization | 🟢 Low | Raw uploads stored as-is; no thumbnail/resize pipeline |
| S3 dependency | 🟢 Low | If S3 is down, entire file system is unavailable (acceptable for file storage) |
| No file type extension validation | 🟢 Low | MIME type validation exists but file extension is derived from original name |

### Risk Mitigation Present

| Mitigation | Status |
|------------|--------|
| Atomic upload-create (`createWithUpload`) | ✅ Eliminates orphan window |
| Rollback on ProductMedia.create() failure | ✅ Deletes orphan FileAsset |
| `cleanupOrphans()` with re-validation | ✅ Each ID is re-validated before delete |
| MIME type whitelist (13 types) | ✅ Prevents malicious file uploads |
| File size limit (10MB) | ✅ Prevents storage exhaustion |
| Batch limit (max 100 per cleanup) | ✅ Prevents mass deletion accidents |
| UUID validation on cleanup | ✅ `@IsUUID('4', { each: true })` |
