## 5. Lifecycle Flow

### 5.1 Before (Two-Step — Orphan Window)

```
┌─────────────────────────────────────────────────────────────────┐
│  STEP 1: User uploads file                                      │
│  POST /files/upload  →  FileAsset created (DB + S3)             │
│                        entityId = placeholder                   │
│                                                                 │
│  ⚠️ ORPHAN WINDOW: User closes browser here                     │
│     → FileAsset exists in DB + S3                               │
│     → No ProductMedia references it                             │
│     → Must be cleaned up via M13.2.7.4 orphan API               │
│                                                                 │
│  STEP 2: User fills metadata + submits                          │
│  POST /products/:id/media  →  ProductMedia created              │
│  M13.2.7.3: entityId updated / rollback on failure              │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 After (Single-Step — No Orphan Window)

```
┌─────────────────────────────────────────────────────────────────┐
│  SINGLE STEP: User selects file + fills metadata + submits      │
│  POST /products/:id/media/upload                                │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ createWithUpload()                                       │   │
│  │                                                          │   │
│  │  1. fileAssetService.upload(file, userId)                │   │
│  │     → FileAsset created (DB + S3)                        │   │
│  │     → entityId = placeholder                             │   │
│  │                                                          │   │
│  │  2. prisma.productMedia.create({...})                    │   │
│  │     → ProductMedia created                               │   │
│  │     → fileAssetId = fileAsset.id                         │   │
│  │                                                          │   │
│  │  3. prisma.fileAsset.update({ entityId: media.id })      │   │
│  │     → entityId updated                                   │   │
│  │                                                          │   │
│  │  ✅ SUCCESS: Return ProductMedia with fileAsset          │   │
│  │                                                          │   │
│  │  ❌ FAILURE: fileAssetService.delete(fileAsset.id)       │   │
│  │     → FileAsset deleted (DB + S3)                        │   │
│  │     → throw original error                               │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ✅ No orphan window — success or complete rollback             │
└─────────────────────────────────────────────────────────────────┘
```

## 6. FileAsset Lifecycle Impact

### 6.1 Orphan Prevention

| Scenario | Before M13.3.1 | After M13.3.1 |
|---|---|---|
| User uploads → closes browser | **Orphan** (needs cleanup API) | **No orphan** (file never uploaded alone) |
| User uploads → creates media → success | FileAsset linked | FileAsset linked (same) |
| User uploads → creates media → DB fails | **Orphan** (needs M13.2.7.3 rollback) | **No orphan** (`createWithUpload` rollback) |
| Network failure during create | **Orphan** (upload succeeded, create lost) | **No orphan** (one request = atomic) |

### 6.2 entityId Update

Same as M13.2.7.3 pattern: `entityId` is updated from placeholder to `ProductMedia.id` on successful creation. Best-effort (logged as `warn` on failure, doesn't block the response).

### 6.3 Rollback

Same as M13.2.7.3 pattern: `FileAssetService.delete()` is called on failure. This reuses the existing `delete()` method which handles both DB and S3 cleanup.

### 6.4 Backward Compatibility

The existing two-step flow (`POST /files/upload` → `POST /products/:productId/media`) is **unchanged** and remains available. The new endpoint is additive.

| Before | After |

| Two-step upload-create created orphan window | Single-step atomic upload-create eliminates orphan window |
