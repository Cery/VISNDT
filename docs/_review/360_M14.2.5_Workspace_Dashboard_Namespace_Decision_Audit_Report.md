## 6. Business Semantic Audit

### 6.1 页面职责证据

`/dashboard` 页面并非公共用户主页，证据如下：

- 使用 `WorkspaceSidebar` 与 `WorkspaceHeader`，视觉结构属于工作区体系（`dashboard/page.tsx:6-7`, `dashboard/page.tsx:49-51`）
- 快捷入口全部指向工作区业务页面：
  - `/workspace/demands`（`dashboard/page.tsx:115`）
  - `/workspace/rfqs`（`dashboard/page.tsx:127`）
  - `/workspace/matches`（`dashboard/page.tsx:137`）
- 加载的是工作区/组织维度数据：
  - `getDemands()` -> `getMyDemands()` -> `GET /demands/my`
  - `getMyInquiries()` -> `GET /inquiries/mine`
  - `getUnreadCount()` -> `GET /notifications/unread-count`

### 6.2 角色语义证据

- Buyer Sidebar 将“仪表盘”映射到 `/dashboard`
- Supplier Sidebar 则有单独首页 `/workspace/supplier`
- `/dashboard` 页面文案使用“组织仪表盘 / 我的仪表盘”，并依据 `user?.organizationId` 展示组织状态（`dashboard/page.tsx:60`, `dashboard/page.tsx:88-90`）

### 6.3 业务语义判断

结论：`/dashboard` 当前实际职责应归类为：

`B. Buyer Workspace Dashboard`

它不是公共用户 Dashboard，也不是与 Workspace 并列的独立业务入口。

## 7. Decision Recommendation

### Decision: MIGRATE /workspace/dashboard

推荐理由：

1. `/dashboard` 的页面结构、快捷入口和数据接口全部指向 Workspace 业务语义，命名上应归入 `/workspace/*`
2. 当前 BUYER 菜单中只有“仪表盘”落在 `/dashboard`，与其余 `/workspace/*` 页面形成明显命名空间断裂
3. `/dashboard` 当前缺少 `RoleGuard`，而 `/workspace` 根路由已纳入 `workspaceRole` 权限模型；未来迁移到 `/workspace/dashboard` 更容易与 Workspace 访问控制体系保持一致
4. 当前迁移依赖面是明确且可枚举的，主要集中在 Sidebar、PublicHeader、登录/注册跳转和路由常量，属于可控范围

补充说明：

- 本次审计不执行迁移
- 若未来实施迁移，建议保留 `/dashboard -> /workspace/dashboard` 的兼容跳转，避免影响现有入口与书签
