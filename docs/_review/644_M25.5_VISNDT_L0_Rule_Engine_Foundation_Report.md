## 3. Rule Contract Design

创建 **`packages/rule-engine-contract`**（`@visndt/rule-engine-contract` v0.1）。

**纯 TypeScript**，无 Database ORM / API Framework / AI SDK 依赖；仅复用 `@visndt/identity-contract` 的 `BusinessEntityType` 用于 Business Identity Integration。

### 3.1 Rule Definition

```typescript
interface RuleDefinition {
  id: string;
  name: string;
  description: string;
  severity: 'INFO' | 'WARNING' | 'ERROR';
  targetType: RuleTargetType; // PRODUCT/DEMAND/RFQ/RFQ_RESPONSE/OFFER/ORGANIZATION/MEDIA/CONTENT
  evaluate: (context: RuleContext) => RuleResult;
}
```

### 3.2 Rule Result

```typescript
interface RuleResult {
  ruleId: string;
  passed: boolean;
  severity: RuleSeverity;
  message: string;
  references?: IdentityReference[]; // 复用 641 Identity Contract
}
```

- `IdentityReference { type, id, createdAt }` 复用 641 `BusinessEntityType`，仅指向对象，不做业务判断。
- 架构边界：`IF condition THEN result`（只读），**禁止 `IF condition THEN modify business data`**。

## 5. Scheduler Boundary

`scheduler.ts` 定义调度**契约**，非生产调度器：

- `ScheduleDefinition { id, ruleId, cadence, note, enabled }`
- `ExecutionTriggerContract { scheduleId, ruleId, trigger, triggeredAt }`
- `RuleExecutionEntry { id, trigger, targetType, options }`

流转设计：`Schedule Definition → Execution Trigger → Rule Execution Entry → Result`。

**禁止**：Cron Service / Queue System / Worker System / Event Bus。

---

## 6. Notification Contract

`notification.ts` 定义**通知意图契约**（Notification = Contract，非 Notification System）：

```typescript
interface NotificationIntent {
  type: string;
  target: string;
  message: string;
  priority: 'LOW' | 'MEDIUM' | 'HIGH';
  ruleId?: string;
  targetRef?: string;
}
```

- 仅定义 Intent，未实现 Email Provider / SMS / Push / 外部消息投递。
- `intentFromResult` 确定性映射（INFO 不通知；ERROR→HIGH，WARNING→MEDIUM）。

## 7. Rule Evaluation Framework

`evaluate.ts` 提供确定性评估框架（纯函数、只读、无副作用）：

- `evaluateRule(rule, target, data, options)`：单对象评估。
- `runRuleEvaluation(rule, subjects, options)`：批处理 → `RuleEvaluationReport`。
- `runRules(rules, subjects, options)`：多规则扁平结果。
