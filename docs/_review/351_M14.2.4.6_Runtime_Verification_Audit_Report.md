## 3. RBAC行为

`RoleGuard` 直接读取 `user.workspaceRole`，当其为 `null` 时立即返回 fallback，不会默认放行到 `BUYER` 或 `SUPPLIER`。

代码证据：

- [`RoleGuard.tsx:L21-L29`](file:///F:/Desktop/VISNDT/VISNDT/apps/web/src/auth/RoleGuard.tsx#L21-L29)

判断：

1. `workspaceRole = null` 时不会默认进入 `BUYER`
2. `workspaceRole = null` 时不会默认进入 `SUPPLIER`
3. `workspaceRole` 不匹配时会返回 `Access denied`

## 4. null边界行为

2. 侧边栏行为本身符合冻结要求

首页已使用 `organization + organizationMember + workspaceRole` 联合判断组织映射状态：

### 4.3 workspace/settings/page.tsx

设置页已使用 `organization + organizationMember + workspaceRole` 联合判断组织状态展示：

- [`workspace/settings/page.tsx:L15-L20`](file:///F:/Desktop/VISNDT/VISNDT/apps/web/src/app/workspace/settings/page.tsx#L15-L20)

### 4.4 边界结论

1. `null` 不会在导航层被伪装成 `BUYER/SUPPLIER`
2. 但 `null` 仍能进入 `/workspace` 与 `/workspace/settings`
3. 这与“`workspaceRole = null` 时拒绝进入工作区”的冻结目标不一致
