## 1. Executive Summary

**目标**: 为 M9.4 Admin Demand Management 设计完整前端架构，在不修改 Backend/Schema 的前提下，实现 Admin 视角的 Demand 列表查看。

**核心决策**: M9.4 Demand Management 为 **READ-ONLY** Admin 视图。Admin 通过 Backend 已有的 Public `GET /demands` 端点查看所有需求，不涉及 Create/Edit（需求创建是 Web 用户侧功能）。

**结论**: **PASS** — 架构方案清晰，与 M9.3 Product 模板高度一致，可直接实施。

## 6. Service 设计

### 6.1 demand.service.ts

```typescript
import { apiClient } from './client';
import type { Demand, DemandListResponse, SearchDemandParams } from '../types/demand.types';

interface ApiResponseWrapper<T> {
  success: boolean;
  data: T;
  message: string;
  timestamp: string;
}

export const demandService = {
  async getList(params: SearchDemandParams): Promise<DemandListResponse> {
    const response = (await apiClient.get('/demands', { params })) as unknown as ApiResponseWrapper<DemandListResponse>;
    return response.data;
  },

  async getById(id: string): Promise<Demand> {
    const response = (await apiClient.get(`/demands/${id}`)) as unknown as ApiResponseWrapper<Demand>;
    return response.data;
  },
};
```

### 6.2 API 映射表

| Service 方法 | HTTP 请求 | Backend 端点 | 权限 |
|---|---|---|---|
| `getList(params)` | GET | `/demands?keyword=&status=&sort=&page=&pageSize=` | Public |
| `getById(id)` | GET | `/demands/:id` | Public |

## 9. 安全检查

### 9.1 认证链路

| 路由 | RequireAuth | Backend Guard | API 可达性 |
|---|---|---|---|
| `/demands` | ✅ | Public (GET) | ✅ |
| `/demands/:id` | ✅ | Public (GET) | ✅ |

### 9.2 安全评估

| 检查项 | 结果 | 说明 |
|---|---|---|
| RequireAuth 保护 | ✅ | AdminLayout 下所有路由 |
| JWT interceptor | ✅ | 复用 apiClient |
| 401 处理 | ✅ | 复用 axios 响应拦截器 |
| API 权限 | ✅ | 使用 Public 端点，无需额外权限 |
| 敏感数据 | ⚠️ | contact info 由 Backend 根据 contactVisible 保护 |

### 9.3 敏感数据处理

Backend `GET /demands` 和 `GET /demands/:id` 的 `contact info protected` 机制：
- 当 `contactVisible: false` 时，Backend 不返回 contact 字段
- Admin 前端无需额外处理
