## 2. Admin UI Architecture

### 2.1 Supplier Product Pool（`/supplier-products`）

- **能力**：List / Status Filter（全部状态 + DRAFT/SUBMITTED/REVIEWING/APPROVED/PUBLISHED/REJECTED）/ Pagination / Status View。
- 表格列：品牌、型号（series+modelNumber）、能力节点（platformProduct.name）、所属组织、状态（StatusTag 语义色）、创建时间、操作（审核）。
- Admin 审核池为**平台级跨组织**读取（Admin govern platform-wide）。

### 2.2 Supplier Product Detail（`/supplier-products/:id`）

卡片分区展示：
- **SupplierProduct Identity**：brand / series / modelNumber / slug / 所属组织 / 状态 / description / technicalDescription / applicationInfo。
- **Platform Capability Binding**：platformProduct.name / slug / status（Product = Capability Authority，仅绑定展示）。
- **Parameters**：SupplierProductParameterValue（含 parameterDefinition.name / value）。
- **Media**：SupplierProductMedia 列表。
- **Governance Status / Review History**：submittedAt / reviewedAt / reviewedBy / reviewedNote / publishedAt / createdAt。

### 2.3 Approval Workflow UI

按当前状态呈现可执行操作，与后端状态机一一映射：

```
DRAFT      → 提交（/submit）
SUBMITTED  → 开始审核（/review）
REVIEWING  → 通过（/approve） | 拒绝（/reject，Modal 必填 reviewedNote）
APPROVED   → 发布（/publish）
REJECTED / PUBLISHED → 终态，无操作
```

Reject 使用 `Modal + Input.TextArea`，服务端 + 前端双重校验 `reviewedNote` 非空。
