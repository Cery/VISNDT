## 3. API Changes

### 3.1 GET /content/public

**Before:**
```
GET /content/public?type=KNOWLEDGE&page=1&pageSize=20
```

**After:**
```
GET /content/public?type=KNOWLEDGE&keyword=超声检测&page=1&pageSize=20
```

**New parameter:**
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `keyword` | `string` | No | Search against `title` and `summary` (case-insensitive ILIKE) |

**Query behavior:**
- When `keyword` is provided, adds `OR` condition: `title ILIKE '%keyword%' OR summary ILIKE '%keyword%'`
- Combined with existing `type` and `status=PUBLISHED` filters
- Backward-compatible: omitting `keyword` preserves existing behavior

### 3.2 GET /content (ADMIN)

Same `keyword` parameter added for symmetry. ADMIN API also supports keyword search on all content (not just PUBLISHED).

## 4. Frontend Changes

### 4.1 Search Service (search.service.ts)

**Before:**
```typescript
// Client-side filtering: fetch 50 items, filter in JS
async function searchKnowledge(keyword, page, pageSize) {
  const result = await getContentList({ type: 'KNOWLEDGE', page, pageSize: 50 });
  const filtered = result.data.filter(c => c.title.includes(keyword) || (c.summary ?? '').includes(keyword));
  return { items: filtered.slice(...), total: filtered.length, searched: true };
}
```

**After:**
```typescript
// Server-side filtering: keyword passed to API
async function searchKnowledge(keyword, page, pageSize) {
  const result = await getContentList({ type: 'KNOWLEDGE', keyword, page, pageSize });
  return { items: result.data ?? [], total: result.total, searched: true };
}
```

**Benefits:**
- Server-side pagination is accurate (total count reflects filtered results)
- Reduced data transfer (no 50-item fetch for every keyword search)
- Consistent pagination behavior (page 2, 3, etc. fetch correct filtered results)
- Search results are stable (no client-side re-filtering)
