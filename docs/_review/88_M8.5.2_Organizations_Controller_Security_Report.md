## Objective

Fix authorization gaps in Organizations Controller discovered in Project Reality Audit. Protect Organization APIs with JWT Authentication, organization ownership isolation, and ADMIN permission control.

## Audit Findings

Before hardening, all 4 organization endpoints were publicly accessible with no authentication or authorization:

| Endpoint | Method | Status | Risk |
|----------|--------|--------|------|
| `/organizations` | GET | Public | Unauthenticated listing of all organizations |
| `/organizations/:id` | GET | Public | Unauthenticated access to any org (including members) |
| `/organizations` | POST | Public | Anyone can create organizations |
| `/organizations/:id` | PATCH | Public | Anyone can modify any organization |

No organization ownership isolation existed — any authenticated user could access any organization's data.

## Modified Files

### 1. `apps/api/src/organizations/organizations.controller.ts`
- Added JWT authentication via `@UseGuards(JwtAuthGuard)` on all endpoints
- Added `@ApiBearerAuth()` decorators for Swagger documentation
- `GET /organizations` → `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles(Role.ADMIN)`
- `GET /organizations/:id` → `@UseGuards(JwtAuthGuard)` + `@CurrentUser()` for ownership validation
- `POST /organizations` → `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles(Role.ADMIN)`
- `PATCH /organizations/:id` → `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles(Role.ADMIN)`

### 2. `apps/api/src/organizations/organizations.service.ts`
- Added `RequestUser` interface for typed user context
- Added `checkOrganizationAccess()` private method for ownership validation:
  - User's own organization → allowed
  - ADMIN role in any organization → allowed
  - Otherwise → `ForbiddenException`
- `findOne()` now accepts `requestUser` parameter and performs ownership check
- `findAll()`, `create()`, `update()` unchanged (only ADMIN can call via controller guards)

### 3. `apps/api/src/organizations/organizations.module.ts`
- Added `AuthModule` import to make JWT guards and decorators available

### 4. `apps/api/test/e2e/organizations/organizations-security.e2e-spec.ts` (NEW)
- 13 test cases across 5 scenarios covering all security requirements

## Security Review

### Authorization Model

| Role | List All Orgs | View Own Org | View Other Org | Create | Update |
|------|:---:|:---:|:---:|:---:|:---:|
| Unauthenticated | 401 | 401 | 401 | 401 | 401 |
| MEMBER (own org) | 403 | 200 | 403 | 403 | 403 |
| ADMIN | 200 | 200 | 200 | 201 | 200 |

### Guard Execution Order

```
ThrottlerGuard → JwtAuthGuard → [RolesGuard] → Controller
```

### Key Security Properties

- **Client-controlled organizationId**: Not applicable — DTOs do not contain organizationId fields
- **Cross-organization access**: Prevented by `checkOrganizationAccess()` in service layer
- **Privilege escalation**: MEMBER cannot create/update organizations; ADMIN-only via RolesGuard
