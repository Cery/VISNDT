## 8. Product Connection Authority Recheck（Section 4.4 Decision Tree）

### 背景（767 Q11A）

767 实现中，Product 连接上下文通过 `product.offers[0]` 获取组织 ID。由于 Product ZB-K60 无关联 Offer（Offer=0），`connectionContext` 返回 `orgId=null`。

### 767 原始代码

```typescript
// 767 implementation: Product → Offer → Organization
const primaryOffer = product.offers[0];
organizationId: primaryOffer?.organizationId ?? null  // → null when Offer=0
```

### 本任务独立审查

#### Case A 判定

M34 Platform Architecture Contract §10.3 明确规定：

> - **Supplier 搜索改为基于 `SupplierProduct.status=PUBLISHED`**（Organization 汇总已发布型号→Capability）作为发现基线。
> - 现有 `searchSuppliers`（依 `Offer.status in SUBMITTED/ACCEPTED`）标记 **legacy**，解除 Supplier 发现对既有交易行为的依赖。

Contract §1.1 定义 Supplier 关系：

> - **Relations**：Category / Offer / **SupplierProduct（`platformProductId`）** / DemandMatch / Inquiry

Contract §13 状态审计：

> - **Supplier 发现边界**：≥1 PUBLISHED SupplyProduct + Organization(type=SUPPLIER) 后端 `discovery.service.ts` 强制 PUBLISHED；**零 Offer 依赖**。

**M34 Contract 明确认可**：Product → SupplierProduct → SUPPLIER Organization 是 Connection Authority，而 Product → Offer → Organization 是 legacy 路径。

**Case A 成立**：现有实现错误地只查询 Product → Offer → Organization，应优先使用 PUBLISHED SupplierProduct → Organization。

### 最小代码修正（768）

修正后 `connectionContext` 方法：

```typescript
// Connection authority source per M34 Contract §1.5 / §16.1 / §10:
//   Supplier = Organization(type=SUPPLIER) derived from PUBLISHED
//   SupplierProduct → Organization. Offer is OPTIONAL / COMMERCIAL CONTEXT
//   / LEGACY and is NOT a core connection authority.
const primarySupplier = product.supplierProducts[0];  // PUBLISHED only
const primaryOffer = product.offers[0];
organizationId:
  primarySupplier?.organizationId ?? primaryOffer?.organizationId ?? null,
```

### 修正边界

- **新 Authority 引入**：无（SupplierProduct → Organization 是 M34 Contract 既有权威）
