## 1. Problem Summary

### 发现的问题

| # | 严重度 | 问题 | 根因 |
|---|:---:|------|------|
| 1 | 🔴 | API 容器 Exit 1 — Prisma 引擎不兼容 | Alpine 3.23 仅有 OpenSSL 3.x，Prisma 5.22.0 默认引擎需 OpenSSL 1.1 |
| 2 | 🔴 | `PRISMA_CLI_BINARY_TARGETS` 未生效 | Docker 缓存了旧 prisma generate 步骤 |
| 3 | 🔴 | `BINARY_TARGETS` JSON 格式 env var 待验证 | 构建因 Docker Desktop 不稳定中断 |
| 4 | 🟡 | Docker Desktop 持续 500 / 挂起 | 资源限制（磁盘空间、内存） |

### 根因分析

```
Alpine 3.23 (node:20-alpine)
  └── OpenSSL 3.5.7 (libssl.so.3)
       └── Prisma 5.22.0 engine: libquery_engine-linux-musl.so.node
            └── 链接 libssl.so.1.1 ❌ 不存在
                 └── 需要 libquery_engine-linux-musl-openssl-3.0.x.so.node
```

Alpine 3.23 已移除 OpenSSL 1.1（EOL），仅提供 OpenSSL 3.x。Prisma 5.22.0 默认引擎二进制编译时链接了 OpenSSL 1.1，导致运行时加载失败。

```
PrismaClientInitializationError: 
Prisma Client could not locate the Query Engine for runtime "linux-musl-openssl-3.0.x".
This happened because Prisma Client was generated for "linux-musl", 
but the actual deployment required "linux-musl-openssl-3.0.x".

Add "linux-musl-openssl-3.0.x" to binaryTargets in schema.prisma:
generator client {
  provider      = "prisma-client-js"
  binaryTargets = ["native", "linux-musl-openssl-3.0.x"]
}
```

FROM deps AS build
COPY --from=prisma /app/node_modules/.prisma node_modules/.prisma
RUN pnpm --filter @visndt/api build

# Stage 4: production (Alpine) — 运行时
FROM node:20-alpine AS production
RUN apk add --no-cache openssl         # OpenSSL 3.x
COPY --from=deps /app/node_modules node_modules
COPY --from=prisma /app/node_modules/.prisma node_modules/.prisma
COPY --from=build /app/apps/api/dist apps/api/dist

## 8. Next Step Recommendation

### 阻断修复

Alpine 3.23 + Prisma 5.22.0 的 OpenSSL 兼容性问题是核心阻断项。推荐按优先级尝试：

**方案 A (推荐):** 在 Schema 中添加 `binaryTargets`
```prisma
generator client {
  provider      = "prisma-client-js"
  binaryTargets = ["native", "linux-musl-openssl-3.0.x"]
}
```
⚠️ 需要修改 Prisma Schema（当前 Freeze 禁止）

**方案 B:** 使用 `BINARY_TARGETS` env var（当前 Dockerfile 方案）
```bash
BINARY_TARGETS='["native","linux-musl-openssl-3.0.x"]' npx prisma generate
```
需要 `--no-cache` 构建验证

**方案 C:** 降级 Alpine 基础镜像
```dockerfile
FROM node:20-alpine3.20  # Alpine 3.20 有 openssl1.1-compat
```

**方案 D:** 切换至 Debian 基础镜像
```dockerfile
FROM node:20-slim  # Debian Bookworm, glibc + OpenSSL 3
```
需要解决 pnpm-lock.yaml 平台一致性问题

### 恢复步骤

1. 重启 Docker Desktop
2. 清理 Docker 资源 (`docker system prune -a`)
3. 尝试方案 A（修改 Schema binaryTargets）或方案 B（`--no-cache` 构建）
4. `docker compose up -d`
5. `docker compose run --rm api sh -c "cd database && npx prisma migrate deploy"`
6. 验证 `curl http://localhost:4000/api/v1/health`
