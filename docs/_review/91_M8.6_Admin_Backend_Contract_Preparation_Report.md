## 2. New APIs

| # | Method | Path | Controller | Auth | Role | Description |
|---|--------|------|------------|------|------|-------------|
| 1 | GET | `/api/v1/admin/dashboard/stats` | AdminController | JWT | ADMIN | Aggregate dashboard statistics |
| 2 | PATCH | `/api/v1/admin/demands/:id` | AdminDemandController | JWT | ADMIN | Admin override — update any demand |
| 3 | GET | `/api/v1/admin/matching/stats` | AdminMatchingController | JWT | ADMIN | Matching engine statistics |

### 2.1 Dashboard Stats Response

```json
{
  "users": { "total": 42, "active": 35 },
  "organizations": { "total": 12 },
  "products": { "total": 150 },
  "demands": { "total": 28, "published": 15 },
  "matching": { "totalMatches": 320 }
}
```

### 2.2 Admin Demand Override

- Uses existing `UpdateDemandDto` (no new DTO needed)
- Bypasses owner check — ADMIN can update any demand
- No changes to `DemandsController` or `DemandsService`

### 2.3 Matching Stats Response

```json
{
  "totalMatches": 320,
  "averageScore": 72.5,
  "hardFailCount": 5,
  "rematchCount": 12
}
```

## 6. Security Review

| Endpoint | JwtAuthGuard | RolesGuard | @Roles(ADMIN) | Public |
|----------|:---:|:---:|:---:|:---:|
| `/admin/dashboard/stats` | Yes | Yes | Yes | No |
| `/admin/demands/:id` | Yes | Yes | Yes | No |
| `/admin/matching/stats` | Yes | Yes | Yes | No |

- All three endpoints are class-level guarded with `@UseGuards(JwtAuthGuard, RolesGuard)` and `@Roles(Role.ADMIN)`
- No public endpoints in the admin module
- No data exposure risk — all endpoints use Prisma aggregate/count operations
- Existing business APIs (`DemandsController`, `MatchingService`) are untouched
