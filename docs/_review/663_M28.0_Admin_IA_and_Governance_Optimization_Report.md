## 5. D5 — Media Center Audit

### 5.1 Reality Scan

`/media` 路由原本存在（`router/index.tsx` → `MediaList`），基于既有 `FileAsset.entityType/entityId` 归属于平台媒体治理页。

### 5.2 IA Decision

将「媒体中心」恢复为**一级菜单**，含子项「媒体管理」指向 `/media`：

```text
媒体中心
    └── 媒体管理    /media
```

不新增 Folder / Collection / Library Entity，仅在既有 `FileAsset` 数据上做展示与筛选。

### 5.3 Media Entity Type

`MediaList.tsx` 增加 `SUPPLIER_PRODUCT`（供应商型号）实体类型支持，与既有 `PRODUCT / ORGANIZATION / DEMAND / RFQ / RFQ_RESPONSE / CONTENT` 一同列出，使媒体归属实体可表达 Platform / SupplierProduct / Organization / Content 媒体。

### 5.4 Runtime Verification

`database/_663_media_verify.mjs`（ADMIN 实际执行）：

```
1) GET /files → total=1   entityType: {"PRODUCT":1}
2) GET /files?entityType=SUPPLIER_PRODUCT → total=0
3) GET /files?entityType=PRODUCT → total=1
4) GET /files?entityType=CONTENT → total=0
```

结论：一级入口可达，列表 / 实体类型筛选正常。供应商型号当前无媒体记录（属数据缺口，非功能缺陷）。

### 5.5 Architecture Fact

SupplierProduct 媒体走独立 `SupplierProductMedia` 表（区别于 `FileAsset`），媒体中心的 `FileAsset` 列表不混入供应商型号底层媒体（这是既有模型事实，非本任务引入）。本任务不加伪造归并。
