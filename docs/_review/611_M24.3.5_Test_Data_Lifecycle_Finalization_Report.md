## 6. Media Lifecycle Implementation

### 6.1 媒体模型现状（已在 schema，无需新增）

- `FileAsset`：`entityType`(PRODUCT/ORGANIZATION/DEMAND/RFQ/RFQ_RESPONSE/CONTENT) + `storageKey` + `mimeType` + `uploadedBy`。
- `ProductMedia`：`productId` + `fileAssetId` + `isPrimary` + `displayOrder`。
- `ContentMedia`：`contentId` + `fileAssetId` + `type`(IMAGE/ATTACHMENT)；`Content.coverImageId`。

### 6.2 关键结论：placeholder 归属前端 fallback 层，非 seed 层

实测前端媒体消费链路：

- `ProductCard.tsx` / `ProductGallery.tsx` / `MediaGallery.tsx` 均通过 `fileUrl(fileAssetId)` 构造 `${API_BASE_URL}/files/${fileAssetId}/download`，**不直接使用 `storageKey`**。
- `FileAsset.storageKey` 是 S3 后端存储 key，**不是外链 URL**。

因此：

1. **`picsum.photos` placeholder 不能在 seed 里写 `FileAsset` 实现**（storageKey 语义为 S3 key，外链 URL 不匹配；且前端走 `/files/{id}/download`，无真实文件会 404）。
2. **正确落点**：`picsum.photos` 应在 `apps/web` 的媒体展示组件 `<img>` 的 `onError`/`EmptyState` 层实现 —— 当 `fileAssetId` 不存在或 `/files/{id}/download` 失败时回退到 picsum 占位。**这属于 612 Web Platform Experience Upgrade 的职责**。
3. 611 本任务**不写 FileAsset**，避免产生无法展示、无法清理的残缺媒体引用。

### 6.3 媒体生命周期验证标准（既定，移交 612 执行验证）

```
Create（FileAsset 上传）→ Attach（ProductMedia/ContentMedia 关联）→ Display（/files/{id}/download）
→ Fallback（无媒体/picsum 占位/Empty State）→ Cleanup（reset 时级联删除 FileAsset+Media 引用）
```

- 允许：`picsum.photos` 用于 Product/Knknowledge/Solution/Banner 占位。
- 禁止：Broken Image（断图）、Blank Layout（空白布局）、UI Collapse（布局坍塌）。

## 7. Cleanup Capability

### 7.1 现状（实测）

| 能力 | 现状 | 局限 |
|---|---|---|
| Reset Admin | `clean_admin.js` + `reset_admin.sql` | 仅 admin 账号/组织/成员 |
| Demo 幂等 upsert | `seed_demo.ts` | 可重复执行与自然键确定性，但**不删除**已存 demo 数据 |
| 局部 deleteMany | `seed_demo.ts` 内 notification/workflowEvent/conversionEvent | 仅三个操作类实体，非全量 |
| 统一 demo reset | **无** | **缺口** |

### 7.2 清理能力设计（Reset Demo Data / Remove Test User / Remove Test Organization / Remove Test Media Reference / Rebuild Demo Dataset）

既定清理范围与删除顺序（严格遵循外键依赖，仅删 `demo.` 命名空间 + `demoId` 确定性 ID）：

```
1. 操作类：WorkflowEvent → Notification → ConversionEvent（demo 用户/实体范围）
2. 响应类：RFQResponse → RFQ → DemandMatch → Demand
3. 供给类：Offer
4. 媒体类：ProductMedia → ContentMedia → FileAsset（entityType∈{PRODUCT,CONTENT} 且属于 demo 实体）
5. 内容类：Content（slug 前缀 demo-）
6. 目录类：Product / ProductParameterValue → ProductCategory → ParameterDefinition → ParameterGroup
7. 身份类：OrganizationMember → User（email 前缀 demo.）→ Organization（demoId 范围）
```

安全门（与 `seed_demo.ts` 一致）：`NODE_ENV !== production` + 显式 `DEMO_DATA_MODE`/确认开关；禁止 TRUNCATE / `DELETE FROM *` / DROP TABLE；只删 demo 命名空间。

> 落地时机：完整 `reset_demo` 脚本涉及外键删除顺序与运行时验证，**建议在 615 Closeout 前作为单独受控节点落地**，本任务先冻结设计契约，避免在无人运行时情况下引入删除顺序缺陷。
