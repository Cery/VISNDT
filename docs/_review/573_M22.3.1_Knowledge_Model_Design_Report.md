## Architecture Design

### 1. Knowledge Entity Model

**Core Principle: Knowledge = Structured Industrial Knowledge Asset**

Knowledge Entity 是 VISNDT 平台结构化知识资产的核心实体，位于 Content Asset Layer 之上，将 Content 信息资产升级为可复用、可关联、可检索的结构化知识。

```
Content Asset Layer (M22.2 — CLOSED)
    |
    | KnowledgeContentRef (引用，不复制)
    v
Knowledge Structured Layer (M22.3 — Model Design)
    |
    | KnowledgeRelation (关联)
    v
Industrial Inspection Knowledge Capability (Future)
```

#### 1.1 KnowledgeEntry

**定位：** 结构化知识条目，是 Knowledge Base 的核心实体。

**与 Content 的关系：** KnowledgeEntry 通过 KnowledgeContentRef 引用 Content，不复制 Content 数据。KnowledgeEntry 拥有独立的 `structuredBody`（JSON 结构化体），用于存储工业检测领域的结构化知识（参数、方法、场景、设备等），这是 Content 的 `content` 字段（Markdown 文本）无法替代的。

**字段设计：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | YES | 主键 |
| `domainId` | UUID (FK) | YES | 所属知识领域 |
| `categoryId` | UUID (FK) | NO | 所属知识分类（可选） |
| `title` | String | YES | 知识标题 |
| `slug` | String (UNIQUE) | YES | SEO 友好 URL 标识 |
| `summary` | String? | NO | 知识摘要 |
| `structuredBody` | Json? | NO | 结构化知识体（JSON），存储领域专用结构化数据 |
| `status` | KnowledgeEntryStatus | YES | 状态：DRAFT / REVIEW / PUBLISHED / ARCHIVED |
| `authorId` | UUID (FK) | YES | 作者 |
| `publishedAt` | DateTime? | NO | 发布时间 |
| `seoTitle` | String? | NO | SEO 标题 |
| `seoDescription` | String? | NO | SEO 描述 |
| `seoKeywords` | String? | NO | SEO 关键词 |
| `createdAt` | DateTime | YES | 创建时间 |
| `updatedAt` | DateTime | YES | 更新时间 |

**关键设计决策：**

- `structuredBody` 为 JSON 类型（`@db.JsonB`），允许存储不同领域的结构化知识而不需要为每种知识类型创建独立模型
- 无 `organizationId` / `supplierId` —— Knowledge 是 Platform Asset，不属于任何 Organization
- 无 `content` 字段 —— 不复制 Content 正文，通过 KnowledgeContentRef 引用
- 无 `embedding` 字段 —— AI Foundation FROZEN，未来扩展预留

#### 1.2 KnowledgeDomain

**定位：** 知识领域层级分类，定义工业检测知识体系的一级/二级分类。

**字段设计：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | YES | 主键 |
| `name` | String | YES | 领域名称 |
| `slug` | String (UNIQUE) | YES | SEO 友好 URL 标识 |
| `description` | String? | NO | 领域描述 |
| `parentId` | UUID (FK) | NO | 父领域（自引用，支持层级） |
| `sortOrder` | Int | YES | 排序权重 |
| `createdAt` | DateTime | YES | 创建时间 |
| `updatedAt` | DateTime | YES | 更新时间 |

**自引用层级：** `parentId` 允许 KnowledgeDomain 形成树形层级结构，支持一级领域 → 二级子领域。

#### 1.3 KnowledgeCategory

**定位：** 领域内的扁平分类，为 KnowledgeEntry 提供更细粒度的分类标签。

**字段设计：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | YES | 主键 |
| `domainId` | UUID (FK) | YES | 所属领域 |
| `name` | String | YES | 分类名称 |
| `slug` | String | YES | 唯一标识（domainId + slug 联合唯一） |
| `description` | String? | NO | 分类描述 |
| `sortOrder` | Int | YES | 排序权重 |
| `createdAt` | DateTime | YES | 创建时间 |
| `updatedAt` | DateTime | YES | 更新时间 |

**约束：** `@@unique([domainId, slug])` 确保同一领域内分类名称唯一。

#### 1.4 KnowledgeContentRef

**定位：** Knowledge 与 Content 的关联桥梁，实现 "Knowledge 引用 Content" 而不复制内容。

**字段设计：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | YES | 主键 |
| `knowledgeId` | UUID (FK) | YES | 知识条目 |
| `contentId` | UUID (FK) | YES | 被引用的内容 |
| `referenceType` | KnowledgeReferenceType | YES | 引用类型：SOURCE / RELATED / SUPPLEMENT |
| `sortOrder` | Int | YES | 排序权重 |
| `createdAt` | DateTime | YES | 创建时间 |

**引用类型定义：**

| 类型 | 说明 |
| --- | --- |
| `SOURCE` | 主引用 —— 知识条目以此 Content 为主要信息来源 |
| `RELATED` | 相关引用 —— 知识条目与此 Content 相关 |
| `SUPPLEMENT` | 补充引用 —— 知识条目以此 Content 为补充信息 |

**关键约束：** `@@unique([knowledgeId, contentId])` 确保同一 Knowledge 不重复引用同一 Content。

#### 1.5 KnowledgeRelation

**定位：** Knowledge Entry 之间的关联关系，构建知识图谱基础。

**字段设计：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | YES | 主键 |
| `sourceId` | UUID (FK) | YES | 源知识条目 |
| `targetId` | UUID (FK) | YES | 目标知识条目 |
| `relationType` | KnowledgeRelationType | YES | 关系类型 |
| `description` | String? | NO | 关系描述 |
| `createdAt` | DateTime | YES | 创建时间 |

**关系类型定义：**

| 类型 | 说明 | 方向 |
| --- | --- | --- |
| `RELATED` | 一般关联 | 双向 |
| `CHILD` | 子知识（source 是 target 的父） | 单向 |
| `PARENT` | 父知识（source 是 target 的子） | 单向（CHILD 的逆） |
| `PREREQUISITE` | 前置知识（source 是 target 的前置） | 单向 |
| `FOLLOWUP` | 后续知识（source 是 target 的后续） | 单向（PREREQUISITE 的逆） |

**约束：** `@@unique([sourceId, targetId, relationType])` 确保同一关系类型不重复。

### 3. Knowledge Classification Model

#### 3.1 三层分类体系

```
KnowledgeDomain (层级)
    ↓
KnowledgeCategory (扁平)
    ↓
KnowledgeEntry (实体)
```

#### 3.2 分类使用场景

- **KnowledgeDomain**：用于知识导航和粗粒度筛选（如 "检测技术" 下的所有知识）
- **KnowledgeCategory**：用于领域内细粒度分组（如 "超声检测" 下的 "探头选择"、"缺陷评定" 等）
- **KnowledgeEntry**：最终的知识实体，关联一个 Domain（必填）和一个 Category（可选）

#### 3.3 禁止模式

- 禁止 Supplier Category（供应商分类）
- 禁止 Seller Category（卖家分类）
- 禁止 Marketplace Category（市场分类）
- 禁止脱离 Industrial Inspection Context 的通用分类

### 4. Knowledge Relation Model

#### 4.1 知识图谱基础

```
KnowledgeEntry A ──RELATED──→ KnowledgeEntry B
KnowledgeEntry A ──CHILD──→ KnowledgeEntry B (B 是 A 的子知识)
KnowledgeEntry A ──PREREQUISITE──→ KnowledgeEntry B (A 是 B 的前置)
```

#### 4.2 关系使用场景

| 关系 | 场景示例 |
| --- | --- |
| `RELATED` | "超声检测原理" 与 "超声检测设备选型" 相关 |
| `CHILD` / `PARENT` | "超声检测" 包含 "A 型显示"、"B 型显示"、"C 型显示" 子知识 |
| `PREREQUISITE` / `FOLLOWUP` | 学习 "缺陷定量评定" 前需先掌握 "缺陷定性识别" |

### 5. Content Reference Model

#### 5.1 Content → Knowledge 引用关系

```
Content (ARTICLE / KNOWLEDGE / SOLUTION / INSIGHT)
    |
    | KnowledgeContentRef (referenceType: SOURCE / RELATED / SUPPLEMENT)
    v
KnowledgeEntry
    |
    | structuredBody (独立结构化知识体)
    v
Public Knowledge Display
```

#### 5.2 引用规则

| 规则 | 说明 |
| --- | --- |
| 不复制 | KnowledgeEntry 不复制 Content.content 正文 |
| 不替代 | KnowledgeEntry 不替代 Content 的独立展示 |
| 可多引 | 一个 KnowledgeEntry 可引用多个 Content |
| 可被多引 | 一个 Content 可被多个 KnowledgeEntry 引用 |
| 单向引用 | Knowledge → Content，Content 不反向引用 Knowledge |

#### 5.3 structuredBody 设计

`structuredBody` 为 JSON 类型，存储工业检测领域的结构化知识。不同领域使用不同的 JSON Schema：

**示例 1：检测技术知识**

## Design Decision Record

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | `structuredBody` 使用 JSON 而非多表 | 不同领域知识结构差异大，JSON 灵活且避免为每种知识类型建表 |
| D2 | KnowledgeDomain 支持自引用层级 | 工业检测领域天然有层级（如 检测技术 → 超声检测 → 相控阵超声） |
| D3 | KnowledgeCategory 为扁平分类 | 层级由 Domain 承载，Category 提供领域内细粒度标签 |
| D4 | KnowledgeContentRef 而非 Knowledge 直接包含 Content 字段 | 禁止复制 Content 数据，保持 Content 为单一信息源 |
| D5 | KnowledgeRelation 为独立关联表 | 支持多对多知识图谱关系，不污染 KnowledgeEntry 主表 |
| D6 | KnowledgeEntry 无 embedding 字段 | AI Foundation FROZEN，未来扩展时再添加 |
| D7 | KnowledgeEntry 无 organizationId | Knowledge = Platform Asset，非 Supplier Asset |
| D8 | KnowledgeEntry 使用与 Content 相同的状态机 | DRAFT → REVIEW → PUBLISHED → ARCHIVED，保持一致性 |

// ===========================================
// M22.3 Knowledge Base: Knowledge Domain
// ===========================================

model KnowledgeDomain {
  id          String   @id @default(uuid()) @db.Uuid
  name        String
  slug        String   @unique
  description String?
  parentId    String?  @map("parent_id") @db.Uuid
  sortOrder   Int      @default(0) @map("sort_order")

  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")

  parent      KnowledgeDomain?  @relation("DomainHierarchy", fields: [parentId], references: [id])
  children    KnowledgeDomain[] @relation("DomainHierarchy")
  categories  KnowledgeCategory[]
  entries     KnowledgeEntry[]

  @@map("knowledge_domain")
}

// ===========================================
// M22.3 Knowledge Base: Knowledge Category
// ===========================================

model KnowledgeCategory {
  id          String   @id @default(uuid()) @db.Uuid
  domainId    String   @map("domain_id") @db.Uuid
  name        String
  slug        String
  description String?
  sortOrder   Int      @default(0) @map("sort_order")

  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")

  domain      KnowledgeDomain     @relation(fields: [domainId], references: [id])
  entries     KnowledgeEntry[]

  @@unique([domainId, slug])
  @@index([domainId])
  @@map("knowledge_category")
}

// ===========================================
// M22.3 Knowledge Base: Knowledge Entry
// ===========================================

enum KnowledgeEntryStatus {
  DRAFT
  REVIEW
  PUBLISHED
  ARCHIVED
}

model KnowledgeEntry {
  id              String               @id @default(uuid()) @db.Uuid
  domainId        String               @map("domain_id") @db.Uuid
  categoryId      String?              @map("category_id") @db.Uuid
  title           String
  slug            String               @unique
  summary         String?
  structuredBody  Json?                @map("structured_body") @db.JsonB
  status          KnowledgeEntryStatus @default(DRAFT)
  authorId        String               @map("author_id") @db.Uuid
  publishedAt     DateTime?            @map("published_at")
  seoTitle        String?              @map("seo_title")
  seoDescription  String?              @map("seo_description")
  seoKeywords     String?              @map("seo_keywords")

  createdAt       DateTime             @default(now()) @map("created_at")
  updatedAt       DateTime             @updatedAt @map("updated_at")

  domain          KnowledgeDomain        @relation(fields: [domainId], references: [id])
  category        KnowledgeCategory?     @relation(fields: [categoryId], references: [id])
  author          User                   @relation(fields: [authorId], references: [id])
  contentRefs     KnowledgeContentRef[]
  sourceRelations KnowledgeRelation[]    @relation("SourceKnowledge")
  targetRelations KnowledgeRelation[]    @relation("TargetKnowledge")

  @@index([domainId])
  @@index([categoryId])
  @@index([authorId])
  @@index([status])
  @@map("knowledge_entry")
}

// ===========================================
// M22.3 Knowledge Base: Content Reference
// ===========================================

enum KnowledgeReferenceType {
  SOURCE
  RELATED
  SUPPLEMENT
}

model KnowledgeContentRef {
  id            String                 @id @default(uuid()) @db.Uuid
  knowledgeId   String                 @map("knowledge_id") @db.Uuid
  contentId     String                 @map("content_id") @db.Uuid
  referenceType KnowledgeReferenceType @default(SOURCE)
  sortOrder     Int                    @default(0) @map("sort_order")

  createdAt     DateTime               @default(now()) @map("created_at")

  knowledge     KnowledgeEntry         @relation(fields: [knowledgeId], references: [id], onDelete: Cascade)
  content       Content                @relation(fields: [contentId], references: [id])

  @@unique([knowledgeId, contentId])
  @@index([knowledgeId])
  @@index([contentId])
  @@map("knowledge_content_ref")
}

// ===========================================
// M22.3 Knowledge Base: Knowledge Relation
// ===========================================

enum KnowledgeRelationType {
  RELATED
  CHILD
  PARENT
  PREREQUISITE
  FOLLOWUP
}

model KnowledgeRelation {
  id           String                 @id @default(uuid()) @db.Uuid
  sourceId     String                 @map("source_id") @db.Uuid
  targetId     String                 @map("target_id") @db.Uuid
  relationType KnowledgeRelationType
  description  String?

  createdAt    DateTime               @default(now()) @map("created_at")

  source       KnowledgeEntry         @relation("SourceKnowledge", fields: [sourceId], references: [id], onDelete: Cascade)
  target       KnowledgeEntry         @relation("TargetKnowledge", fields: [targetId], references: [id], onDelete: Cascade)

  @@unique([sourceId, targetId, relationType])
  @@index([sourceId])
  @@index([targetId])
  @@map("knowledge_relation")
}
