## 2. Current Architecture Review

### 2.1 Related Schema Status

#### 2.1.1 Product Schema (Global Catalog)

```
Product
├── id, categoryId, name, model, description, status
├── No organizationId / createdBy → Global Catalog ✓
├── ProductParameterValue (via parameterDefinitionId)
│   ├── value: String (exact match)
│   └── valueNumber: Float? (range query, M7.3.1)
├── ProductParameterDefinition (association)
├── ProductMedia (M7.2.3)
└── ProductCategory (hierarchical)
```

**关键约束：**
- Product 是 Global Catalog，不属于任何 Organization
- 索引：`[name]`, `[model]`, `[categoryId]`, `[status]`
- 通过 `ProductParameterValue` 关联参数体系

#### 2.1.2 Parameter Schema

```
ParameterDefinition
├── id, name, code (unique), dataType, unit, required
├── dataType: ParameterDataType { STRING, NUMBER, BOOLEAN, ENUM }
├── ParameterGroup (optional grouping)
├── ParameterOption[] (enum values)
└── ProductParameterValue[] (actual product values)

ProductParameterValue
├── id, productId, parameterDefinitionId
├── value: String (always present)
├── valueNumber: Float? (M7.3.1, for numeric range)
├── @@unique([productId, parameterDefinitionId])
├── @@index([parameterDefinitionId, value])
└── @@index([parameterDefinitionId, valueNumber])
```

**关键能力：**
- 参数定义有明确的 dataType 区分
- 数值参数支持 valueNumber 范围查询
- 枚举参数通过 ParameterOption 定义可选值

#### 2.1.3 Organization Schema

```
Organization
├── id, name, type, status
├── OrganizationMember[] (role: ADMIN | MEMBER)
└── User[] (members via organizationId)

OrganizationMember
├── @@unique([organizationId, userId])
└── role: String (ADMIN / MEMBER)
```

#### 2.1.4 Offer Schema

```
Offer
├── id, organizationId, productId, title, description, status
├── @@unique([organizationId, productId])
└── RFQResponse[] (reverse relation)
```

**关键关系：**
- Offer 属于 Organization（组织级别）
- Offer 引用 Product（Global Catalog 中的产品）
- 一个 Organization 对同一 Product 只能有一个 Offer
- RFQResponse 可以引用 Offer 作为响应内容

#### 2.1.5 Auth Schema (M6 Freeze)

```
JwtPayload
├── sub: string       (user ID)
├── email: string
├── name: string | null
└── organizationId: string | null

AuthRequest.user
├── id: string
├── email: string
├── name?: string | null
└── organizationId?: string | null

Roles: ADMIN | MEMBER
JwtAuthGuard: Bearer token validation
RolesGuard: Organization membership + role check
```

**M6 Freeze 约束：不可修改 Auth Module、JWT Payload、User Schema。**

## 3. Proposed Schema Design

### 3.1 Demand（增强）

```prisma
model Demand {
  id                   String       @id @default(uuid()) @db.Uuid
  title                String
  description          String?
  organizationId       String?      @db.Uuid
  createdBy            String       @db.Uuid
  status               DemandStatus @default(DRAFT)
  
  // 业务字段增强
  quantity             Int?         @map("quantity")
  quantityUnit         String?      @map("quantity_unit")
  expectedDeliveryDate DateTime?    @map("expected_delivery_date")
  budgetRange          String?      @map("budget_range")
  
  // 联系方式保护
  contactName          String?      @map("contact_name")
  contactPhone         String?      @map("contact_phone")
  contactEmail         String?      @map("contact_email")
  contactVisible       Boolean      @default(false) @map("contact_visible")
  
  // 发布/关闭时间戳
  publishedAt          DateTime?    @map("published_at")
  closedAt             DateTime?    @map("closed_at")
  closeReason          String?      @map("close_reason")

  createdAt            DateTime     @default(now()) @map("created_at")
  updatedAt            DateTime     @updatedAt @map("updated_at")

  // 关系
  createdByUser        User          @relation(fields: [createdBy], references: [id])
  organization         Organization? @relation(fields: [organizationId], references: [id])
  rfq                  RFQ?
  parameters           DemandParameter[]   // ← 替代 parametersJson
  matches              DemandMatch[]       // ← 新增匹配结果

  @@index([organizationId])
  @@index([createdBy])
  @@index([status])
  @@index([publishedAt])
  @@map("demand")
}
```

#### 字段设计说明

| 字段 | 类型 | 说明 | 设计理由 |
|------|------|------|----------|
| `quantity` | Int? | 需求数量 | 工业NDT设备采购核心字段 |
| `quantityUnit` | String? | 数量单位（台/套/件） | 配合 quantity 使用 |
| `expectedDeliveryDate` | DateTime? | 期望交付日期 | 供应商评估关键因素 |
| `contactName` | String? | 联系人姓名 | 联系方式保护基础 |
| `contactPhone` | String? | 联系电话 | 联系方式保护基础 |
| `contactEmail` | String? | 联系邮箱 | 联系方式保护基础 |
| `contactVisible` | Boolean | 联系方式是否公开 | `false` 时仅对匹配供应商可见 |
| `publishedAt` | DateTime? | 发布时间 | 状态流转审计 |
| `closedAt` | DateTime? | 关闭时间 | 状态流转审计 |
| `closeReason` | String? | 关闭原因 | 业务闭环记录 |

### 3.2 DemandStatus 状态流转（增强）

```
                    ┌─────────────┐
                    │    DRAFT    │  ← 创建初始状态
                    └──────┬──────┘
                           │ publish()
                    ┌──────▼──────┐
                    │  PUBLISHED  │  ← 发布后供应商可见
                    └──────┬──────┘
                           │ createRFQ() / match()
                    ┌──────▼──────┐
                    │ PROCESSING  │  ← 进入询价/匹配流程
                    └──────┬──────┘
                      ╱         ╲
                     ╱           ╲
            close() ╱             ╲ cancel()
           ┌──────▼──────┐   ┌────▼──────┐
           │   CLOSED    │   │ CANCELLED  │  ← 终态
           └─────────────┘   └───────────┘

补充转换：
  DRAFT      → CANCELLED  (直接取消)
  PUBLISHED   → DRAFT      (撤回重新编辑)
  PUBLISHED   → CANCELLED  (发布后取消)
```

**状态转换表：**

| 当前状态 | 允许目标状态 | 触发条件 |
|----------|------------|----------|
| DRAFT | PUBLISHED | 用户发布 |
| DRAFT | CANCELLED | 用户取消 |
| PUBLISHED | PROCESSING | 创建RFQ或触发匹配 |
| PUBLISHED | DRAFT | 撤回编辑 |
| PUBLISHED | CANCELLED | 用户取消 |
| PROCESSING | CLOSED | 完成采购/手动关闭 |
| PROCESSING | CANCELLED | 取消采购 |
| CLOSED | — | 终态 |
| CANCELLED | — | 终态 |

### 3.3 DemandParameter（结构化参数需求）

```prisma
model DemandParameter {
  id                    String  @id @default(uuid()) @db.Uuid
  demandId              String  @map("demand_id") @db.Uuid
  parameterDefinitionId String  @map("parameter_definition_id") @db.Uuid
  
  // 参数需求表达
  value                 String?  // 精确值要求
  valueMin              Float?   @map("value_min")  // 最小值要求
  valueMax              Float?   @map("value_max")  // 最大值要求
  required              Boolean  @default(true)     // 是否必须满足
  priority              Int      @default(0) @map("priority")  // 优先级（0=普通，1=重要，2=关键）
  
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  demand              Demand              @relation(fields: [demandId], references: [id])
  parameterDefinition ParameterDefinition @relation(fields: [parameterDefinitionId], references: [id])

  @@unique([demandId, parameterDefinitionId])
  @@index([parameterDefinitionId])
  @@map("demand_parameter")
}
```

#### 与 ProductParameterValue 的关系

```
DemandParameter                        ProductParameterValue
┌──────────────────────┐              ┌──────────────────────────┐
│ parameterDefinitionId │──────────────│ parameterDefinitionId     │
│ value: "2.8mm"       │  精确匹配    │ value: "2.8mm"           │
│ valueMin: 2.0        │  范围匹配    │ valueNumber: 2.8         │
│ valueMax: 3.0        │              │                          │
│ required: true       │              │                          │
│ priority: 2          │              │                          │
└──────────────────────┘              └──────────────────────────┘

匹配逻辑：
1. 如果 DemandParameter.value 存在 → 精确匹配 ProductParameterValue.value
2. 如果 DemandParameter.valueMin/valueMax 存在 → 范围匹配 ProductParameterValue.valueNumber
3. 如果 required=false → 不满足时不排除产品
4. 如果 required=true  → 不满足时排除产品
```

**设计优势：**
- 替代 `parametersJson`，与已有 ParameterDefinition 体系对齐
- 支持精确匹配和范围匹配，与 ProductParameterValue 查询能力一致
- `required` 字段区分必须满足和可选偏好
- `priority` 字段支持加权匹配排序

### 3.4 DemandMatch（产品匹配结果）

```prisma
enum DemandMatchStatus {
  PENDING    // 待审核
  MATCHED    // 已匹配
  REVIEWED   // 已审核
  ACCEPTED   // 已接受
  REJECTED   // 已拒绝
  EXPIRED    // 已过期
}

model DemandMatch {
  id         String            @id @default(uuid()) @db.Uuid
  demandId   String            @map("demand_id") @db.Uuid
  productId  String            @map("product_id") @db.Uuid
  
  // 匹配结果
  matchScore     Float           @map("match_score")    // 匹配分数 0-100
  matchStatus    DemandMatchStatus @default(PENDING) @map("match_status")
  matchDetails   Json?           @map("match_details")  // 匹配详情 JSON
  
  // 后续 Offer 扩展预留
  offerId        String?         @map("offer_id") @db.Uuid  // 关联 Offer
  
  matchedAt  DateTime?  @map("matched_at")
  reviewedAt DateTime?  @map("reviewed_at")
  
  createdAt  DateTime @default(now()) @map("created_at")
  updatedAt  DateTime @updatedAt @map("updated_at")

  demand  Demand  @relation(fields: [demandId], references: [id])
  product Product @relation(fields: [productId], references: [id])
  offer   Offer?  @relation(fields: [offerId], references: [id])

  @@unique([demandId, productId])
  @@index([productId])
  @@index([offerId])
  @@index([matchStatus])
  @@index([matchScore])
  @@map("demand_match")
}
```

#### 匹配流程设计

```
1. Demand 发布 (PUBLISHED)
   │
2. 触发匹配计算 (Trigger Match)
   │
   ├── 遍历所有 Product
   ├── 对比 DemandParameter ↔ ProductParameterValue
   ├── 计算 matchScore (0-100)
   │
3. 生成 DemandMatch (PENDING)
   │
   ├── 需求方审核 (REVIEWED)
   │   ├── ACCEPTED → 关联 Offer
   │   └── REJECTED
   │
4. Offer 扩展 (未来)
   └── DemandMatch.offerId → Offer
      └── 供应商可基于匹配结果创建专属 Offer
```

### 4.4 联系方式保护设计

```
GET /demands/:id (Public)

Response (contactVisible=false):

  "description": "...",
```

- 需求方 OWNER/ADMIN：始终可查看完整联系方式

## 5. Security Impact

### 5.1 当前安全风险

| # | 风险 | 当前状态 | 影响 |
|---|------|----------|------|
| S1 | RFQ `createdBy` 客户端传入 | `CreateRfqDto.createdBy` 直接使用 | 可伪造创建者身份 |
| S2 | RFQ/RFQResponse 无认证 | 所有端点无 `@UseGuards(JwtAuthGuard)` | 未认证访问 |
| S3 | Demand 列表公开 | `GET /demands` 无权限控制 | 所有需求信息暴露 |
| S4 | Demand 更新仅 ADMIN | MEMBER 无法管理自己创建的需求 | 权限粒度不足 |

### 5.2 安全加固建议

| # | 建议 | 实现方式 |
|---|------|----------|
| S1 | RFQ createdBy 从 JWT 提取 | Controller 使用 `@CurrentUser()` 替代 DTO 字段 |
| S2 | RFQ/RFQResponse 增加认证 | 添加 `@UseGuards(JwtAuthGuard)` + `@ApiBearerAuth()` |
| S3 | Demand 列表增加过滤 | Public 仅返回 PUBLISHED/PROCESSING 状态的需求 |
| S4 | Demand 增加所有者检查 | Service 层验证 `createdBy === user.id \|\| user.role === ADMIN` |
| S5 | 联系方式保护 | 根据 `contactVisible` 和匹配状态控制可见性 |

### 5.3 数据隔离验证

| 场景 | 验证结果 |
|------|----------|
| Organization A 查看 Organization B 的 Demand | ✅ 通过 organizationId 隔离 |
| 非成员修改 Demand | ✅ 通过 createdBy 验证 |
| 公开访问 Draft 状态 Demand | ✅ 通过 status 过滤 |
| 未认证创建 Demand | ✅ 通过 JwtAuthGuard |
