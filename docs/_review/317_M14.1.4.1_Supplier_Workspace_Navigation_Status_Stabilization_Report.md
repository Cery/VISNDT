## 3. 修改原因

本次修改针对 316 审计报告确认的两个前端稳定性问题：

1. Supplier RFQ 列表页存在已实现的详情页，但列表卡片没有任何正向入口，普通用户无法从 UI 进入 RFQ Detail。
2. Supplier Response 页面把 `response.status` 传给 `RFQStatusBadge`，导致 `SUBMITTED / VIEWED / ACCEPTED / REJECTED` 使用了错误的状态映射与样式语义。

对应处理如下：

1. 在 Supplier RFQ 列表卡片上新增基于 Next.js `Link` 的“查看详情”入口，目标路径为 `/workspace/supplier/rfqs/${rfq.id}`。
2. 新增独立的 `RFQResponseStatusBadge` 组件，仅处理 `SUBMITTED / VIEWED / ACCEPTED / REJECTED`。
3. 在 Supplier Response 页面将原 `RFQStatusBadge` 替换为 `RFQResponseStatusBadge`。

本次仅替换状态展示组件，不改变数据获取、分页、错误处理和页面结构。
