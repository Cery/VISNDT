```
Content Model
```

## 4. Content Editing Strategy Decision

| Option | 方案 | 评估 |
| --- | --- | --- |
| **A（推荐）** | Markdown Content + Preview Rendering | 成本低、纯文本向后兼容（现有 `content` 字段可直接承载 Markdown）、易迁移、与 SEO 摘要/纯文本兼容、渲染可控（Admin 预览 + Web 服务端渲染） |
| B | Rich Text Editor + HTML Storage | 编辑体验好但 HTML 存储带来 XSS 清洗、编辑器锁定、迁移成本高 |
| C | Headless CMS Integration | 短期最省力但引入外部依赖、数据外置、破坏现有 Content 架构统一性 |

**决策**：推荐 **Option A — Markdown Content + Preview Rendering**。
- 存储：复用现有 `Content.content` 字段（Text），以 Markdown 语法书写。
- 渲染：Admin 端 Markdown 编辑器 + 预览面板；Web 端服务端 Markdown → HTML 渲染（安全渲染库，无 XSS）。
- 迁移：现有纯文本内容天然兼容 Markdown，零数据迁移。
- Release 阶段：M18 实施（本任务不实施）。

## 5. Media Management Evolution Plan

**当前**：`Content.coverImageId → FileAsset`（单封面，FileAsset 已含 MinIO 存储）。

**未来演进规划**（M18 实施，本任务仅规划）：

```
Content  1 ── N   ContentMedia   N ── 1   FileAsset
```

能力覆盖：
- 多图片（文章/案例多图）
- 图文混排（Markdown 内嵌图片引用）
- 产品案例图片（Solution 场景）
- 检测报告附件（技术文档/报告下载）

**规划要点**：
- 新增关联模型 `ContentMedia`（contentId + fileAssetId + sortOrder + caption + type[mage/attachment]）。
- 复用既有 `FileAsset` 存储体系，不新建存储子系统。
- 保持 `Content.coverImageId` 为首图/封面语义，ContentMedia 为正文内嵌媒体。
- 本任务**不创建**该模型，仅作设计规划。

## 6. SEO Evolution Plan

**当前**：`seoTitle` / `seoDescription` / `seoKeywords` 三个字段承载基础 SEO，满足 MVP。

**未来演进规划**（M18 实施，本任务仅规划）：
- **OpenGraph / Twitter Card**：详情页已输出基础 OpenGraph（title/description/type），可补充 image、locale、site_name。
- **Structured Data**：Article / HowTo / Product 等 JSON-LD 结构化数据。
- **Sitemap Integration**：`/sitemap.xml` 动态生成（覆盖 /knowledge、/solutions 及详情页）。
- **Canonical URL**：详情页输出 canonical，避免重复内容。
- **Content Metadata Management**：集中管理 SEO 元数据（标题模板、默认 OG 图、关键词规则）。

**约束**：**禁止**当前阶段拆分 `SeoMetadata` 模型；保持 SEO 元数据承载于 Content 既有字段，深化能力通过 M18 前瞻规划实现。
