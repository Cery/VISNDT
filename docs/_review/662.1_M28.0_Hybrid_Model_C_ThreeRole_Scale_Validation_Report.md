## 11. Offer / SupplierProduct Understanding

- **SupplierProduct = 我的具体型号**：清晰（brand/series/modelNumber 标识）。
- **Offer = 我对这个型号的商业能力/报价**：清晰（offer 绑 supplierProductId，价格带展示）。
- **一个 SupplierProduct 可有多个 Offer**：当前每 PUBLISHED 型号 1 个 ACTIVE Offer，数据链完整。
- **Offer 不能代替型号**：schema 实证 Offer 双绑 `productId + supplierProductId`，型号独立存在。
- **多个型号可存在于同一 Platform Product 下**：VX-6000 下 7 型号（3 供应商）实证。

**结论：SupplierProduct/Offer 概念当前无混淆，无需概念重构。**

## 14. Batch Operation Decision Gate

评估依据：当前审核队列 3（SUBMITTED 2 + REVIEWING 1）/ 单条操作 ~6 次点击 / 100 型号投影队列 15。

- 当前重复操作成本：低（队列 3，~18 次点击/轮）。
- 100 型号投影：队列 15，~90 次点击/轮 → 批量才有意义。
- 错误风险：当前低（逐条人工确认）。
- **最终结论：Batch Operation = NOT YET REQUIRED**（Future Candidate：D8 批量操作，待审核队列 ≥ 15 触发）。
