## 4. Feature Implementation

### 4.1 Content Menu
`AdminLayout.menuItems` 新增 `{ key: '/content', icon: <FileTextOutlined />, label: '内容管理' }`，Admin 导航闭环完成。

### 4.2 Admin Route
`router/index.tsx` 在 AdminLayout children 下新增：

| Route | 页面 | 用途 |
| --- | --- | --- |
| `/content` | ContentList | 内容列表 |
| `/content/create` | ContentCreate | 创建草稿 |
| `/content/:id` | ContentEdit | 编辑 / 生命周期管理 |

### 4.3 Content List
`ContentList` 展示字段：Title / Type / Status / Author / Created Time / Updated Time；支持基础筛选（type、status）与分页；调用 Admin Content API（`contentService.getList`）。未实现复杂搜索。

### 4.4 Content Editor Foundation
`ContentForm` 共享表单（基本信息 title/slug/type/summary/content + SEO seoTitle/seoDescription/seoKeywords），默认 DRAFT；创建走 `POST /content`，编辑走 `PATCH /content/:id`。

### 4.5 Lifecycle Operations
`ContentEdit` 根据 status 动态展示操作按钮（均带 Modal 确认）：

| 当前状态 | 按钮 | 调用 |
| --- | --- | --- |
| DRAFT | 提交审核 | `POST /content/:id/submit` |
| REVIEW | 审核通过 | `POST /content/:id/review` |
| REVIEWED/REVIEW 完成 | Publish（后端 review 即发布；publish 接口已封装备用） | `POST /content/:id/publish` |
| PUBLISHED | 归档 | `POST /content/:id/archive` |

## 5. Architecture Impact

遵循既有分层，未引入越层调用：

```
Admin Page (ContentList / ContentCreate / ContentEdit)
   ↓
Components (ContentForm)
   ↓
Service Layer (content.service.ts)
   ↓
API Wrapper (apiClient)
   ↓
Backend Content API (/api/v1/content)
```

- 页面无直接 `fetch()` / `axios()` / 直接 `apiClient` 业务调用
- 业务逻辑未进入 UI Component（组件仅承载表单展示与提交回调）
