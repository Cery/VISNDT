# 3. Architecture Constraint

## Product-Centric Principle

VISNDT 核心定位：
```

+
Business Matching Platform

```
不是：
```

AI Consultant Platform

```
不是：
```

Marketplace Platform

```
不是：
```

Automatic Decision System

```
---

## Permanent Boundary Rules


### Knowledge Boundary

必须保持：
```

Knowledge ≠ Score Input

```
Knowledge 用于：

- Context
- Explanation
- Reference
- Content Discovery

禁止：

- 修改匹配分数
- 修改排序权重
- 影响 MatchScore


---

### AI Boundary

必须保持：
```

AI ≠ Matching Engine

```
AI 不得：

- 替代 Matching
- 自动决策
- 自动推荐设备
- 修改业务结果


---

### Search Boundary

必须保持：
```

Search ≠ Ranking Engine

```
Search 用于：

- 产品发现
- 内容发现
- 数据查询

禁止：

- 未验证自动排序优化
- 黑盒 Ranking


---

### Analytics Boundary

必须保持：
```

Analytics ≠ Automatic Optimization

```
Analytics 用于：

- 数据观察
- 行为分析
- 决策辅助

禁止：

- 自动修改系统行为


---

### Data Boundary

新增能力必须优先考虑：
```

Reuse Existing Model

> 

Extend Existing Capability

> 

Create New Entity

```
新增数据库：

必须经过架构审核。
