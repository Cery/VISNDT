## 一、项目概述

### 技术栈
- **前端框架**：React 18 (Admin) + Next.js (Web) + TypeScript
- **UI组件库**：Ant Design v5 (Admin) + Tailwind CSS (Web)
- **后端框架**：NestJS + TypeScript
- **数据库**：PostgreSQL + Prisma ORM
- **认证**：JWT (HttpOnly Cookies) + CSRF (Double Submit Cookie)
- **包管理**：pnpm (Monorepo)

### 架构
- 4个应用模块：apps/api (NestJS后端), apps/web (Next.js前台), apps/admin (React后台), database (Prisma)
- 3个部署服务：PostgreSQL, MinIO (S3存储), Node.js API

## 三、核心业务流分析

### 数据流图

```
[需求创建] → POST /demands → status=DRAFT
    ↓
[需求发布] → PATCH /demands/:id/publish → status=PUBLISHED
    ├─→ 异步 MatchingService.match()
    │     ├─→ 查同分类ACTIVE产品
    │     ├─→ 逐产品参数评分 (加权匹配)
    │     ├─→ 过滤低分 → DemandMatch upsert
    │     └─→ 通知创建者
    └─→ 自动创建 RFQ (status=DRAFT)
    ↓
[创建RFQ] → POST /rfqs → 关联 Demand
    ↓
[供应商报价] → POST /offers → Offer(status=SUBMITTED)
    ├─→ RFQResponse 记录
    └─→ WorkflowEvent 记录
    ↓
[匹配管理] → DemandMatch(status=PENDING)
    → REVIEWED → ACCEPTED
              → REJECTED
    ↓
[询价 (独立链路)] → POST /inquiries → 关联 Product
    → Inquiry(NEW) → PROCESSING → REPLIED → CLOSED
```

### 状态机

| 实体 | 状态流转 |
|------|---------|
| Demand | DRAFT → PUBLISHED → SUBMITTED → PROCESSING → CLOSED / CANCELLED |
| RFQ | DRAFT → OPEN → RESPONDING → CLOSED / CANCELLED |
| Offer | DRAFT → ACTIVE → SUBMITTED → ACCEPTED / REJECTED / WITHDRAWN |
| Inquiry | NEW → PROCESSING → REPLIED → CLOSED |
| DemandMatch | PENDING → MATCHED → REVIEWED → ACCEPTED / REJECTED / EXPIRED |

## 四、权限体系分析

### 用户-组织关系
- 多对多（N:N）通过 OrganizationMember 表
- User.organizationId 指向当前组织（快捷引用）
- 组织隔离在各 Service 层自行实现，无统一中间件

### 权限注解分布
- 公开接口：GET /products, GET /demands, GET /product-categories, GET /organizations/:id, POST /auth/login, POST /auth/register, POST /inquiries
- 需认证：GET /demands/my, POST /demands, 所有通知/用户接口
- 仅ADMIN：产品CRUD, 分类CRUD, 参数管理, 组织管理, 用户管理, 审计日志

## 六、架构层面大类问题总结

### 1. 数据模型缺陷
- Offer 缺少金额字段，无法支撑报价业务闭环
- 审计日志缺少 IP 地址字段，审计不完整
- 无软删除机制，数据不可恢复

### 2. 安全与权限
- 多个公开接口缺乏数据访问控制
- 无统一组织隔离中间件，各服务层实现不一致
- 参数管理全局共享，不满足多租户隔离需求

### 3. 功能完整性
- 前台缺少通知中心、报价查看、Inquiry查看、多组织切换等核心功能
- 匹配结果页面缺少用户交互操作
- 前台仪表盘统计口径不准确

### 4. 术语与一致性
- "RFQ" vs "询价单" 术语不统一
- 前台"收到的询价"Card数据源错误（显示RFQ数而非Inquiry数）

### 5. 审计与可追溯性
- 审计日志缺乏主动写入机制
- 审计日志不完整（无IP地址）
- 批量操作审计粒度不清晰

### 6. 用户体验
- 搜索无防抖、无服务端搜索
- 物理删除无回收站
- 无通知中心
- 无虚拟滚动
- 页码切换不回到顶部
