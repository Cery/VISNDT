## 1. Phase Overview

本阶段新增 `DemandMatch` 数据模型和 `DemandMatchStatus` 枚举，建立 Demand 与 Product 的匹配结果存储能力。为后续匹配算法实现和 Offer 扩展提供数据基础。

**原则：只实现 Schema，不实现匹配算法和 API。**

### 设计目标

| 目标 | 说明 |
|------|------|
| 匹配结果存储 | Demand → Product 的匹配记录 |
| 匹配分数 | `matchScore` 量化匹配程度 |
| 匹配状态流转 | PENDING → MATCHED → REVIEWED → ACCEPTED / REJECTED / EXPIRED |
| 匹配详情 | `matchDetails` JSON 记录逐参数匹配结果 |
| Offer 扩展预留 | `offerId` 关联供应商 Offer |

## 3. Schema Changes

### 3.1 DemandMatchStatus 枚举

```prisma
enum DemandMatchStatus {
  PENDING    // 待审核 — 匹配结果已生成，等待需求方审核
  MATCHED    // 已匹配 — 初步匹配完成
  REVIEWED   // 已审核 — 需求方已查看匹配结果
  ACCEPTED   // 已接受 — 需求方确认此匹配
  REJECTED   // 已拒绝 — 需求方拒绝此匹配
  EXPIRED    // 已过期 — 匹配超时失效
}
```

**状态流转：**

```
                    ┌─────────────┐
                    │   PENDING   │  ← 匹配算法生成
                    └──────┬──────┘
                           │ review()
                    ┌──────▼──────┐
                    │  REVIEWED   │  ← 需求方已查看
                    └──────┬──────┘
                      ╱         ╲
                     ╱           ╲
            accept()╱             ╲ reject()
           ┌──────▼──────┐   ┌────▼──────┐
           │  ACCEPTED   │   │ REJECTED  │
           └──────┬──────┘   └───────────┘
                  │
                  │ (关联 Offer)
                  ▼
            ┌──────────┐
            │  Offer   │  ← 供应商报价
            └──────────┘

  任意非终态 ──→ EXPIRED  (超时 / 手动过期)
```

### 3.2 DemandMatch 模型

```prisma
model DemandMatch {
  id          String             @id @default(uuid()) @db.Uuid
  demandId    String             @map("demand_id") @db.Uuid
  productId   String             @map("product_id") @db.Uuid
  matchScore  Float              @map("match_score")
  matchStatus DemandMatchStatus  @default(PENDING) @map("match_status")
  matchDetails Json?              @map("match_details")
  offerId     String?            @map("offer_id") @db.Uuid
  matchedAt   DateTime?          @map("matched_at")
  reviewedAt  DateTime?          @map("reviewed_at")

  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  demand  Demand  @relation(fields: [demandId], references: [id])
  product Product @relation(fields: [productId], references: [id])
  offer   Offer?  @relation(fields: [offerId], references: [id])

  @@unique([demandId, productId])
  @@index([productId])
  @@index([matchStatus])
  @@index([matchScore])
  @@map("demand_match")
}
```

### 3.6 索引设计

| 索引 | 类型 | 用途 |
|------|------|------|
| `@@unique([demandId, productId])` | UNIQUE | 同一需求对同一产品只有一条匹配记录 |
| `@@index([productId])` | INDEX | 按产品查询所有匹配 |
| `@@index([matchStatus])` | INDEX | 按状态筛选匹配 |
| `@@index([matchScore])` | INDEX | 按分数排序匹配 |

### 3.7 外键约束

| 外键 | 引用 | ON DELETE | ON UPDATE |
|------|------|-----------|-----------|
| `demand_id` | `demand(id)` | RESTRICT | CASCADE |
| `product_id` | `product(id)` | RESTRICT | CASCADE |
| `offer_id` | `offer(id)` | SET NULL | CASCADE |

**关键设计决策：**
- `demand_id` / `product_id` → RESTRICT：防止删除有关联匹配的需求或产品
- `offer_id` → SET NULL：删除 Offer 时不清除匹配记录，保留匹配历史
