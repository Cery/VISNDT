## 3. Implementation Readiness Matrix

### 3.1 Business Model Readiness — ✅ PASS
- **Platform Product = Capability Node**：Category / Standard Capability / Standard Parameter / Search Index / SEO Authority / Knowledge Relation / Public Capability Node；无 supplier 厂商/商业字段。
- **Supplier Product = Independent Domain Entity**：brand / series / modelNumber / description / media / docs / override / extension / application info；归属 Supplier Organization。
- **Offer = Commercial Layer（Offer != Product）**：availability / quotation / commercial terms / RFQ response。
- 三实体职责非重叠、边界清晰 → **PASS**。

### 3.2 Database Implementation Readiness — ✅ READY
未来实施范围（660.2 冻结，本期不落库）：
- 新实体：`SupplierProduct`（独立实体）、`SupplierProductMedia`、`SupplierProductParameterValue`。
- 演进：`Offer.supplierProductId`（可空，兼容双绑）。
- 枚举：`SupplierProductStatus`（DRAFT/SUBMITTED/REVIEWING/APPROVED/PUBLISHED/REJECTED）、`FileEntityType.SUPPLIER_PRODUCT`。
- **Product 表零修改**（不触碰 `Product.organizationId`）；Entity FK：SupplierProduct→Organization / →Platform Product(onDelete: Restrict)。
- 实施序：Phase 1 Schema → Phase 2 Migration（Strategy B+C）。

### 3.3 API Implementation Readiness — ✅ READY
API 边界冻结（660.3）：
- SupplierProduct Domain（Admin Pool + Buyer Query）。
- Offer Evolution（双绑 create 校验 + Capability→SupplierProduct→Offer 三级查询）。
- Capability Discovery（`/capabilities/:id` CapabilityDetailDTO）。
- Approval Workflow（Admin submit/review/approve/reject/publish）。
- **无 API 暴露数据库 Join 结构**，一律走 Capability DTO / SupplierProduct DTO / Offer DTO。

### 3.4 Permission Readiness — ✅ READY
- **Admin**：Platform Product Management / SupplierProduct Approval / Publishing Governance / Data Governance。
- **Supplier**：当前 Phase = **Offer Management Only**；SupplierProduct Draft Submission = **Future Candidate（NOT M28 first implementation）**。
- **Buyer**：Read Capability / View Supplier Products / View Offers / Inquiry / RFQ（Read Only）。
- 边界无交叉、无越权缺口 → **READY**。

## 5. Risk Assessment

| # | 风险 | 缓解 | 等级 |
|-|-|-|-|
| **R1** SupplierProduct ownership | 必须保持 Organization 归属（SupplierProduct.organizationId 派生，禁止全局 / Product 承载） | organizationId + platformProductId 双 FK 强制归属；Offer 创建校验 `supplierProduct.organizationId === Offer.organizationId` | 可控 |
| **R2** Offer 兼容 | 过渡期必须保留 `productId`（能力聚合） | Strategy B 兼容双绑：`supplierProductId` 可空新增，保留 `@@unique([organizationId, productId])`，不回填完成前不弃 productId | 可控 |
| **R3** Search / Matching | 必须持续 Platform Product Based（确定性绑 Capability Node 标准参数） | Search Index Source = Platform Product；Matching / DemandMatch / RFQ 链路 NONE | 可控 |
| **R4** SEO | 必须持续 Platform Product Canonical Authority | Canonical = Platform Product 能力节点；Supplier 型号经 Spec Long Tail 下沉、权重不超平台 | 可控 |
| **R5** Permission 扩展 | SupplierProduct self-service（Draft Submission / Direct Publish）不可入 M28 首轮实现 | 明确 Future Candidate；首轮 Supplier 仅 Offer Management；Admin 唯一 Approve/Publish | 可控 |
| **R6** 数据回填 | 存量 Offer 的 supplierProductId 回填（阶段2）有数据清洗风险 | 低批次批量任务 + 先读后写 + organizationId/platformProductId 匹配校验；非首轮阻塞项 | 低 |

**结论**：全部风险命中既有冻结红线与缓解策略，**无未缓解高风险**。
