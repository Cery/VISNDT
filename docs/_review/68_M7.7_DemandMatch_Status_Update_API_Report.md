## 3. API Changes

### 3.1 PATCH /demands/:id/matches/:matchId — 更新匹配状态

**认证：** JwtAuthGuard (+ @ApiBearerAuth)

**请求体：**

```typescript
{
  status: DemandMatchStatus;   // 必填，目标状态
  notes?: string;              // 可选，备注
}
```

**请求示例：**

```json
POST /demands/{demand-uuid}/matches/{match-uuid}
Content-Type: application/json
Authorization: Bearer <token>

{
  "status": "REVIEWED",
  "notes": "参数匹配度较高，推荐进一步沟通"
}
```

**成功响应：**

```json
{
  "code": 200,
  "message": "Match status updated",
  "data": {
    "id": "match-uuid",
    "demandId": "demand-uuid",
    "productId": "product-uuid",
    "matchScore": 85.5,
    "matchStatus": "REVIEWED",
    "reviewedAt": "2026-07-19T12:00:00.000Z",
    "product": {
      "id": "product-uuid",
      "name": "工业内窥镜A型",
      "category": { "name": "内窥镜" }
    },
    "offer": null
  }
}
```

**错误响应：**

| 条件 | 状态码 | 消息 |
|------|--------|------|
| 无组织 | 400 | User must belong to an organization |
| Demand 不存在 | 404 | Demand {id} not found |
| 无权限 | 400 | You do not have permission to modify this demand |
| 匹配不属于该 Demand | 404 | DemandMatch {matchId} not found on demand {demandId} |
| 非法状态转换 | 400 | Cannot transition from {from} to {to}. Allowed transitions: {list} |

**非法转换示例：**

```
// 从 ACCEPTED 尝试转换到 REVIEWED
Request:  { "status": "REVIEWED" }
Response: 400 — "Cannot transition from ACCEPTED to REVIEWED. Allowed transitions: none"

// 从 MATCHED 尝试转换到 ACCEPTED（跳过了 REVIEWED）
Request:  { "status": "ACCEPTED" }
Response: 400 — "Cannot transition from MATCHED to ACCEPTED. Allowed transitions: REVIEWED"
```

## 4. State Machine

### 4.1 状态转换图

```
                    ┌─────────┐
                    │ PENDING │  (初始状态)
                    └────┬────┘
                         │
                    [MATCHED] ← 匹配算法执行
                         │
                    ┌────▼────┐
                    │ MATCHED │
                    └────┬────┘
                         │
                    [REVIEWED] ← 用户评审
                         │
                    ┌────▼────┐
                    │REVIEWED │
                    └──┬───┬──┘
                       │   │
              [ACCEPTED]   [REJECTED]
                       │   │
                  ┌────▼─┐ ┌▼───────┐
                  │ACCEPT│ │REJECTED│  (终态)
                  └──────┘ └────────┘
```

### 4.2 转换白名单

```typescript
const MATCH_TRANSITIONS: Record<DemandMatchStatus, DemandMatchStatus[]> = {
  PENDING:  [MATCHED],                    // → 匹配算法
  MATCHED:  [REVIEWED],                   // → 用户评审
  REVIEWED: [ACCEPTED, REJECTED],         // → 接受/拒绝
  ACCEPTED: [],                           // 终态
  REJECTED: [],                           // 终态
  EXPIRED:  [],                           // 终态
};
```

### 4.3 转换与操作映射

| 转换 | 触发者 | reviewedAt | WorkflowEvent | 说明 |
|------|--------|------------|---------------|------|
| PENDING → MATCHED | 匹配算法 | — | `SUBMITTED` | 算法完成匹配 |
| MATCHED → REVIEWED | Demand 方 | ✅ 设置 | `RESPONDED` | 用户评审 |
| REVIEWED → ACCEPTED | Demand 方 | — | `ACCEPTED` | 接受匹配 |
| REVIEWED → REJECTED | Demand 方 | — | `REJECTED` | 拒绝匹配 |

### 4.4 审计记录

每次状态变更通过 `$transaction` 原子性记录 WorkflowEvent：

```json
{
  "entityType": "DEMAND",
  "entityId": "demand-uuid",
  "action": "RESPONDED",
  "operatorId": "user-uuid",
  "metadata": {
    "matchId": "match-uuid",
    "productId": "product-uuid",
    "previousStatus": "MATCHED",
    "newStatus": "REVIEWED",
    "notes": "参数匹配度较高，推荐进一步沟通"
  }
}
```

## 5. Security Impact

### 5.1 安全分析

| 检查项 | 说明 | 风险 |
|--------|------|------|
| 组织隔离 | 验证 Demand 所有权，仅同组织可操作 | ✅ 已保护 |
| 身份验证 | JwtAuthGuard，无公开访问 | ✅ 已保护 |
| 状态注入 | 白名单验证，拒绝非法转换 | ✅ 已保护 |
| 跨组织操作 | match 绑定 demand，通过 demand 隔离 | ✅ 已保护 |
| 事务原子性 | 状态变更 + 审计同步，失败回滚 | ✅ 已保护 |
| 终态保护 | ACCEPTED/REJECTED/EXPIRED 不可再转换 | ✅ 已保护 |

### 5.2 安全守卫链

```
Request
  │
  ├─ 1. JwtAuthGuard (Controller)
  │     └─ 验证 JWT 有效性
  │
  ├─ 2. validateDemandOwnership(demandId, user)
  │     ├─ user.organizationId 存在
  │     ├─ Demand 存在
  │     └─ isCreator || isSameOrg
  │
  ├─ 3. match 验证
  │     └─ match.id === matchId && match.demandId === demandId
  │
  ├─ 4. 状态转换白名单
  │     └─ MATCH_TRANSITIONS[currentStatus].includes(targetStatus)
  │
  └─ 5. $transaction
        ├─ demandMatch.update({ matchStatus, reviewedAt })
        └─ workflowEvent.create({ action, metadata })
```
