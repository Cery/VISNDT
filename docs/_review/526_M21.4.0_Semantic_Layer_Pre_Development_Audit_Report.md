## 5. Gap Analysis

### 5.1 P0 — Must Resolve Before M21.4 Development

| ID | Gap | Impact | Mitigation |
|----|-----|--------|------------|
| **GAP-01** | **No Vector Index on embedding columns** | All vector similarity searches would be sequential scans (O(n)), unusable for production | Create IVFFlat or HNSW index on `content.embedding`, `product.embedding`, `content_chunk.embedding` |
| **GAP-02** | **No pgvector Similarity Function** | PostgreSQL cannot compute cosine similarity without a registered function; `<=>` operator not available | Create `cosine_similarity` or `l2_distance` function using pgvector operators |
| **GAP-03** | **No Semantic Module** | No code structure exists for semantic search; embedding+retrieval logic is scattered in EmbeddingService | Create `apps/api/src/semantic/` module with `semantic.service.ts`, `semantic.controller.ts`, `retrieval.service.ts` |

### 5.2 P1 — Required for M21.4 Feature Completion

| ID | Gap | Impact | Mitigation |
|----|-----|--------|------------|
| **GAP-04** | **No Embedding Data Populated** | All embedding columns are NULL; semantic search returns empty results | Run Admin-triggered embedding generation for all PUBLISHED Content and non-ARCHIVED Products |
| **GAP-05** | **No Semantic Search API** | No `/semantic/search` endpoint for content/product semantic search | Design and implement GET/POST `/semantic/search` with query embedding + vector similarity |
| **GAP-06** | **No Entity Aggregation Strategy** | Content and Product results are separate; no unified search across entity types | Design unified search response format with entity type discrimination and mixed ranking |
| **GAP-07** | **No Relevance Scoring/Ranking** | pgvector returns raw cosine distance; no business-level relevance ranking | Implement ranking layer: vector distance × content quality score × recency boost |

### 5.3 P2 — Future Enhancement

| ID | Gap | Impact | Mitigation |
|----|-----|--------|------------|
| **GAP-08** | **No Demand Embedding** | Demand cannot be semantically matched to Products beyond structured parameter matching | Add `Demand.embedding VECTOR(1536)` for semantic demand→product matching |
| **GAP-09** | **No Organization Embedding** | Supplier profiles cannot be semantically searched | Add `Organization.embedding VECTOR(1536)` for supplier capability discovery |
| **GAP-10** | **No Cross-Entity Semantic Mapping** | Content→Product semantic bridging not possible (e.g., "find products related to this knowledge article") | Design semantic entity mapping table or similarity computation |

### 6.3 Semantic Module Design

**Proposed Module Structure:**

```
apps/api/src/semantic/
├── semantic.module.ts          # Module registration
├── semantic.controller.ts      # Search API endpoints
├── dto/
│   ├── semantic-search.dto.ts  # Search request DTO
│   └── semantic-result.dto.ts  # Search response DTO
├── retrieval.service.ts        # Vector similarity queries
├── ranking.service.ts          # Relevance scoring & ranking
└── embedding-cache.service.ts  # Query embedding caching
```

**Module Boundary:**

- **IN**: Query text → Embedding generation → Vector similarity → Entity resolution → Ranking → Response
- **OUT**: Never modify Content/Product/Matching/Offer business logic
- **DEPENDS ON**: EmbeddingService (for query embedding), PrismaService (for data access)
- **Independent**: No dependency on business workflow modules

## 9. Risk Analysis

### 9.1 Technical Risks

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| **pgvector index build failure** | Low | High | IVFFlat is well-documented; test on dev first; fallback to sequential scan for small datasets |
| **OpenAI API rate limiting** | Medium | Medium | Batch with delays; queue-based embedding generation; consider local embedding model (e.g., sentence-transformers) as fallback |
| **Vector dimension mismatch** | Low | High | text-embedding-3-small always outputs 1536; validate dimension after each generation |
| **Prisma raw SQL injection risk** | Medium | High | Use parameterized queries (`$1::vector`); never concatenate user input into raw SQL |
| **Embedding data staleness** | Medium | Low | Content edit → needs re-embedding; implement re-embedding trigger in Admin UI |
| **Vector search performance** | Medium | Medium | IVFFlat with proper `lists` parameter; monitor query latency; HNSW upgrade if needed |

### 9.2 Architecture Risks

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| **Semantic module leaks into business logic** | Medium | High | Strict module boundary enforcement; no import of semantic module from business modules |
| **Embedding generation becomes blocking** | Low | Medium | Keep Admin Manual Trigger; never auto-generate on Content/Product save |
| **Search API exposes internal data** | Medium | High | Only search PUBLISHED Content; only search non-ARCHIVED Products; never expose internal fields |
| **pgvector extension removal** | Low | Critical | Document migration history; pgvector is part of PostgreSQL ecosystem; no removal expected |

### 9.3 Business Risks

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| **Semantic search replaces structured matching** | Low | High | Semantic Layer is additive; structured Matching is the primary business flow; Semantic Search is discovery, not matching |
| **User expects Google-like search** | Medium | Low | Manage expectations: Semantic Search is capability discovery, not full-text search; set clear UX boundaries |
| **No embedding data = no search results** | High | High | M21.4.2 (Data Population) must complete before any search API is exposed to users |
