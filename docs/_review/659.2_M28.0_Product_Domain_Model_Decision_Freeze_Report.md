## 2. Existing Product Domain Reality

- **Product = 平台全球目录（Global Catalog）**：无 organizationId / ownerId，`createdById` 仅审计，仅 Admin `POST/PATCH /products`。
- **Supplier Capability = Product + Offer（Model B）**：`Offer(organizationId, productId)` @@unique，供应商只能对既有目录产品建 Offer，organizationId 服务端派生。
- **Product 单实体过度承载**：同时承担平台标准 / 展示 / SEO / 搜索 / 报价 /（间接）供应商能力载体——这是演化的动机，但必须保留全局唯一目录。
- **约束冻结**：`Product.organizationId / ProductFamily / ProductModel / SupplierOffering` 禁止、Supplier 店铺化禁止、Product 不属于 Organization。

**选定 Model C（限定版）**：不新增供应商自有目录；`Supplier Product` = **派生供应商变体**。

## 4. Final Product Domain Decision

```
Platform Product
      |
Supplier Product（派生供应商变体）
      |
      Offer
      |
Supplier Organization
```

- **Platform Product**（保留全局权威）= 现有 Product
- **Supplier Product** = 供应商变体（不新顶层实体，落 Offer/变体层）
- **Offer** = 商业能力声明（保持绑 Platform Product）

## 5. Entity Responsibility Freeze

### 5.1 Platform Product（负责）

- ✅ Category（目录分类）
- ✅ Standard Capability（标准能力）
- ✅ Standard Parameter（标准参数）
- ✅ Search Index（搜索索引）
- ✅ SEO Entry（权威 SEO 入口）
- ✅ Public Capability Node（公开能力节点）
- NOT ❌：Supplier Brand / Supplier Model / Commercial Offer / Quotation

### 5.2 Supplier Product（负责）

- ✅ Supplier Brand（供应商品牌）
- ✅ Series（系列）
- ✅ Model Number（型号）
- ✅ Product Description（供应商描述）
- ✅ Supplier Media（供应商媒体）
- ✅ Supplier Parameters（供应商参数覆盖）
- ✅ Technical Documents（技术文档）
- ✅ Application Information（应用信息）
- **归属**：Supplier Organization
- **状态流**（落变体层，非全库 Product）：`Draft → Submitted → Reviewing → Approved → Published / Rejected`

### 5.3 Offer（负责）

- ✅ Commercial Capability（商业能力）
- ✅ Availability（供货能力）
- ✅ Inquiry Response（询价响应挂接）
- ✅ Quotation（报价语义）
- ✅ RFQ Relation（RFQ 关联）
- ✅ Supplier Business Commitment（供应商商业承诺）
- **明确：`Offer != Product`**——Offer 是商业层，Product 是能力层，二者解耦。

## 6. Product Governance Workflow（冻结）

```
Supplier Side:
  Supplier → Create Supplier Product Draft → Submit Review

Admin Side:
  Admin → Review → Approve → Publish → Public Display
           └→ Reject（退回/驳回）
```

- 全局 **Platform Product 仍由 Admin 唯一维护**，不走供应商提交。
- 审批流作用于**供应商变体层**，不污染全库 Product status。

## 7. Permission Boundary（冻结）

### Admin（负责）
- Platform Product 创建 / Platform Category 管理 / Standard Parameter 治理 / Supplier Product 审批 / Content 治理 / 数据纠错

### Supplier（负责）
- Supplier Product Draft / Own Product Info / Own Media / Own Capability Description / Offer 管理

### Supplier（禁止）
- ❌ 修改 Platform Product
- ❌ 修改 Global Category
- ❌ 修改 Standard Parameter Definition

## 8. Buyer Experience（冻结）

**Buyer Product Discovery Model（三层）**：
1. **第一层 Platform Capability**——直达公开能力节点（全局权威产品呈现）
2. **第二层 Supplier Products**——该能力下各供应商专属变体/型号
3. **第三层 Commercial Offers**——商业报价 / 询价 / RFQ 入口

三层由上而下渐进，体验始终由「能力」驱动，非「店铺/卖家」驱动。
