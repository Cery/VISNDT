## 5. Found Issues

### Issue #1 (CRITICAL): `GET /files/:id` endpoint does not exist

**Severity:** CRITICAL  
**Type:** Missing Backend Endpoint  
**Discovery:** Code audit of `apps/api/src/file-asset/file-asset.controller.ts`

**Description:**
The backend FileAsset controller defines three endpoints:
- `POST /files/upload`
- `GET /files/:id/download`
- `DELETE /files/:id`

There is **no** `GET /files/:id` endpoint to retrieve a single FileAsset record by ID.

**Impact:**
The frontend `fileAssetService.getById()` method was calling this non-existent endpoint, which would result in a 404 error. This affected:
- `ProductMediaList.tsx` — failed to resolve FileAsset metadata for each row
- `ProductMediaEdit.tsx` — failed to load the current file for display

**Root Cause Analysis:**
The backend `ProductMediaService` already includes `fileAsset` in its responses via `include: { fileAsset: true }` in the Prisma queries. The frontend was not leveraging this data — instead, it was making a separate (broken) API call to `GET /files/:id`.
