## 4. Feature Implementation

### 4.1 Knowledge 动态化

`apps/web/src/app/knowledge/page.tsx`：Hero 区域保持不变；列表区域改为通过 `getContentList({ type: 'KNOWLEDGE', pageSize: 50 })` 动态拉取，展示标题 / 摘要 / 发布时间，卡片链接指向 `/knowledge/[slug]`。API 不可用时降级为空状态（`暂无已发布的知识内容`），不阻塞页面渲染。

### 4.2 Solution 动态化

`apps/web/src/app/solutions/page.tsx`：Hero 区域保持不变；列表区域改为通过 `getContentList({ type: 'SOLUTION', pageSize: 50 })` 动态拉取，展示标题 / 摘要 / 发布时间，卡片链接指向 `/solutions/[slug]`。API 不可用时降级为空状态。

### 4.3 Detail 页面

- `apps/web/src/app/knowledge/[slug]/page.tsx`：知识详情，含面包屑、作者、发布时间、摘要引言、正文（纯文本 + `prose` 排版）。内容不存在时 `notFound()` 返回 404。
- `apps/web/src/app/solutions/[slug]/page.tsx`：解决方案详情，结构同上。

### 4.4 SEO Metadata

两个详情页均实现 `generateMetadata()`，复用 M16.3 `apps/web/src/lib/seo.ts` 的 `SITE_DESCRIPTION` 等常量，来源优先级：`seoTitle` / `seoDescription` → `title` / `summary` → 站点默认值；并输出 `openGraph`。列表页保留静态 `metadata`。

## 5. Architecture Impact

遵循既有分层，未引入越层调用：

```
Web Page (/knowledge /knowledge/[slug] /solutions /solutions/[slug])
   ↓
Content Service (services/content.service.ts)
   ↓
API Wrapper (lib/api/content.ts)
   ↓
Backend Content API (GET /content/public, /content/public/:slug)
```

- 页面无直接 `fetch()` / `axios()` / 直接 `apiClient` 业务调用
- Service 层仅封装数据获取，不含页面逻辑
- 仅消费 `status=PUBLISHED` 内容
