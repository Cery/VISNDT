## 三、平台化定义与审计维度

**平台化** = 双端（Web/Admin）共享一套**统一的、专业的、工业级的跨端设计系统**，消除"页与页、端与端"的视觉与交互割裂。

审计 8 维度：

1. Design Token（颜色/间距/字体/圆角/阴影）
2. 图标体系（Icon System）
3. 原子组件层（Button/Input/Card/Badge/Tag/Table/Pagination）
4. 状态系统（Empty/Error/Loading）
5. 页面模板与 SectionHeader
6. 信息架构 / 导航 / 面包屑
7. 表单规范
8. 数据可视化 / 图表配色

## 五、平台化差距清单（分级）

### P0（平台化硬伤，阻断统一）

| # | 差距 | 说明 |
|---|------|------|
| G1 | **双端设计系统割裂** | Web（Tailwind 手写）与 Admin（Ant Design）无跨端共享 token/组件/图标源，平台视觉语言分裂为两套 |
| G2 | **Web 无图标体系** | Web 零图标库，用 77 处 emoji 顶替专业图标，workspace 尤其严重，直接破坏平台专业感 |

### P1（一致性差距，需优先收敛）

| # | 差距 | 说明 |
|---|------|------|
| G3 | **Web 缺原子 UI 组件层** | 无 `ui/` Button/Input/Card/Badge/Table 原子组件，各页手写样式，无法保证一致性 |
| G4 | **双端 primary 色值不一致** | Web `--primary` ≈ `#3b82f6`，Admin `#2563eb`，双端品牌主色未对齐 |
| G5 | **SectionHeader 未全量 + 三套实现** | Web `brand/SectionHeader`、Admin `dashboard/SectionHeader`、Admin `operation-center/OperationSectionHeader` 各自实现；Web 仅 home 使用 |
| G6 | **列表分页不统一** | Web `Pagination` 仅 3 文件使用，其余列表页分页策略不一 |

### P2（细节完善）

| # | 差距 | 说明 |
|---|------|------|
| G7 | 登录/注册表单规范 | 表单细节未达平台标准（M24.4.9 Level C3） |
| G8 | 信息架构/导航/面包屑 | 双端导航、面包屑、页面模板未统一 |
| G9 | 媒体资产体系 | 629 Decision B：无版本/组织隔离/软删除（4.5/10），拖累平台资产专业度 |

## 八、结论与下一步

**结论：CONDITIONAL PASS（平台化尚未达标）**

- 平台已具备「结构完整 + 分段设计系统雏形」，但 Web/Admin 双端设计系统割裂、Web 缺图标体系与原子组件层，尚未达到「平台化」的统一专业标准。
- 根因非功能缺陷，而是**缺一个跨端统一的设计系统地基**。

**Next Step：M24.6.0 设计系统架构决策**（audit/decision，先定跨端 Design Token 单一事实源 + 图标库选型 + 组件层策略，再进入实现）。

> 本审计全程零代码变更，仅产出差距清单 + 演进路线，并落盘 V3.2.3 执行指令与项目文档同步。
