## 4. FileAsset Integration

### 4.1 file-asset.service.ts Enhancements

```typescript
// New method: Get signed URL for download/preview
async getSignedUrl(fileAssetId: string): Promise<string>
// Calls GET /files/:id/download, handles both string URL and { url } object responses

// New method: Get FileAsset record by ID  
async getById(fileAssetId: string): Promise<FileAsset>
// Calls GET /files/:id for metadata retrieval
```

### 4.2 file-utils.tsx Utilities

```typescript
// File type icon mapping
getFileTypeIcon(fileType: FileType): React.ReactNode
// Returns: FileImageOutlined | FileTextOutlined | FileProtectOutlined | FileUnknownOutlined

// Human-readable file size
formatFileSize(bytes: number): string
// Returns: e.g., "1.5 MB", "256 KB"
```

### 4.3 Async URL Resolution Pattern

All image previews use a state-based async resolution pattern:
1. On data load, `getById()` retrieves FileAsset metadata
2. For IMAGE types, `getSignedUrl()` resolves the signed URL
3. URL is stored in component state (`signedUrlCache` / `signedUrl`)
4. `<Image src>` uses the resolved URL string (not a Promise)

### 4.4 Download Flow

1. User clicks Download button
2. `fileAssetService.getSignedUrl(fileAssetId)` is called
3. A temporary `<a>` element is created with the signed URL
4. `download` attribute is set to the original file name
5. `click()` triggers the browser download
6. Temporary element is cleaned up

## 5. Security Impact

| Aspect | Assessment |
|---|---|
| **Authorization** | All API calls go through `apiClient` which injects JWT `Authorization` header via interceptor |
| **Signed URLs** | File download uses backend-generated signed URLs (time-limited, S3/MinIO native) |
| **No Direct S3 Access** | Frontend never accesses S3/MinIO directly; all file access goes through backend API |
| **Input Validation** | File upload uses `accept` attribute restrictions; backend validates file size and type |
| **No New API Endpoints** | Only uses existing `GET /files/:id/download` and `GET /files/:id` endpoints |
| **XSS Prevention** | React JSX auto-escapes; no `dangerouslySetInnerHTML` used |
| **No New Dependencies** | Zero new npm packages added |
