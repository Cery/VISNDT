## 一、目标与范围

**目标**：落实你「不同供应商资料——图片 / 描述 / 插图 / 资质 / 规格书——分开管理」的核心诉求，对 `FileAsset`（媒体资产）做最小迁移：

1. 规格书 vs 普通文档细分（`SPEC_SHEET`）、插图细分（`ILLUSTRATION`）
2. 供应商组织级隔离**落列**（`organizationId`）
3. 媒体生命周期状态（`status`）与软删除（`deletedAt`）——回收站能力

**范围边界（本门禁只允许触碰）**：`FileAsset` 模型 + `FileType` 枚举 + 新增 `FileAssetStatus` 枚举 + `Organization` 反向关系。**不新增任何业务表**，不触碰 Matching / Search / Product 核心模型 / AI / 知识映射 / RBAC。

## 四、迁移 DDL（`prisma migrate dev` 自动生成预期 + 手写回填）

预计迁移名：`add_file_asset_isolation_and_file_type_taxonomy`

### 4.1 枚举扩展

```sql
-- AlterEnum: FileType
ALTER TYPE "FileType" ADD VALUE 'SPEC_SHEET';
ALTER TYPE "FileType" ADD VALUE 'ILLUSTRATION';

-- CreateEnum: FileAssetStatus
CREATE TYPE "FileAssetStatus" AS ENUM ('DRAFT', 'ACTIVE', 'ARCHIVED');
```

### 4.2 FileAsset 结构性变更

```sql
-- Add columns (nullable / with default → 非阻塞写入)
ALTER TABLE "file_asset"
  ADD COLUMN "organization_id" UUID,
  ADD COLUMN "status" "FileAssetStatus" NOT NULL DEFAULT 'ACTIVE',
  ADD COLUMN "deleted_at" TIMESTAMP(3);

-- Indexes
CREATE INDEX "file_asset_organization_id_idx" ON "file_asset"("organization_id");
CREATE INDEX "file_asset_status_idx" ON "file_asset"("status");
CREATE INDEX "file_asset_deleted_at_idx" ON "file_asset"("deleted_at");

-- Foreign key (组织删除→媒体归属置空，不级联删媒体)
ALTER TABLE "file_asset"
  ADD CONSTRAINT "file_asset_organization_id_fkey"
  FOREIGN KEY ("organization_id") REFERENCES "organization"("id")
  ON DELETE SET NULL ON UPDATE CASCADE;
```

### 4.3 数据回填（迁移后一次性执行）

```sql
-- 回填 organization_id：现有文件经 uploaded_by → user.organization_id
UPDATE "file_asset" fa
SET "organization_id" = u."organization_id"
FROM "user" u
WHERE fa."uploaded_by" = u."id"
  AND u."organization_id" IS NOT NULL
  AND fa."organization_id" IS NULL;

-- status 默认 ACTIVE（DDL 默认值已覆盖存量行）；deleted_at 保持 NULL（软删未删除态）
-- 断言：回填后 organization_id 为 NULL 的行 = 上传者无组织的行（如管理员上传的公共素材）
```

## 五、回滚策略

因本迁移为**纯增量**（加列/加枚举值，未改写既有列），回滚顺序：

1. `ALTER TABLE "file_asset" DROP CONSTRAINT "file_asset_organization_id_fkey";`
2. `DROP INDEX "file_asset_organization_id_idx"; DROP INDEX "file_asset_status_idx"; DROP INDEX "file_asset_deleted_at_idx";`
3. `ALTER TABLE "file_asset" DROP COLUMN "organization_id", DROP COLUMN "status", DROP COLUMN "deleted_at";`
4. `DROP TYPE "FileAssetStatus";`
5. `FileType` 枚举值为**新增且迁移时无数据引用**，PG 不支持直接 DROP VALUE，需重建类型（或保留枚举值，无副作用）。因无存量数据写入新值，保留不构成风险。

> 回滚安全结论：**可无损回滚**，不丢失任何既有文件数据；唯一残留为 `FileType` 枚举多了两个可用值（无害）。
