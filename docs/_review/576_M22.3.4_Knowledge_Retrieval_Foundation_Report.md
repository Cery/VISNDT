## Execution Summary

### Objective

建立 Knowledge Retrieval Foundation 基础能力，使 Knowledge Classification 与 Knowledge Association 产出的知识资产进入可公开访问状态，形成完整的 Knowledge Asset Layer → Retrieval Foundation → Public Knowledge Access Capability 链路。

### Deliverables

**API Capability** — 5 Public Knowledge Query Endpoints:

| Method | Endpoint | Access | Description |
| --- | --- | --- | --- |
| GET | `/knowledge/public/domains` | PUBLIC | 查询所有知识领域（含分类/条目计数） |
| GET | `/knowledge/public/domains/:slug` | PUBLIC | 按 slug 查询知识领域详情（含分类列表） |
| GET | `/knowledge/public/categories` | PUBLIC | 查询知识分类（支持 domainId 筛选） |
| GET | `/knowledge/public/entries` | PUBLIC | 查询已发布知识条目（支持 domainId/categoryId/status=PUBLISHED/pageSize/page 筛选） |
| GET | `/knowledge/public/entries/:slug` | PUBLIC | 按 slug 查询已发布知识条目详情（含 contentRefs + relations） |

**Web Capability** — 3 Knowledge Public Pages:

| Route | Page | Description |
| --- | --- | --- |
| `/knowledge-base` | Knowledge Home | 领域导航 + 最新知识条目列表 |
| `/knowledge-base/domains/[slug]` | Domain Page | 领域详情 + 分类展示 + 条目列表 |
| `/knowledge-base/[slug]` | Entry Detail | 结构化内容渲染 + 内容引用展示 + 知识关联展示 |

| `apps/api/src/knowledge/knowledge.module.ts` | 注册 KnowledgePublicController |
| `apps/api/src/knowledge/index.ts` | 导出 KnowledgePublicController |

### API Design Constraints

- 所有 Public Endpoints 仅返回 `status = PUBLISHED` 的知识条目
- Content References 通过 `include` 关联返回，不复制 Content 内容
- Knowledge Relations 通过 `sourceRelations` / `targetRelations` 双向返回
- 支持分页（pageSize/page）和筛选（domainId/categoryId）

| `apps/web/src/app/knowledge-base/error.tsx` | Knowledge Home 错误处理 |

### Web Design Constraints

- 路由使用 `/knowledge-base` 前缀，与现有 `/knowledge`（Content 类型）区分
- 结构化内容通过 `structuredBody.sections` 渲染，支持 title + content 分段
- 内容引用按 referenceType 分组展示（SOURCE / RELATED / SUPPLEMENT）
- 知识关联按 relationType 分组展示（RELATED / CHILD / PARENT / PREREQUISITE / FOLLOWUP）
- 所有页面支持 loading.tsx 和 error.tsx 状态处理
