## 3. Issue Resolution

### P1-01: Product slug lookup P2023

**Root Cause**: `ProductsService.findOne(id)` 仅支持 `findUnique({ where: { id } })`，当传入 slug（如 `demo-mv4500-hd-electronic-borescope`）时，Prisma 将非 UUID 字符串传入 `id` 列（`@db.Uuid`），抛出 P2023（Inconsistent column data）。

**Fix**: 在 `findOne()` 中添加 UUID 格式检测，支持双模式查询：

```typescript
// UUID format regex: 8-4-4-4-12 hex digits (lenient — supports demo deterministic IDs)
private static readonly UUID_REGEX = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

async findOne(idOrSlug: string) {
  const isUuid = ProductsService.UUID_REGEX.test(idOrSlug);
  const product = await this.prisma.product.findUnique({
    where: isUuid ? { id: idOrSlug } : { slug: idOrSlug },
    include: { /* ... existing includes ... */ },
  });
  if (!product) throw new NotFoundException(`产品 ${idOrSlug} 未找到`);
  return product;
}
```

**Key Design Decisions**:
- UUID regex 使用 lenient 格式（不强制 version/variant nibble），以兼容 demo 数据的 SHA-256 确定性 ID
- 复用 `findUnique`（slug 字段为 `@unique`），无需 `findFirst`
- 保持 include relations 不变，零 contract 变更

**Files Changed**:
- `apps/api/src/products/products.service.ts`: UUID/slug 双模式查询逻辑
- `apps/api/src/products/products.controller.ts`: Swagger doc 更新（`id` → `id or slug`）
