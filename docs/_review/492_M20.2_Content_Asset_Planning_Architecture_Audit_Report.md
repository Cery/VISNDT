## 3. Existing Architecture Analysis

### 3.1 Content Asset Boundary Mapping

Mapping current implementation to the four asset categories:

| Asset Category | Current Implementation | Status |
|----------------|------------------------|--------|
| **Product Asset** | Product model, categories, parameters, ProductCenter | Complete (M19) |
| **Knowledge Asset** | KNOWLEDGE ContentType, `/knowledge` pages, SEO | **Operational** |
| **Solution Asset** | SOLUTION ContentType, `/solutions` pages, SEO | **Operational** |
| **Business Asset** | `/business` (static), `/about` (static) | **Static/Not Content-Managed** |

### 3.2 Architecture Strengths

1. **Content Domain is mature**: Full lifecycle (DRAFT→REVIEW→PUBLISHED→ARCHIVED), version history, media management, scheduled publish, SEO metadata
2. **Public/Admin separation**: Public API only exposes PUBLISHED content with public-safe projection
3. **Workflow integration**: Content transitions emit WorkflowEvent and AuditLog
4. **SEO foundation**: Dynamic metadata, JSON-LD, OpenGraph, sitemap, canonical URLs
5. **Content model is unified**: Single Content model with type discriminator (KNOWLEDGE/SOLUTION/ARTICLE/INSIGHT)
6. **Media management**: ContentMedia → FileAsset → S3 storage chain with atomic upload-create

### 3.3 Architecture Gaps

| Gap | Severity | Description |
|-----|----------|-------------|
| Content-Search Integration | High | Content not searchable via `/search`; search only covers products |
| Content Tagging/Taxonomy | High | No tagging system beyond ContentType; no cross-content linking |
| Business Asset Management | Medium | `/business` and `/about` are static pages, not content-managed |
| ARTICLE/INSIGHT Frontend | Medium | ARTICLE and INSIGHT types defined but no public frontend routes |
| robots.txt | Low | Missing robots.txt for crawler directives |
| Content-to-Product Linking | Medium | No way to link content articles to related products |
| Content Analytics | Low | No content view tracking or engagement metrics |
| Content Recommendation | Medium | No cross-content or content-to-product recommendation |
| AI Content Assistant | Low | No AI-assisted content generation or editing |

## 4. Content Asset Model Proposal

### 4.1 Four-Layer Content Asset Architecture

```
┌─────────────────────────────────────────────────────────┐
│                    VISNDT Content Asset System            │
├─────────────────────────────────────────────────────────┤
│  Product Asset          │  Knowledge Asset               │
│  ─────────────          │  ───────────────               │
│  • Product parameters   │  • Detection methods           │
│  • Product capabilities │  • Industry standards          │
│  • Technical specs      │  • Application knowledge       │
│  (Product Model, M19)   │  • Technical articles          │
│                         │  (KNOWLEDGE ContentType)        │
├─────────────────────────┼────────────────────────────────┤
│  Solution Asset         │  Business Asset                │
│  ──────────────         │  ──────────────                │
│  • Industry solutions   │  • Company introduction        │
│  • Application scenarios│  • Industry cases              │
│  • Inspection workflows │  • Service capabilities        │
│  (SOLUTION ContentType) │  (ARTICLE + static pages)      │
└─────────────────────────┴────────────────────────────────┘
```

### 4.2 Content Type Expansion Proposal

| ContentType | Current | Proposed | Rationale |
|-------------|---------|----------|-----------|
| KNOWLEDGE | Operational | Keep | Detection methods, standards, technical articles |
| SOLUTION | Operational | Keep | Industry solutions, application scenarios |
| ARTICLE | Defined, no route | Add `/articles` route | General articles, industry news |
| INSIGHT | Defined, no route | Add `/insights` route | Parameter encyclopedia, technical deep-dives |
| BUSINESS | **New** | Add as ContentType | Replace static `/business` page with managed content |
| CASE | **New** | Add as ContentType | Industry case studies, customer success stories |

### 4.3 Content Tagging & Taxonomy Model (Future)

```
ContentTag {
  id, name, slug, type (TOPIC|INDUSTRY|APPLICATION|TECHNOLOGY)
}

ContentTagRelation {
  contentId, tagId
}
```

This enables:
- Cross-content linking (related articles, related solutions)
- Content filtering by industry/application
- SEO-friendly tag pages
- Content-to-product linking via shared tags

### 4.4 Content-Search Integration (Future)

Content should be discoverable through the global search:
- Index content title, summary, and SEO fields
- Distinguish content types in search results (Article vs Product)
- Add content tab/filter to search results page
- Maintain Database Query First approach (no Elasticsearch)
