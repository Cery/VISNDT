## 4. Frontend Architecture Impact

- **API Client 变化**：`lib/api/products.ts` 由「扁平 params」改为「`buildProductsQuery()` 序列化 + 经 endpoint 透传」，支持数组嵌套对象；`apiClient.ts` 本身未改（保持 `fetch` + 扁平 searchParams），通过 endpoint 传递括号记法避免破坏字面量 `[`/`]`。
- **State 变化**：`products/page.tsx` 新增 `parameterFilters: ProductParameterFilter[]` 状态，变更即 `setPage(1)` 并纳入 TanStack queryKey 触发重取，实现「UI State → Query Params Object → API Request」可预测链路。
- **Component 变化**：新增 `ParameterFilterPanel`（动态渲染筛选，无硬编码业务参数），`ProductFilter` 集成该区块；数据源为 `parameter-definition.service`（后端 `GET /parameter-definitions` 列表 + ENUM 详情 options）。

### API 验证（Network Request 预期）

选择 NUMBER 参数范围或 ENUM 参数后，`GET /products` 请求将携带：

```
GET /products?status=ACTIVE&page=1&pageSize=12&parameterFilters[0][parameterDefinitionId]=<uuid>&parameterFilters[0][valueMin]=2&parameterFilters[0][valueMax]=3
```

或 ENUM 精确匹配：`parameterFilters[0][parameterDefinitionId]=<uuid>&parameterFilters[0][value]=<optionValue>`。

### 功能场景设计

| 场景 | 预期 |
| --- | --- |
| 场景1：选择 NUMBER 参数范围（min/max） | 请求携带 `valueMin`/`valueMax`，后端按 `valueNumber` 区间过滤，产品列表仅返回范围内产品 |
| 场景2：选择 ENUM 参数 | 请求携带 `value`（option），后端按 `parameterValues.value` 精确匹配，仅返回匹配产品 |
| 场景3：清除筛选（面板「清除」） | `parameterFilters` 置空，请求不携带筛选，恢复全部产品 |

> 说明：本环境未能启动实时后端进行浏览器端到端实测；上述验证基于构建通过 + 后端既有 `parameterFilters` 处理逻辑（`products.service.ts`：value/valueMin/valueMax 互斥校验、NUMBER 走 `valueNumber` 区间、其余走 `value` 精确匹配）与前端序列化实现的一致性确认。建议在联调环境按下表做一次真实页面测试（见下节）。
