### 4.3 Data Flow Analysis

**目录列表（`/products`）**

```
useQuery(getProducts)           → GET /products（keyword / categoryId / parameterFilters / sort / pagination / status=ACTIVE）
useQuery(getCategories)         → GET /product-categories（page=1, pageSize=100）
useQuery(getFilterParameterDefinitions) → GET /parameter-definitions + 详情合并 ENUM options（前端组装）
```

后端 `ProductsService.findAll()`：
- 关键词 OR（name / model / description）
- 分类过滤 `categoryId`
- 参数过滤 `parameterFilters`（精确匹配 `value` 或数值范围 `valueMin/valueMax`），多参数 AND 逻辑
- `include: { category, createdBy.organization }` —— **不含 `media`、不含 `parameterValues`**

**详情（`/products/[slug]`）**

```
GET /products/:id-or-slug → include: category, parameterValues(→parameterDefinition), media, offers(→organization), createdBy(→organization)
```

**比较（`/products/compare?ids=`）**：复用 `ProductCard` 复选框（MAX 4）→ `CompareBar` → `CompareTable`。

## 5. Category Architecture Audit

Schema（`schema.prisma` `model ProductCategory`）：

- `parentId`（自引用 `parent`/`children`，`CategoryTree` 关系）— **树形结构已建模**
- `products` / `demands` / `knowledgeMappings` 关联
- 索引：`@@index([parentId])`

后端 `GET /product-categories`（`findAll`）已 `include: { children: true }`，**API 层已返回树形子分类**。

**但前端 `ProductFilter` 对 `categories` 做 `categories.map()` 平铺渲染，忽略 `children`** —— 树形导航能力在数据/API 层具备、UI 层未消费。一级/二级分类导航当前不可用。

结论：**树能力已具备，UI 未落地**。

## 6. Parameter Architecture Audit

Schema 模型链：

- `ParameterGroup`（分组）
- `ParameterDefinition`（name / code / dataType / unit / required / group）
- `ParameterOption`（ENUM 选项，`onDelete: Cascade`）
- `ProductParameterValue`（value + valueNumber，`@@unique([productId, parameterDefinitionId])`，含 value/valueNumber 索引，支持筛选加速）
- `ProductParameterDefinition`（产品-参数关联，displayOrder）

后端筛选能力（`SearchProductDto` + `ProductsService.findAll`）：
- 精确匹配 `value`
- 数值范围 `valueMin/valueMax`（`valueNumber` 字段，gte/lte）
- 多参数 AND 逻辑，值/范围互斥校验

**Gap**：`/products` 页面的 `getFilterParameterDefinitions()` 拉取 **全站** `GET /parameter-definitions`（page=1, pageSize=100），**无分类上下文**。相比之下，Search 侧（`search-context.service.ts`）已实现 `computeCategorySpecific` 的分类专属参数计算。

结论：**参数筛选能力（精确+范围+AND）已完备，但不支持分类上下文筛选（全站参数平铺）**。

## 8. Product Center vs Search Boundary

| 维度 | Product Center（`/products`） | Search（`/search`） |
| --- | --- | --- |
| 定位 | 目录发现（Catalog Discovery） | 主动检索（Unified Retrieval） |
| 实体范围 | 仅 Product | 5 实体（Product / Knowledge / Content / Solution / Supplier） |
| 关键词 | ✅ name/model/description | ✅ 统一聚合 |
| 分类 | ✅ categoryId 单选平铺 | ✅ 分类 Tab + 分类专属 Facet |
| 参数筛选 | ✅ 精确+范围，**全站参数** | ✅ 精确+范围，**分类专属参数（category-specific）** |
| 比较 | ✅ Compare 专有能力 | ❌ |
| 供应商 | ✅ 详情页询价入口 | ✅ Supplier 实体 Tab |

**能力重叠**：两者均具备关键词 + 分类 + 参数筛选能力，但从职责看应保持 **Search = 主动检索（多实体、跨域、分类上下文）**，**Product Center = 目录发现（纯产品、树形分类导航、比较、商业转化）**。M24.2 改造应强化 Product Center 的「目录化」差异能力，而非与 Search 重叠的部分。

## 10. M24.2 Target Architecture Recommendation

仅方向建议（**本任务禁止实施**）：

1. **目录化导航**：消费 `ProductCategory.parentId/children`，实现一级/二级分类树形导航（数据/API 已就绪，仅 UI）。
2. **列表媒体能力**：在列表 API 最小化 `include media`（或 `isPrimary` 首图），卡片渲染真实图片（`ProductMedia` 已具备）。
3. **分类上下文参数**：将 `/products` 参数面板从「全站参数」收口为「选中分类的参数」（复用/对齐 Search `search-context` 的分类专属参数语义，但保持 Product 单实体目录定位）。
4. **卡片参数摘要**：`include` 关键 `parameterValues` 以在卡片展示 2–3 条核心参数（可选，P2）。
5. **保持边界**：Product Center 不做多实体聚合（那是 Search 的职责）、不引入 AI 推荐、不引入 Supplier Store。
