## 2. Current Schema Reality（Model B 现状扫描）

基于 `database/prisma/schema.prisma` 真实扫描：

**Product Domain**
- `Product`：`categoryId` 必填、`status String @default("DRAFT")`（非枚举）、`slug @unique?`、`seoTitle?`、`embedding Unsupported("vector(1536)")?`、`createdById?` **仅审计**；**无 organizationId/ownerId** → 平台全球目录，能力节点。
- `ProductCategory`：树（parentId/children），slug 唯一。
- `ProductMedia`：`productId + fileAssetId? + mediaType(FileType) + isPrimary + displayOrder`，product Cascade。
- `ProductParameterValue`：`@@unique([productId, parameterDefinitionId])` → 平台参数实例。
- `ProductParameterDefinition`：`@@unique([productId, parameterDefinitionId])` → 平台参数目录关联。
- `ParameterDefinition/ParameterGroup/ParameterOption`：平台级全局参数（`code` 唯一）。

**Supplier Domain**
- `Organization`/`OrganizationMember`（role String）：组织本体与成员，无产品归属字段。
- `Offer`：`@@unique([organizationId, productId])`，**绑定 Product 能力节点**；`price Decimal(12,2)/currency/status(OfferStatus)`。
- `FileAsset`：**已含 `entityType(FileEntityType)+entityId`、`organization_id`、`status(FileAssetStatus)`、`deleted_at` 软删** → 已具备 supplier/organization 归属分层基础。

**Commercial Domain**
- `Demand`/`DemandParameter`：需求侧，`categoryId?`。
- `DemandMatch`：`@@unique([demandId, productId])`，**依赖 `Product.productId` 能力节点**。
- `RFQ`：`demandId + sourceMatchId? + targetOrganizationId?`。
- `RFQResponse`：`@@unique([rfqId, organizationId])` + `offerId?`。
- `Inquiry`：`productId?` + `organizationId?`。

**FileEntityType 现状**：`PRODUCT / ORGANIZATION / DEMAND / RFQ / RFQ_RESPONSE / CONTENT`（**缺 `SUPPLIER_PRODUCT`** → 660.2 属主枚举扩展点）。

**结论**：Model B = `Offer→Product(能力节点)`、`DemandMatch→Product`、供应商厂商信息当前**冗余散落在 Offer 商业字段 + Supplier 显示表**（见 659 P1 制造商展示偏差），无型号级事实源。FileAsset 已具备 org 隔离，利好 Media/ Document 演进。

## 3. SupplierProduct Prisma Model Design（未来设计，不落库）

设计草案（供 660.2 冻结 Schema 方向，验证 660.1 §3.1）：

```prisma
enum SupplierProductStatus {
  DRAFT
  SUBMITTED
  REVIEWING
  APPROVED
  PUBLISHED
  REJECTED
}

model SupplierProduct {
  id                 String                @id @default(uuid()) @db.Uuid
  organizationId     String                @map("organization_id") @db.Uuid
  platformProductId  String                @map("platform_product_id") @db.Uuid

  // Product Identity
  brand              String
  series             String?
  modelNumber        String
  slug               String?               @unique // 供应商型号 URL（可选）

  // Content
  description        String?
  technicalDescription String?             @map("technical_description")
  applicationInfo    String?               @map("application_info")

  // Governance
  status             SupplierProductStatus @default(DRAFT)
  submittedAt        DateTime?             @map("submitted_at")
  reviewedAt         DateTime?             @map("reviewed_at")
  reviewedBy         String?               @map("reviewed_by") @db.Uuid
  reviewedNote       String?               @map("reviewed_note")
  publishedAt        DateTime?             @map("published_at")

  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  organization    Organization  @relation(fields: [organizationId], references: [id])
  platformProduct Product       @relation(fields: [platformProductId], references: [id], onDelete: Restrict)
  reviewedByUser  User?         @relation("SupplierProductReviewer", fields: [reviewedBy], references: [id])

  parameterValues SupplierProductParameterValue[]
  media           SupplierProductMedia[]
  offers          Offer[]

  @@index([organizationId])
  @@index([platformProductId])
  @@unique([organizationId, platformProductId, modelNumber])
  @@index([modelNumber])
  @@index([status])
  @@map("supplier_product")
}
```

**Index 设计**：`organizationId` / `platformProductId` / `@@unique([organizationId, platformProductId, modelNumber])` / `modelNumber` / `status`。

**红线**：
- `platformProductId → Product` 的 FK 用 `onDelete: Restrict`（能力节点是引用基线，不被型号级删除破坏）。
- `Product` 表**零改动**；不新增 `Product.organizationId / supplierId / supplierBrand / supplierModel / commercialField`。

## 4. SupplierProductStatus 设计（冻结）

```
DRAFT → SUBMITTED → REVIEWING → APPROVED → PUBLISHED
                            ↘ REJECTED
```

- 该状态**属于 SupplierProduct 生命周期**，**不是** Platform Product 状态。
- `Product.status`（String）维持平台治理语义，互不混用。
- 新增 enum `SupplierProductStatus`，作为独立枚举冻结于未来 Schema（660.2 不落库）。

## 5. Offer Schema Evolution Design

### Current → Future

```prisma
// Current
Offer { organizationId, productId }  @@unique([organizationId, productId])

// Future（Option C 兼容双绑，设计草案）
model Offer {
  ...
  organizationId   String  @map("organization_id") @db.Uuid
  productId        String  @map("product_id") @db.Uuid          // capability aggregation（能力节点）
  supplierProductId String? @map("supplier_product_id") @db.Uuid // commercial source → 新增可空
  ...
}
```

### 字段策略

| 项 | 设计 |
|-|-|
| Nullable | `supplierProductId` **新增且可空**（分阶段回填）；`productId` 保持必填（能力聚合，不做约束破坏） |
| Index | 新增 `@@index([supplierProductId])` |
| Unique | 保留 `@@unique([organizationId, productId])`；未来演进为 `@@unique([organizationId, supplierProductId])`（过渡方案不强制） |
| Foreign Key | `supplierProductId → SupplierProduct.id`，`onDelete: Restrict`（商业引用不稳定删除） |

## 6. Parameter Schema Design

### 6.1 Platform Parameter（标准参数）

- `ParameterDefinition`（平台全局目录，Admin 治理）+ `productParameterValue`（能力节点默认值）+ `productParameterDefinition`（目录关联）。
- **归属 Platform Product**，供应商不可改全局定义。

### 6.2 Supplier Override（覆盖平台参数）

设计草案：`SupplierProductParameterValue`，引用**同一条 `ParameterDefinition`**。

```prisma
model SupplierProductParameterValue {
  id                    String @id @default(uuid()) @db.Uuid
  supplierProductId     String @map("supplier_product_id") @db.Uuid
  parameterDefinitionId String @map("parameter_definition_id") @db.Uuid
  value                 String
  valueNumber           Float? @map("value_number")

  supplierProduct    SupplierProduct    @relation(fields: [supplierProductId], references: [id], onDelete: Cascade)
  parameterDefinition ParameterDefinition @relation(fields: [parameterDefinitionId], references: [id])

  @@unique([supplierProductId, parameterDefinitionId])
  @@map("supplier_product_parameter_value")
}
```

> 示例：Platform `Resolution=HD` → Supplier Override `Full HD`。

### 6.3 Supplier Extension（供应商扩展）

| 方案 | 说明 | 评估 |
|-|-|-|
| **A 复用 ParameterDefinition（推荐）** | 扩展能力同样引用平台 `ParameterDefinition`（必要时新增 `scope` 标记或伪全局定义），用 `SupplierProductParameterValue` 承载 | ✅ 复用既有参数语义/过滤/索引；避免自由键值表难治理 |
| B 独立 Extension Value | 新增 Supplier 私有 key-value 表 | ⚠️ 无法参与能力过滤/标准化比较，治理差 |

**推荐 = 方案 A**：Override 与 Extension 统一走 `SupplierProductParameterValue`，扩展参数以平台定义（或标注 supplier-scope 的定义）为锚点。

## 7. Media Schema Design

### 7.1 SupplierProductMedia

```prisma
model SupplierProductMedia {
  id                String   @id @default(uuid()) @db.Uuid
  supplierProductId String   @map("supplier_product_id") @db.Uuid
  fileAssetId       String?  @map("file_asset_id") @db.Uuid
  mediaType         FileType @map("media_type")
  documentType      String?  @map("document_type") // MANUAL/SPEC/CERT/INSPECTION_CASE（文档区分）
  title             String?
  altText           String?  @map("alt_text")
  isPrimary         Boolean  @default(false) @map("is_primary")
  displayOrder      Int      @default(0) @map("display_order")

  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  supplierProduct SupplierProduct @relation(fields: [supplierProductId], references: [id], onDelete: Cascade)
  fileAsset       FileAsset?      @relation(fields: [fileAssetId], references: [id])

  @@index([supplierProductId])
  @@index([fileAssetId])
  @@map("supplier_product_media")
}
```

### 7.2 FileEntityType 扩展评估

**结论：需要新增 `SUPPLIER_PRODUCT`**，使 `FileAsset.entityType=SUPPLIER_PRODUCT+entityId=supplierProductId` 可承载媒体与文档，与既有 `PRODUCT/ORGANIZATION/CONTENT` 归属模型一致。此为属主枚举扩展点，交 660.x 实现阶段落库。

## 8. Document Storage Design

**确认持续采用 `FileAsset + Media Relation` 承载，不新增独立 Document Entity**：

- Manual / Specification / Certificate / Inspection Case → `FileAsset(entityType=SUPPLIER_PRODUCT, fileType=SPEC_SHEET/DOCUMENT/CERTIFICATE/...)` + `SupplierProductMedia.documentType` 区分。
- 复用既有 upload / org 隔离 / status / 软删能力；避免重复元数据表（文档 = 媒体+类型组合，非独立业务实体）。
- 禁止无必要新增 `SupplierProductDocument` 实体。

## 9. Migration Impact Assessment

| 域 | 影响 | 结论 |
|-|-|-|
| **Product** | `NONE` | 平台能力节点零改动，不加属主字段 |
| **Offer** | `ADD supplierProductId`（可空 + FK + index） | 兼容双绑演进，非破坏 |
| **DemandMatch** | `NONE`（继续 `productId`） | 匹配仍确定性绑 **Platform Product 标准参数**，不引入型号级 |
| **RFQ / RFQResponse** | `NONE`（经 DemandMatch/Offer 间接关联） | 复用既有链路，是否暴露 `supplierProductId` 属 API 层（交 660.3），Schema 不加字段 |
| **Search** | `NONE`（Index Source = Platform Product） | 检索索引锚定能力节点 |
| **SEO** | `NONE`（Canonical = Platform Product） | 权威 URL 锚定能力节点；Supplier 型号降权由 Web 层控制 |
| **Inquiry** | `NONE`（productId 能力节点） | 保持现状 |

**兼容策略**（Migration Strategy B=兼容双绑 + C 渐进）：
1. 阶段0（当前）：不动，`Offer→Product`（Model B 稳定）。
2. 阶段1：新增 `SupplierProduct` + `SupplierProductStatus` + `SupplierProductParameterValue` + `SupplierProductMedia` + `SupplierProduct` document 承载；`Offer.supplierProductId`（可空）+ FK + index；`FileEntityType` 增 `SUPPLIER_PRODUCT`。
3. 阶段2：存量 Offer 批量回填 `supplierProductId`（数据清洗，低批次）。
4. 阶段3：`Offer.productId` 收敛为能力聚合冗余字段（经 SupplierProduct→PlatformProduct 继承），最终 `productId` 仅作能力节点关联。

**本任务不落库/不迁移，仅锁定 Schema 方向。**

## 10. Final Schema Architecture Decision

**Future Prisma Domain Model（冻结方向，Code State = Documentation State）**：

```
PlatformProduct(Product)
    1 ───────── N
SupplierProduct
    1 ───────── N
Offer（productId 能力聚合 + supplierProductId 型号源，Option C）
    N ───────── 1
Organization
```

- **Parameter Ownership**：Standard=`ProductParameterValue`（Platform）；Override=`SupplierProductParameterValue`（引用同 ParameterDefinition）；Extension=复用 ParameterDefinition + `SupplierProductParameterValue`（方案 A）。
- **Media Ownership**：Platform=`ProductMedia`；Supplier Product=`SupplierProductMedia`；Organization=`FileAsset.org`；Content=`ContentMedia`。`FileEntityType` 需增 `SUPPLIER_PRODUCT`。
- **Document Ownership**：`FileAsset + SupplierProductMedia.documentType`（Manual/Spec/Cert/InspectionCase），不新增实体。
- **Offer**：`organizationId` + `productId`(能力聚合, 保留) + `supplierProductId`(新增可空, 商业源)。

**状态 = AUTHENTICATED PASS（Schema Implementation Design Complete）。** 设计仅在文档/冻结层；Schema 未落库、未迁移。

**红线**：NO `Product.organizationId` / Supplier Store / Marketplace / Payment / Order / ERP。Platform Product 维持无属主全局能力节点。

**遗留**（交 660.3 API Architecture + M28 开发阶段）：SupplierProduct CRUD/审批 API、Offer 双绑写读、FileEntityType 枚举落库、SupplierProductMedia/ParameterValue 落库、批处理回填 SQL。
