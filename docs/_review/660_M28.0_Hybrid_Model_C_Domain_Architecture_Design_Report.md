## 2. Current Domain Reality Snapshot

基于真实 Schema 快照（`database/prisma/schema.prisma`）：

| 领域对象 | 现实定义 |
|---|---|
| `Product` | 平台全球目录，**无 organizationId / ownerId**；`status String @default("DRAFT")`（非枚举）；`slug @unique` + `seoTitle`；`embedding vector(1536)`；`categoryId` 必填；`createdById` 仅审计 |
| `ProductCategory` | 分类树（`parentId`+`children`），`slug @unique`，承载 `products/demands/knowledgeMappings` |
| `ProductMedia` | `productId + fileAssetId? + mediaType + isPrimary + displayOrder`，级联删除 |
| `ProductParameterValue` | `@@unique(productId, parameterDefinitionId)`，平台参数实例 |
| `ProductParameterDefinition` | `@@unique(productId, parameterDefinitionId)`，平台参数关联 |
| `ParameterGroup/Definition/Option` | 平台级参数目录（code 唯一） |
| `Offer` | `@@unique(organizationId, productId)`；**绑定 Product（非供应商实体）**；`OfferStatus` 枚举 |
| `Organization` | 组织本体（无产品归属） |
| `OrganizationMember` | 组织-成员 |
| `Demand / DemandMatch / RFQ / RFQResponse` | 匹配、审批、询报价链路，`DemandMatch` 绑 `productId + offerId?` |
| `Content / ContentMedia` | 内容与媒体（媒体归属 `entityType+entityId`） |
| `FileAsset` | 通用媒体：`entityType`(PRODUCT/ORG/DEMAND/RFQ/CONTENT) + `entityId` + `organizationId?` + 软删 |

**结论**：当前 = **Model B（Platform Product × Offer）**，`Product` 单实体过度承载平台/展示/SEO/搜索/报价/（间接）供应商能力载体。这就是 Model C 改良的切入点。

## 3. Hybrid Model C Architecture

冻结模型：

```
Platform Product（Capability Node，全局权威，现有 Product 演化）
      │
Supplier Product（独立领域实体 Route A）
      │
      Offer（商业能力层）
      │
Supplier Organization
```

三层职责解耦：**能力层（Platform Product）→ 供应商产品层（Supplier Product）→ 商业层（Offer）→ 组织（Supplier Organization）**。

## 4. Platform Product Definition（冻结）

**定位 = Capability Node**，不是「供应商产品 / 型号 / 商业产品」。

```
Category            （分类树）
    + Capability Node（能力节点，现有 Product = 全局目录演化）
    + Standard Capability Definition（标准能力定义）
    + Standard Parameter Definition（标准参数定义）
```

设计目标——平台回答：**「用户需要什么检测能力？」**

示例：`工业视频内窥镜 → 6mm 电子内窥镜 Capability Node → 供应商型号展示`

**Platform Product 禁止包含**：
- ❌ Supplier Brand / Supplier Model
- ❌ Commercial Price
- ❌ Supplier Media
- ❌ Supplier Description

保留字段能力：Global Category、Standard Parameter Definition、Search Index、SEO Entry、Public Capability Node。

## 5. Supplier Product Definition（冻结 · Route A）

选择 **Route A：Supplier Product = Independent Domain Entity**（独立领域实体，非现有 Product 上叠加 organizationId）。

```
Platform Product
      │
Supplier Product（独立实体）
      │
Supplier Organization
```

**Supplier Product 负责**：Supplier Brand / Series / Model Number / Supplier Description / Supplier Media / Technical Documents / Supplier Specific Parameters / Application Information。

**Supplier Product 不负责**：Global Category / Platform Capability / Standard Parameter Definition / Commercial Offer。

> 红线对齐：Route A 避免触碰冻结的 `Product.organizationId`——Platform Product 维持无属主全局目录；Supplier Product 为其**关联子实体**，归属 Supplier Organization。

## 6. Offer Definition（冻结）

**`Offer != Product`**——Offer 是 **Commercial Capability Layer**（商业能力层）。

**Offer 负责**：Availability（供货能力）/ Quotation（报价）/ Business Contact（商务联系）/ RFQ Response（询价响应）/ Commercial Terms（商务条款）。

**Offer 关系评估**（架构建议）：

| 方案 | 现状 | 建议 |
|---|---|---|
| Offer → Product | Model B 现状 | ❌ 丢失供应商型号维度，商业绑定过粗 |
| Offer → SupplierProduct | 未来 | ⚠️ 单一绑定，丢失能力节点聚合 |
| **Offer → SupplierProduct + PlatformProduct**（推荐） | — | ✅ 同时表达「哪个能力节点 + 哪家供应商的哪个型号」 |

**输出架构建议**：Off = `SupplierProduct` + `PlatformProduct` + `SupplierOrganization`。即未来 Offer 双向引能力层（PlatformProduct，聚合/搜索/SEO 权威）与产品层（SupplierProduct，型号/品牌/媒体）。**现有 Offer→Product 迁移为兼容过渡，见 660.1 数据库架构设计。**

## 8. Product Governance Workflow（冻结）

### Phase 1（Current）—— Admin Central Governance（冻结，不开放供应商自主提交）

```
Admin
  ↓
Supplier Product Pool Management
  ↓
Admin Approval
  ↓

```

说明：当前 **供应商会员暂不直接管理产品池**。Supplier Product 由 Admin 基于供应商能力集中建模与维护。

```
Supplier → Draft Submission → Admin Review → Approved → Public
```

## 9. Parameter Ownership Architecture（冻结）

**Platform Standard Parameters（属于 Platform Product）**：Diameter / Resolution / Working Length / View Direction / Field Angle 等全局标准参数。

**Supplier Parameters（属于 Supplier Product）**：Custom Technology / Special Configuration / Certification / Accessories / Brand Feature 等供应商专属参数。

**关系**：`Platform Parameter + Supplier Override / Extension`——Supplier Product 继承平台标准参数，并允许供应商覆盖值或扩展自定义参数。

**禁止**：供应商修改 Global Parameter Definition（全局参数定义）。

## 10. Media Ownership Architecture（冻结）

解决现状「所有媒体混合管理」问题，按归属分层：

| 媒体类型 | 归属 | 设计 |
|-|-|-|
| Platform Media | Platform Product | `FileEntityType.PRODUCT`，平台能力配图（Capability 呈现） |
| Supplier Product Media | Supplier Product | 供应商型号主图/多视图，归属 Supplier Organization |
| Organization Media | Supplier Organization | 企业资质/LOGO `FileEntityType.ORGANIZATION` |
| Content Media | Content | `FileEntityType.CONTENT` |

**必须回答：**
1. **产品图片归属** → Platform Product（能力节点媒体）+ Supplier Product Media（供应商型号媒体）分置
2. **供应商宣传视频归属** → Supplier Product Media（技术演示）或 Organization Media（企业宣传）
3. **技术文档归属** → Supplier Product（Technical Documents / SPEC）
4. **SEO 展示媒体来源** → Platform Media（能力权威首图）+ Supplier Product Media（型号/品牌），复用 `FileAsset.organizationId` + 承接 `entityType/entityId/referenceType` 区分层级

## 11. Search Architecture Boundary（冻结）

**搜索核心索引 = Platform Product（Capability Node）**。

结果形态（不是 100 个供应商产品页）：
```
Capability Node
   ↓
Supplier Product Count
   ↓
Supplier Selection
```

**Search Index Ownership**：单一权威索引绑定 `Platform Product`；Supplier Product 作为聚合计数与二段筛选维度，**不碎片化全局检索**。Matching 同理保持对 Platform Product 标准参数确定性匹配（冻结）。

## 12. SEO Architecture Boundary（冻结）

| 层级 | 负责 |
|-|-|
| Platform Product SEO | Capability Landing / Category Authority / Knowledge Relation |
| Supplier Product SEO | Supplier Brand / Model Search / Technical Long Tail |

**Canonical Strategy**：以 `Platform Product`（能力节点）为**唯一权威 canonical**；Supplier Product 页降权、避免争夺权威。
**URL Strategy**：`/products/[slug]`（Platform，权威）承载能力；供应商型号走供应商域子路径，语义独立不冲突。
**Duplicate Prevention**：顶部去重（Pretending）；供应商型号避免重复 Keyword 自重叠加；`seoTitle` 以能力层为权威，型号页做补充后缀。
