## 1. Problem Summary

### M12.5.1 发现的问题

| # | 严重度 | 问题 | 根因 |
|---|:---:|------|------|
| 1 | 🔴 | Admin Docker 构建失败 | 缺少 workspace package.json + pnpm 符号链接不兼容 |
| 2 | 🔴 | 数据库 0 个表 | 迁移未执行 |
| 3 | 🟡 | API 构建上下文 175MB+ | `.dockerignore` 未排除 `**/node_modules/` |
| 4 | 🟢 | docker-compose `version` 过时 | Compose v5.3.0 废弃该属性 |

### 根因分析

Admin Dockerfile 在 `pnpm install` 时只复制了 `apps/admin/package.json`，未复制 `apps/api/package.json` 和 `database/package.json`。pnpm workspace 需要所有工作区 package.json 才能正确解析依赖。此外，pnpm 默认的符号链接策略在 Docker 中可能导致 `tsc` 无法解析模块路径。

## 3. Docker Changes

### 3.1 Admin Dockerfile 修复

**Before:**
```dockerfile
COPY apps/admin/package.json apps/admin/
RUN pnpm install --frozen-lockfile
```

**After:**
```dockerfile
RUN echo "node-linker=hoisted" > .npmrc
COPY apps/api/package.json apps/api/
COPY apps/admin/package.json apps/admin/
COPY database/package.json database/
RUN pnpm install --frozen-lockfile
```

| 变更 | 原因 |
|------|------|
| 复制所有 workspace `package.json` | pnpm 需要完整 workspace 结构 |
| `node-linker=hoisted` | 扁平化 node_modules 确保 tsc 可解析模块 |
| 移除 `.npmrc` 的 COPY | 由 RUN 动态创建 |

### 3.2 API Dockerfile 修复

所有 4 个阶段 (deps, prisma, build, production) 均应用相同修复。

### 3.3 .dockerignore 优化

| 新增排除 | 效果 |
|----------|------|
| `**/node_modules/` | 递归排除所有 node_modules |
| `**/dist/` | 递归排除所有构建输出 |
| `docs/` | 排除文档 (不参与构建) |
| `docker/` | 排除 Docker 配置 |
| `.trae-cn/` | 排除 IDE 缓存 |

### 3.4 docker-compose.yml 修复

移除 `version: "3.8"` — Docker Compose v5.3.0 已废弃该属性。
