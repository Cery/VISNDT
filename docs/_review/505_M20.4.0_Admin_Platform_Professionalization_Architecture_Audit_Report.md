## 5. Schema & API Impact Assessment

### 5.1 Schema Impact

| Requirement | Schema Change? | Alternative |
|-------------|---------------|-------------|
| Dashboard Charts | NO | Frontend-only chart rendering from existing API data |
| Product Import/Export | NO | Frontend Excel parsing + existing Product API |
| Commercial Funnel | NO | Multi-API aggregation on frontend |
| RBAC | NO (existing) | User.role field exists but is hardcoded; backend already has @Roles() decorator |
| Media Library | NO | FileAsset already exists; just need unified view |
| Content Stats | NO | Aggregate from existing API responses |

**Schema Impact**: **NONE** — All M20.4.1 development can be done without schema changes.

### 5.2 API Impact

| Requirement | New API? | Alternative |
|-------------|---------|-------------|
| Dashboard Enrichment | YES (optional) | Backend can add content/inquiry/offer counts to existing /admin/dashboard/stats |
| Product Export | NO | Frontend generates Excel from existing list API |
| Product Import | NO | Frontend parses Excel → calls existing POST /products API |
| RBAC Enforcement | Partially | Backend already has @Roles(ADMIN) guard; needs role differentiation |
| Media Library | NO | Existing FileAsset API sufficient |

**API Impact**: **MINIMAL** — Dashboard stats enrichment is the only recommended backend change (add content/inquiry/offer counts to /admin/dashboard/stats). All other gaps are frontend-only.

### 5.3 Frontend Impact

All M20.4.1 development is **Admin frontend only**:
- `apps/admin/src/*` — modifications only
- No `apps/web` changes
- No `apps/api` changes (except optional dashboard stats)
