## 2. Existing Content Audit

**模型**：`Content`（`database/prisma/schema.prisma` L797–833）
- `type: ContentType`（= ARTICLE / KNOWLEDGE / SOLUTION / INSIGHT）
- `status: ContentStatus`（DRAFT / REVIEW / PUBLISHED / ARCHIVED）、`scheduledPublishAt`、`publishedAt`
- SEO 字段：`seoTitle / seoDescription / seoKeywords`
- 多态关联：`ContentMedia` / `ContentRevision` / `ContentChunk` / `ContentTagRelation` / `KnowledgeContentRef`
- 公开入口：Web `/knowledge`（`getContentList({type:'KNOWLEDGE'})`）、`/articles`、`/insights`、`/solutions` + 各 `[slug]` 详情
- Admin CMS：`/content`（ContentList，按 status 治理：已发布/审核中/已归档）、`/content/tags`

**现状特征**：Content 是「多态商业/运营内容资产」，通过 `type` 区分载体。其中 `Knowledge` 被用作**内容型知识**（≠ KnowledgeEntry 专业知识）。

## 3. Existing Knowledge Audit

**模型**：`KnowledgeEntry`（schema.prisma L1032–1062）+ `KnowledgeDomain`（L968）+ `KnowledgeCategory`（L987）
- `domainId` / `categoryId` 双层分类；`slug @unique`；`structuredBody Json`
- `status: KnowledgeEntryStatus`（DRAFT / REVIEW / PUBLISHED / ARCHIVED）、`publishedAt`
- SEO 字段：`seoTitle / seoDescription / seoKeywords`
- 关联：`KnowledgeContentRef`、`KnowledgeRelation`（RELATED/CHILD/PARENT/PREREQUISITE/FOLLOWUP）、`ProductCategoryKnowledgeMapping`（产品↔知识确定性映射）
- 公开入口：Web `/knowledge-base`（列表 + `[slug]` 详情 + `domains/[slug]`）
- 现有枚举：`KnowledgeEntryStatus` / `KnowledgeReferenceType` / `KnowledgeRelationType`；**无 KnowledgeEntryType 类型枚举**（类型由 `category` 承载）。
- Admin CMS：`/knowledge/*`（KnowledgeDomainList / KnowledgeCategoryList / KnowledgeEntryList）

**现状特征**：KnowledgeEntry 是**专业知识资产**（结构化知识库），带 domain/category 分类、知识关系、产品映射。

## 4. Final Architecture Decision

### 4.1 Accepted Architecture（冻结）

```
Content（商业 / 运营传播资产）
├ Article   商业文章 / 新闻
├ Solution  解决方案
└ Insight   行业洞察 / 观点

KnowledgeEntry（工业检测专业知识资产）
├ Technical Knowledge   技术知识
├ Inspection Method     检测方法
└ Application Case      应用案例
```

### 4.2 Responsibility Boundary（职责边界）

| 维度 | Content | KnowledgeEntry |
|---|---|---|
| 定位 | 运营传播资产（面向传播/获客/SEO 自然流量） | 专业知识资产（面向专业检索/能力展示/产品映射） |
| 载体 | 多态 Content.type | domain + category 双分类知识条目 |
| 内容形态 | 富文本展示型（文章/方案/洞察） | 结构化知识（structuredBody + 关系 + 产品映射） |
| 消费场景 | 内容中心 / 公开文章门户 | 知识库 / 产品↔知识关联 / 匹配上下文 |
| 权威 URL | /articles /insights /solutions | /knowledge-base |

### 4.3 Content.type=KNOWLEDGE 处置决策

- **决定**：`Content.type = KNOWLEDGE` **进入废弃路线（Deprecate）**，不作为主要知识体系继续扩展使用。
- 处理方式：
  - **保留枚举值**（不删 `ContentType.KNOWLEDGE`，避免变更 Schema/迁移，兼容既有存量数据）；
  - 运营侧不再新建 KNOWLEDGE 类型内容，新知识统一落 `KnowledgeEntry`；
  - 存量 Content.type=KNOWLEDGE 内容由运营方逐步迁移至 `ARTICLE`/`INSIGHT`，或对应 `KnowledgeEntry`；
  - **本任务只做决策，不实施迁移 / 不执行 Redirect / 不改 Schema**。

### 4.4 Knowledge 类型表达

- `TECHNICAL_KNOWLEDGE / INSPECTION_METHOD / APPLICATION_CASE` 为**概念类型层**，由既有 `KnowledgeCategory`（知识分类）承载，**无需新增字段/枚举**，零 Schema 变更。

## 5. URL Strategy Decision

### 现状映射（实测确认）

| URL | 底层模型 | 现状 |
|---|---|---|
| `/knowledge`（列表 + `[slug]`） | **Content.type=KNOWLEDGE** | 内容型知识展示 |
| `/knowledge-base`（列表 + `[slug]` + `domains/[slug]`） | **KnowledgeEntry** | 专业知识库 |

### 收敛决策（Decision Only）

- **唯一知识权威入口**：`/knowledge-base`（KnowledgeEntry）= 专业知识唯一入口。
- `/knowledge`：随 Content.type=KNOWLEDGE 废弃而**不再作为知识权威入口**；存量内容迁移后可回归为「内容中心（Article/Insight/Solution）」聚合语义之一，或并入 `/knowledge-base`。
- **本任务禁止执行 Redirect**（仅决策）；URL 收敛动作归 M27.2/M27.3 实施门禁。

## 6. SEO Impact Assessment

| 项 | 现状 | 决策后方向 |
|---|---|---|
| sitemap | 同时收录 `/knowledge`（Content）与 `/knowledge-base`（KnowledgeEntry） | 以 `/knowledge-base` 为知识权威；消除 KNOWLEDGE 内容型 URL 的 SEO 语义重叠 |
| JSON-LD / BreadcrumbList | `/knowledge-base/[slug]` 已实现 | 保持为知识结构化数据权威 |
| canonical | `/knowledge-base/${slug}` | 保持；未来为 `/knowledge`(Content 类) 收敛到类型页 |
| 风险 | 同语义两套 URL（/knowledge vs /knowledge-base）稀释权重 | 收敛后避免重复收录；迁移后建议 301（M27.2/3 实施） |

## 7. Schema Impact Assessment

### 结论：**零 Schema 变更（UNCHANGED / Decision Only）**

| 检查项 | 结果 |
|---|---|
| 现有模型满足目标架构 | ✅ `Content` 多态 + `KnowledgeEntry` 独立台账本满足 |

| Knowledge 类型 | 由既有 `KnowledgeCategory` 承载，无新增枚举/字段 |
| Migration | **NONE**（本任务） |
