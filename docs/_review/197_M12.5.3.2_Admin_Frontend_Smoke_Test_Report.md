## 5. Findings

### Finding #1: passwordHash Exposed in User API Responses

| Attribute | Detail |
|-----------|--------|
| **Severity** | Low |
| **Category** | Security |
| **Description** | The `GET /users` and `GET /users/:id` endpoints return the `passwordHash` field in the response body. |
| **Evidence** | `"passwordHash":"$2b$10$9tiGO5u9css9g4hkJjuPZeeZEk1cVnr9Oe1m7GA2.Qs6rEFwTfoA6"` |
| **Root Cause** | Prisma `findMany`/`findUnique` returns all fields by default. |
| **Recommendation** | Use Prisma `select` or `omit` to exclude `passwordHash` from API responses. |

### Finding #2: Admin Container Healthcheck Failing

| Attribute | Detail |
|-----------|--------|
| **Severity** | Low |
| **Category** | Infrastructure |
| **Description** | The admin container shows `unhealthy` status in `docker compose ps` despite the service being fully functional (HTTP 200, all routes working). |
| **Evidence** | `docker inspect visndt-admin` shows: `"Status":"unhealthy","FailingStreak":40`, with output `"wget: can't connect to remote host: Connection refused"` |
| **Root Cause** | The Dockerfile healthcheck (`CMD wget -qO- http://localhost:80`) fails inside the container, likely due to network configuration in Docker Desktop for Windows. The service is accessible from the host machine (`curl http://localhost` returns 200). |
| **Impact** | Low — does not affect service availability. Docker Compose's `depends_on` with `condition: service_healthy` for admin is not used by any service. |
| **Recommendation** | Replace `wget` with `curl` in the healthcheck, or use `CMD wget -qO- http://127.0.0.1:80` to test connectivity. |
