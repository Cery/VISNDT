## 11. Supplier Discovery Foundation

**Before / Problem / Exact Change / Why No Schema / Impact**（§4.7 记录）：

| 项 | 内容 |
|---|---|
| **Before** | `searchSuppliers` 基于 `Offer.status in (SUBMITTED, ACCEPTED)` 聚合 Organization，返回 `offerCount/offerTitles`。 |
| **Problem** | (1) Supplier Context 来源违反 §4.6（Offer-only 不被接受）；(2) `SUBMITTED/ACCEPTED` 与库内 Offer 生命周期不匹配 → **恒 0 结果**，Supplier 维度实际不可发现。 |
| **Exact Change** | `apps/api/src/search/search.service.ts`（仅此 1 文件）。重构 `searchSuppliers` 为 **aggregate PUBLISHED `SupplierProduct` → `Organization(type=SUPPLIER)`**：`where { status: PUBLISHED, organization:{type:'SUPPLIER'}, OR[branch/series/modelNumber/platformProduct(Product)] }`，按 `organizationId` 聚合 `SupplierDiscoveryItem { organizationId, organizationName, publishedSupplyProductCount, productNames, seriesValues }`，`total=去重组织数`，`items` 遵循 skip/take。同步更新 `SupplierDiscoveryItem` 接口与头注释（删除 Offer 依赖）。 |
| **Why No Schema** | 复用既有 `supplier_product` + `organization`（`type` 字段）+ `platformProduct` 关系；Supplier = Organization 语义角色，无需新建表/Migration。 |
| **Impact** | Supplier 维度结果由「恒 0 + 依赖交易」转为「基于已发布供给的确定性发现基」；`unified` 响应 `suppliers{items,total}` 形状与 analytics（仅读 `.total`）不变；前端不消费 `suppliers.items`（仅消费 `supplierProducts.organization`），无前端/契约破坏。 |

- **AC-06 PASS**：Supplier Context 基于 PUBLISHED SupplyProduct + Organization。
- **AC-07 PASS**：Supplier 发现不再要求 Offer。
