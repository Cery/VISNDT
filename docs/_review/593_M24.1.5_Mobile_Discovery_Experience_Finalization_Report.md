# 6. 发现真实缺陷与最小修复

审计中发现 2 个影响移动端体验正确性的真实缺陷：

## Defect 1 — 搜索错误吞没（Error State 失效）

- **问题**：`apps/web/src/services/search.service.ts` 的 `unifiedSearch` 使用 `try/catch` 捕获所有异常并静默返回空结果集。当 `GET /search` 出错时，前端永远展示「暂无结果」而非「搜索失败」错误 UI，违反 Case 13（Error State：不得出现白屏 / 状态清空）。
- **影响**：移动端 Error State 与 Retry 能力失效。
- **修复**：移除 `try/catch`，直接 `throw`，由调用方 `SearchPageContent.executeSearch` 的 `catch { setError(true) }` 捕获并展示错误 UI + 「重新搜索」按钮。
- **文件**：[search.service.ts](f:/Desktop/VISNDT/VISNDT/apps/web/src/services/search.service.ts)

## Defect 2 — 筛选状态变更导致重复搜索请求

- **问题**：搜索 effect 依赖 `activeFacet` 对象。当 query 切换触发 `resetAll` 产生全新空状态对象时，即使语义上筛选状态未变，也会因为对象引用变化触发一次多余搜索请求，违反 Case 18（Request Duplication：一次明确 Filter Action = 一次预期请求）。
- **修复**：新增 `facetKey`（稳定字符串：`category|param:val,val;...`），作为搜索 effect 依赖，替换原 `activeFacet` 对象引用依赖。
- **文件**：[SearchPageContent.tsx](f:/Desktop/VISNDT/VISNDT/apps/web/src/app/search/SearchPageContent.tsx)

两项修复均为最小改动，未触及业务逻辑、数据库、API 契约。

**Defect Fix: PASS（最小修复，未扩大范围）**
