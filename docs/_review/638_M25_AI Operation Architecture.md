## 一、任务目标与关键前提

### 1.1 目标

平台在**少人力**条件下，由平台统一完善五类供给（内容、能力、供应商入驻、产品能力发布、知识/方案发布），并通过**设立规则 + 依托 AI** 自动处理需求、报价、匹配、线索分发与自动对接，实现「自运转」。

### 1.2 关键前提（必须首先厘清）

评估前需区分两条本质不同的自动化路径：

| 路径 | 本质 | 当前状态 |
|------|------|---------|
| **规则引擎自动化**（确定性规则/状态机/事件驱动） | `if-then` / 参数比对 / 状态流转，**无任何 AI 介入** | ✅ **现已具备，可立即推进** |
| **AI 智能化**（LLM/RAG/Agent 自主决策、自动生成） | 模型推理、语义生成、自主 mutation | ⛔ **FROZEN（仅契约，runtime 未激活）** |

> 核心结论先行：**「自运转」的 80% 可通过规则引擎自动化实现，无需解冻 AI；剩余 20%（自动内容撰写、自然语言需求解析、智能报价建议、自动回复）依赖 AI，当前被冻结约束锁定，需走「解冻门禁」后才可评估落地。**

## 二、当前可自动化能力盘点（规则引擎，非 AI）

### 2.1 已落地、可支撑「自运转」的确定性能力

| 能力 | 实现位置 | 自运转价值 |
|------|---------|-----------|
| 确定性匹配 | `matching.service.ts`（Demand 参数 → 候选 Product → ScoringService → DemandMatch） | 需求发布后**自动**生成匹配结果，零人工 |
| RFQ 自动生成 | `rfqs.service.ts`（`create-rfq-from-match`，sourceMatchId 定向） | 匹配 → 定向 RFQ 自动下发，零人工 |
| 事件驱动通知 | `workflow-events` + `notifications`（RFQ/响应/匹配触发） | 状态变更**自动**触达买卖双方 |
| 内容定时发布 | `content.scheduler.ts` + `scheduledPublishAt` | 内容**自动**按计划发布，零人工 |
| 内容版本 | `content-revision`（version + snapshot） | 内容修改可追溯，支撑半自动审核 |
| 审计日志 | `audit-log`（全操作落库） | 为「自动化动作」提供可追溯依据 |
| 语义检索 | `semantic`（embedding + vector + ranking，M21.4） | 检索/排序已确定性化，非 LLM |
| 媒体隔离/生命周期 | `file-asset`（organizationId/status/deletedAt，B.2） | 供应商资料自动归位到组织 |

> 上述全部为**确定性规则**，不违反「Matching 确定性与 AI 冻结」约束，是自运转的既有根基。

### 2.2 规则层可补强、但尚未闭环的自动化点

| # | 自动化点 | 当前缺口 | 依赖 AI? |
|---|---------|---------|:---:|
| R1 | 询盘 Inquiry → 报价/线索自动流转 | Inquiry 状态仍手工推进 | ❌ 否（规则即可） |
| R2 | RFQ 到期自动关闭/催办 | 无定时任务扫描 `closedAt` | ❌ 否 |
| R3 | 需求到期自动关闭/匹配结果自动过期 | 无 `expiredAt` 清理 | ❌ 否 |
| R4 | 供应商入驻自动审核规则（资质→状态） | 入驻流程半人工 | ❌ 否 |
| R5 | 产品/Offer 资质缺项自动提示 | 无完整性校验规则 | ❌ 否 |
| R6 | 线索自动分发到最相关供应商 | 可复用确定性匹配结果 + 通知 | ❌ 否 |

## 三、自运转可行性分级评估

### 3.1 评估矩阵（逐项）

| 自运转诉求 | 可行性 | 依赖 | 落地方式 |
|-----------|:-------:|------|---------|
| 需求自动匹配 | ✅ 已具备 | 确定性匹配 | 现状可用 |
| 匹配自动转 RFQ | ✅ 已具备 | 确定性匹配 + RFQ | 现状可用 |
| 线索自动分发供应商 | 🟡 规则可达 | 匹配结果 + 通知 | R6，规则补强 |
| 报价自动触达/提醒 | 🟡 规则可达 | 事件通知 + 定时任务 | R1/R2 |
| 内容自动定时发布 | ✅ 已具备 | content.scheduler | 现状可用 |
| 产品/知识/方案结构化发布 | 🟡 规则可达 | 表单 + 完整性校验 | R4/R5 |
| 供应商入驻自动审核 | 🟡 规则可达 | 资质规则状态机 | R4 |
| **自然语言需求解析**（口述→结构化参数） | 🔴 AI 依赖 | LLM | 解冻后 |
| **自动撰写内容/方案** | 🔴 AI 依赖 | LLM/RAG | 解冻后 |
| **智能报价建议** | 🔴 AI 依赖 | LLM + 历史数据 | 解冻后 |
| **自动回复询盘/客服** | 🔴 AI 依赖 | LLM Assistant | 解冻后 |
| **匹配语义解释**（自然语言解释为何匹配） | 🔴 AI 依赖 | LLM | 解冻后 |

### 3.2 分级结论

| 等级 | 比例（估算） | 说明 |
|------|:---:|------|
| ✅ 已可达（现状能力） | ~50% | 确定性匹配、RFQ、通知、内容定时发布 |
| 🟡 规则可达（规则引擎，无需 AI，可立即补强） | ~30% | 询盘流转、到期关闭、线索分发、入驻审核、完整性校验 |
| 🔴 AI 依赖（需解冻门禁） | ~20% | 自然语言理解、内容生成、智能报价、自动回复 |

**结论：少人力自运转在当前架构下「主体可行」，通过补齐规则引擎自动化（30%）即可覆盖 80% 场景；AI 只作为「锦上添花」的第二阶段，不构成自运转的前提。**

## 四、自运转架构方案（分 L0/L1/L2 三层）

### L0：规则引擎自运转层（✅ 推荐立即实施，零 AI、零解冻）

> 目标：用「定时任务 + 状态机 + 事件通知 + 确定性匹配」闭环剩余 30% 规则可达场景。

**核心组件**：

```
自运转规则引擎（新增，纯确定性）
├─ Scheduler 层（定时扫描）
│   ├─ RFQ 到期关闭扫描（closedAt）
│   ├─ Demand 到期关闭扫描（closedAt）
│   ├─ Inquiry 超时升级提醒
│   └─ DemandMatch 过期扫描（EXPIRED）
├─ AutoFlow 层（状态自动流转）
│   ├─ Inquiry NEW → 匹配最相关 Offer → 生成线索通知 → PROCESSING
│   ├─ RFQ OPEN → 无响应到期 → CLOSED
│   └─ 供应商入驻：资质提交 → 规则校验 → ACTIVE/待补全
├─ Distribution 层（线索自动分发）
│   └─ 复用 DemandMatch 结果 → 按 matchScore 排序 → 定向通知目标组织
└─ Completeness 层（完整性校验）
    ├─ Product/Offer 缺失必填参数提示
    └─ 供应商资质证书过期提示
```

**落地约束**：全部基于现有 `WorkflowEvent` / `Notification` / `DemandMatch` / `Inquiry` 模型，**不新增业务表**，仅新增 Scheduler 服务与状态流转逻辑，符合「No new business tables」冻结约束。Matching 引擎、Product Model、Schema 核心关系均 UNCHANGED。

### L1：AI 辅助层（🔴 需解冻门禁，仅契约评估）

> 目标：AI 作为「Assistant」而非「Matching Engine」，在人类在环（Human-in-the-loop）前提下辅助运营。

**可评估的 AI 能力（当前 `ai.service.ts` 中 6 项均 PLANNED）**：

| 能力 ID | 能力 | 自运转角色 | 解冻后落地形态 |
|---------|------|-----------|--------------|
| CAP-001 | Semantic Search | 检索辅助 | 已由 semantic 确定性实现覆盖 |
| CAP-002 | Business Analysis | 运营洞察 | 聚合数据自然语言摘要 |
| CAP-003 | Smart Recommendations | 推荐辅助 | 内容/产品推荐（后端仍是确定性排序 + AI 文案） |
| CAP-004 | Admin Assistant | 运营助手 | 待办摘要、线索摘要、通知摘要 |
| CAP-005 | Audit Intelligence | 审计智能 | 风险检测预警 |
| CAP-006 | Anomaly Detection | 异常检测 | 数据异常监控 |

**关键约束（不可突破）**：

1. **AI 是 Assistant，不是 Matching Engine**（`AI_CAPABILITY_BOUNDARIES` + `ai-capability.guard.ts` 强制：`mutationAllowed: false`、`noAutonomousDecision`、`humanInLoop`）。
2. **AI 不可写业务**：自动报价/自动接单/自动成交等 mutation 能力当前被契约锁死（`noBusinessMutation`）。
3. **AI 不可作为匹配分数输入**：匹配仍为确定性参数比对，AI 仅可做「匹配结果的自然语言解释」，不改分。
4. **AI 不可自动生成并直接发布内容**：内容生成需人类审核（humanInLoop），且当前 `content` 生命周期为确定性状态机。

### L2：AI 自动对接层（🔴 远期，需重大架构评审）

> 目标：AI 自主完成「需求理解 → 报价 → 接单 → 成交」闭环。

**结论：当前强烈不建议，且被多重冻结约束禁止**（`noAutonomousDecision` + `noBusinessMutation` + 供应商/交易冻结边界）。若未来评估，必须满足：

- 单独架构评审 + ADR，明确 AI 自主决策的边界与责任；
- 保留 humanInLoop 兜底；
- 不动 Matching/Scoring/Product Model/Schema 核心关系。

## 五、五类供给的统一运营方案（少人力）

### 5.1 目标：平台统一完善，而非依赖供应商自助

| 供给类型 | 统一运营动作 | 自动化支撑 | AI 依赖 |
|---------|-------------|-----------|:---:|
| 内容（文章/洞察） | 定时发布 + 版本 + 审核时间线 | content.scheduler（✅） | 撰写需 AI |
| 能力（产品参数/分类） | 参数组/定义统一模板 | 规则校验（🟡 R5） | ❌ |
| 供应商入驻 | 资质提交 → 规则审核 | R4 状态机（🟡） | 审核可 AI 辅助 |
| 产品能力发布 | 结构化表单 + 完整性校验 | R5（🟡） | ❌ |
| 知识/方案发布 | 确定性映射 + 定时发布 | 现有知识链（✅） | 撰写需 AI |

**建议运营分工**：平台统一「录入 + 审核 + 发布」三权，供应商自助「提交 + 补充」，AI（解冻后）辅助「草稿生成 + 摘要 + 校验」，但**发布权与成交权始终保留人类在环**。

## 六、风险与约束

| 风险 | 等级 | 缓解 |
|------|------|------|
| 解冻 AI 会触碰「Matching 确定性」「AI 不是 Matching Engine」冻结约束 | 高 | 严格区分 L0 规则引擎（零 AI）与 L1 AI 辅助（humanInLoop），L1 需独立解冻门禁 |
| 自动流转逻辑引入状态脏值/误触发 | 中 | 所有自动流转复用 WorkflowEvent + AuditLog 可追溯；先做「扫描报告」再灰度自动执行 |
| 少人力导致内容供给质量不足（无 AI 生成） | 中 | 优先模板化结构化内容 + 复用现有确定性映射，AI 生成留待解冻 |
| 自动线索分发打扰供应商 | 中 | 分发前按 matchScore 阈值过滤 + 通知聚合降频 |
| 「自动对接/自动成交」误判平台定位（工业撮合，非交易/AI 顾问平台） | 高 | 严守定位：平台做「信息 + 撮合 + 线索对接」，不做自动交易 |

## 七、分阶段落地建议

| 阶段 | 内容 | 是否需解冻 AI | 冻结影响 |
|------|------|:---:|---------|
| **阶段一（本轮可做）** | L0 规则引擎自运转：询盘流转、到期关闭、线索分发、入驻审核、完整性校验（R1~R6） | ❌ 否 | 仅新增 Scheduler + 状态流转，Schema 核心关系 UNCHANGED |
| **阶段二（解冻门禁后）** | L1 AI 辅助：运营待办摘要、线索摘要、异常检测、匹配结果自然语言解释 | ✅ 需 | 需独立 ADR + 解冻评审，确认 humanInLoop |
| **阶段三（远期）** | L2 AI 自动对接 + 自动内容生成 | ✅ 需重大评审 | 需重新评估定位与边界 |

## 八、结论

**结论：CONDITIONAL PASS（自运转「主体可行」，但被冻结约束分为两段）**

1. **少人力自运转在当前架构下主体可行**：约 80% 场景可由「规则引擎自动化」（L0）覆盖，且零 AI、零解冻、不新增业务表，是稳健的落地路径。
2. **AI 角色被定位为 Assistant，而非自运转引擎**：当前 AI 为 FROZEN（6 项能力均 PLANNED，`availableCapabilities=0`），且契约明确禁止「自主决策、业务写入」。任何 AI 自动处理需求/报价/对接的诉求，都必须先过「解冻门禁 + ADR」，且保留 humanInLoop。
3. **推荐路径**：先落地 L0（规则引擎，稳妥见效），AI 作为第二阶段「辅助增强」，并以「意大利面式最小侵入、人类在环」为原则，不改变确定性匹配与撮合定位。

> 本报告零代码变更，未触及任何冻结模块（Matching / Scoring / Product Model / Schema / AI runtime / Search Ranking 均 UNCHANGED）。
