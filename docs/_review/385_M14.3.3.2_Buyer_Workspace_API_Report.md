## 2. Workspace API 新增说明

本次在既有 `WorkspaceModule` 基础上新增 Buyer Workspace 只读聚合 API，全部挂载在 `/workspace/buyer/*` 命名空间下：

- `GET /workspace/buyer/overview`
  - 返回 Buyer 组织维度的 Demand / Match / RFQ / RFQResponse / Notification 聚合摘要
- `GET /workspace/buyer/demands`
  - 返回当前 Buyer organization 下的 Demand 列表
  - 返回字段：`id`、`title`、`status`、`createdAt`、`updatedAt`、`matchCount`、`rfqCount`
- `GET /workspace/buyer/pending-decisions`
  - 返回当前 Buyer organization 下待处理的 `RFQResponse.status = SUBMITTED` 数据
  - 关联返回 RFQ、Demand、Supplier Organization 摘要字段

实现原则：

- Workspace 仅作为聚合查询层
- 所有查询均通过 `WorkspaceService` 直接读取 Prisma
- 未迁移、复写或修改既有领域模块业务逻辑

## 3. Buyer 权限验证说明

三个 Buyer Workspace API 全部复用现有：

- `JwtAuthGuard`
- `@CurrentUser()`
- `AuthRequest['user']`

在 `WorkspaceService` 内统一执行 Buyer 访问前置校验：

1. `workspaceRole === 'BUYER'`
2. `organizationId` 必须存在

若任一条件不满足，接口抛出 `ForbiddenException`，不会返回跨组织数据。

## 4. Prisma 查询范围说明

本次所有查询均严格限制在当前登录用户的 `organizationId` 范围内：

- `Demand`
  - `where: { organizationId: currentOrganizationId }`
- `DemandMatch`
  - `where: { demand: { organizationId: currentOrganizationId } }`
- `RFQ`
  - `where: { demand: { organizationId: currentOrganizationId } }`
- `RFQResponse`
  - `where: { rfq: { demand: { organizationId: currentOrganizationId } } }`
- `Notification`
  - `where: { status: UNREAD, user: { organizationId: currentOrganizationId } }`

Buyer Pending Decisions API 额外限制：

- 仅返回 `RFQResponse.status = SUBMITTED`
- 仅返回其上游 `rfq.demand.organizationId = currentOrganizationId` 的记录

因此查询边界保持为 Buyer 自身组织，不读取其他组织 Demand / RFQ / Response 数据。
