## 6. Route Architecture

| 场景 | URL | 说明 |
|------|-----|------|
| Public Product | `/products/[slug]` | 公开 Catalog 权威 |
| Buyer Evaluations（一级） | `/workspace/evaluations` | 认证 BUYER 私有 |
| 状态过滤 | `/workspace/evaluations?state=COMPARING` | query param |
| 参数对比选中 | `/workspace/evaluations?state=COMPARING&compare=<id>` | transient selection，非新路由 |
| Evaluation → Target | `/products/[slug]` / Supplier 能力面（deep link） | 跳回被评估对象 |
| Evaluation → Connection | → 既有 Inquiry flow（复用） | 单一入口 |

**三一律（Browser URL = UI State = Backend Resource Identity）成立。**
**禁止：** `/shortlists` `/favorites` `/watchlists` `/comparisons` `/buyer-evaluation-system`（除非架构论证必要——本任务判定不必要）。

**Route = CLEAR**

## 7. Evaluation State Architecture

| State | 产品语义 | 可见 | 终态 | 回退 |
|-------|---------|:---:|:---:|:---:|
| INTERESTED | 感兴趣/稍后回顾 | 是 | 否 | 是 |
| SHORTLISTED | 短名单备选池 | 是 | 否 | 是 |
| COMPARING | 正在对比选型 | 是 | 否 | 是 |
| CONTACTED | 已发起 Connection | 是 | 读侧准终态 | 状态可回退但不抹除 Inquiry |

**COMPARING = Persistent state（数据库枚举成员），非 temporary UI view。**
- persistence：`BuyerEvaluation.state=COMPARING`。
- UI 消费：Workspace「Comparing」视图 = 对该持久化状态的过滤；**不新增** Comparison 模型 / 表 / 状态机。
- transient compare selection（`compare=<ids>`）= Frontend transient state，**不写 DB**。

**Evaluation State = CLEAR**

## 8. Product vs SupplierProduct Architecture

| 维度 | Product Eval | SupplierProduct Eval |
|------|-------------|---------------------|
| 语义 | Capability/Catalog 评估 | Specific Supplier-owned supply 评估 |
| 供应商信息 | 不显式单一 Supplier | **必须显示** SupplierProduct.organization(type=SUPPLIER) |
| 状态 | BuyerEvaluation.state | BuyerEvaluation.state |
| Connection | Product → 官方 PUBLISHED SupplierProduct → Organization | 该 SupplierProduct → Organization |
| 跳转 | Product Detail | Supplier 能力面 / Product Detail |

**禁止：** Product = Supplier；Product Eval 自动等价 SupplierProduct Eval（不同 targetType）。

## 9. Connection Architecture

**原则（Connection CTA 唯一入口）：** Evaluation **不直接创建** Inquiry；Evaluation → `GET /evaluations/:id/connection` → **进入既有 Inquiry flow**。

- `Evaluation ≠ Inquiry`；`Evaluation → Connection Context → Existing Inquiry`。
- **禁止第二套 Inquiry / Connection 权威。**
- Contacted = 已连接状态的评估标记（PATCH state），不反向承载 Inquiry 数据。

**Connection = CLEAR**

| Mobile | CLEAR（同等级约束） |
| Scope | CLEAR（无扩展） |

### 最终判定：M34.7 Implementation Gate = **READY WITH CONDITIONS**

**Conditions（非阻断）：**
1. **API state-filter（服务端）**：若 UI 需要按 state 分页、且前端过滤不满足，需独立 Future Authorization 补 `GET /evaluations?state=` 服务端过滤。当前前端可按返回数据过滤（Conditional 满足核心场景）。
2. **768≈140px overflow**：历史基线，非阻断；M34.7 新 UI 不得制造新溢出，追加回归避免恶化。
3. **Existing compare 组件边界**：复用「参数对比表现层思路」，不得直接沿用公开 Compare 数据通路；需在 Implementation 阶段明确数据源 = BuyerEvaluation 过滤集。
4. **设计系统边界**：Workspace 走 Tailwind 体系，避免 AntD 组件耦合（Web 与 Admin 保持边界）。

> 以上均为 NON-BLOCKING conditions。若未来在授权 Implementation 时需更大 (e.g. server state filter) 改动，必须单独授权。
