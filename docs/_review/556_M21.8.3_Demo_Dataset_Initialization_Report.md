## 4. Demo Dataset Implementation

### 4.1 Seed Script Architecture

**File**: `VISNDT\database\seed_demo.ts`

**Run Command**: `npx tsx seed_demo.ts`

**Architecture**:

```
Safety Gates
    ↓
Parameter Groups + Definitions
    ↓
Categories
    ↓
Users + Organizations (Identity)
    ↓
Products (with Parameters)
    ↓
Offers (Product → Organization)
    ↓
Demands (with Parameters)
    ↓
DemandMatches (Demand → Product)
    ↓
RFQs (Demand → Organization)
    ↓
RFQResponses (RFQ → Organization)
    ↓
Content
    ↓
Notifications
    ↓
WorkflowEvents
    ↓
ConversionEvents (7-day analytics)
    ↓
Validation (14 entity checks)
```

### 4.2 Safety Mechanisms

| Mechanism | Implementation |
| --- | --- |
| Safety Gate | NODE_ENV !== 'production' + DEMO_DATA_MODE === 'true' |
| Demo Namespace | `demo.` email prefix + `demo-` content slug + `DEMO_` deterministic IDs |
| Deterministic IDs | `crypto.createHash('sha256').update('VISNDT_DEMO_' + seed)` → 32 hex chars |
| Idempotency | Upsert operations by unique keys (email, slug, composite keys) |
| Scope Cleanup | Notifications / WorkflowEvents / ConversionEvents cleaned by demo user/product IDs before seed |
| Production Isolation | No TRUNCATE / DROP / DELETE FROM *; only demo-scoped deleteMany |

### 4.3 Demo Identity Design

| Entity | Identifier Pattern | Example |
| --- | --- | --- |
| User | `demo.{role}@{index}@visndt.local` | `demo.admin@visndt.local` |
| Organization | `DEMO_ORG_` + deterministic hash | `明视工业检测设备有限公司` |
| Product | `demo-{model}-{category}` slug | `demo-mv4500-hd-electronic-borescope` |
| Content | `demo-{topic}` slug | `demo-how-to-choose-industrial-borescope` |
| Other | UUID via `demoId()` function | 32-char deterministic hex |
