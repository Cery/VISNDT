### Assessment

This is not just style inconsistency. Under the current structure:

- `AuthGuard` ensures the user is authenticated.
- Supplier content components still mount for authenticated non-supplier users.
- Their `useEffect` hooks can start protected data requests before `RoleGuard` renders `Access denied`.

Impact:

- Wrong-role authenticated users may trigger Supplier-only data fetches.
- UI denial happens after request start, so role boundary is enforced too late in the page lifecycle.
- The problem is frontend RBAC expression drift, not a duplicate of existing `TD-003` or `TD-005`.

Risk level:

`HIGH`
