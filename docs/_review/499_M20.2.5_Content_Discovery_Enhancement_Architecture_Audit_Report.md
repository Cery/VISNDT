## 3. Content Discovery Capability Analysis

### 3.1 Critical Gap: publicContentSelect Excludes Tags

**Current `publicContentSelect` (line 25-53):**

```typescript
const publicContentSelect = {
  id, type, title, slug, summary, content,
  publishedAt, seoTitle, seoDescription, seoKeywords,
  createdAt, updatedAt,
  author: { select: { id, name } },
  coverImage: { select: { id, fileName, mimeType } },
  media: { select: { id, type, caption, altText, sortOrder, fileAsset } },
} // ← NOTE: tags NOT included
```

**Impact:** The public content detail page (`GET /content/public/:slug`) returns content WITHOUT its associated tags. This means:

- Content detail pages CANNOT display tag chips
- Content detail pages CANNOT link to related tag pages
- Users CANNOT navigate from a content page to tag-based discovery

**This is the single architectural gap preventing Level 1 Discovery.**

### 3.2 Discovery Capability Assessment

| Level | Capability | Current State | Mechanism |
|-------|-----------|---------------|-----------|
| **L1** | Show tags on content detail | ❌ | `publicContentSelect` excludes tags |
| **L1** | Tag chips → tag landing page | ❌ | No tag data on detail page |
| **L1** | Content list filtered by tag | ✅ | `GET /content/public?tag=slug` |
| **L1** | Tag landing page | ✅ | `/tags/[slug]` |
| **L2** | Same-type related content | ❌ | No "More from [type]" section |
| **L2** | Same-type list page | ✅ | `/knowledge`, `/solutions`, etc. |
| **L2** | Cross-type navigation | ❌ | No navigation between types |
| **L3** | Content → Product | ❌ | Deferred to M20.3+ |
| **L3** | Content → Inquiry | ❌ | Deferred to M20.3+ |

### 3.3 Discovery Funnel Analysis

```
User Entry Point
    │
    ├── Search (M20.1 Frozen) → Product
    ├── Direct Navigation → /knowledge, /solutions, /articles, /insights
    ├── Tag Landing → /tags/[slug] → Content list filtered by tag
    └── Content Detail → ❌ No next step (no tags, no related content)
                              ↑
                         DEAD END
```

**The content detail page is currently a dead end.** Users have no discovery path after reading a single article. This is the primary gap.

## 4. Architecture Questions — Answered

### 4.1 Q1: Can ContentTag support related content recommendation?

**Answer: YES**

The existing `ContentTag` + `ContentTagRelation` model is sufficient for tag-based discovery.

**Mechanism:**
1. Content A has tags [X, Y, Z]
2. Query: `GET /content/public?tag=X` returns all content with tag X
3. This includes Content A itself (can be filtered out on frontend)

**Prerequisite:** Content detail pages must expose their tags. This requires adding `tags` to `publicContentSelect`.

**Without this prerequisite:** Tag-based discovery is impossible from the detail page level.

### 4.2 Q2: Is ContentRelation needed for M20.2.5?

**Answer: NO**

Tag-based discovery (via `ContentTagRelation`) already provides the "related content" capability without a dedicated `ContentRelation` model.

**Comparison:**

| Approach | Pros | Cons |
|----------|------|------|
| Tag-based (existing) | Zero Schema change, already implemented | Coarse-grained (all same-tag content) |
| ContentRelation (new model) | Precise control, editorial curation | New Schema, new API, new Admin UI, new migration |

**Decision:** Tag-based discovery is sufficient for M20.2.5. ContentRelation is a Future Candidate for M20.3+.

### 4.3 Q3: Is Product Relation needed for M20.2.5?

**Answer: NO — Deferred to M20.3+**

Content → Product linking requires:
- New `ContentProductRelation` model
- New Schema migration
- New API endpoints
- New Admin UI (product selector in content editor)
- This falls outside M20.2 scope

### 4.4 Q4: Does Discovery affect Search?

**Answer: NO — M20.1 Search remains Frozen**

Content Discovery is a separate concern from Product Search:
- Discovery operates within the Content domain (tag-based navigation, type-based browsing)
- Search operates within the Product domain (keyword search, category filter, parameter filter)
- No cross-contamination

```diff
const publicContentSelect = {
  id, type, title, slug, summary, content,
  publishedAt, seoTitle, seoDescription, seoKeywords,
```

| Security | **None** — tags are public metadata |
