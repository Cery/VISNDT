### 2.3 Web Match Detail Page Structure

```
Match Detail (/workspace/matches/[matchId])
├── ← 返回匹配列表
├── Match Summary (Card)
│   ├── 需求标题 (link to demand)
│   ├── 需求 ID, 状态 Badge
│   └── Meta: 匹配ID, 创建时间, 更新时间, 组织
├── Score Overview (Card)
│   ├── MatchScore bar + percentage
│   └── 评分说明 (确定性参数匹配)
├── Knowledge Context (Card)
│   ├── 检测领域 / 分类
│   ├── 相关技术资料 (entries with summary)
│   ├── 前置知识 (blue tags)
│   ├── 相关知识 (default tags)
│   ├── 进阶学习 (green tags)
│   └── 免责声明 (不影响匹配评分)
└── Review Actions (Card)
    ├── 查看需求详情
    └── 返回匹配列表
```

### 2.4 Admin Match Detail Knowledge Context

```
Match Detail (/demands/:demandId/matches/:matchId)
├── Card 1: 匹配摘要
├── Card 2: 需求参数
├── Card 3: 匹配详情 (explanation)
├── Card 4: 知识上下文 (NEW)
│   ├── 检测领域 (Tag)
│   ├── 相关技术资料 (entries with summary)
│   ├── 前置知识 (blue Tags)
│   ├── 相关知识 (default Tags)
│   ├── 进阶学习 (green Tags)
│   └── 免责声明
└── Card 5: 生命周期操作
```

### 2.5 API Consumption

Both Web and Admin consume `GET /matches/:id/knowledge-context` (586).

- **Web:** `lib/api/knowledge-context.ts` → `getMatchKnowledgeContext(matchId)` → `ApiResponse<KnowledgeContext>`
- **Admin:** `api/match.service.ts` → `matchService.getKnowledgeContext(matchId)` → `ApiResponseWrapper<KnowledgeContext>`
