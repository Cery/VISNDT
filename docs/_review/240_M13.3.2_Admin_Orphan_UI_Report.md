## 4. UI Implementation

### 4.1 Page: FileAssetOrphanList

**Route:** `/files/orphans` (ADMIN only, inside `RequireAuth`)

**Page States:**

| State | UI |
|---|---|
| Loading | Centered `<Spin size="large" />` |
| Empty | `<Alert type="success">` with "No Orphan Files" message + Refresh button |
| Error | `<Alert type="error">` with error message + Retry button |
| Success | `<Table>` with rowSelection + Cleanup button |

**Columns:**

| Column | Width | Description |
|---|---|---|
| File | 260px | File type icon + file name |
| Type | 110px | `<Tag>` colored by type (IMAGE=blue, DOCUMENT=green, CERTIFICATE=gold, OTHER=default) |
| MIME | 200px | MIME type (ellipsis) |
| Size | 100px | Formatted file size (KB/MB/GB) |
| Storage Key | 280px | Copyable storage key |
| Created | 170px | Formatted date |

**Cleanup Flow:**

```
1. User selects rows via checkbox
2. Click "Cleanup Selected (N)" → danger button
3. Confirm Modal:
   - "You are about to delete N orphan file(s)"
   - Red warning: "This action will permanently delete the files"
   - "Yes, Delete" (danger) / "Cancel"
4. POST /files/orphans/cleanup { ids: [...] }
5. Success → message.success() + auto-refresh
6. Failed → message.warning() with deleted/failed counts
```

**Reused Components:**
- `getFileTypeIcon()` from `utils/file-utils.tsx`
- `formatFileSize()` from `utils/file-utils.tsx`
- `fileAssetService` from `api/file-asset.service.ts`

### 4.2 PageState Pattern

```typescript
type PageState =
  | { status: 'loading' }
  | { status: 'error'; message: string }
  | { status: 'empty' }
  | { status: 'success'; data: FileAsset[] };
```

Consistent with all existing admin pages (OfferList, SupplierList, etc.).
