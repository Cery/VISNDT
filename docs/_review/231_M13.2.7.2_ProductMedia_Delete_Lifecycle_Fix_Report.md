#### `remove()` Method — Full Replacement

**Before (2 lines):**
```typescript
async remove(productId: string, id: string) {
  const media = await this.findOne(productId, id);
  return this.prisma.productMedia.delete({ where: { id: media.id } });
}
```

**After (35 lines):**
```typescript
async remove(productId: string, id: string) {
  const media = await this.findOne(productId, id);

  // Save FileAsset info before deleting ProductMedia
  const fileAsset = media.fileAsset;
  const storageKey = fileAsset?.storageKey ?? null;
  const fileAssetId = fileAsset?.id ?? null;

  // Delete ProductMedia first (FK constraint is on ProductMedia side)
  await this.prisma.productMedia.delete({ where: { id: media.id } });

  // Delete FileAsset DB record if it exists
  if (fileAssetId) {
    try {
      await this.prisma.fileAsset.delete({ where: { id: fileAssetId } });
      this.logger.log(`FileAsset deleted: ${fileAssetId}`);
    } catch (err) {
      this.logger.error(
        `Failed to delete FileAsset ${fileAssetId}: ${(err as Error).message}`,
      );
    }
  }

  // Delete file from S3/MinIO — best-effort, after DB consistency
  if (storageKey) {
    try {
      await this.storage.deleteObject(storageKey);
      this.logger.log(`Storage object deleted: ${storageKey}`);
    } catch (err) {
      this.logger.error(
        `Failed to delete storage object ${storageKey}: ${(err as Error).message}`,
      );
    }
  }
}
```

### 4.2 Design Decisions

| Decision | Rationale |
|---|---|
| **Delete ProductMedia first** | FK constraint is on `product_media.file_asset_id` (ON DELETE SET NULL). Deleting ProductMedia first avoids FK violations. |
| **FileAsset delete after ProductMedia** | If FileAsset delete fails, ProductMedia is already gone — consistent with original behavior of just deleting ProductMedia. |
| **S3 delete after DB operations** | Ensures DB consistency first. If S3 delete fails, the file remains but has no DB record — a lesser evil than DB inconsistency. |
| **try/catch for FileAsset and S3** | Non-critical cleanup failures should not block the ProductMedia deletion. Errors are logged for monitoring. |
| **No return value change** | Controller doesn't use the return value (`ApiResponse.ok(null, ...)`), so removing the `return` is safe. |
| **No module import needed** | `StorageModule` is `@Global()`, so `StorageService` is available for injection without modifying `ProductMediaModule`. |

            Download URL returns 404 (FileAsset not found).

### 5.2 Exception Handling

| Scenario | Behavior |
|---|---|
| ProductMedia not found | `NotFoundException` thrown (unchanged) |
| FileAsset not found | `fileAsset` is `null` — skip cleanup, delete ProductMedia normally |
| FileAsset DB delete fails | Error logged, ProductMedia already deleted |
| S3 delete fails | Error logged, DB already cleaned |
| S3/MinIO unreachable | Error logged, DB already cleaned |
| Concurrent delete | Standard Prisma error handling applies |
