```prisma
model FileAsset {
  id         String         @id @default(uuid()) @db.Uuid
  entityType FileEntityType @map("entity_type")    // 'PRODUCT' (hardcoded)
  entityId   String         @map("entity_id")      // placeholder → updated by M13.2.7.3
  fileType   FileType       @map("file_type")      // IMAGE | DOCUMENT | CERTIFICATE | OTHER
  fileName   String         @map("file_name")
  storageKey String         @map("storage_key")    // S3/MinIO key
  mimeType   String         @map("mime_type")
  fileSize   Int            @map("file_size")
  uploadedBy String         @map("uploaded_by") @db.Uuid

  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  uploader User           @relation(fields: [uploadedBy], references: [id])
  media    ProductMedia[] // ← Reverse relation: one FileAsset → many ProductMedia

  @@index([entityType, entityId])  // ← NOW USEFUL after M13.2.7.3
  @@index([uploadedBy])
  @@map("file_asset")
}
```

### 3.2 ProductMedia ↔ FileAsset Relation

```prisma
model ProductMedia {
  // ...
  fileAssetId  String?  @map("file_asset_id") @db.Uuid  // NULLABLE
  fileAsset FileAsset? @relation(fields: [fileAssetId], references: [id])
  //                            ↑ OPTIONAL
}
```

- **FK:** `ON DELETE SET NULL` — when FileAsset deleted, `fileAssetId` → NULL
- **Reverse:** `FileAsset.media ProductMedia[]` — one-to-many (one FileAsset can be linked to multiple ProductMedia, though in practice it's typically 1:1)
- **Nullable:** `fileAssetId` is nullable — ProductMedia can exist without a FileAsset

## 4. Orphan Generation Analysis

### 4.1 Definition of an Orphan FileAsset

A FileAsset is **orphan** when it has no associated ProductMedia record. This can be detected via:

```typescript
// Prisma query for orphan FileAssets
prisma.fileAsset.findMany({
  where: {
    media: { none: {} },  // No ProductMedia records reference this FileAsset
  },
})
```

Or, using the `entityId` field (post-M13.2.7.3):

```typescript
// FileAssets with placeholder entityId (never linked to ProductMedia)
prisma.fileAsset.findMany({
  where: {
    entityId: '00000000-0000-0000-0000-000000000000',
  },
})
```

### 4.2 Orphan Generation Paths (Post-M13.2.7.3)

| Case | Scenario | Orphaned? | M13.2.7.3 Fixes? | Notes |
|---|---|---|---|---|
| **Case 1** | User uploads → closes page before creating ProductMedia | ✅ YES | ❌ No | Frontend-side issue. FileAsset exists in DB + S3 with no ProductMedia. |
| **Case 2** | Network failure: upload succeeds, create request lost | ✅ YES | ❌ No | Same as Case 1 but caused by network. |
| **Case 3** | Historical data: pre-M13.2.7.1 orphans | ✅ YES | ❌ No | Orphans from before any delete lifecycle fix. |
| **Case 4** | Backend crash during create (before rollback) | 🟡 POSSIBLE | ⚠️ Partial | M13.2.7.3 rollback only works if the process stays alive. Process crash during create = orphan. |
| **Case 5** | Create fails → rollback also fails | 🟡 POSSIBLE | ⚠️ Partial | M13.2.7.3 logs error but FileAsset remains. |
| **Case 6** | Normal create → success | ✅ NO | ✅ Yes | FileAsset correctly linked to ProductMedia. |
| **Case 7** | Normal delete → remove() cascade | ✅ NO | ✅ Yes (M13.2.7.2) | FileAsset deleted with ProductMedia. |

### 4.3 Orphan Detection Math

```
Orphan FileAsset = FileAsset WHERE media.none() OR entityId = placeholder

Pre-M13.2.7.3 orphans:
  entityId = "00000000-0000-0000-0000-000000000000"
  AND NO ProductMedia.fileAssetId = FileAsset.id

Post-M13.2.7.3 orphans (Case 1, 2, 4, 5):
  entityId = "00000000-0000-0000-0000-000000000000"  ← never updated
  AND NO ProductMedia.fileAssetId = FileAsset.id
```

**Key Insight:** After M13.2.7.3, any FileAsset with `entityId = '00000000-...'` is definitively orphaned — the entityId update only happens on successful create.

### 7.2 方案B: Manual Cleanup Endpoint (Read + Delete)

```
GET  /files/orphans          — List orphans
POST /files/orphans/cleanup   — Delete specified orphans
```

| Aspect | Assessment |
|---|---|
| **Complexity** | MEDIUM — 2 new methods in FileAssetService + 2 new endpoints |
| **API Change** | ✅ New `GET /files/orphans` + `POST /files/orphans/cleanup` |
| **Frontend** | ❌ No changes needed (API-only) |
| **Migration** | ❌ No changes needed |
| **Prisma Schema** | ❌ No changes needed |
| **Risk** | LOW — cleanup requires explicit ID list (no accidental mass delete) |
| **Capability** | View + delete orphans (DB + S3) in batch |
| **Cleanup** | Admin provides list of FileAsset IDs to delete |

**Implementation:**
```typescript
// FileAssetService
async cleanupOrphans(ids: string[]): Promise<{ deleted: number; failed: string[] }> {
  let deleted = 0;
  const failed: string[] = [];

  for (const id of ids) {
    try {
      await this.delete(id); // reuses existing delete() which handles DB + S3
      deleted++;
    } catch (err) {
      failed.push(id);
      this.logger.error(`Failed to cleanup orphan ${id}: ${(err as Error).message}`);
    }
  }

  return { deleted, failed };
}
```

### 7.3 方案C: Scheduled Auto-Cleanup (Cron)

```
@Cron('0 3 * * *')  // Daily at 3 AM
async autoCleanupOrphans() { ... }
```

| Aspect | Assessment |
|---|---|
| **Complexity** | MEDIUM — requires `@nestjs/schedule` |
| **Risk** | **HIGH** — auto-delete without human review. Risk of deleting files still in use. |
| **Suitability** | ❌ NOT recommended for production V1 |

**Verdict: NOT recommended.** Production environments should not auto-delete files without human review. Race conditions (user uploading while cron runs) could cause data loss.

### 10.2 Implementation Outline

#### File: `apps/api/src/file-asset/file-asset.service.ts`

Add two methods:

```typescript
/**
 * Find orphan FileAssets — records with no associated ProductMedia.
 */
async findOrphans() {
  return this.prisma.fileAsset.findMany({
    where: {
      entityId: '00000000-0000-0000-0000-000000000000',
      media: { none: {} },
    },
    orderBy: { createdAt: 'desc' },
  });
}

/**
 * Clean up specified orphan FileAssets (DB + S3).
 * Reuses existing delete() for each orphan.
 * @param ids - Array of FileAsset IDs to delete
 * @returns Count of deleted and failed IDs
 */
async cleanupOrphans(ids: string[]) {
  let deleted = 0;
  const failed: string[] = [];

  for (const id of ids) {
    try {
      await this.delete(id); // Reuses existing DB + S3 delete
      deleted++;
    } catch (err) {
      failed.push(id);
      this.logger.error(
        `Failed to cleanup orphan ${id}: ${(err as Error).message}`,
      );
    }
  }

  return { deleted, failed };
}
```

#### File: `apps/api/src/file-asset/file-asset.controller.ts`

Add two endpoints (BEFORE `GET :id/download`):

```typescript
/**

@Roles(Role.ADMIN)

@ApiBearerAuth()
@ApiOperation({ summary: 'Clean up orphan FileAssets (ADMIN only)' })
async cleanupOrphans(@Body() body: { ids: string[] }) {
  const result = await this.service.cleanupOrphans(body.ids);
  return ApiResponse.ok(result, 'Orphan cleanup completed');
}
```
