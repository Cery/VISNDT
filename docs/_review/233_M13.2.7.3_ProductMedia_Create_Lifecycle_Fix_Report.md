**Change 2 — `create()` Method (Full Replacement):**

```typescript
async create(productId: string, dto: CreateProductMediaDto) {
  await this.ensureProductExists(productId);

  try {
    const productMedia = await this.prisma.productMedia.create({
      data: {
        productId,
        fileAssetId: dto.fileAssetId,
        mediaType: dto.mediaType,
        title: dto.title,
        description: dto.description,
        isPrimary: dto.isPrimary,
        displayOrder: dto.displayOrder,
      },
      include: { fileAsset: true },
    });

    // Update FileAsset entityId to point to this ProductMedia
    if (dto.fileAssetId) {
      try {
        await this.prisma.fileAsset.update({
          where: { id: dto.fileAssetId },
          data: { entityId: productMedia.id },
        });
        this.logger.log(
          `FileAsset ${dto.fileAssetId} entityId updated to ${productMedia.id}`,
        );
      } catch (err) {
        this.logger.warn(
          `Failed to update FileAsset ${dto.fileAssetId} entityId: ${(err as Error).message}`,
        );
      }
    }

    return productMedia;
  } catch (err) {
    // Rollback: delete orphan FileAsset if create failed
    if (dto.fileAssetId) {
      try {
        await this.fileAssetService.delete(dto.fileAssetId);
        this.logger.log(
          `Rolled back orphan FileAsset ${dto.fileAssetId} (DB + S3)`,
        );
      } catch (cleanupErr) {
        this.logger.error(
          `Failed to cleanup orphan FileAsset ${dto.fileAssetId}: ${(cleanupErr as Error).message}`,
        );
      }
    }
    throw err; // Re-throw original error
  }
}
```

## 5. Transaction / Error Handling

### 5.1 Error Handling Strategy

| Scenario | Behavior | Log Level |
|---|---|---|
| ProductMedia created + entityId updated | ✅ Success — entityId = productMedia.id | `log` |
| ProductMedia created + entityId update fails | ✅ ProductMedia still returned; entityId remains placeholder | `warn` |
| ProductMedia create fails + FileAsset exists | ✅ FileAsset deleted (DB + S3); original error thrown | `log` |
| ProductMedia create fails + FileAsset cleanup fails | ⚠️ Both fail; original error thrown; cleanup error logged | `error` |
| No fileAssetId in DTO | ✅ Normal flow — no entityId update, no rollback needed | N/A |

### 5.2 Design Decisions

| Decision | Rationale |
|---|---|
| **entityId update is best-effort** | ProductMedia is already created; entityId is metadata. Failure here should not fail the API. |
| **Rollback uses `fileAssetService.delete()`** | Reuses existing, tested logic that handles both DB and S3 cleanup. No duplication. |
| **Original error is always re-thrown** | The client sees the correct error. Cleanup errors are logged but don't mask the original error. |
| **No Prisma transaction** | ProductMedia creation and entityId update are separate operations. A transaction would add complexity without benefit — entityId is not critical for data integrity. |
