## 3. Public API Review

### 3.1 Endpoint

| Endpoint | 用途 | 访问控制 |
| --- | --- | --- |
| `GET /content/public` | 公开已发布内容列表（type 筛选 + 分页） | 匿名公开（仅 PUBLISHED） |
| `GET /content/public/:slug` | 公开已发布内容详情 | 匿名公开（仅 PUBLISHED） |

### 3.2 Query Security

**PUBLISHED Isolation — PASS ✅**
- 列表：`findAllPublic` 在 `Prisma` 查询 `where` 中强制 `status: ContentStatus.PUBLISHED`（DB 层 `findMany` + `count`），**无**先全量 `findMany()` 再前端过滤。
- 详情：`findPublishedBySlug` 使用 `findFirst({ where: { slug, status: PUBLISHED } })`，slug 与 PUBLISHED **双条件同处数据库查询**，**无**仅 `findUnique(slug)` 再判断。

**Slug Isolation — PASS ✅**
- slug 作为筛选条件传入 Prisma（参数化查询），无字符串拼接，无 SQL 注入风险。
- 未发布内容（DRAFT/REVIEW/ARCHIVED）因 `status=PUBLISHED` 条件被数据库直接排除，无泄露。

**Pagination — 整改后 PASS ✅**
- 原状：`pageSize` 仅 Swagger `maximum: 100` 文档声明，**无运行时校验**（Medium Risk）。
- 整改：`QueryContentDto.pageSize` 补充 `@Min(1)` / `@Max(100)` 校验，`page` 补充 `@Min(1)`，限制 `MAX_PAGE_SIZE <= 100`。

### 3.3 Response Security（字段暴露分析）

**原状（440 初版）— 风险 ⚠️**
- 公开端点直接返回原始 Prisma Model（`include: author`），暴露了 `status`、`archivedAt`、`authorId`、`author.email`（PII）等内部字段，违反 §3.2 禁止暴露清单。

**整改（本任务最小修复）— PASS ✅**
- 新增 `publicContentSelect` 公开安全投影，仅暴露：

| 允许暴露 | 禁止暴露（已剔除） |
| --- | --- |
| id / type / title / slug / summary / content | status |
| publishedAt / seoTitle / seoDescription / seoKeywords | archivedAt |
| createdAt / updatedAt | authorId |
| author.name | author.email |
| coverImage（id/fileName/mimeType） | storageKey（内部存储键） |

- 列表与详情均改用投影，公开面不再返回内部字段与 PII。
