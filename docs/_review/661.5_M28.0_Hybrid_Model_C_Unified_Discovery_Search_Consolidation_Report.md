## 2. 661.4 Reality Review

661.4 将 SupplierProduct 搜索做成了**独立的二级搜索入口**：

- 后端：`GET /search/supplier-models`（独立 Service + DTO）。
- 前端：独立页面 `/supplier-models` + 一级导航「供应商型号」。

661.5 现实评估结论：

- `/supplier-models` 页面原先**具备完整搜索功能**（Facet 侧栏 + 结果 + 加载更多），与 `/search` 存在**两套结果渲染逻辑**，属于信息架构重复。
- 一级导航中「搜索」与「供应商型号」同时存在，形成**两个并列 Discovery 入口**，违反「唯一主搜索入口」约束。

**661.5 处置**：见 §3 / §7。

## 3. Search Information Architecture Assessment

### 3.1 唯一主搜索入口

本任务后，公开搜索入口收敛为：

```
/search
   |
   +── Capability（products）
   +── SupplierProduct（supplierProducts / type=supplier-product）
   +── Supplier（suppliers）
   +── Knowledge（knowledge）
   +── Content（content）
   +── Solution（solutions）
   |
   +── Unified Facets（category / brand / series / technical params / commercial availability）
```

### 3.2 Supplier Model Page Decision（§3.2 必答）

`/supplier-models` **保留，但仅作为向后兼容重定向**：

- **不是主搜索入口**：页面执行 `redirect('/search?type=supplier-product')`，无独立搜索 UI。
- **不是独立搜索体系**：与 `/search` 共享同一 Search Contract（`/search` 统一端点 + `/search/context` 上下文 + `/search/supplier-models` Facet 数据源）。
- **SEO / Navigation / Search Fragmentation 影响**：
  - SEO：页面 metadata 设 `robots: { index: false, follow: true }`，避免重复索引；旧链接（deep link）自然解析到统一搜索页 supplier-product Tab，**无 SEO 分裂**。
  - Navigation：一级导航中「供应商型号」已移除，**无导航重复**。
  - Search Fragmentation：所有查询最终落在 `/search`，**无搜索碎片化**。

**回答「是否仍存在两个独立搜索入口？」**：

> **否。** `/search` 是唯一主搜索入口；`/supplier-models` 仅是保留型 302 重定向，不承载独立搜索能力、不进入一级导航、不产生独立索引。

## 4. Unified Search Integration

### 4.1 Backend（apps/api/src/search/**）

`search.service.ts` 将 `SupplierProduct` 纳入统一搜索模型：

- `search()` 方法扩展签名：`(query, page, pageSize, category, filters, brand, series, hasActiveOffer)`。
- `Promise.all` 并行检索 6 个维度：`products / supplierProducts / knowledge / content / solutions / suppliers`。
- 新增 `searchSupplierProducts()` 适配器（DTO Projection，见 §5）。
- 返回契约 `UnifiedDiscoveryResponse` 新增 `supplierProducts` 维度，**既有 5 个维度契约不变**（§4.3 兼容性）。

`dto/unified-search.dto.ts` 扩展统一搜索 DTO：

- `brand?`：SupplierProduct 维度品牌过滤（contains, case-insensitive）。
- `series?`：SupplierProduct 维度系列过滤（contains, case-insensitive）。
- `hasOffer?`：SupplierProduct 维度商用可用性过滤（`"true"` → ≥1 个 ACTIVE Offer）。

`search.controller.ts`：`GET /search` 将 `dto.hasOffer === 'true'` 解析为 `hasActiveOffer` 并透传 service；`GET /search/supplier-models`（661.4 端点）保留。

### 4.2 Frontend（apps/web）

- `lib/api/search.ts`：`UnifiedDiscoveryResponse` 新增 `supplierProducts` 维度；`searchUnified` 扩展 `brand / series / hasOffer` 参数。
- `services/search.service.ts`：`SearchDomain` 新增 `'supplier-product'`；`UnifiedSearchResults` 新增 `supplierProducts`；新增 `mapSupplierProduct` 投影函数。
- `app/search/SearchPageContent.tsx`：supplier-product Tab 激活时复用 `/search/supplier-models` 聚合 SupplierProduct 结果；「供应商型号」结果区使用 `SupplierProductResultCard`；Facet 面板使用 `SupplierModelFacetPanel`。
- `components/search/SearchTypeTabs.tsx`：新增「供应商型号」Tab（`supplier-product`）。
- `components/search/GlobalSearchBar.tsx`：类型下拉新增「供应商型号」。

### 4.3 既有搜索兼容（D 项）

`Knowledge / Content / Solution / Supplier / Product` 搜索能力**未退化**：

- `searchProducts`：`ACTIVE` + category + 参数过滤（filter-before-pagination）保持。

## 5. SupplierProduct Search Projection

统一搜索 DTO 通过 **DTO Projection** 表达，**未直接暴露 Prisma Relation**（§9 约束满足）。

```ts
interface SupplierProductDiscoveryItem {
  capability: { id; name; slug; categoryId } | null;   // Capability（Platform Product 权威）
  supplierProduct: { id; brand; series; modelNumber; slug; status; platformProductId };
  commercialSummary: { offerCount; activeOfferCount; priceFrom; priceTo; currency };
  inquiryAvailable: boolean;                            // 恒 true（PUBLISHED 可询价）
}
```

**DTO Projection 验证**：`searchSupplierProducts` 的 Prisma `select` 仅取 `supplierProduct` 自身字段 + `platformProduct`（能力锚定）+ `offers`（仅 id/status/price/currency 用于聚合）；返回前经 `projected[]` 显式映射为 DTO，**不返回裸 relation / 数据库 Join 结构**。

**Search Result Role（§5.2）**：

- SupplierProduct = **Search Discovery Dimension**，不是 Independent Search Authority。
- `platformProduct`（Capability）仍是结果锚点：结果卡片以能力为中心，型号为维度（见 §6 UX）。

**Inquiry Available**：PUBLISHED SupplierProduct 均携带 `inquiryAvailable: true`，点击结果卡片 → 能力详情（`/products/:slug`）→ Supplier Models Tab →「咨询此型号」→ 既有 Inquiry → 既有 RFQ（链路见 §10）。

## 6. Facet Integration

统一 Facet 收敛（§7 约束满足）：

| Facet 族 | 收敛来源 | Unified 表达 |
| --- | --- | --- |
| Capability Facet | `category`（既有 `/search`）+ `platformProduct.categoryId` | `GET /search?category=` + supplier-product 内部能力过滤 |
| Supplier Facet | `brand` / `series`（新增统一参数） | `GET /search?brand=&series=`（contains, case-insensitive） |
| Technical Facet | 既有 Parameter System（`filters` 复用 `parameterDefinitionId:value` 协议） | `parameterValues.some`（SupplierProductParameterValue）——**未重新定义参数体系** |
| Commercial Facet | `hasOffer`（`"true"`） | `offers.some({ status: ACTIVE })` |

**禁止项验证**：未引入 `Paid Ranking / Sponsored Result / Commercial Ranking`；`hasOffer` 仅作二进制存在性过滤，不参与排序权重。

**UX（§6 目标）**：搜索结果**不产生大量 SupplierProduct 重复卡片**——SupplierProduct 以「能力锚定 + 型号维度」组织（`SupplierProductResultCard` 展示父级能力 + 品牌/系列/型号 + 商用摘要），用户路径为「先找能力 → 再筛供应商型号 → 查看型号 → 进入 Inquiry」，而非「一个型号一个搜索结果」。

## 8. Published Boundary Verification

服务端 WHERE 强制（`searchSupplierProducts`）：

```ts
ands.push({ status: SupplierProductStatus.PUBLISHED });
```

- 仅 `PUBLISHED` SupplierProduct 进入统一搜索候选集。
- `DRAFT / SUBMITTED / REVIEWING / APPROVED / REJECTED` 均不进入结果。
- Facet 聚合同样在 `PUBLISHED` 候选集上执行（同一 `where` 驱动 count + findMany）。
- `GET /search/supplier-models`（661.4 端点）保持同一边界。

**Case D / Case E**：Draft SupplierProduct = NOT FOUND；Published SupplierProduct = FOUND（均由服务端 WHERE 强制，前端仅消费服务端已过滤结果）。
