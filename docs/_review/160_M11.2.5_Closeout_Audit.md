## 3. Notification Architecture Final Snapshot

```
┌─────────────────────────────────────────────────────────┐
│                    BUSINESS EVENTS                       │
│                                                         │
│  E1: RFQ Created    E2: RFQ Status Changed              │

│  E5: Response Rejected  E6: Match Completed             │
│  E7: Match Status Changed  E8: Offer Created            │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│                NOTIFICATION TRIGGER                      │
│                                                         │
│  try/catch wrapped — fire-and-forget                    │
│  NotificationsService.create()                          │
│  NotificationsService.createForOrganization()           │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼

                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│                 NOTIFICATION RECORD                      │

                       │

│  PATCH /notifications/:id/read — mark read              │
│  Admin Dashboard Badge — unread count                   │
└─────────────────────────────────────────────────────────┘
```

### Architecture Principles

| 原则 | 实现 |
|------|------|
| **Fire-and-forget** | 所有通知触发 try/catch 包裹，失败不影响主流程 |
| **Internal-only** | 不暴露通知创建 API，仅内部 Service 调用 |
| **Zero cost** | 0 database changes, 0 API changes, 0 dependencies |
| **Decoupled** | 业务模块仅注入 NotificationsService，无循环依赖 |
