## 4. Database Changes

### Schema

新增 `ContentRevision` 模型：

```prisma
model ContentRevision {
  id             String   @id @default(uuid()) @db.Uuid
  contentId      String   @map("content_id") @db.Uuid
  version        Int
  title          String
  summary        String?
  content        String
  seoTitle       String?  @map("seo_title")
  seoDescription String?  @map("seo_description")
  seoKeywords    String?  @map("seo_keywords")
  coverImageId   String?  @map("cover_image_id") @db.Uuid
  snapshot       Json?
  createdBy      String   @map("created_by") @db.Uuid
  createdAt      DateTime @default(now()) @map("created_at")

  contentRef Content @relation(fields: [contentId], references: [id], onDelete: Cascade)

  @@index([contentId, version])
  @@map("content_revision")
}
```

`Content` 模型新增反向关系 `revisions ContentRevision[]`。

关系：`Content` 1:N `ContentRevision`，删除策略 `onDelete: Cascade`（Content 删除级联删除 Revision）；`User` 删除沿用既有关系策略（`createdBy` 仅记录操作者 ID，不建外键约束以避免破坏既有 User 删除策略）。

### Migration

- 迁移文件：`20260812043433_m18_4_2_content_revision/migration.sql`
- 内容：`CREATE TABLE content_revision`（主键 + `content_id` FK CASCADE + `@@index([contentId, version])`）

## 5. Revision Architecture Verification

### Version Strategy

- 首次创建：`version = 1`
- 后续 update：`max(version) + 1`（`createSnapshot` 内查询当前最大版本号自增）
- 状态变更（submit/review/publish/archive，`transition()`）**不**创建 revision

### Snapshot Fields

保存：`title`、`summary`、`content`（markdown）、`seoTitle`、`seoDescription`、`seoKeywords`、`coverImageId`、`snapshot`。

不保存：`status`、workflow metadata、audit metadata（状态属 WorkflowEvent，操作属 AuditLog）。

### Boundary Design

| 系统 | 职责 | 承担内容 |
| --- | --- | --- |
| WorkflowEvent | 业务流程时间线 | CREATED / SUBMITTED / REVIEWED / OPENED / CLOSED |
| AuditLog | 系统行为审计 | CREATE / UPDATE / STATUS_CHANGE（actor/action/old/new） |
| ContentRevision | 历史内容快照 | title/summary/content/SEO/coverImageId |

三者分离，禁止合并。`ContentRevisionService` 快照仅通过事务由 `ContentService` 内部调用，不承担状态/审计记录。
