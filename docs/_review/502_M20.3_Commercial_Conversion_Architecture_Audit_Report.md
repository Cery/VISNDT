## 6. Schema Impact Assessment

### 6.1 Decision

```
Schema Change: NO
New Model: NONE
New Migration: NONE
```

### 6.2 Rationale

Content does not need a direct Schema-level relation to Product or Inquiry:

| Approach | Schema Change | Migration | Pros | Cons |
|----------|---------------|-----------|------|------|
| **ContentProductRelation** | YES | YES | Direct link, editorial control | Breaks M20.2 freeze, adds coupling |
| **ContentInquiryRelation** | YES | YES | Tracks content-originated inquiries | Adds unnecessary complexity |
| **Frontend CTA only** | NO | NO | Zero Schema change, no migration | No backend tracking of content→conversion |

The frontend-only approach is the correct architectural choice for M20.3. It:
- Preserves M20.2 Schema freeze
- Leverages existing Inquiry API (productId + organizationId)
- Requires no migration
- Allows content editors to manually link products via markdown content
- Provides a clear upgrade path to ContentProductRelation in M20.4+ if needed

### 6.3 Prohibited Models

The following remain prohibited:

```
ContentProductRelation    ← REJECTED for M20.3
ContentInquiryRelation    ← REJECTED for M20.3
ContentDemandRelation     ← REJECTED for M20.3
ContentRFQRelation        ← REJECTED for M20.3
ContentOrganizationRelation ← REJECTED for M20.3
```
