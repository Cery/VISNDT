## 1. Phase Overview

本阶段实现 Demand 生命周期管理 API，包括发布（DRAFT → PUBLISHED）和关闭（PUBLISHED/PROCESSING → CLOSED）两个核心流程。所有状态变更通过 WorkflowEvent 进行审计记录，使用数据库事务保证原子性。

**原则：Schema 不修改，Migration 不创建。**

### 实现的能力

| 端点 | 方法 | 认证 | 状态流转 | 审计 |
|------|------|------|----------|------|
| `POST /demands/:id/publish` | JWT | DRAFT → PUBLISHED | ✅ WorkflowEvent |
| `POST /demands/:id/close` | JWT | PUBLISHED/PROCESSING → CLOSED | ✅ WorkflowEvent |

## 3. API Changes

### 3.1 端点总览（含 M7.5.1）

```
GET    /demands               → findAll()      [Public]   列表
GET    /demands/my            → findMy()       [JWT]      我的组织
GET    /demands/:id           → findOne()      [Public]   详情
POST   /demands               → create()       [JWT]      创建（+ WorkflowEvent）
PATCH  /demands/:id           → update()       [JWT]      更新
POST   /demands/:id/publish   → publish()      [JWT]      发布 🆕
POST   /demands/:id/close     → close()        [JWT]      关闭 🆕
```

### 3.2 POST /demands/:id/publish

**认证：** JwtAuthGuard (+ @ApiBearerAuth)

**状态流转：** `DRAFT` → `PUBLISHED`

**请求体：** 无

**成功响应：**

```json
{
  "code": 200,
  "message": "Demand published",
  "data": {
    "id": "uuid",
    "status": "PUBLISHED",
    "publishedAt": "2026-07-19T12:00:00.000Z",
    ...
  }
}
```

**错误响应：**

| 条件 | 状态码 | 消息 |
|------|--------|------|
| 无组织 | 400 | User must belong to an organization to publish a demand |
| 不存在 | 404 | Demand {id} not found |
| 无权限 | 400 | You do not have permission to publish this demand |
| 非 DRAFT | 400 | Cannot publish demand with status {status}. Only DRAFT can be published. |

**副作用：**
- `status` → `PUBLISHED`
- `publishedAt` → 当前时间戳
- 创建 `WorkflowEvent` (action=OPENED, metadata={previousStatus, newStatus})

### 3.3 POST /demands/:id/close

**认证：** JwtAuthGuard (+ @ApiBearerAuth)

**状态流转：** `PUBLISHED` / `PROCESSING` → `CLOSED`

**请求体：**

```json
{
  "reason": "需求已满足"  // 可选
}
```

**成功响应：**

```json
{
  "code": 200,
  "message": "Demand closed",
  "data": {
    "id": "uuid",
    "status": "CLOSED",
    "closedAt": "2026-07-19T12:00:00.000Z",
    "closeReason": "需求已满足",
    ...
  }
}
```

**错误响应：**

| 条件 | 状态码 | 消息 |
|------|--------|------|
| 无组织 | 400 | User must belong to an organization to close a demand |
| 不存在 | 404 | Demand {id} not found |
| 无权限 | 400 | You do not have permission to close this demand |
| 非 PUBLISHED/PROCESSING | 400 | Cannot close demand with status {status}. Only PUBLISHED, PROCESSING can be closed. |

**副作用：**
- `status` → `CLOSED`
- `closedAt` → 当前时间戳
- `closeReason` → 请求中的 reason（可选）
- 创建 `WorkflowEvent` (action=CLOSED, metadata={previousStatus, newStatus, closeReason})

### 3.4 创建增强（M7.5.1 补充）

`POST /demands` 创建时新增 `WorkflowEvent` 审计记录：

```typescript
// Record CREATED workflow event
await this.workflowEvents.create({
  entityType: WorkflowEntityType.DEMAND,
  entityId: demand.id,
  action: WorkflowAction.CREATED,
  operatorId: user.id,
});
```

## 4. State Machine Validation

### 4.1 完整状态流转图

```
                         ┌─────────────────────┐
                         │                     │
                         ▼                     │
                    ┌─────────┐                │
              ┌─────│  DRAFT  │                │
              │     └────┬────┘                │
              │          │ publish()            │
              │          │ POST /demands/:id/publish
              │          ▼                     │
              │     ┌──────────┐               │
              │     │PUBLISHED │               │
              │     └────┬─────┘               │
              │          │                     │
              │          │ createRFQ()         │
              │          │ (未来)               │
              │          ▼                     │
              │     ┌───────────┐              │
              │     │ PROCESSING│              │
              │     └─────┬─────┘              │
              │           │                    │
              │           │                    │
              │     close()                    │
              │     POST /demands/:id/close    │
              │           │                    │
              │           ▼                    │
              │     ┌──────────┐   cancel()    │
              └─────│  CLOSED  │◄──────────────┘
                    └──────────┘
                         ▲
                         │
                    ┌──────────┐
                    │CANCELLED │  (update status)
                    └──────────┘
```

### 4.2 状态转换合法性矩阵

| 当前状态 → | DRAFT | PUBLISHED | PROCESSING | CLOSED | CANCELLED |
|-----------|-------|-----------|------------|--------|-----------|
| → DRAFT | — | ❌ | ❌ | ❌ | ❌ |
| → PUBLISHED | ✅ publish() | — | ❌ | ❌ | ❌ |
| → PROCESSING | ❌ | ✅ update() | — | ❌ | ❌ |
| → CLOSED | ❌ | ✅ close() | ✅ close() | — | ❌ |
| → CANCELLED | ✅ update() | ✅ update() | ✅ update() | ❌ | — |

### 4.3 验证守卫

```typescript
// M7.5.1: 终态阻止更新
const TERMINAL_STATUSES = [CLOSED, CANCELLED];

// M7.5.2: 仅 DRAFT 可发布
const PUBLISHABLE_STATUSES = [DRAFT];

// M7.5.2: 仅 PUBLISHED/PROCESSING 可关闭
const CLOSABLE_STATUSES = [PUBLISHED, PROCESSING];
```

### 4.4 事务原子性

Publish 和 Close 操作使用 `$transaction` 交互式事务，保证状态变更和审计记录同步：

```typescript
const [updated] = await this.prisma.$transaction(async (tx) => {
  // 1. 更新 Demand 状态 + 时间戳
  const updatedDemand = await tx.demand.update({ ... });
  // 2. 创建 WorkflowEvent 审计记录
  await tx.workflowEvent.create({ ... });
  return [updatedDemand];
});
```

## 5. Security Impact

### 5.1 安全改进

| 改进项 | 说明 | 严重程度 |
|--------|------|----------|
| 所有权验证 | publish/close 均验证创建者或同组织权限 | 🟡 High |
| 状态合法性 | 严格的状态流转白名单，防止非法状态跳转 | 🟡 High |
| 事务原子性 | 状态变更 + 审计记录同步，防止不一致 | 🟡 High |
| 审计追踪 | 每个状态变更创建 WorkflowEvent，含 operatorId + metadata | 🟡 Medium |
| 组织隔离 | 所有操作验证 user.organizationId | 🟡 High |
