## 3. Mobile Architecture Assessment

### 3.1 Mobile Entry Strategy

VISNDT 当前架构为单一 Web 平台（`apps/web` + `apps/admin`），Mobile 体验建设可选择以下路径：

| Path | Description | Recommendation |
| --- | --- | --- |
| Responsive Web | 增强现有 Web 响应式，适配移动浏览器 | **Phase 1 (P0)** — 零新增架构，快速验证 |
| PWA | 渐进式 Web App，离线缓存 + 安装 | **Phase 2 (P1)** — 低成本移动体验提升 |
| React Native | 独立 Mobile App，原生体验 | **Phase 3 (P2)** — 需 Mobile BFF + Push Notification |
| Flutter | 跨平台原生 App | **Phase 3 Alternative** — 与 RN 评估后选择 |

**Recommendation**: M21.5 按 Responsive Web → PWA → Native App 分阶段演进，避免一次性大架构变更。

### 3.2 API Consumption Strategy

当前 API 架构已为 Mobile 消费做好准备：

```
Mobile Client
    ↓ (HTTPS + JWT Bearer Token)
Existing API Boundary (apps/api)
    ↓
Existing Business Capability (Product/Content/Workspace/...)
    ↓
Database
```

| Aspect | Readiness | Note |
| --- | --- | --- |
| RESTful API | READY | 所有 API 为 RESTful JSON |
| Authentication | READY | JWT Bearer Token，Mobile SDK 原生支持 |
| Rate Limiting | READY | 全局 ThrottlerGuard (100 req/min) |
| Response Format | READY | 统一 ApiResponse 包装 |
| Pagination | READY | 公共 API 已支持分页 |
| CORS | READY | 已配置 |

**Result: API consumption path confirmed. Mobile can consume existing APIs directly. PASS.**

### 3.3 Authentication Strategy
