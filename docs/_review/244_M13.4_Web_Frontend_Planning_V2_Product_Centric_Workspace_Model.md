## Executive Summary

本报告基于商业模型对齐审计 (243) 的结论，对 M13.4 Web Frontend 架构进行全面重新设计。核心变更：

| # | 变更项 | 242 规划 (旧) | 244 规划 (新) |
|---|--------|-------------|------------|
| 1 | 供应商目录页 | `/suppliers` + `/suppliers/[slug]` | ❌ 删除 |
| 2 | 供应商门户 | "Supplier Portal" 独立区域 | ✅ 合并为统一 Dashboard |
| 3 | 导航栏 | Products / Categories / **Suppliers** / About | Products / Categories / Solutions / Knowledge |
| 4 | 产品详情 | 产品信息 + 规格 | 产品信息 + 规格 + **制造商信息区块** |
| 5 | Sitemap | 包含 supplier 条目 | 仅产品 + 分类 |
| 6 | 用户角色 | Buyer Portal / Supplier Portal 分离 | 统一 Dashboard，角色功能区 |

## 1. Web 整体信息架构

### 1.1 核心设计原则

```
❌ 禁止模式:
  用户 → 浏览供应商 → 进入供应商主页 → 查看供应商产品 → 发起询盘

✅ 正确模式:
  用户 → 搜索产品 → 产品详情 → 看到制造商信息 → 发起询盘/联系
```

### 1.4 与 242 规划的关键差异

| 区域 | 242 规划 | 244 V2 规划 | 理由 |
|------|---------|------------|------|
| 导航栏 | Products / Categories / Suppliers / About | Products / Categories / Solutions / Knowledge | 删除 Suppliers 入口，增加 Solutions + Knowledge |
| 公开页面 | 含 `/suppliers`, `/suppliers/[slug]` | 删除所有 supplier 独立页面 | 防止供应商店铺化 |
| 认证区域 | Buyer Portal + Supplier Portal 两个独立区域 | 统一 Dashboard + 角色功能区 | 同一平台不同角色 |
| 产品详情 | 仅产品信息 | 产品信息 + 制造商信息区块 | 供应商作为产品来源展示 |
| Sitemap | 含 supplier 条目 | 仅产品 + 分类 | SEO 聚焦产品 |

### 2.2 路由中间件

```
middleware.ts:
  ├── Public routes → 无拦截
  ├── Auth routes (/login, /register) → 已登录则重定向到 /dashboard
  └── Protected routes → 未登录则重定向到 /login?callbackUrl=...
      ├── /dashboard → 所有角色可访问
      ├── /demands/* → 需要 Buyer 角色
      ├── /workspace/* → 需要 Supplier 角色
      └── /rfqs/* → 需要 Buyer 或 Supplier 角色

### 5.3 Dashboard 角色自适应

```
Dashboard 加载逻辑:
  1. 获取当前用户 JWT
  2. 解析角色: role + organization.type
  3. 渲染对应的 Dashboard 视图:
     - Buyer 角色 → 显示 Buyer Dashboard
     - Supplier 角色 → 显示 Supplier Dashboard
     - 两者兼具 → 显示完整 Dashboard (含两个功能区)
     - 无特定角色 → 显示基础 Dashboard (浏览引导)
```

### 5.4 角色判断逻辑

// 判断用户是否为 Buyer (有采购权限)
function isBuyer(user: User): boolean {
  return user.role === 'USER' || user.role === 'ORG_ADMIN';
  // 所有已注册用户都可以是 Buyer
}

// 判断用户是否为 Supplier (属于供应商组织)
function isSupplier(user: User): boolean {
  return user.organization?.type === 'supplier';
  // 通过 Organization.type 判断，而非独立 Supplier 模型
}
```

## 12. SEO 策略

### 12.1 平台定位

**VISNDT** 是工业检测设备产品信息平台。SEO 策略聚焦于产品页面，以产品关键词为搜索流量入口。

### 12.3 Metadata 策略
