## Client Design

### `apps/web/src/lib/api/workspace.ts`

- Reuses existing `apiClient` from `apps/web/src/lib/api-client.ts`
- Implements read-only `GET` functions only
- Returns `ApiResponse<T>.data` directly
- Does not add business transformation, filtering, reshaping, or aggregation logic
- Defines frontend TypeScript interfaces to mirror the current backend Workspace DTO contract

### `apps/web/src/services/workspace.service.ts`

- Added as a thin wrapper because current project structure already uses `services/*` as a page-facing layer
- Delegates directly to `lib/api/workspace.ts`
- Does not duplicate fetching logic
- Does not introduce extra mapping or composition

## Auth Compatibility

- Confirmed `apiClient` always sends `credentials: 'include'`
- Workspace client uses only `apiClient`, so auth cookies continue to flow unchanged
- New functions are all `GET` requests, so they do not trigger CSRF mutation handling paths
- Existing 401 auto-refresh behavior in `apiClient` remains in effect
