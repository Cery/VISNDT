## 1. 执行摘要

本报告是 M24.3「前端体验升级 + 多角色测试体系」的**唯一基准（Baseline）**。按约束要求，**忽略 `industrial-ui-redesign-plan.md` v2.0 及 M21.8(554/555) 已做过的前端升级，一切以本次实测现状重新出发**。

核心结论：

1. **三端技术栈异构**：Web = Next.js + Tailwind（自研工业视觉 token）；Admin = Vite + Ant Design（默认主题）；API = NestJS。Web 与 Admin **无法共享同一套视觉 token**，必须拆为两条独立战线。
2. **Web 前端能力边界已相当完备**：44 条路由 + 约 100 个组件 + 17 个 Service + 17 个 API Wrapper，分层清晰（组件 → Service → API Wrapper → Backend API）。
3. **存在 `/dashboard` 与 `/workspace` 双轨遗留**，是首要治理对象。
4. **页面类型现状**：绝大部分核心页已是「平台型」，但仍有少量「官网型」残留；**无商城残留**（冻结边界验证通过）。
5. **Admin 功能广度已到 Enterprise SaaS 级别，但视觉仍是默认 AntD 通用后台**，未接入工业品牌体系。
6. **测试账号与用户规划不一致**：seed 脚本中不存在 `buyer@visndt.com` / `supplyer@visndt.com` / 密码 `admin23456`。
7. **首页 Hero 已符合「工业检测解决方案平台」定位**，可作为后续方案的「保留锚点」。

### 4.3 架构分层（符合 M16 收敛后的既定分层）

```
app/(route)/page.tsx
  → components/**/*.tsx
  → services/*.service.ts        (17 个)
  → lib/api/*.ts                 (17 个 API Wrapper)
  → lib/api-client.ts            (统一 client，含 CSRF/401 刷新)

```

- `services/`：auth、category、content、demand、inquiry、knowledge-base、match、notification、offer、organization、parameter-definition、parameter-group、product、rfq、search、user、workspace
- `hooks/`：仅 `useFacetFilterState.ts`、`useSearchContext.ts`（TanStack Query Provider 已装但业务以 Service 层为主）
- `lib/`：`api-client.ts`（CSRF 双提交 + 401 refresh）、`csrf.ts`、`seo.tsx`、`responsive.ts`、`search-utils.tsx`、`analytics/`

### 4.5 布局结构（关键边界问题）

- 根 `layout.tsx` 全局包裹 `PublicHeader` + `main` + `PublicFooter`（见 `apps/web/src/app/layout.tsx`）。
- 仅 `products/layout.tsx` 存在一个子 layout。
- **`workspace/` 目录无独立 `layout.tsx`**：workspace 页面仍被根 layout 的 `PublicHeader/PublicFooter` 包裹，同时页面内部再套 `WorkspaceLayout`（自含 Sidebar/Header）。这造成 Workspace 内存在「Public 头 + Workspace 侧栏」的混合观感，是本次重构需重点治理的布局边界。
