## 1. Executive Summary

VISNDT 前端体验的目标态升级（一轮收敛）：

```
Industrial Product Website
        ↓
Industrial Capability Discovery Platform
```

- **不是**：Corporate Website Only（官网）、Marketplace（商城）、Store（店铺）、E-commerce（电商）。
- **是**：面向工业检测能力「发现 → 评估 → 决策 → 转化」的**平台型**体验，连接检测需求方与能力提供商。

三套体验体系独立设计、独立 token，**禁止强行统一视觉**：

| 体系 | 受众 | 目标态 |
|---|---|---|
| Web Platform UI | 匿名浏览 / 潜在需求方 | Industrial Capability Discovery Platform |
| Workspace UI | Buyer（采购工程师）/ Supplier（能力提供商） | Demand Management / Capability Provider Workspace |
| Admin Console UI | 平台运营 | Industrial Operation Console |

## 2. Current State Reference

继承 607_M24.3.1 的实测结论（唯一现状基线）：

- **技术结构**：Web = Next.js 15 + Tailwind + 自研工业 token；Admin = Vite + AntD 默认主题；API = NestJS。三端分离。
- **路由规模**：Web 44 Routes，Admin 75+ Routes。
- **页面类型**：核心页已是平台型，about/business/login/register 残留官网型；**无商城残留**。
- **架构分层**：`page → components → services(17) → lib/api(17) → api-client` 分层清晰，复用基础好。
- **现存问题（P1）**：
  1. `/dashboard` ↔ `/workspace` 双轨遗留
  2. `workspace/` 无独立 layout，双层布局观感混合
  3. Admin 视觉为默认 AntD，未接入工业品牌
  4. Search 权重不足（仅 Header 窄搜索，未成一级能力）
  5. Media / Test Data 缺口（详情页缺真实媒体，测试账号与规划不一致）

## 3. Experience Architecture Target

定义 `VISNDT Experience System` = 三体系，每体系由「信息架构(IA) + 视觉语言 + 交互范式」三者构成：

```
VISNDT Experience System
├── Web Platform UI      —— 信息：能力目录；视觉：工业精密；交互：发现-筛选-比选
├── Workspace UI         —— 信息：业务闭环；视觉：工业高效；交互：任务-状态-流转
└── Admin Console UI     —— 信息：运营数据；视觉：工业操控；交互：管理-监控-治理
```

三体系共享一套**语义概念**（Product / Supplier Capability / Demand / RFQ / Search Discovery），但视觉 token 各自独立，通过 §10 的「语义对齐表」保持一致心智，不强行统一 token 值。

## 5. Product Center Experience Architecture

核心命题：

```
Product = Global Capability Catalog（不属于任何 Organization）
Supplier = Capability Provider（能力展示，非 Store Owner）
```

围绕「能力发现 → 评估 → 决策 → 转化」四段设计：

| 环节 | 组件 | 设计要点 |
|---|---|---|
| **发现** | ProductCard / ProductGrid | 突出「检测能力参数」而非「商品属性」：型号(mono)、核心参数、分类标签、能力亮点 |
| **评估** | ProductDetailContent / ProductParameters / ProductGallery | 产品头部 → 核心参数 → 能力优势 → 应用场景 → 技术资料 → 相关知识 → 相关产品 → 供应能力 → 询价入口 |
| **决策** | CompareBar / CompareTable | 参数对比，能力比选 |
| **转化** | InquiryForm / SupplierCapabilityList | 快速询价，能力提供商清单 |

**边界**：详情页与列表页不得出现价格、库存、销量、购物车、下单按钮。转化入口只允许「询价 Inquiry」与「提交需求 Demand」。

## 6. Search Discovery Redesign（一级能力）

当前：`GlobalSearchBar`（Header 窄搜索）→ `/search`。搜索权重不足。

升级为 **Industrial Capability Discovery** 五段链：

```
Header Search（入口）
    ↓
Search Landing（专用落地，类型切换 + query context 摘要）
    ↓
Search Result（多实体分区：Product / Knowledge / Solution / Supplier Capability）
    ↓
Facet Filtering（参数化筛选）
    ↓
Product / Knowledge / Solution / Supplier Capability（下钻）
```

复用已有实现资产（不重新造能力）：

- **入口**：`GlobalSearchBar` + `SearchSuggestionDropdown`（②联动建议，已修）。
- **落地**：`/search` + `SearchPageContent` + `SearchTypeTabs`（类型切换）+ `useSearchContext`（query 级上下文摘要，独立于分页）。
- **结果**：`SearchResultSection` 按实体分区 + 各 `ResultCard`（Product/Knowledge/Solution/Supplier）。
- **筛选**：`ParameterFacet` + `useFacetFilterState` + `SearchFilter`（参数化 faceting）。
- **后端契约**（不变）：`GET /search`、`GET /search/context`（Search ≠ Marketplace Search；search-context = Search → Product Population → Category Context → Relevant Parameters）。

设计强化点：
1. Header 搜索入口保留，但视觉权重提升为「发现」级。
2. Search Landing 顶部提供 query-level context（相关分类、参数 facet、可用值），形成「能力发现」而非「关键词命中」的感知。
3. 结果分区明确区分五类实体，Supplier 结果以「Capability Provider 卡片」呈现（非店铺卡片）。

## 10. Design System

**原则：Web 与 Admin 两套 token 独立，禁止强行统一；通过「语义对齐表」保持心智一致。**

### 10.1 Web：Tailwind Token（已存在，规范化增强）

现有基础（`globals.css` + `tailwind.config.ts`）已定义，§612 执行时在现状上规范化，不推翻：

- 主色 `primary`（蓝 `221.2 83.2% 53.3%`）+ 工业辅助 `industrial.cyan`（`190 85% 45%`）/ `amber` / `slate` / `dark`
- 字体 `--font-inter` + `--font-jetbrains-mono`（自托管）
- 阴影 `industrial-sm/md/lg`
- 背景图案 `grid-pattern` / `dot-pattern`（grid/dot-sm/md）
- 动效 `animate-fade-in` / `animate-slide-up`

### 10.2 Admin：Ant Design Token（待定制）

在 `ConfigProvider theme.token` 上建立「工业运营」映射（§613 执行），不动组件库结构：

| semantic 语义 | Web (Tailwind) | Admin (AntD token) |
|---|---|---|
| 主操作 | primary 蓝 | `colorPrimary` |
| 科技强调 | industrial-cyan | `colorInfo` / 强调色 |
| 警示 | destructive / amber | `colorWarning` / `colorError` |
| 功能底色 | industrial-slate | `colorBgLayout` / `colorBgContainer` |

### 10.3 语义对齐表（共享心智，不共享 token 值）

三体系统一使用同一语义命名（能力/需求/RFQ/匹配/询价/发现），确保跨端概念一致，但视觉实现各自独立。

## 13. Freeze Boundary

全程生效的冻结边界：

**禁止（Do NOT）：**
- Schema Change / API Change / Migration
- Marketplace / Store / Price / Order / Payment / Cart
- 供应商店铺化（Supplier Store / 独立供应商目录首页）
- AI Runtime 激活 / 自动内容生成 / RAG
- 修改 `apps/web` / `apps/admin` / `apps/api` / `schema.prisma` / API Contract（本 608 任务）

**保持（MUST HOLD）：**
- `Product = Global Catalog`（不属于任何 Organization）
- `Supplier = Capability Provider`（非 Store Owner / Marketplace Seller）
- `Search = Industrial Capability Discovery`（非商品/店铺搜索）
- `AI = Frozen`（仅 interface/contract）
- `Matching = Deterministic`（Demand Parameters → Product Parameters → Score → Match）
