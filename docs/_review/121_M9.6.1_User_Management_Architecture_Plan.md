## Backend User Domain Analysis

### Users 模块结构

```
apps/api/src/users/
├── users.controller.ts   ← 5 个端点
├── users.service.ts      ← findAll, findOne, create, update
├── users.module.ts
└── dto/
    ├── create-user.dto.ts   ← email, passwordHash, organizationId?
    └── update-user.dto.ts   ← email?, passwordHash?, status?, organizationId?
```

### Users API 清单 (5 个端点)

| # | 端点 | Method | 权限 | 说明 |
|---|---|---|---|---|
| 1 | `/users` | GET | ADMIN | 用户列表 (分页) |
| 2 | `/users/:id` | GET | ADMIN / Self | 用户详情 |
| 3 | `/users` | POST | ADMIN | 创建用户 |
| 4 | `/users/:id` | PATCH | ADMIN / Self | 更新用户 |
| 5 | — | — | — | (无 DELETE) |

### PaginationDto 参数

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| page | number | 1 | 页码 |
| pageSize | number | 20 | 每页条数 (max 100) |

### 权限模型

| 端点 | ADMIN | Self | 说明 |
|---|---|---|---|
| `GET /users` | ✅ | ❌ | 全局列表 |
| `GET /users/:id` | ✅ | ✅ | 详情 |
| `POST /users` | ✅ | ❌ | 创建 |
| `PATCH /users/:id` | ✅ | ✅ (受限) | 更新；Self 不能改 status/orgId |

### 关键发现

| 发现 | 详情 | 影响 |
|---|---|---|
| 无 search/filter 参数 | `GET /users` 仅支持 page/pageSize | 需 client-side 过滤 |
| 无 include organization | `findAll` 不 include org 关系 | 列表不显示 org 名 |
| 无 role 字段 | User 表无 role；role 在 OrganizationMember | 需额外查询 |
| 无 DELETE | 无删除用户端点 | 安全设计 |

## Admin Requirement Analysis

### User Management 需求

| 需求 | 优先级 | API 支持 | 实现方式 |
|---|---|---|---|
| 用户列表 | High | ✅ `GET /users` | 分页 + client-side 过滤 |
| 用户搜索 (email) | Medium | ❌ | Client-side filter |
| 用户状态筛选 | Medium | ❌ | Client-side filter |
| 用户详情 | High | ✅ `GET /users/:id` | 详情页 |
| 创建用户 | Low | ✅ `POST /users` | 可选 M9.6.2 |
| 更新用户状态 | Low | ✅ `PATCH /users/:id` | 可选 M9.6.2 |
| 组织列 | Medium | ⚠️ 无 include | 需后端 include 或通过 orgId 关联 |

### Organization Management 需求

| 需求 | 优先级 | API 支持 | 实现方式 |
|---|---|---|---|
| 组织列表 | High | ✅ `GET /organizations` | 分页 |
| 组织详情 | High | ✅ `GET /organizations/:id` | 详情页 |
| 创建组织 | Low | ✅ `POST /organizations` | 可选 |

|---|---|---|

**M9.6.2 (可选): User Detail + Organization Detail**

### Client-side 过滤策略

由于 `GET /users` 无 search/filter 参数：
- 首次加载获取全部数据
- 前端 search/filter 基于已加载数据
- Pagination 仍使用服务端分页

**简化方案**: 使用服务端分页 + client-side 搜索 (前端对当前页数据过滤)，或直接使用服务端分页作为唯一数据源。

## Security Impact

| 检查项 | 结果 |
|---|---|
| `/users` 端点 | ✅ ADMIN only |
| `/organizations` 端点 | ✅ ADMIN only |
| RequireAuth 保护 | ✅ 路由在 AdminLayout 下 |
| JWT 调用链 | ✅ 复用 apiClient |
| 敏感数据 | ⚠️ passwordHash 字段在 API 返回中 |

**注意**: `GET /users` 返回 `passwordHash` 字段。前端应确保不渲染此字段，但这不是前端安全问题（哈希后不可逆）。
