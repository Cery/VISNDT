## Component Architecture

```
Home.tsx
├── State: PageState (discriminated union)
│   ├── { status: 'loading' }
│   ├── { status: 'error'; message: string }
│   └── { status: 'success'; stats: DashboardStats }
│
├── Data Fetching
│   ├── useEffect → fetchStats() on mount

├── Loading State
```

## API Usage

### Data Flow

```
Home.tsx mount
  → useEffect
    → fetchStats()
      → dashboardService.getStats()
        → apiClient.get('/admin/dashboard/stats')
          → [Backend] GET /api/v1/admin/dashboard/stats
          → JWT Bearer (injected by interceptor)
          → AdminController.getStats()
          → AdminService.getDashboardStats()
          → ApiResponse.ok(stats)
        ← { success, data: DashboardStats, message, timestamp }
      ← response.data (DashboardStats)
    → setPageState({ status: 'success', stats })
  → Render 5 stat cards
```

### Type Safety

- `PageState` is a discriminated union — TypeScript narrows `stats` access to the `'success'` branch only
- All stat values are typed as `number` via `DashboardStats`
- Error message extraction uses `instanceof Error` guard

## Security Impact

| Aspect | Status |
|---|---|
| Auth requirement | Inherited — `/admin/dashboard/stats` requires JWT + ADMIN role |
| Auth header | Injected by existing request interceptor |
| 401 handling | Existing response interceptor → clearAuth + redirect to /login |
| No new auth bypass | Home page does not access auth state directly |
| Data exposure | Dashboard page is behind `RequireAuth` in router |
| Error message safety | Wrapped in `instanceof Error` guard; no raw error objects leaked |

**Assessment**: No new security surface. All auth and authorization are handled by existing infrastructure.
