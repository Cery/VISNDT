## 4. Media Library 审计（核心专项）

### 4.1 当前模型实测（prisma）

**`FileAsset`**（`schema.prisma` L702-724）
`id, entityType(FileEntityType), entityId, fileType(FileType), fileName, storageKey, mimeType, fileSize, uploadedBy, createdAt, updatedAt`

**`ProductMedia`**（L366-385）
`productId, fileAssetId, mediaType(FileType), title, description, isPrimary, displayOrder`

**`ContentMedia`**（L823-839）
`contentId, fileAssetId, type, caption, altText, sortOrder`

**枚举**：`FileEntityType = PRODUCT | ORGANIZATION | DEMAND | RFQ | RFQ_RESPONSE | CONTENT`；`FileType = IMAGE | DOCUMENT | CERTIFICATE | OTHER`

### 4.2 存储与关联逻辑

- 物理存储：`storage/storage.service.ts` → S3 Compatible（MinIO），`upload/getSignedUrl/deleteObject`。
- 上传闭环：`file-asset` 先建 `FileAsset`（entityId 占位）→ `product-media` / `content-media` `createWithUpload` 绑定 `entityId` → 失败回滚 + 孤儿文件清理（`FileAssetOrphanList`）。
- 发布控制点：`file-asset.download()` 对未发布 `Content` 关联文件拒绝下载。

### 4.3 能力覆盖矩阵

| 能力 | 当前状态 | 说明 |
|---|---|---|
| 多供应商图片隔离 | **部分（弱）** | `FileAsset` 无 `organizationId`，仅靠 `uploadedBy→User→Organization` 间接推导；无直接隔离键 |
| 产品图片管理 | ✅ | `ProductMedia` + `isPrimary/displayOrder` |
| 内容插图管理 | ✅ | `ContentMedia` + `caption/altText` |
| 文件版本管理 | ❌ | `FileAsset` 无版本号/版本链 |
| 发布审核（资产级） | 部分 | 仅 Content 下载侧有发布门禁，资产本身无 `status` |
| SEO 图片 | 部分 | `ContentMedia.altText` 有；产品/媒体无系统化 alt 策略 |
| 删除恢复（软删） | ❌ | 硬删除，无 `deletedAt`/回收站 |
| 分类检索 | ❌ | 无 `MediaFolder/MediaTag`，仅按 `entityType|entityId` 索引 |

### 4.4 核心缺口

1. **无统一媒体中心**：`MediaList` 偏“总表”，缺乏按运营分类浏览（产品图/文档/供应商资产/知识图/方案图/证书/技术文档）的目录视图。
2. **缺版本**：`FileAsset` 无 `version`，多次上传覆盖性替换，无法回溯。
3. **缺权限/隔离维度**：无 `MediaPermission`，多供应商隔离依赖间接推导。
4. **缺软删恢复**：无回收站/恢复入口。
5. **缺分类元数据**：无 `MediaFolder/MediaTag/MediaRelation`，无法按标签/目录运维。

### 4.5 建议目标结构（新增能力，非本轮实施）

```
Media Library
├── Product Images          (ProductMedia)
├── Product Documents       (FileAsset: DOCUMENT)
├── Supplier Assets         (供应商上传，建议加 organizationId 隔离)
├── Knowledge Images        (ContentMedia / 知识条目)
├── Solution Images         (ContentMedia / 解决方案)
├── Certification Files     (FileType: CERTIFICATE)
└── Technical Documents     (FileType: DOCUMENT)
```

建议待评估新增模型：`MediaFolder` / `MediaTag` / `MediaRelation` / `MediaVersion` / `MediaPermission`。**该方向属架构级演进，需单独立项、先送架构评审，本审计不作为结论性实施指令。**
