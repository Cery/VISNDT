# VISNDT 全站综合设计审计报告（深度版）

> 审计范围：Web（Next.js）全站 56+ 页面 + Admin（Vite/React）全站 78+ 页面
> 审计维度：UI布局、视觉设计、功能交互、页面切换、动效体验、移动端适配、跨端一致性
> 审计日期：2026-08-27
> 审计方式：源码级逐页静态分析

---

## 执行摘要

### 综合评分

| 维度 | Web 评分 | Admin 评分 | 跨端一致性 |
|------|---------|-----------|-----------|
| 首页/营销页 | ⭐⭐⭐☆☆ | — | — |
| 产品中心 | ⭐⭐⭐☆☆ | ⭐⭐☆☆☆ | ❌ 不统一 |
| 内容页（文章/方案/知识） | ⭐⭐☆☆☆ | ⭐⭐☆☆☆ | ❌ 风格迥异 |
| 工作区（Buyer/Supplier） | ⭐⭐⭐☆☆ | — | — |
| Admin 仪表盘 | — | ⭐⭐☆☆☆ | — |
| Admin 列表/表单 | — | ⭐⭐⭐☆☆ | — |
| 移动端适配 | ⭐⭐⭐☆☆ | ⭐☆☆☆☆ | ❌ Admin 几乎不可用 |
| 交互/动效 | ⭐⭐☆☆☆ | ⭐☆☆☆☆ | ❌ 两端均薄弱 |
| **综合** | **5.5/10** | **4.0/10** | **严重分裂** |

**核心结论**：
1. Web 端"能用但不够专业"——页面多但设计品质参差不齐，内容页（文章/方案/知识）尤其薄弱
2. Admin 端"功能可用但设计粗糙"——Ant Design 默认样式未做任何品牌定制，内联样式泛滥
3. 移动端适配"基础达标但体验粗糙"——Web 端有响应式框架但细节未打磨，Admin 端几乎无移动端考虑
4. 交互动效"严重缺失"——页面切换生硬、状态变化无反馈、操作成功无感知

## 一、Web 端逐页设计审计

### 1.1 首页（Home / page.tsx）

#### 页面结构
```
HeroSection（深色全屏横幅）
  ↓ CategorySection（产品分类 4 列网格）
  ↓ FeaturedProductsSection（推荐产品 4 列网格）
  ↓ SolutionsSection（行业方案 3 列网格）
  ↓ PlatformFlowSection（平台流程 4 步骤）
  ↓ KnowledgeCenterSection（知识中心 3 列网格）
  ↓ CapabilityProviderSection（能力提供商 4 列网格）
  ↓ InquiryCTA（底部转化区深色横幅）
```

#### 设计缺陷详细分析

**1.1.1 HeroSection — 首屏视觉张力不足（P1）**

- **问题**：`bg-industrial-dark`（#0f172a 级深蓝灰）背景过暗，叠加 `bg-grid-pattern` 网格线后整体显得"脏"和"压抑"
- **问题**：顶部三个光晕（`blur-[120px]`）是静态的，无呼吸感，且青色光晕与蓝色光晕在深色背景上几乎融为一体
- **问题**：SVG 网络节点图（opacity 0.16）过于抽象，普通用户无法感知这是"工业检测"相关元素
- **问题**：标题"工业无损检测 产品与技术方案 一站式平台"行距过紧，`leading-tight` 在中文长标题中显得拥挤
- **问题**：三个 CTA 按钮（浏览产品/探索解决方案/提交需求）视觉权重相同，用户无法判断主次操作
- **移动端**：`py-24 md:py-32 lg:py-36` 在 375px 下高度约 400px，内容被严重压缩，标题 `text-4xl` 折行后可达 4–5 行

**1.1.2 CategorySection — 分类卡片缺乏辨识度（P2）**

- **问题**：6 个分类卡片使用完全相同的图标（通用文档图标），用户无法通过图标快速识别分类类型
- **问题**：卡片描述显示的是 `cat.slug`（URL 友好的英文标识），而非中文描述，对中文用户无意义
  - 代码：`{cat.slug}` → 显示如 "industrial-borescopes" 而非 "工业内窥镜"
- **问题**：加载状态使用 4 个骨架屏，但实际分类数量可能远多于 4 个，骨架屏数量与实际不符

**1.1.3 FeaturedProductsSection — 推荐区缺乏差异化（P2）**

- **问题**："推荐产品"与下方"能力提供商"区块视觉上无区分，都是白色卡片+阴影
- **问题**：`bg-industrial-slate`（浅灰）与前后区块的纯白背景切换过于频繁，阅读节奏被打断

**1.1.4 SolutionsSection — 方案卡片交互不一致（P2）**

- **问题**：6 个方案卡片全部链接到 `/solutions`（同一个页面），而非各自的详情页
  - 代码：`href={/solutions}`（硬编码，未使用 `sol.slug`）
  - 用户点击"航空航天检测"和"汽车检测"进入同一页面，预期落空
- **问题**：方案图标风格不统一——飞机、汽车、管道使用相同的闪电图标（`M13 10V3...`）

**1.1.5 PlatformFlowSection — 步骤箭头在移动端断裂（P2）**

- **问题**：桌面端 4 步骤之间的箭头连接符（`hidden lg:block`）在移动端完全隐藏，步骤间的逻辑关系在移动端丢失
- **问题**：步骤编号徽章（`absolute -top-3 -right-3`）在卡片hover时可能被相邻卡片遮挡

**1.1.6 KnowledgeCenterSection — 知识入口无实质内容预览（P2）**

- **问题**：6 个知识域卡片全部链接到 `/knowledge-base`，未展示任何实际知识条目数量或最新内容
- **问题**：与 SolutionsSection 卡片样式完全一致，用户难以区分"行业方案"和"知识中心"

**1.1.7 CapabilityProviderSection — CTA 按钮风格分裂（P1）**

- **问题**："发现检测能力"按钮使用渐变（`bg-gradient-to-r from-primary to-industrial-cyan`）
- **问题**："成为能力提供商"按钮使用白底边框
- **问题**：这与 HeroSection 的 CTA 风格不一致（Hero 是青渐变 + 白边框 + 白边框三种）

**1.1.8 InquiryCTA — 底部转化区与 Hero 区视觉重复（P2）**

- **问题**：同样是深色背景+光晕+居中大标题，与首屏 HeroSection 视觉语言完全重复
- **问题**："Get Started" 英文眉标在中文页面中突兀，且全部大写 tracking-widest 过于夸张

**1.1.9 首页整体布局问题（P1）**

- **问题**：所有区块都是 `max-w-[1200px] mx-auto px-6`，布局完全扁平，无侧边栏、无辅助导航、无吸顶元素
- **问题**：区块间距统一为 `py-20`（80px），缺乏节奏变化——重要区块和次要区块间距相同
- **问题**：无任何面包屑或位置指示器（首页本身不需要，但进入子页面后需要）

### 1.2 产品中心页（Products / page.tsx）

#### 页面结构
```
页面标题区（工业检测能力目录）
  ↓ 分类快捷筛选（pill buttons）
  ↓ 搜索框
  ↓ 左右布局：侧边栏筛选 + 主内容区
      主内容区：活跃筛选标签 → 产品网格 → 分页
  ↓ 底部对比浮动栏（CompareBar）
```

#### 设计缺陷详细分析

**1.2.1 页面标题区 — 信息层级混乱（P2）**

- **问题**：`IndustrialBadge`（"工业检测能力发现"）+ `h1`（"工业检测能力目录"）+ 描述段落 + 总数统计 + 分类 pills 全部堆叠在一个白色卡片内
- **问题**：卡片内上下 padding `py-7 sm:py-9` 过大，在移动端占据约 40% 视口高度，实际产品列表被推到屏幕外

**1.2.2 分类快捷筛选 — pills 数量失控（P2）**

- **问题**：`categories.slice(0, 8)` 最多显示 8 个分类 pill，但工业检测分类可能远超 8 个
- **问题**：无"更多分类"展开按钮，用户无法看到全部分类
- **问题**：选中状态的 pill（`bg-primary/10 text-primary`）与未选中状态（`bg-slate-50`）对比度不够

**1.2.3 侧边栏筛选 — 移动端体验差（P1）**

- **问题**：`lg:w-64 flex-shrink-0` 在移动端（<1024px）完全消失，所有筛选条件不可见
- **问题**：没有为移动端提供筛选入口（如底部抽屉或顶部折叠面板）
- **问题**：在 768px–1024px 平板区间，侧边栏和主内容区并排显示，但 `lg:w-64` + `gap-8` 导致主内容区仅剩约 60% 宽度，产品卡片严重压缩

**1.2.4 产品网格 — 列数与内容不匹配（P1）**

- **问题**：`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4` 在 1280px 下 4 列，每列约 270px
- **问题**：ProductCard 包含图片+对比复选框+分类徽章+名称+型号+参数标签+描述+供应商，270px 宽度下信息严重截断
- **问题**：`line-clamp-2` 在 270px 宽度下中文标题仅能显示 8–10 个字符

**1.2.5 活跃筛选标签 — 视觉噪音（P2）**

- **问题**：关键词/分类/参数筛选各有一个 pill，但三个 pill 样式完全相同，用户难以快速区分筛选类型
- **问题**："清除全部"按钮是简单的下划线文字，无按钮轮廓，在密集的标签群中难以发现

**1.2.6 分页组件 — 样式简陋（P3）**

- **问题**：使用自定义 Pagination 组件，但仅提供上一页/页码/下一页，无"跳转到"输入框
- **问题**：页码在移动端（375px）超过 5 页时会溢出容器

**1.2.7 对比浮动栏 — 移动端遮挡内容（P1）**

- **问题**：CompareBar 固定在页面底部，在移动端占据约 60px 高度
- **问题**：当产品列表滚动到底部时，最后的 1–2 个产品卡片被 CompareBar 遮挡
- **问题**：CompareBar 在空状态（未选择任何产品）时仍然渲染，只是内容为空，造成不必要的 DOM 开销

### 1.3 产品详情页（Product Detail / [slug]/page.tsx）

#### 页面结构
```
面包屑导航
  ↓ 两栏布局：左侧 ProductDetailNav（锚点导航）+ 右侧 ProductDetailContent
      ProductDetailContent（Tab 切换）：
        - 能力概览（overview）：图片画廊 + 产品信息 + 能力档案
        - 技术参数（specifications）：参数表格
        - 能力型号（supplier-models）：供应商型号列表
        - 能力提供商（suppliers）：供应商询价区
        - 文档证书（documents）：文档卡片网格
        - 相关知识（knowledge）：知识条目列表
        - 相关能力（related）：相关产品推荐
      底部：相关方案 + DemandCTA
```

#### 设计缺陷详细分析

**1.3.1 面包屑导航 — 截断处理粗糙（P2）**

- **问题**：当前产品名称使用 `truncate max-w-[120px] sm:max-w-[200px]`，在长产品名时显示"..."
- **问题**：无 Tooltip 或展开机制查看完整名称

**1.3.2 左侧锚点导航 — 移动端完全缺失（P1）**

- **问题**：`ProductDetailNav` 在 `lg:flex-row` 下显示在左侧，但在移动端（<1024px）完全消失
- **问题**：7 个 Tab 的内容在移动端只能通过顶部 Tab 栏切换，但 Tab 栏在滚动后会吸顶（`sticky top-0`），在 375px 宽度下 7 个 Tab 需要横向滚动，用户可能不知道后面还有更多 Tab

**1.3.3 Tab 栏 — 吸顶后无视觉区分（P2）**

- **问题**：`sticky top-0 z-10 bg-white border-b border-slate-200` 吸顶后与页面内容无阴影过渡
- **问题**：激活 Tab 的指示器是 `border-b-2 border-primary`，但在快速滚动时可能产生视觉闪烁

**1.3.4 能力概览 Tab — 信息布局失衡（P2）**

- **问题**：左侧图片画廊与右侧信息区采用 `lg:grid-cols-2`，但图片区高度可能远小于信息区，导致右侧信息过长时左侧出现大量空白
- **问题**：产品名称 `text-3xl font-extrabold` 与型号 `font-mono text-sm` 的对比度过大，中间缺少中间层级（如副标题或品牌名）

**1.3.5 供应商询价区 — 表单与展示混杂（P2）**

- **问题**：`SupplierInquirySection` 将"已有报价展示"和"提交新询价表单"放在同一区域，未做视觉分区
- **问题**：当供应商较多时，询价表单被推到页面底部，用户可能需要滚动很久才能找到表单

**1.3.6 文档证书 Tab — 卡片信息不完整（P2）**

- **问题**：文档卡片仅显示类型标签（证书/规格书/插图/文档）和标题，无文件大小、上传日期、下载次数等元信息
- **问题**：文档卡片无可点击的下载链接，仅作展示用途

**1.3.7 相关能力/知识/方案 — 三个区块样式不统一（P2）**

- **问题**：`RelatedProductsSection`、`RelatedKnowledge`、`RelatedSolutions` 三个组件分别由不同开发者实现，卡片样式存在差异
- **问题**：`RelatedProducts` 使用 ProductCard（圆角 12px + 阴影），`RelatedKnowledge` 使用自定义列表（无边框），`RelatedSolutions` 使用另一套卡片样式

**1.3.8 空状态 — 缺乏引导（P2）**

- **问题**：技术参数 Tab 在无参数时使用 `EmptyState` 组件，但 EmptyState 仅显示图标和文字，无"添加参数"或"联系管理员"的引导操作

### 1.4 搜索页（Search / page.tsx + SearchPageContent.tsx）

#### 页面结构
```
SearchHero（深色横幅 + 搜索框）
  ↓ SearchTypeTabs（全部/产品/知识/方案/供应商型号）
  ↓ 左右布局：SearchFilter 侧边栏 + 结果列表
      结果列表：SearchResultSummary + 结果卡片 + 分页
```

#### 设计缺陷详细分析

**1.4.1 SearchHero — 深色区与全站浅色主题冲突（P1）**

- **问题**：`bg-industrial-dark` 深色横幅与首页浅色主题形成强烈对比，用户从首页进入搜索页时产生明暗跳变
- **问题**：搜索框在深色背景上使用深色边框，焦点状态不明显

**1.4.2 筛选侧边栏 — 层级过多（P2）**

- **问题**：筛选面板包含分类 Tab + 通用筛选 + 分类特定筛选，三级层级在移动端完全无法展示
- **问题**：分类特定筛选（`f_<categoryId>` URL 参数）在 UI 上无清晰说明，用户不理解为什么切换分类后筛选条件会变化

**1.4.3 搜索结果卡片 — 类型辨识度低（P2）**

- **问题**：`ProductResultCard`、`KnowledgeResultCard`、`SolutionResultCard`、`SupplierProductResultCard` 四种卡片类型差异不够明显
- **问题**：用户混合搜索时，难以快速区分"平台产品"和"供应商型号"

**1.4.4 空状态 — 无搜索建议（P2）**

- **问题**：`SearchEmptyState` 仅显示"未找到结果"，无"热门搜索"、"相关分类"或"清除筛选"的快捷操作

### 1.5 文章/方案详情页（Articles/[slug] / Solutions/[slug]）

#### 页面结构
```
面包屑
  ↓ 封面图（如有）
  ↓ 标题 + 元信息（作者/日期/阅读时间）
  ↓ 摘要（左边框强调）
  ↓ 标签
  ↓ Markdown 正文
  ↓ 媒体画廊
  ↓ CTA 区块
  ↓ 相关推荐
```

#### 设计缺陷详细分析

**1.5.1 封面图处理 — 尺寸无规范（P2）**

- **问题**：`max-h-[400px] object-cover` 可能导致封面图被严重裁剪，特别是含有文字信息的封面图
- **问题**：无占位图/骨架屏，加载时页面布局跳动

**1.5.2 元信息区域 — 信息单薄（P2）**

- **问题**：仅显示作者名+日期+阅读时间，缺少"更新日期"、"分类"、"浏览量"等元信息
- **问题**：作者名无头像、无个人主页链接，缺乏人格化

**1.5.3 摘要样式 — 视觉权重过高（P2）**

- **问题**：`border-l-4 border-primary/30 pl-4` 左边框+内边距使摘要看起来像"引用块"而非摘要
- **问题**：摘要字号 `text-base` 与正文相同，无法从视觉上区分摘要和正文

**1.5.4 标签样式 — 过于朴素（P3）**

- **问题**：`bg-slate-100 text-slate-600 rounded-full` 的标签与全站其他标签（如 CapabilityBadge 的渐变背景）风格不一致

**1.5.5 Markdown 渲染 — 缺乏排版优化（P2）**

- **问题**：`MarkdownRenderer` 未针对中文进行排版优化，无段落首行缩进、无中文引号替换、无表格横向滚动处理
- **问题**：代码块无复制按钮，技术类文章中代码块较多时不便使用

**1.5.6 媒体画廊 — 位置突兀（P2）**

- **问题**：`MediaGallery` 放在 Markdown 正文之后，而非与正文穿插展示
- **问题**：媒体项无标题/描述覆盖，用户不知道每张图片的说明

**1.5.7 CTA 区块 — 与内容割裂（P2）**

- **问题**：`ContentProductCTA` 和 `DemandCTA` 在文章底部以独立卡片形式出现，与正文无过渡
- **问题**：CTA 卡片样式与正文差异过大，产生"广告感"

**1.5.8 相关推荐 — 智能度低（P3）**

- **问题**：`RelatedProducts` 使用最新产品（`sortBy: createdAt`），而非与文章主题相关的产品
- **问题**：`RelatedKnowledge` 使用最新知识条目，无主题关联

### 1.6 知识中心页（Knowledge / knowledge-base/page.tsx）

#### 设计缺陷详细分析

**1.6.1 知识列表 — 与文章列表无区分（P2）**

- **问题**：知识条目列表与文章列表使用相同布局，用户难以感知"知识"与"文章"的内容差异
- **问题**：知识条目的"领域"（Domain）分类在列表中未展示，仅展示标题和摘要

**1.6.2 知识详情 — 缺乏结构化展示（P2）**

- **问题**：知识条目（KnowledgeEntry）通常包含结构化数据（如参数说明、标准引用），但页面使用普通 Markdown 渲染，未针对结构化知识做特殊排版

### 1.7 登录/注册页（Login / Register）

#### 设计缺陷详细分析

## 三、移动端专项审计

### 3.1 Web 端移动端适配

#### 3.1.1 断点覆盖

| 断点 | 宽度 | 覆盖情况 | 问题 |
|------|------|---------|------|
| 默认 | <640px | 基础 | 大量页面未针对 375px 优化 |
| sm | ≥640px | 部分 | 两列布局启动过早 |
| md | ≥768px | 部分 | 平板区间体验粗糙 |
| lg | ≥1024px | 良好 | 侧边栏显示阈值合理 |
| xl | ≥1280px | 良好 | 4 列网格过密 |

#### 3.1.2 首页移动端问题（P1）

- **HeroSection**：`text-4xl` 在 375px 下折行严重，3 行标题+3 行描述+CTA 按钮组+快速入口，首屏完全无法一屏展示
- **CategorySection**：`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4` 在 375px 下单列显示，4 个分类需要滚动 2 屏
- **SolutionsSection**：方案卡片横向布局（`flex gap-4`）在 375px 下图标和文字挤在一起，`line-clamp-2` 导致描述不统一
- **PlatformFlowSection**：步骤箭头完全隐藏，4 个步骤卡片垂直堆叠，用户感知不到流程关系
- **InquiryCTA**：与 HeroSection 相同的深色背景，移动端上下两个深色区块夹击中间浅色内容区，产生"夹心"视觉效果

#### 3.1.3 产品中心移动端问题（P1）

- **筛选缺失**：侧边栏在 <1024px 完全消失，移动端用户无法使用任何筛选功能
- **对比功能**：`CompareBar` 固定在底部，在 375px 下占据约 15% 视口高度，且最后的 1–2 个产品被遮挡
- **分页**：页码在 375px 下超过 5 页时横向溢出

#### 3.1.4 产品详情移动端问题（P1）

- **Tab 栏**：7 个 Tab 在 375px 下必须横向滚动，但无滚动指示器，用户可能不知道还有更多 Tab
- **图片画廊**：`ProductGallery` 在移动端可能未提供缩略图导航或滑动手势
- **参数表格**：技术参数 Tab 的表格在移动端横向溢出，阅读困难

#### 3.1.5 工作区移动端问题（P1）

- **侧边栏**：`WorkspaceSidebar` 在移动端使用抽屉模式（`fixed md:sticky`），但抽屉打开时仅显示导航，无用户头像/角色标识
- **Header**：`h-14` 顶部栏在移动端仅显示汉堡菜单+"组织工作区"+用户名，无通知入口

### 3.2 Admin 端移动端适配

#### 3.2.1 整体评估：几乎不可用（P0）

- **问题**：Admin 端使用 Ant Design 默认布局，未针对移动端做任何优化

- **问题**：表格 `scroll={{ x: 'max-content' }}` 在移动端必须横向滚动，且操作列固定在右侧时遮挡严重
- **问题**：表单输入框在 375px 下宽度不足，日期选择器等复杂组件难以操作
- **问题**：侧边导航（如有）在移动端未提供折叠/展开机制

```css
/* globals.css 中定义的动效 */
```

## 七、改进优化方案（全站版）

### 7.1 核心原则

1. **不动后端**：所有优化纯前端样式/布局/组件，不涉及 API/Schema/数据
2. **移动端优先**：本次优化的重点之一是移动端体验，特别是 Admin 端的基础移动端适配
3. **分阶段实施**：P0→P1→P2→P3，每阶段可独立交付
4. **向后兼容**：不破坏现有业务功能，增量优化

### 7.2 第一阶段：移动端基础适配 + 设计系统统一（P0 + 关键 P1）

#### 7.2.1 Admin 移动端基础适配

- **目标**：Admin 端在 768px 以上可用，375px 基础可用
- **措施**：
  - 统计卡片 `Row gutter={16}` → `gutter={[8, 16]}`
  - 表格增加卡片化备选视图（移动端 <768px 时切换）
  - 表单布局改为响应式（大屏双列、小屏单列）
  - 侧边导航增加移动端折叠按钮

#### 7.2.2 Web 端移动端体验修复

- **产品中心**：为移动端增加筛选抽屉（底部滑出）
- **产品详情**：Tab 栏增加"更多"下拉菜单（移动端 375px 下显示前 3 个 Tab + "更多"）
- **对比页**：增加移动端卡片式对比视图
- **首页**：HeroSection 在移动端改为 `text-2xl` + 减少描述行数

#### 7.2.3 设计系统统一（同原报告 M32.0）

- 创建 Design System 文档（5 个文档）
- 冻结品牌色（Blue Primary / Cyan Secondary / Amber Accent）
- Admin 登录页重构（紫蓝渐变 → 工业风格）
- CTA 按钮统一为纯色（去除渐变）

### 7.3 第二阶段：页面级体验优化（P1 + P2）

#### 7.3.1 首页重塑

- **HeroSection**：
  - 背景改为浅色（`bg-white` +  subtle 网格线）
  - 光晕改为动态漂移（CSS animation）
  - 标题改为 `text-3xl md:text-4xl lg:text-5xl`，减少移动端折行
  - CTA 统一为 `bg-primary` 纯色，主按钮+次按钮两级
- **SolutionsSection**：
  - 每个方案卡片链接到对应 slug（`/solutions/${sol.slug}`）
  - 为每个方案使用独特图标
- **PlatformFlowSection**：
  - 移动端增加步骤编号连接线（垂直虚线）
- **CategorySection**：
  - 显示中文描述而非 slug
  - 为不同分类使用不同图标

#### 7.3.2 产品中心优化

- **ProductCard**：
  - `xl:grid-cols-4` → `xl:grid-cols-3`
  - 参数列表仅保留 1 个核心参数
  - 描述改为 `line-clamp-1`
- **筛选面板**：
  - 移动端增加筛选图标按钮（点击弹出底部抽屉）
- **CompareBar**：
  - 未选择产品时完全隐藏（`display: none`）
  - 选择产品时增加"向上滑出"动画

#### 7.3.3 产品详情优化

- **Tab 栏**：
  - 吸顶时增加 `shadow-sm` 区分内容
  - 移动端改为下拉选择器（<640px）
- **锚点导航**：
  - 移动端增加浮动按钮（FAB）快速跳转
- **相关区块统一**：
  - 统一 `RelatedProducts`、`RelatedKnowledge`、`RelatedSolutions` 的卡片样式

#### 7.3.4 内容页（文章/方案/知识）优化

- **排版增强**：
  - Markdown 渲染增加中文排版优化（段落间距、引用样式、表格横向滚动）
  - 代码块增加复制按钮
- **元信息增强**：
  - 增加"更新日期"、"分类"、"浏览量"
  - 作者名增加头像
- **媒体画廊**：
  - 支持点击放大（Lightbox）
  - 图片下方显示标题/描述
- **CTA 区块**：
  - 改为与正文风格更一致的卡片（浅色边框而非深色背景）

#### 7.3.5 Admin 仪表盘优化

- **信息分区**：
  - 将密集卡片分组为可折叠 Panel（使用 AntD `Collapse`）
  - 默认展开"能力总览"和"待处理事项"，其他折叠
- **图表交互**：
  - 增加时间范围筛选器（近7天/30天/90天）
  - 图表增加 Tooltip 详情

### 7.4 第三阶段：交互与动效升级（P2 + P3）

#### 7.4.1 页面切换过渡

- Web 端：使用 `framer-motion` 或 Next.js 的 `template.tsx` 实现页面间淡入淡出
- Admin 端：使用 Ant Design `ConfigProvider` 的 `transition` 配置或自定义路由过渡

#### 7.4.2 状态反馈增强

- 全局 Toast 组件（Web 端新建，Admin 端使用 AntD `message`）
- 按钮点击增加涟漪效果（Web 端使用 Tailwind `active:scale-95`）
- 表单提交增加进度指示（大文件上传时）

#### 7.4.3 动效升级

```css
/* 新增动效 */
@keyframes staggerFadeIn {
  from { opacity: 0; transform: translateY(12px); }
  to { opacity: 1; transform: translateY(0); }
}

@keyframes drift {
  0%, 100% { transform: translate(0, 0); }
  50% { transform: translate(20px, -10px); }
}

/* 网格项交错入场 */
.stagger-children > * {
  animation: staggerFadeIn 0.4s ease-out both;
}
.stagger-children > *:nth-child(1) { animation-delay: 0ms; }
.stagger-children > *:nth-child(2) { animation-delay: 80ms; }
.stagger-children > *:nth-child(3) { animation-delay: 160ms; }
/* ... */
```

#### 7.4.4 滚动体验优化

- 全站增加"回到顶部"按钮（滚动超过 500px 时显示）
- 分页切换后自动滚动到内容顶部
- Tab 切换后重置滚动位置

### 7.5 第四阶段：品牌深化（P3）

- **中文字体**：引入 Noto Sans SC（Web CDN + Admin ConfigProvider）
- **工业元素**：Hero 区域增加 subtle 抽象网格线（opacity 3%，CSS animation 缓慢漂移）
- **MatchScore**：保留线性进度条，增加匹配因子展开解释
- **深色模式**：评估延期至 M35+

## 十、结论

VISNDT 当前前端设计处于"功能可用但品质参差、两端分裂、移动端粗糙"的状态。本次全站审计相比上一版报告，**新增覆盖**了：

1. **Web 端全部 56+ 页面的逐页分析**（首页、产品中心、产品详情、搜索、文章/方案/知识详情、工作区各子页面、对比页、登录/注册等）
2. **Admin 端全部 78+ 页面的分类分析**（仪表盘、所有列表页、详情/编辑页、知识管理、参数管理等）
3. **移动端专项深度审计**（375px/768px/1024px 三断点逐页排查）
4. **交互与动效专项审计**（页面切换、状态反馈、滚动体验、现有动效盘点）
5. **内容页（文章/方案/知识）专项设计缺陷分析**

**最紧迫的五大问题**：
1. **P0-1**：Admin 与 Web 设计系统完全分裂
2. **P0-3**：Admin 端移动端几乎不可用
3. **P1-2**：产品中心筛选在移动端完全缺失
4. **P1-9**：产品详情页锚点导航在移动端缺失
5. **P1-11**：解决方案卡片全部链接到同一页面（用户体验欺骗）

**预期效果**：按本路线图实施后，VISNDT 将具备：
- Web 端：专业工业 SaaS 平台的视觉质感，移动端流畅可用
- Admin 端：与 Web 端统一的品牌认知，移动端基础可用
- 跨端：用户感知为"同一产品"的不同视图，而非两个独立产品
- 交互：页面切换平滑、操作反馈及时、动效克制但有记忆点
