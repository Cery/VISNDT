## 4. Findings

### Finding #1: GET /users/me Returns 500 (P2023) Instead of 404

| Attribute | Detail |
|-----------|--------|
| **Severity** | Medium |
| **Endpoint** | `GET /api/v1/users/me` |
| **Expected** | 404 Not Found (no `/users/me` route defined) |
| **Actual** | 500 Internal Server Error with `Database error: P2023` |
| **Root Cause** | The string "me" is captured by the `:id` route parameter and passed to Prisma's `findUnique({ where: { id: "me" } })`. Prisma attempts to parse "me" as a UUID, fails, and throws `P2023: Inconsistent column data: Error creating UUID, invalid character`. |
| **Impact** | Clients receive a 500 instead of a meaningful 404. |
| **Recommendation** | Either implement a `/users/me` route before the `:id` route, or add UUID validation in the controller to return 400/404 for non-UUID inputs. |

### Finding #2: passwordHash Exposed in User API Responses

| Attribute | Detail |
|-----------|--------|
| **Severity** | Low |
| **Endpoints** | `GET /api/v1/users`, `GET /api/v1/users/:id` |
| **Expected** | passwordHash should not be returned to clients |
| **Actual** | `passwordHash` field is included in API responses |
| **Root Cause** | The Prisma `findMany`/`findUnique` queries return all fields by default, including `passwordHash`. |
| **Impact** | Security: password hashes are exposed to API consumers. |
| **Recommendation** | Use Prisma `select` or `omit` to exclude `passwordHash` from query results. |

### Finding #3: Organization API Not Publicly Readable

| Attribute | Detail |
|-----------|--------|
| **Severity** | Low |
| **Endpoints** | `GET /api/v1/organizations`, `GET /api/v1/organizations/:id` |
| **Expected** | Public read access (per project memory: "explicitly public read-only APIs") |
| **Actual** | 401 Unauthorized (JWT Guard required) |
| **Root Cause** | Organization controller requires `@UseGuards(JwtAuthGuard)` on all endpoints. |
| **Impact** | Organizations cannot be browsed without authentication; frontend search/listing requires login. |
| **Recommendation** | Review if this is intentional. If public read access is desired, remove JWT Guard from GET endpoints. |

## 10. Appendix: Infrastructure Note

The Dockerfile at `apps/api/Dockerfile` copies `database/prisma/schema.prisma` but does not copy `database/prisma/migrations/`. This means `prisma migrate deploy` has no migrations to apply in a fresh deployment. During this test, migrations were manually copied into the container.

**Recommendation**: Add the following line to the Dockerfile:
```dockerfile
COPY database/prisma/migrations/ database/prisma/migrations/
```
