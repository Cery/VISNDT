## 8. Findings

### Finding #1: passwordHash Exposed in User API Responses
- **Severity**: LOW
- **Source**: Report #197 (M12.5.3.2)
- **Status**: Still present
- **Affected Endpoints**: `GET /api/v1/users`, `GET /api/v1/users/:id`
- **Description**: Both user list and detail endpoints return the `passwordHash` field in the response body.
- **Recommendation**: Use Prisma `select` to exclude `passwordHash` from query results. Not fixed per M12.5 freeze rules.

### Finding #2: Admin Container Healthcheck Failure
- **Severity**: LOW
- **Source**: Report #197 (M12.5.3.2)
- **Status**: Still present
- **Description**: Admin container healthcheck uses `wget` which returns `Connection refused` internally, but the service is accessible externally at `http://localhost:80`.
- **Recommendation**: Replace `wget` with `curl` in Dockerfile healthcheck, or use `127.0.0.1` instead of `localhost`.

### Finding #3: No Seed Data for Products and Demands
- **Severity**: INFO
- **Description**: Products and Demands collections are empty (0 records). Dashboard shows 0 products, 0 demands, 0 matches.
- **Impact**: Product Management and Demand/Matching flows cannot be fully tested in the current environment.
- **Recommendation**: Consider adding seed data for integration testing in future phases.

### Finding #4: Docker CLI Unavailable in Current Session
- **Severity**: INFO
- **Description**: `docker` command was not found in PATH during this test session. All Docker-dependent tests were performed via API health checks and HTTP requests.
- **Impact**: `docker compose ps` and `docker compose build` could not be executed directly.
- **Note**: Services were confirmed running from previous session (M12.5.3.2).
