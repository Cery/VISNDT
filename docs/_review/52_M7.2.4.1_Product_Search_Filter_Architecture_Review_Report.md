```typescript
async findAll(pagination: PaginationDto) {
  const { page = 1, pageSize = 20 } = pagination;
  const skip = (page - 1) * pageSize;

  const [data, total] = await Promise.all([
    this.prisma.product.findMany({
      skip,
      take: pageSize,
      orderBy: { createdAt: 'desc' },
      include: { category: true },
    }),
    this.prisma.product.count(),
  ]);

  return { data, total, page, pageSize, totalPages: Math.ceil(total / pageSize) };
}
```

## 3. Product Search Analysis

### 3.1 Keyword Search

**可搜索字段**:

| 字段 | 类型 | 当前索引 |
|------|------|---------|
| `name` | String | ❌ 无索引 |
| `model` | String? | ❌ 无索引 |
| `description` | String? | ❌ 无索引 |

**评估**:

| 方案 | 查询示例 | 适用规模 | 复杂度 | 推荐度 |
|------|---------|---------|--------|--------|
| `contains` | `{ name: { contains: '内窥镜' } }` | < 1000 | 低 | ⭐⭐⭐ MVP |
| `startsWith` | `{ name: { startsWith: 'IND' } }` | < 1000 | 低 | ⭐⭐ 辅助 |
| PostgreSQL `tsvector` | `to_tsvector('chinese', name)` | < 10000 | 中 | ⭐⭐⭐ 进阶 |
| `pg_trgm` | trigram 模糊匹配 | < 10000 | 中 | ⭐⭐ 辅助 |
| Elasticsearch | 全文索引 | 无限 | 高 | ⭐ 未来 |

**推荐**: M7.2.4.2 先用 Prisma `contains` 实现 MVP，支持 name/model/description 三字段 OR 组合搜索。M7.5+ 按需引入 PostgreSQL Full Text Search。

### 3.2 Category Filter

**当前数据结构**:

```
ProductCategory {
  id, name, code, parentId   // 树形结构
  parent → ProductCategory?
  children → ProductCategory[]
}
```

**当前索引**: `@@index([parentId])` 在 ProductCategory，`@@index([categoryId])` 在 Product。

**查询需求**:

| 场景 | 示例 | 实现方式 |
|------|------|---------|
| 一级分类 | "工业内窥镜" | `where: { category: { code: 'industrial_endoscope' } }` |
| 子分类 | "管道内窥镜" | `where: { categoryId: 'uuid' }` |
| 多级分类 | "工业内窥镜" + 所有子类 | 先查子分类 ID 列表，再 `where: { categoryId: { in: [...] } }` |

**推荐**: 一级/子分类直接用 `categoryId` 过滤。多级分类需要先查询分类树，再展开为 ID 列表做 `in` 查询。建议封装为 `findDescendantIds(categoryCode)` 工具方法。

### 3.3 Parameter Filter

**当前数据结构**:

```
ProductParameterValue {
  productId, parameterDefinitionId, value  // String 存储
  product → Product
  parameterDefinition → ParameterDefinition {
    name, unit, dataType, parameterGroupId, ...
  }
}
```

**查询需求**: NDT 领域典型参数筛选

| 查询 | 示例 | 难度 |
|------|------|------|
| 单参数等值 | `镜头直径 = 2.8mm` | 低 |
| 单参数范围 | `分辨率 >= 100万` | 中 (value 为 String) |
| 多参数 AND | `直径 < 3mm AND 长度 > 2m` | 中 |
| 参数 OR | `直径 2.8mm OR 3.0mm` | 中 |

**核心问题**: `value` 字段为 `String` 类型，无法直接做数值比较（`gte`/`lte`）。

**方案对比**:

| 方案 | 描述 | 优点 | 缺点 | 推荐 |
|------|------|------|------|------|
| **A: Prisma Relation Filter** | `where: { parameterValues: { some: { ... } } }` | 无需改 Schema | 多参数 AND 需多次嵌套；String 无范围比较 | ⭐⭐⭐ MVP |
| **B: JSON 参数存储** | Product 新增 `parametersJson` 字段 | 查询灵活 | 破坏参数体系；数据冗余 | ❌ 不推荐 |
| **C: 独立 Search Index** | 同步到 Elasticsearch | 性能最优 | 架构复杂度高 | ⭐ 未来 |

**推荐**: 方案 A。M7.2.4.2 实现单参数等值筛选（`some: { parameterDefinitionId, value }`）。范围查询受限于 String 类型，暂不实现，留待 M7.3 参数体系增强时考虑。

### 3.4 Pagination

**当前**: offset-based (`skip`/`take`)，默认 20/页，最大 100/页。

| 方案 | 适用规模 | 优点 | 缺点 |
|------|---------|------|------|
| Offset | < 10000 | 简单，支持跳页 | 大 offset 性能差 |
| Cursor | 无限 | 稳定性能 | 不支持跳页，实现复杂 |

**推荐**: 保持 offset pagination。VISNDT MVP 产品规模预期 < 1000，offset 完全够用。不引入 cursor 增加复杂度。

## 5. Recommended Architecture

### 5.1 查询参数 DTO 设计

```typescript
// 建议新增: apps/api/src/products/dto/search-product.dto.ts
export class SearchProductDto extends PaginationDto {
  keyword?: string;          // 搜索 name, model, description
  categoryId?: string;       // 分类筛选
  status?: string;           // 状态筛选
  parameterFilters?: {       // 参数筛选
    parameterDefinitionId: string;
    value: string;
  }[];
  sortBy?: string;           // 排序字段
  sortOrder?: 'asc' | 'desc';
}
```

### 5.2 Service 查询模式

```typescript
// 建议架构
async search(dto: SearchProductDto) {
  const where: Prisma.ProductWhereInput = {};

  // Keyword
  if (dto.keyword) {
    where.OR = [
      { name: { contains: dto.keyword } },
      { model: { contains: dto.keyword } },
      { description: { contains: dto.keyword } },
    ];
  }

  // Category
  if (dto.categoryId) {
    where.categoryId = dto.categoryId;
  }

  // Status
  if (dto.status) {
    where.status = dto.status;
  }

  // Parameter (single filter MVP)
  if (dto.parameterFilters?.length) {
    where.AND = dto.parameterFilters.map(f => ({
      parameterValues: { some: { parameterDefinitionId: f.parameterDefinitionId, value: f.value } },
    }));
  }

  return this.prisma.product.findMany({
    where,
    skip, take,
    orderBy: { [dto.sortBy ?? 'createdAt']: dto.sortOrder ?? 'desc' },
    include: { category: true },
  });
}
```

### 5.3 API 路径

**推荐**: 扩展 `GET /products`，不新增独立 search 端点。

```
GET /products?keyword=内窥镜&categoryId=xxx&status=ACTIVE&page=1&pageSize=20
```

**理由**:
- RESTful 惯例：search 是 findMany 的变体，不是独立资源
- 避免 `/products/search` 与 `/products/:id` 路由冲突
- Swagger 文档更清晰（单一端点，多 query 参数）
