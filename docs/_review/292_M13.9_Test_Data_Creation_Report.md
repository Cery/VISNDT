## 2. 测试数据创建过程

### 2.1 产品激活（DRAFT → ACTIVE）

#### 2.1.1 背景

平台初始状态下，通过种子数据创建的产品默认为 **DRAFT** 状态。DRAFT 状态的产品不会在前台产品列表中展示，需要由 Admin 角色用户手动将其状态变更为 **ACTIVE**。

#### 2.1.2 激活流程

通过 API PATCH 请求将产品状态从 DRAFT 更新为 ACTIVE：

```
PATCH /api/products/{productId}/status
Content-Type: application/json

{
  "status": "ACTIVE"
}
```

| 序号 | 产品名称 | 型号 | 分类 | 父分类 | 激活前状态 | 激活后状态 | 激活结果 |

| 1 | VX-6000 | VX-6000-HD | 视频内窥镜 | 工业内窥镜 | DRAFT | ACTIVE | 成功 |
| 2 | FB-3000 | FB-3000-PRO | 光纤内窥镜 | 工业内窥镜 | DRAFT | ACTIVE | 成功 |
| 3 | US-800 | US-800-DIGITAL | 超声检测 | — | DRAFT | ACTIVE | 成功 |
| 4 | AOI-5000 | AOI-5000-3D | 视觉检测 | — | DRAFT | ACTIVE | 成功 |
| 5 | PP-100 | PP-100-LITE | 工业内窥镜 | — | DRAFT | ACTIVE | 成功 |

### 2.3 供应商用户创建（邀请码机制）

#### 2.3.1 邀请码机制说明

平台采用邀请码（Invitation Code）机制进行用户注册。Admin 用户创建组织后，系统为该组织生成邀请码，用户通过邀请码完成注册并自动关联至对应组织。

#### 2.3.2 注册流程

```
1. Admin 创建组织 → 系统生成邀请码
2. 将邀请码提供给目标用户
3. 用户访问注册页面，填写邀请码
4. 系统验证邀请码有效性 → 创建用户并关联组织
```

## 6. 发现的问题

### 6.1 产品初始状态为 DRAFT

**问题描述**：通过种子数据或 API 创建的产品，初始状态均为 DRAFT，不会在前台产品列表中展示。

**影响范围**：所有新创建的产品。

**当前解决方案**：Admin 用户需通过 API `PATCH /api/products/{id}/status` 手动将产品状态更新为 ACTIVE。

**建议**：考虑在 Admin 后台产品管理页面增加"一键激活"按钮，或支持批量激活操作，提升操作效率。

---

### 6.2 Offer 创建存在唯一约束问题

**问题描述**：通过 API 创建 Offer 时，如果同一供应商（organizationId）已对同一产品（productId）创建过 Offer，再次创建会触发唯一约束异常。

**影响范围**：通过 API 批量创建 Offer 时可能失败。

**当前解决方案**：创建前先通过 GET 请求检查是否存在重复，或使用不同的 Offer 编号（code）。

**建议**：考虑在 API 层面返回更友好的错误提示，明确告知是哪个字段触发了唯一约束。

---

### 6.3 用户注册需要有效邀请码

**问题描述**：用户注册流程依赖邀请码机制，没有有效邀请码的用户无法注册并关联组织。

**影响范围**：所有需要关联组织的用户注册。

**当前解决方案**：Admin 先创建组织并获取邀请码，再将邀请码分发给用户。

**建议**：
- 考虑增加邀请码有效期管理
- 支持邀请码批量生成和导出
- 考虑增加"公开注册"选项（可选关联组织）

---

### 6.4 PowerShell 中文显示乱码

**问题描述**：在 Windows PowerShell 环境中执行 API 请求时，包含中文名称的响应数据显示为乱码。

**影响范围**：Windows 环境下的命令行测试。

**原因分析**：PowerShell 默认编码（通常为 GBK/GB2312）与 API 响应的 UTF-8 编码不匹配。

**解决方案**：
- 使用 `[Console]::OutputEncoding = [Text.Encoding]::UTF8` 设置控制台编码
- 或使用 `curl` 配合 `--output` 参数将结果保存到文件后查看
- 或使用 Postman / Insomnia 等 GUI 工具进行 API 测试

## 8. 结论和建议

### 8.1 结论

本次测试数据创建工作已全部完成，覆盖了 VISNDT 平台 M13.9 版本的核心业务实体。共计创建和维护了 **6 个产品**（全部 ACTIVE）、**9 个分类**、**6 个组织**、**11 个用户**、**9 个 Offer**、**3 个参数组**和 **8 个参数定义**。数据完整性验证通过，前后台功能均可正常使用。

### 8.2 后续建议

1. **产品激活流程优化**：建议在 Admin 后台增加批量激活功能，减少逐一手动激活的操作成本。

2. **Offer 唯一约束处理**：建议在 API 层面提供更友好的冲突提示，或支持"更新已有 Offer"的 UPSERT 操作。

3. **邀请码管理增强**：建议增加邀请码有效期、使用次数限制、批量生成等功能，提升供应商入驻管理效率。
