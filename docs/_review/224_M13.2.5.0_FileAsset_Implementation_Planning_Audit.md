### 7.2 Data Flow

```
1. UPLOAD FLOW:
   User selects file
   → Ant Design Upload validates (size, type)
   → POST /files/upload (multipart/form-data)
   → FileAssetService.upload(file, userId)
   → StorageService.upload(buffer, fileName, mimeType)
   → S3Client.putObject({ Bucket, Key, Body, ContentType })
   → prisma.fileAsset.create({ data: { ... } })
   → Return { fileAssetId, fileName, mimeType, fileSize }

2. CREATE MEDIA FLOW:
   User selects file (upload completes)
   → User fills form (mediaType, title, etc.)
   → POST /products/:id/media (JSON body with fileAssetId)
   → ProductMediaService.create(productId, dto)
   → Return ProductMedia

3. DOWNLOAD FLOW:
   User clicks download
   → GET /files/:id/download
   → FileAssetService.getSignedUrl(id)
   → prisma.fileAsset.findUnique({ where: { id } })
   → StorageService.getSignedUrl(storageKey, 900s)
   → S3Client.getSignedUrl('getObject', { Bucket, Key, Expires })
   → 302 redirect to signed URL

4. DELETE FLOW:
   User confirms delete
   → DELETE /files/:id
   → FileAssetService.delete(id)
   → prisma.fileAsset.findUnique({ where: { id } })
   → StorageService.deleteObject(storageKey)
   → S3Client.deleteObject({ Bucket, Key })
   → prisma.fileAsset.delete({ where: { id } })
```

### 7.3 File Naming Convention

```
storageKey format: {entityType}/{entityId}/{timestamp}-{uuid}.{ext}

Example:
  PRODUCT/abc-123/20260728-093025-a1b2c3d4.jpg
  ORGANIZATION/def-456/20260728-093030-cert.pdf
```

Benefits:
- Hierarchical — easy to list/delete by entity
- Unique — UUID prevents collisions
- Sortable — timestamp prefix for time-based ordering

### 7.4 Rate Limiting

| Endpoint | Limit | Rationale |
|----------|:---:|-----------|
| `POST /files/upload` | 10 req/min | File upload is expensive |
| `GET /files/:id/download` | 30 req/min | Signed URL generation is cheap |
| `DELETE /files/:id` | 10 req/min | Infrequent operation |

## 9. Risk Assessment

| Risk | Severity | Mitigation |
|------|:---:|------------|
| S3 SDK memory usage | 🟡 Medium | Stream uploads, don't buffer in memory |
| MinIO container startup | 🟢 Low | Healthcheck + depends_on |
| Multer file size abuse | 🟡 Medium | FileSizeValidator (10MB), rate limiting |
| Orphaned S3 objects | 🟡 Medium | Transactional delete (DB + S3), GC job |
| MIME type spoofing | 🟡 Medium | Server-side `file-type` detection |
| Signed URL expiration | 🟢 Low | 15-min default, configurable |
| CORS for MinIO | 🟢 Low | MinIO CORS config in startup script |
