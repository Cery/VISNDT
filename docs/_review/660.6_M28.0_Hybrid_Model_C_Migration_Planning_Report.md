## 2. Migration Change Set

### Change A — Enum `SupplierProductStatus`

新增枚举值：

```
DRAFT / SUBMITTED / REVIEWING / APPROVED / PUBLISHED / REJECTED
```

该变更在 PostgreSQL 中为 **append-only 枚举扩展**（`CREATE TYPE supplier_product_status AS ENUM (...) `），不触发现有表数据，向后兼容（R1 LOW）。

### Change B — Enum `FileEntityType` 扩展

新增值：
- `SUPPLIER_PRODUCT`

用途：
- `FileAsset.entityType` + `SupplierProductMedia` 文档关联头。

### Change C — 创建 `supplier_product`

对应 `SupplierProduct` Prisma Model（`@@map("supplier_product")`）。

| 分类 | 列 |
| ---- | -- |
| Identity | `id` / `organization_id` / `platform_product_id` |
| Product Identity | `brand` / `series` / `model_number` / `slug` |
| Content | `description` / `technical_description` / `application_info` |
| Governance | `status` / `submitted_at` / `reviewed_at` / `reviewed_by` / `reviewed_note` / `published_at` |
| Audit | `created_at` / `updated_at` |

约束与索引：
- `@@unique([organization_id, platform_product_id, model_number])`
- `@@index([organization_id])`
- `@@index([platform_product_id])`
- `@@index([model_number])`
- `@@index([status])`
- `slug @unique`

### Change D — 创建 `supplier_product_media`

对应 `SupplierProductMedia` Prisma Model。

- 关联：`supplier_product_id` (FK → supplier_product, **ON DELETE CASCADE**) / `file_asset_id?` (FK → file_asset, 默认行为)
- 字段：`media_type`(FileType) / `document_type?` / `title?` / `alt_text?` / `is_primary` / `display_order`
- 索引：`@@index([supplier_product_id])` / `@@index([file_asset_id])`

用途（供应商型号媒体）：Image / Manual / Specification / Certificate / Inspection Case。

### Change E — 创建 `supplier_product_parameter_value`

对应 `SupplierProductParameterValue` Prisma Model。

- 关联：`supplier_product_id` (FK → supplier_product, **ON DELETE CASCADE**) / `parameter_definition_id` (FK → parameter_definition)
- 字段：`value` / `value_number?`
- 约束：`@@unique([supplier_product_id, parameter_definition_id])` + `@@index([parameter_definition_id])`

用途：供应商型号参数覆盖（ParameterDefinition + SupplierProduct Value）。

### Change F — 扩展 `offer`

- 新增列：`supplier_product_id` **nullable**（FK → supplier_product, **ON DELETE RESTRICT**）
- 新增索引：`@@index([supplier_product_id])`
- 保留：`@@unique([organization_id, product_id])` / `@@index([product_id])` / `@@index([status])`

兼容双绑结构：

```
Offer
  organization_id
  product_id            ← Capability Aggregation
  supplier_product_id?  ← Commercial Source (NULL in Phase 1)
```

## 4. Foreign Key Strategy (Frozen)

| 源列 | 目标 | ON DELETE | 理由 |
| ---- | ---- | --------- | ---- |
| `supplier_product.organization_id` | `organization.id` | RESTRICT | 供应商型号属于组织资产，不可随组织删除断裂。 |
| `supplier_product.platform_product_id` | `product.id` | RESTRICT | Platform Product 是能力节点；禁止「删能力节点→供应商型号失效」。 |
| `supplier_product_media.supplier_product_id` | `supplier_product.id` | CASCADE | 媒体生命周期跟随型号。 |
| `supplier_product_parameter_value.supplier_product_id` | `supplier_product.id` | CASCADE | 参数值生命周期跟随型号。 |
| `offer.supplier_product_id` | `supplier_product.id` | RESTRICT | 商业记录不可因型号删除而断裂。 |
| `supplier_product_media.file_asset_id` | `file_asset.id` | (default) | 可选文件资产关联。 |
| `supplier_product_parameter_value.parameter_definition_id` | `parameter_definition.id` | (default) | 参数定义引用。 |

## 5. Data Compatibility Planning

### Existing Data Strategy

当前 `Offer` 结构：`organizationId + productId`（必填，`@@unique([organization_id, product_id])`）。

迁移后：

```
Offer
  organization_id
  product_id
  supplier_product_id = NULL   ← 全部现存 Offer 保持 NULL
```

### Phase 1 Requirement

禁止执行：
```
UPDATE offer SET supplier_product_id = ...
```
原因：本轮不存在可靠「型号 → 平台能力 + 组织归属」映射数据源；强制回填会造成错误商业绑定。

### Breaking Change Analysis

- ❌ 无列删除 / 无列改名 / 无列 NOT NULL 收紧
- ✅ 仅新增 nullable 列 + 新表 + append-only 枚举扩展
- ✅ `@@unique([organization_id, product_id])` 保留，既有 Offer 唯一键行为不变
- → **零 breaking change**

### Future Backfill Condition (M28.x Offer SupplierProduct Backfill)

必须同时满足：
1. Organization Match（Offer.organization_id 命中 SupplierProduct.organization_id）
2. PlatformProduct Match（Offer.product_id 命中 SupplierProduct.platform_product_id）
3. Supplier Model Identity Verified（brand + series + model_number 人工/受控确认）

满足后方可进入**独立任务**：`M28.x Offer SupplierProduct Backfill`（本任务 **NOT EXECUTED**）。

## 6. Rollback Strategy Design

### Principle

冻结：**NO destructive rollback（无破坏性回滚）**。

### Rollback Window

允许的受控回滚：
```
Migration Applied → Validation Failed → Controlled Reverse Migration
```
窗口：迁移应用后、生产数据写入前的观察与验证阶段。

### Rollback Rules

允许删除新增（前提：无生产数据依赖）：
- `supplier_product`
- `supplier_product_media`
- `supplier_product_parameter_value`

禁止：
- 直接删除 `offer.supplier_product_id`（若已有生产数据写入）；应保留 nullable 列或分步降级。

### Production Safety Rule

冻结的启用序列：
```
Migration → Observation Window → Data Validation → Enable Runtime Usage
```
禁止迁移后立即开放业务写入（写入需在独立 Gate / Runtime Enablement 阶段开启）。
