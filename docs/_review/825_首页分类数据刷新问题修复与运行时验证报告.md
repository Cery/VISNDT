## 1. 问题描述

管理端新增 / 修改 / 删除分类后，首页能力分类版块（`CategorySection`）与公共目录页（`/categories`、`/products`）不随数据变更即时刷新，用户返回首页仍看到旧分类（已删除分类残留；新增 / 修改分类不出现）。

### 根因

React Query 全局 `staleTime: 60s`，且 Next.js App Router 客户端导航返回缓存路由时页面组件可能不会重新挂载（`refetchOnMount` 不触发、无 focus 事件），导致：

- **D1（组件层）**：目录查询在 60s 内视为「新鲜」，窗口 / 路由返回均不触发重拉；
- **D2（全局失效器层）**：`queryClient.invalidateQueries` 默认 `refetchType:'active'` 只重拉「活跃观察者」挂载中的查询；App Router 缓存还原导航时观察者未必处于 active，删除分类在部分渲染路径上残留。

## 2. 修复内容

### 2.1 组件层强制目录过期（D1 收口）

对全部公共目录消费点设置 `staleTime: 0` + `refetchOnWindowFocus: true` + `refetchOnMount: 'always'`，使目录数据始终视为过期，窗口焦点回归 / 路由重新进入即重拉：

| 文件 | 变更 |
|---|---|
| [CategorySection.tsx](file:///f:/Desktop/VISNDT/VISNDT/apps/web/src/components/home/CategorySection.tsx#L21-L28) | 首页能力分类：新增 `staleTime: 0` |
| [FeaturedProductsSection.tsx](file:///f:/Desktop/VISNDT/VISNDT/apps/web/src/components/home/FeaturedProductsSection.tsx#L10-L18) | 首页推荐产品：新增 `staleTime: 0` |
| [categories/page.tsx](file:///f:/Desktop/VISNDT/VISNDT/apps/web/src/app/categories/page.tsx#L32-L39) | 能力分类页：新增 `staleTime: 0` |
| [products/page.tsx](file:///f:/Desktop/VISNDT/VISNDT/apps/web/src/app/products/page.tsx#L98-L105) | 产品中心分类筛选：新增 `staleTime: 0` |

### 2.2 全局路由失效器（D2 收口）

[providers.tsx](file:///f:/Desktop/VISNDT/VISNDT/apps/web/src/app/providers.tsx#L25-L32)：`CatalogRouteInvalidator` 在进入 `/`、`/categories`、`/products` 时，将 `invalidateQueries` 的 `refetchType` 由默认 `'active'` 改为 `'all'`，防御性强制刷入缓存，确保任何渲染路径都读到最新目录，删除分类不残留。

### 2.3 阻塞构建的既有类型缺陷（非本任务核心，低风险修复）

`pnpm build` 因预先存在的 TypeScript 契约不一致阻塞（`knowledge-base` 类型 error），为满足「build exit 0」工程规约一并最小化修复：

- [knowledge-base/[slug]/page.tsx](file:///f:/Desktop/VISNDT/VISNDT/apps/web/src/app/knowledge-base/[slug]/page.tsx#L322)：页面访问了 `RelatedProductItem` 类型中不存在的 `status` 字段（后端 `knowledge.service.ts findRelatedProducts` 已按 `status:'ACTIVE'` 过滤且 select 不含 status，故恒为可用）。改为常量 `sub: '可用'`，消除对不存在字段的依赖。
