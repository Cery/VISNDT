### 2.2 SupplierProductsService 职责

- `createDraft(input)`：创建 `SUPPLIER_PRODUCT` DRAFT 实体。强制校验 platformProductId 存在（capability binding），全部新实体起始 `DRAFT`。
- `findOne(id, organizationId)`：归属隔离查询（跨组织读取被拒绝 → NotFound）。
- `findAllByOrganization(organizationId, {status,page,pageSize})`：组织内分页列表 + 可选状态过滤。
- `validateForOrganization(id, organizationId)`：校验归属 + 能力绑定一致性。
- 私有 `ensurePlatformProductExists()`：确保 SupplierProduct 始终锚定真实 Platform Capability Node（Product）。

### 2.3 OffersService Extension（双绑校验边界）

在 `apps/api/src/offers/offers.service.ts`：
- 注入 `SupplierProductsService`。
- `create()` 增加 `validateSupplierBinding(dto.supplierProductId, user.organizationId, dto.productId)`：
  - `offer.organizationId == supplierProduct.organizationId`
  - `offer.productId == supplierProduct.platformProductId`
  - 任一不一致 → `BadRequestException`（reject invalid binding）。
  - 未提供 `supplierProductId`（legacy）→ no-op，兼容既有 Offer。
- 新增私有 `validateSupplierBinding()`（双绑规则实现）。
- **数据兼容**：`create()` 写入 `supplierProductId ?? null`，旧 Offer（无绑定）保持 NULL 有效。

### 2.4 DiscoveryService Foundation（聚合基础结构）

`Capability（Platform Product）→ SupplierProducts → Offers` 内部聚合：
- `findCapabilityGraph(platformProductId, {includeDrafts})`：能力节点 → 已发布 SupplierProducts（确定性排序 createdAt desc, id asc）→ 其 Offers；含 `_meta` 计数。
- `findSupplierProductCommercials(supplierProductId, organizationId?)`：单 SupplierProduct 的商业记录（Offers）+ 能力回溯，支持归属隔离。
- 纯内部读聚合，**不修改 Search / Matching / 任何既有模块**。

### 2.5 DI 接线

- `offers.module.ts`：import `SupplierProductsModule`。
- `app.module.ts`：import `SupplierProductsModule`、`DiscoveryModule`。
