## 6. New/Updated TD Decision

### 6.1 `TD-001` Decision

Decision:

- Rename from `RFQ Create Service Boundary Normalization`
- To `Workspace Frontend Service Boundary Normalization`

Reason:

- `408` originally established the service-boundary concern through Buyer RFQ Create.
- `413` confirmed the same category now also includes:
  - Demand Create bypass
  - Match page mixed service/API mutation
  - Notifications page direct API usage without service abstraction

Conclusion:

- Keeping the old name would understate the real scope.
- A widened name is better than splitting multiple small service-boundary TDs at this stage.

### 6.2 `TD-002` Decision

Decision:

- Keep unchanged.

Reason:

- Current registry wording already explicitly covers:
  - `RFQResponse CREATE`
  - `MATCH_CREATED`
  - broader lifecycle event coverage gap

Conclusion:

- No split or rename is needed in this round.

### 6.3 `TD-004` Decision

Decision:

- Keep unchanged.

Reason:

- `409` identified the strongest subject inconsistency in match-related event writes.
- `412` already expanded the registry to capture this as an independent governance item.

### 6.4 `TD-005` Decision

Decision:

- Keep unchanged.

Reason:

- The generic lifecycle mutation boundary remains a dedicated backend/API hardening concern.
- Its semantics are distinct from event-coverage debt and from frontend service-boundary debt.

### 6.5 `TD-006` Decision

Decision:

- Add new TD: `Workspace Frontend Access Boundary Normalization`

Coverage:

- Supplier `RoleGuard` placement
- permission check before protected content mount
- frontend RBAC execution order normalization

Reason:

- `413` identified a separate debt category from `TD-003` and `TD-005`.
- This problem is about frontend access-boundary timing and component mount order, not RFQ lifecycle gating and not backend lifecycle mutation surfaces.

### 6.6 Supplier Dual Entry Decision

Decision:

- Do not add a standalone TD.

Reason:

- `401` already normalized route ownership.
- `413` classifies the remaining issue as low-risk UX/navigation cognition residue.
- Current governance priority should stay on lifecycle traceability, mutation boundary, service boundary, and access boundary issues.

Registry treatment:

- Keep as attached note only.
