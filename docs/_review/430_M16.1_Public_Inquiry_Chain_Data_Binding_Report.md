## 4. Architecture Impact

### Frontend Impact

- 严格遵循 `Page → Service → API Wrapper → Backend API` 分层，未引入 `Page 直接调用 API`。
- 产品详情页复用既有 `getProduct` service 与 `lib/api/products.ts` wrapper，仅扩展了类型与数据推导逻辑。
- `InquirySection` / `InquiryForm` 未改动其内部结构，仅上游补齐了 `offerId` / `organizationId` 数据。

### Backend Impact

- 仅扩展 `ProductsService.findOne` 的 Prisma `include`，属于查询层增强。
- 未改动 Controller / Service 分层，未绕过 `Controller → Service → Domain Logic → Persistence`。

### Domain Impact

- Inquiry 域现状已具备：创建接口校验 `productId` + `offerId`（归属校验）+ `organizationId`（一致性校验），并落库 `productId` / `organizationId` / 联系人信息，创建后向组织成员发送通知（referenceId=Inquiry.id）。
- 本次补齐了前端到该域的数据供给，使 Inquiry 提交具备「来源产品 + 来源组织 + 可追踪信息」。
