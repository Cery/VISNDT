## 4. Query Design

### 4.1 匹配列表查询

```typescript
// 组织隔离层
await this.validateDemandOwnership(demandId, user);
// → 验证 Demand 存在且 user 属于同一组织

// filter
where: { demandId, matchStatus?: DemandMatchStatus }

// sort whitelist
sortMap = {
  score:   { matchScore: 'desc' },   // 按匹配度降序
  latest:  { createdAt: 'desc' },     // 最新创建
  updated: { updatedAt: 'desc' },     // 最近更新
}

// includes
include: {
  product: { include: { category: true } },  // 产品 + 分类
  offer: true,                                 // 报价（可选）
}
```

### 4.2 匹配详情查询

```typescript
// 双重验证：demand ownership + match belongs to demand
where: { id: matchId, demandId }

// 扩展 includes
include: {
  product: { include: { category: true } },
  offer: true,
  demand: { include: { parameters: { include: { parameterDefinition: true } } } },
}
```

### 4.3 组织隔离

```
Request
  │
  ├─ 1. JwtAuthGuard (Controller)
  │     └─ 验证 JWT 有效性
  │
  ├─ 2. validateDemandOwnership(demandId, user)
  │     ├─ user.organizationId 存在
  │     ├─ Demand 存在
  │     └─ demand.createdBy === user.id || demand.organizationId === user.organizationId
  │
  └─ 3. 查询 DemandMatch
        └─ where: { demandId, ... }  // 仅查询该 Demand 的匹配
```

## 5. Security Impact

### 5.1 安全分析

| 检查项 | 说明 | 风险 |
|--------|------|------|
| 组织隔离 | 所有端点验证 Demand 所有权，仅同组织可见 | ✅ 已保护 |
| 身份验证 | 全部端点 JwtAuthGuard，无公开访问 | ✅ 已保护 |
| 跨组织访问 | 匹配结果绑定 Demand，通过 Demand 隔离 | ✅ 已保护 |
| SQL 注入 | Prisma 参数化查询 | ✅ 无风险 |
| 排序注入 | sort 白名单 Map，非法值回退 score | ✅ 无风险 |
| 数据泄露 | 不暴露其他组织匹配数据 | ✅ 无风险 |

### 5.2 与已有安全模型一致性

| 安全层 | 实现方式 | 复用 |
|--------|----------|------|
| 认证 | JwtAuthGuard | 与 Demand 写端点一致 |
| 所有权验证 | `validateDemandOwnership()` | 复用已有辅助方法 |
| 组织隔离 | `demand.organizationId === user.organizationId` | 与 DemandParameter 一致 |
