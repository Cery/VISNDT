关键结论（回答 Mandatory Dependency Questions）：

1. Product Detail 通过 `ProductsService.findOne()`（uuid/slug 双模式）获得 Product（含 `category`）。
2. Product 通过 `categoryId` / `category` 关系获得 ProductCategory。
3. `ProductCategoryKnowledgeMapping` 已具备可查询关系（`@@unique([productCategoryId, knowledgeCategoryId])` + 双向 index），且 `isActive` 软开关已存在。
4. KnowledgeCategory 已有公开 API（`GET /knowledge/public/categories`）与 Service 查询。
5. KnowledgeEntry 已可通过 `GET /knowledge/public/entries` / `entries/:slug` 查询。
6. KnowledgeEntry 具有 `status` 枚举（DRAFT / REVIEW / PUBLISHED / ARCHIVED）与 `publishedAt` 字段。
7. Knowledge Detail 路由为 `/knowledge-base/[slug]`（`getEntryBySlug`）。
8. Product Detail 原本无 Related / Knowledge 区域（本次新增 knowledge tab）。

## 6. Mapping Resolution

`products.service.ts#findRelatedKnowledge(idOrSlug)`：

1. 以 uuid/slug 双模式查询 Product，仅 `select { id, categoryId }`。
2. 若 Product 不存在 → `NotFoundException`。
3. 查询 `productCategoryKnowledgeMapping`：`where { productCategoryId: product.categoryId, isActive: true }`，`orderBy { sortOrder: 'asc' }`。
4. 零 mapping → 返回 `[]`（空态）。

---

## 7. Knowledge Resolution

在映射得到的 `knowledgeCategoryId` 集合上：

1. 查询 `knowledgeEntry.findMany`：`where { categoryId: { in: [...categoryOrder.keys()] }, status: 'PUBLISHED' }`，仅 select 轻量字段（id / title / slug / summary / publishedAt / categoryId / category / domain）。
2. 不返回 `structuredBody` / body / 大内容 payload / 内部审计字段。

## 8. API Impact

- 新增端点：`GET /products/:id/related-knowledge`（PUBLIC，支持 uuid 或 slug）。
- Controller：`ProductsController.findRelatedKnowledge`。
- Service：`ProductsService.findRelatedKnowledge`。
- 响应：轻量 `RelatedKnowledgeItem[]`（id / title / slug / summary / publishedAt / category / domain），复用 `ApiResponse` 包装。

分类：**API = MODIFIED（最小只读扩展）** —— 因为 Repository 中不存在「从 Product 出发解析相关知识」的读出能力（现有 `knowledge/public` 端点以 Domain/Category 为入口，非 Product 入口）。该扩展为完成闭环所必需的最小只读补齐，未新建独立 Content / Knowledge Runtime / Engine。

## 10. Deduplication

按 `KnowledgeEntry.id` 去重（`Map<string, Entry>`）。虽然单条 entry 逻辑上只属于一个 category，但去重逻辑仍对「多 KnowledgeCategory 指向同一 KnowledgeEntry」的防御性保证成立（Case E）。

---

## 11. Ordering

稳定、可解释排序：

1. `mapping.sortOrder`（按知识分类）升序；
2. 同分类内 `publishedAt` 降序（`null` 视为 0）；
3. 完全相同时 `id` 升序兜底。

未引入 AI / 随机 / 热度排序。

---

## 12. Published / Active Filtering

- 映射层：`isActive: true`（软开关，软删除/停用的映射不参与）。
- 条目层：`status: 'PUBLISHED'`（DRAFT / REVIEW / ARCHIVED 均不返回）。

与 Repository 当前 `KnowledgeEntryStatus` 枚举名完全一致。
