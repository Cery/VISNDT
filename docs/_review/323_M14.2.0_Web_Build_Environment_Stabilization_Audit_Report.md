### 3.1 `apps/web/eslint.config.mjs`

文件内容确认如下：

```js
import { dirname } from "path";
import { fileURLToPath } from "url";
import { FlatCompat } from "@eslint/eslintrc";

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

const compat = new FlatCompat({
  baseDirectory: __dirname,
});

const eslintConfig = [
  ...compat.extends("next/core-web-vitals", "next/typescript"),
];

export default eslintConfig;
```

结论：

- `eslint.config.mjs` 直接从 `@eslint/eslintrc` 导入 `FlatCompat`

## 4. 依赖分析

### 4.1 `pnpm list @eslint/eslintrc -r`

只读检查结果显示：

- `@visndt/web` 下 `eslint 9.39.5` 依赖 `@eslint/eslintrc 3.3.6`
- `eslint-config-next 15.5.20` 的依赖链也间接落到 `@eslint/eslintrc 3.3.6`

关键结论：

- `@eslint/eslintrc` 在 workspace 中**存在安装记录**
- 但它是 `@visndt/web` 的**传递依赖**，不是 `apps/web/package.json` 中的直接声明

### 4.2 `pnpm why @eslint/eslintrc`

只读检查结果显示来源为：

- `@visndt/web -> eslint -> @eslint/eslintrc`
- `@visndt/web -> eslint-config-next -> ... -> eslint -> @eslint/eslintrc`
- `@visndt/api` 也通过自身 `eslint` 链路间接依赖该包

结论：

- 来源位置明确是 `eslint` 体系的传递依赖
- 不属于 `apps/web` 自己显式声明的包

### 4.3 node_modules 状态

检查结果：

- `F:\Desktop\VISNDT\VISNDT\node_modules\.pnpm` 中存在：
  - `@eslint+eslintrc@3.3.6`
  - `@eslint+eslintrc@3.3.6_supports-color@8.1.1`
- 但以下路径均不存在：
  - `F:\Desktop\VISNDT\VISNDT\node_modules\@eslint\eslintrc`
  - `F:\Desktop\VISNDT\VISNDT\apps\web\node_modules\@eslint\eslintrc`

补充验证：

```text
node --input-type=module -e "import('@eslint/eslintrc')"
```

在 `F:\Desktop\VISNDT\VISNDT\apps\web` 下直接失败：

```text
Cannot find package '@eslint/eslintrc' imported from F:\Desktop\VISNDT\VISNDT\apps\web\[eval1]
```

同时直接导入 `./eslint.config.mjs` 也失败：

```text
Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@eslint/eslintrc' imported from F:\Desktop\VISNDT\VISNDT\apps\web\eslint.config.mjs
```

结论：

- `@eslint/eslintrc` **已安装在 pnpm virtual store**
- 但 `apps/web` 运行时可见的顶层解析路径中**没有对应入口**
- 因此这里不是“包未下载”，而是“当前项目上下文无法把它当作可直接 import 的顶层依赖”

### 4.4 ESLint 配置来源分析

结论分两层：

1. `apps/web/eslint.config.mjs` 中 `import { FlatCompat } from "@eslint/eslintrc"` 这一写法，对 `@eslint/eslintrc@3.3.6` 来说**语法上是成立的**
2. 当前失败的根因不是 import 语句拼写错误，而是 `apps/web` 本身未直连可解析的 `@eslint/eslintrc` 入口

### 4.5 pnpm workspace 解析分析

为什么 `dev` 可能可运行而 `build` 失败：

- `apps/web` 的 `dev` 脚本是 `next dev -p 3000`
- 本次复现中，`next build` 的编译、静态页面生成都完成了
- 真正报错发生在：

```text
Linting and checking validity of types ...
```

这说明当前问题是在 build 过程加载 ESLint 配置时触发，而不是页面业务代码编译阶段触发。

审计判断：

- `build` 会稳定经过 ESLint 配置解析链路
- `dev` 并不等价于同一条 lint/build 校验路径
- 因此“dev 可运行但 build 失败”与 pnpm 严格依赖解析、以及 `eslint.config.mjs` 直接 import 传递依赖的组合是一致的
