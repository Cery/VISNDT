## 1. Phase Overview

本阶段新增 `DemandParameter` 数据模型，建立 Demand 与 ParameterDefinition 之间的结构化参数关系。替代原有的 `parametersJson` 自由格式 JSON，使 Demand 参数需求与 Product 参数体系对齐，为后续 DemandMatch 产品匹配算法提供结构化基础。

**原则：只实现 Schema，不实现 API 和 Match Algorithm。**

### 设计目标

| 目标 | 说明 |
|------|------|
| 结构化参数需求 | 替代 `parametersJson`，使用类型安全的关系模型 |
| 与 ParameterDefinition 对齐 | 引用已有参数定义体系 |
| 支持精确/范围匹配 | `value`（精确）+ `valueMin`/`valueMax`（范围） |
| 支持必须/可选 | `required` 字段区分必须满足和偏好参数 |
| 支持优先级排序 | `priority` 字段支持加权匹配 |

## 3. Schema Changes

### 3.1 新增 DemandParameter 模型

```prisma
model DemandParameter {
  id                    String  @id @default(uuid()) @db.Uuid
  demandId              String  @map("demand_id") @db.Uuid
  parameterDefinitionId String  @map("parameter_definition_id") @db.Uuid
  value                 String?
  valueMin              Float?  @map("value_min")
  valueMax              Float?  @map("value_max")
  required              Boolean @default(true)
  priority              Int     @default(0)

  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  demand              Demand              @relation(fields: [demandId], references: [id])
  parameterDefinition ParameterDefinition @relation(fields: [parameterDefinitionId], references: [id])

  @@unique([demandId, parameterDefinitionId])
  @@index([parameterDefinitionId])
  @@map("demand_parameter")
}
```

### 3.2 字段详细说明

| # | 字段 | 数据库列 | 类型 | 默认值 | 用途 |
|---|------|----------|------|--------|------|
| 1 | `id` | `id` | UUID | uuid() | 主键 |
| 2 | `demandId` | `demand_id` | UUID | — | 关联 Demand |
| 3 | `parameterDefinitionId` | `parameter_definition_id` | UUID | — | 关联 ParameterDefinition |
| 4 | `value` | `value` | String? | NULL | 精确值需求（如 "2.8mm"） |
| 5 | `valueMin` | `value_min` | Float? | NULL | 最小值需求 |
| 6 | `valueMax` | `value_max` | Float? | NULL | 最大值需求 |
| 7 | `required` | `required` | Boolean | `true` | 是否必须满足 |
| 8 | `priority` | `priority` | Int | `0` | 优先级 (0=普通, 1=重要, 2=关键) |
| 9 | `createdAt` | `created_at` | DateTime | now() | 创建时间 |
| 10 | `updatedAt` | `updated_at` | DateTime | updatedAt | 更新时间 |

### 3.3 双向 Relation

### 3.4 与 ProductParameterValue 的关系对比

```
DemandParameter                        ProductParameterValue
┌──────────────────────┐              ┌──────────────────────────┐
│ parameterDefinitionId │──────────────│ parameterDefinitionId     │
│ value: "2.8mm"       │  精确匹配    │ value: "2.8mm"           │
│ valueMin: 2.0        │  范围匹配    │ valueNumber: 2.8         │
│ valueMax: 3.0        │              │                          │
│ required: true       │  (业务层)    │ (无此概念)                │
│ priority: 2          │  (业务层)    │ (无此概念)                │
└──────────────────────┘              └──────────────────────────┘
```

**匹配逻辑（未来 M7.4.4）：**
1. `DemandParameter.value` 存在 → 精确匹配 `ProductParameterValue.value`
2. `DemandParameter.valueMin/valueMax` 存在 → 范围匹配 `ProductParameterValue.valueNumber`
3. `required=false` → 不满足时不排除产品，但降低 matchScore
4. `required=true` → 不满足时排除产品

### 3.5 索引设计

| 索引 | 类型 | 用途 |
|------|------|------|
| `@@unique([demandId, parameterDefinitionId])` | UNIQUE | 同一 Demand 不能重复定义同一参数 |
| `@@index([parameterDefinitionId])` | INDEX | 按参数定义查询所有需求 |

### 3.6 外键约束

| 外键 | 引用 | ON DELETE | ON UPDATE |
|------|------|-----------|-----------|
| `demand_id` | `demand(id)` | RESTRICT | CASCADE |
| `parameter_definition_id` | `parameter_definition(id)` | RESTRICT | CASCADE |

**RESTRICT 语义：** 如果 Demand 或 ParameterDefinition 有关联的 DemandParameter，不允许删除。保证数据完整性。
