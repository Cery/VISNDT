## 4. Cookie Configuration

### 4.1 Cookie Creation (`setAuthCookies`)

#### File: `apps/api/src/auth/auth.controller.ts` (Line 26-49)

```typescript
private getCookieOptions() {
  const isProduction = this.configService.get<string>('NODE_ENV') === 'production';
  return {
    httpOnly: true,
    secure: isProduction,
    sameSite: 'lax' as const,
    path: '/',
    maxAge: parseInt(
      this.configService.get<string>('JWT_REFRESH_EXPIRES_IN') ?? '604800', 10,
    ) * 1000,
  };
}

private setAuthCookies(res, accessToken, refreshToken) {
  const cookieOpts = this.getCookieOptions();
  res.cookie('access_token', accessToken, {
    ...cookieOpts,
    maxAge: parseInt(
      this.configService.get<string>('JWT_EXPIRES_IN') ?? '86400', 10,
    ) * 1000,
  });
  res.cookie('refresh_token', refreshToken, cookieOpts);
}
```

### 4.2 Cookie Clearing (`clearAuthCookies`)

#### File: `apps/api/src/auth/auth.controller.ts` (Line 52-55)

```typescript
private clearAuthCookies(res: Response) {
  res.clearCookie('access_token', { path: '/' });
  res.clearCookie('refresh_token', { path: '/' });
}
```

#### clearCookie vs setCookie Comparison

| Attribute | `setCookie` | `clearCookie` | Match? |
|-----------|-------------|---------------|--------|
| `path` | `'/'` | `'/'` | ✅ |
| `httpOnly` | `true` | **Not specified** | 🔴 **MISMATCH** |
| `secure` | `isProduction` | **Not specified** | 🔴 **MISMATCH** |
| `sameSite` | `'lax'` | **Not specified** | 🔴 **MISMATCH** |

### 🔴 Finding: clearCookie Attribute Mismatch

**Line 52-55:** `clearCookie()` only specifies `path: '/'` but does not include `httpOnly`, `secure`, or `sameSite` attributes. Per the [Express documentation](https://expressjs.com/en/api.html#res.clearCookie), `res.clearCookie()` requires matching `path` and `domain` attributes to successfully clear the cookie. If `httpOnly`, `secure`, or `sameSite` differ from the original `setCookie` call, the browser may not clear the cookie.

**Impact:**
- In development (`secure: false`): ✅ Low risk — cookie will clear correctly
- In production (`secure: true`): 🔴 **cookie may NOT be cleared** — `secure` attribute mismatch means the browser won't identify the correct cookie to clear
- `sameSite: 'lax'` mismatch: 🔴 **cookie may NOT be cleared** — browsers may treat this as a different cookie

**Note:** This is a **pre-existing issue** from M13.5.1 implementation. Not introduced in this audit phase.

## 7. CSRF Risk Assessment

### 7.1 Current Protection

| Layer | Mechanism | Status |
|-------|-----------|--------|
| Cookie | `sameSite: 'lax'` | ✅ Prevents CSRF on POST from cross-site |
| Cookie | `httpOnly: true` | ✅ Prevents XSS from reading tokens |
| CORS | `credentials: true` + origin whitelist | ✅ Restricts cross-origin requests |
| Helmet | Default headers | ✅ Basic security headers |
| Token | CSRF token | ❌ **Not implemented** |

### 7.2 Risk Scenarios

| Scenario | Risk | Mitigation |
|----------|------|------------|
| XSS steals cookie | **None** — HttpOnly | ✅ `httpOnly` prevents JS access |
| CSRF from attacker.com | **Low** — SameSite Lax | ✅ `sameSite: 'lax'` blocks cross-site POST |
| CSRF from subdomain | **Medium** | ⚠️ `sameSite: 'lax'` allows same-site requests |
| CSRF from same origin | **Medium** | ⚠️ No CSRF token — requires same-origin XSS |

### 7.3 CSRF Risk Summary

| Risk | Severity | Recommendation |
|------|----------|----------------|
| Same-site CSRF (subdomain) | 🟡 Medium | Add CSRF token (double-submit cookie or `csrf-csrf`) |
| Same-origin CSRF (XSS) | 🟡 Medium | CSP header + CSRF token |
| Cross-site CSRF | 🟢 Low | `sameSite: 'lax'` effectively blocks |

**Assessment:** Basic CSRF protection is adequate for current scope. For production, a CSRF token mechanism should be added in M13.5.2.2.
