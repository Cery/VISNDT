## 5. Issues Found & Fixed（仅真运行时暴露）

### 5.1 明视组织 UUID variant 位非法

- **现象**：E2E 创建询价失败，报 `organizationId must be a UUID`。
- **根因**：明视组织 ID `926d5a96-e1be-455c-dd58-8f4a79b6735d` 的 variant 位为 `d`，不符合 RFC 4122 UUID v4（variant 位应为 `8`/`9`/`a`/`b`），被 `@IsUUID()` 拒绝。根源于 `seed_demo.ts` 的 `demoId()` 未强制 version/variant 位。
- **修复（两处）**：
  1. `database/seed_demo.ts` `demoId()`：强制 version 位（index 12）= `4`、variant 位（index 16）= `8`，确保未来 seed 生成合法 v4 UUID。
  2. `database/tmp_fix_org_uuid.sql`：事务级联修正存量数据，将明视组织 ID variant 位 `d → 8`（新 ID `926d5a96-e1be-455c-8d58-8f4a79b6735d`），同步级联更新 6 张引用表（user / organization_member / offer / rfq / rfq_response）。

### 5.2 E2E 脚本询价 ID 提取逻辑错误

- **现象**：`createdInquiryId` 恒为空，断言失败（尽管询价实际创建成功）。
- **根因**：脚本误从 `data.id` 提取，而 `POST /inquiries` 实际响应结构为 `data.inquiry.id`（`inquiries.service.ts` 返回嵌套 `inquiry` 对象，`ApiResponse.ok` 包装在 `data` 下）。
- **修复**：`database/e2e_runtime.ts` 将 `const createdInquiryId = inqRes.json?.data?.id ?? ''` 修正为 `const createdInquiryId = inqRes.json?.data?.inquiry?.id ?? ''`。
