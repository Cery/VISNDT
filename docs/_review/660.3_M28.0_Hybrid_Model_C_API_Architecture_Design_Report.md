## 2. Current API Reality（Model B 现状扫描）

基于 `apps/api/src` 真实扫描：

**Products（`products.controller`，Controller `products`）**
- `GET /products`（public）：关键字 + categoryId + status + parameterFilters 搜索。
- `GET /products/:id|slug`、`GET /products/:id/related-knowledge`、`GET /products/:id/related-products`（public）。
- `POST /products`、`PATCH /products/:id`、`DELETE /products/:id`（**ADMIN only**，注释明确 `@Roles(ADMIN)`）。

**Offers（`offers.controller`，Controller `offers`）— Hybrid Model B 商业层**
- `GET /offers`、`GET /offers/:id`（public，include organization + product）。
- `POST /offers`（authenticated）：**organizationId 服务端派生自 `user.organizationId`，DTO 不接受**；`CreateOfferDto = productId + title + description + price + currency`（**无 supplierProductId**）。
- `PATCH /offers/:id`（org-scoped `findFirst { id, organizationId }`）。
- `POST /offers/:id/submit|accept|reject|withdraw`（org-scoped）。
- `DELETE /offers/:id`、`batch-delete`、`batch-status`（**ADMIN only**）。

**Search（`search.controller`，Controller `search`）**
- `GET /search?q=`（public）：Unified Industrial Discovery（products / knowledge / content / solutions / suppliers）。
- `GET /search/context`（public）：query-level Search Context（category facet / parameter facet）。

**Matching（`matching.controller`，Controller `matches`）**
- `GET /matches/:id/knowledge-context`（authenticated，read-side）。

**Role 模型（`role.enum.ts`）**：仅 `ADMIN` / `MEMBER`（**无独立 SUPPLIER 角色**；Supplier 能力 = MEMBER + organizationId 派生，经 workspace supplier offers 管理）。

**结论（Model B API Reality）**：Capability（Product）+ Commercial（Offer）两层 API 已成型；Supplier 型号无独立 API 实体；**未暴露 `supplierProductId`**；Supplier capability 经 `product → offers → organization` 三级间接表达。`CreateOfferDto` 目前 productId 必填、无 supplierProductId —— 正是 660.3 需冻结的 Offer 双绑扩展点。

## 3. SupplierProduct API Boundary（未来设计，冻结 API 域）

### 3.1 API 分层（冻结）

```text
Capability Domain API     → /products（Platform Product = Capability Node，Admin 治理，暂不改）
Supplier Product Domain API → /supplier-products（新，Supplier Product 独立实体）
Commercial Offer API     → /offers（进化：productId * supplierProductId 双绑）
Discovery API            → /search + /capabilities（聚合）
RFQ API                  → /rfqs + /matches（既有链路，NONE）
```

### 3.2 Admin Supplier Product Pool（SupplierProduct Governance API）

冻结职责：SupplierProduct Governance + Approval Workflow + Public Availability Control。

```text
POST   /admin/supplier-products                    # Admin 创建 Draft
POST   /admin/supplier-products/:id/submit         # DRAFT → SUBMITTED
POST   /admin/supplier-products/:id/review         # SUBMITTED → REVIEWING
POST   /admin/supplier-products/:id/approve        # REVIEWING → APPROVED
POST   /admin/supplier-products/:id/reject         # REVIEWING → REJECTED（带 reviewedNote）
POST   /admin/supplier-products/:id/publish        # APPROVED → PUBLISHED
GET    /admin/supplier-products                    # Query（status/org/platformProductId/page）
GET    /admin/supplier-products/:id                # Detail（含 media/parameters/media/offers）
```

状态机（restrict，由 Service 收敛，非裸状态透传）：

```text
DRAFT → SUBMITTED → REVIEWING → APPROVED → PUBLISHED
                            ↘ REJECTED
```

Workflow **属于 SupplierProduct Domain**；不属于 Platform Product / Offer / Organization 状态流。

### 3.3 SupplierProduct Query（Buyer / Public）

冻结查询方向 **Platform Product（Capability Node）→ Supplier Products（型号）**，非独立供应商目录搜索：

```text
GET /products/:id/suppliers        # Capability → 该能力节点的已 PUBLISHED 供应商型号列表（含 media/params）
GET /supplier-products/:slug       # Supplier Product 详情（PUBLISHED only）
GET /supplier-products/:id/media   # 型号媒体
GET /supplier-products/:id/parameters # 型号参数（Override + Extension，交 661.x 演进；本期只冻结契约）
```

## 4. Approval Workflow API Boundary（冻结）

- Workflow 归属：**SupplierProduct Domain**（专用审批端点，见 §3.2）。
- 平台：**不使用 `Product.status`** 承载 Supplier 审批（Product.status 保持平台治理语义）。
- 不新增通用 Workflow 引擎；沿用既有 `WorkflowEvent`/`AuditLog` 记录范式（实现阶段复用，本期不改 Schema）。
- Reject 必须带 `reviewedNote`；Reviewer = Admin（`reviewedBy`/`reviewedAt` 落 SupplierProduct，见 660.2）。

## 5. Offer Dual Binding API（进化契约）

保持兼容 `organizationId + productId + supplierProductId(optional)`。

### 5.1 Create Offer

```ts
CreateOfferDto（未来）:
  organizationId      string      // 仍服务端派生，DTO 不接受，保持现状
  productId           string      // capability aggregation（能力节点，必填）
  supplierProductId?  string      // commercial source（型号，可选）NEW
  title               string
  description?        string
  price?              number
  currency?           string      // 默认 CNY
```

创建时强校验（Service 层）：

- 若 `supplierProductId` 提供，必须满足：
  - `supplierProduct.organizationId === Offer.organizationId`（型号归属发起组织）
  - `supplierProduct.platformProductId === Offer.productId`（型号能力节点一致）
- 违反任一 → 422 / BadRequest（保证双绑一致性，防跨组织/跨能力错误绑定）。

### 5.2 Update Offer

- **Supplier**：仅改 **自己的 Offer**（org-scoped）的商业字段（commercial fields / availability / description）；**禁止**改 Platform Product、禁止改 SupplierProduct ownership（`productId` / `supplierProductId` 不做解绑与重绑，如需换型号走新建）。
- **Admin**：运营/治理可调整状态与披露（现有 batch-status 保留）。

### 5.3 Query Offer（返回三级结构）

API 返回必须支持 **Capability → SupplierProduct → Offer** 三级，**禁止只返回裸 Offer List**（避免前端回退旧 Model B 重绑）。

```ts
SupplierProductOfferDTO（未来，汇聚型）:
  platformProduct: { id, slug, name, categoryId, ... }        // Capability Node
  supplierProducts: [
    {
      supplierProduct: { id, slug, brand, series, modelNumber, status, ... },
      offers: [ { id, price, currency, status, ... } ]        // 唯一 (orgId, productId)
    }
  ]
```

## 6. Buyer Discovery API

冻结：Buyer API **不暴露数据库结构**（不直接吐 Prisma Offer/SupplierProduct 原始联接）。体验模型 = Platform Capability → Supplier Products → Commercial Offers。

推荐契约（Capability-packed Read API）：

```ts
GET /capabilities/:id      →  CapabilityDetailDTO
CapabilityDetailDTO:
  platformProduct: { ... }        // 能力节点权威信息（含平台参数/media/related knowledge）
  supplierProducts: [
    {
      supplierProduct: { ... },   // PUBLISHED 型号（brand/series/modelNo/media/params）
      offers: [ { ... } ]         // 该组织该型号的 ACTIVE/SUBMITTED Offer
    }
  ]
```

与 M22.4 统一发现（`/search`）定位互补：`/search` 面向「找能力」，`/capabilities/:id`+`/products/:id/suppliers` 面向「在一项能力下比较供应商型号与报价」。

## 7. Permission Architecture（冻结）

| 角色 | 权限 | 说明 |
|-|-|-|
| **Admin** | Platform Product Management / SupplierProduct Approve+Publish / Data Governance | 既有 `Role.ADMIN` + 新 SupplierProduct 审批端点 |
| **Supplier** | **仅 Offer Management（阶段1）**；未来预留 SupplierProduct Draft Submission（阶段2） | 当前**禁止** Direct Publish / 改 Platform Product / 改 Global Parameter；Supplier 能力 = MEMBER + orgId 派生（现状保留） |
| **Buyer** | Read Only / Discovery / Inquiry / RFQ | 公开只读 + 询价/需求 |

> 实施提示：未来若引入独立 Supplier 角色，应新增 `Role.SUPPLIER` 枚举（交实现阶段评估并扩展 role.enum，本期仅冻结权限边界，不改代码）。

## 10. Final API Architecture Decision

**Task Status = PASS（API Architecture Design Complete / Hybrid Model C API Contract Freeze）**。

- **API 分层冻结**：Capability（/products）→ Supplier Product（/supplier-products，新）→ Commercial（/offers 双绑）→ Discovery（/search + /capabilities）→ RFQ（/rfqs，NONE）。
- **SupplierProduct API DEFINED**：Admin Pool（create/submit/review/approve/reject/publish/query）+ Buyer Query（capability→supplier list / supplier detail / media / parameters）。
- **Approval Workflow API DEFINED**：归属 SupplierProduct Domain；`DRAFT→SUBMITTED→REVIEWING→APPROVED→PUBLISHED / ↘REJECTED`；不污染 `Product.status`。
- **Offer Evolution API DEFINED**：`organizationId + productId + supplierProductId(optional)`；创建时强校验 `supplierProduct.organizationId === org` 且 `supplierProduct.platformProductId === productId`；查询返回三级结构；Supplier 仅改自家 Offer 商业字段。
- **Buyer Discovery API DEFINED**：`CapabilityDetailDTO`（platformProduct + supplierProducts[{ supplierProduct, offers[] }]），不暴露数据库结构。
- **Permission Boundary DEFINED**：Admin（products + supplier approval/publish + governance）；Supplier（阶段1 Offer 管理 only，阶段2 预留 Draft；禁止直发/改平台/改全局参数）；Buyer（read-only + inquiry + RFQ）。
- **保留现状不动**：`GET/POST/PATCH/DELETE /products`（Admin 治理）、`/search`/`/search/context`、`/matches/:id/knowledge-context`、`/rfqs` 链路；Offer 的 org 派生逻辑、batch 管理、submit/accept/reject/withdraw 保持。
- **零代码**：Database / Prisma / Migration / Frontend / Admin UI / Supplier UI 全 UNCHANGED / NONE。红线保留：NO Product.organizationId / Supplier Store / Marketplace / Payment / Order / ERP。

**遗留（交 660.4 Readiness Assessment + M28 开发阶段）**：`Role.SUPPLIER` 枚举是否引入、SupplierProduct CRUD/审批具体路由与 Guard、OffersService 双绑校验落地、DiscoveryService 聚合实现、Admin Supplier Product Pool UI、Web 消费 CapabilityDetailDTO。
