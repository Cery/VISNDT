### 4.2 NOT Reusable

| Admin Pattern | Why Not | Web Alternative |
|---|---|---|
| Ant Design | Admin-only component library | Tailwind CSS + shadcn/ui |
| React Router 7 | Client-side SPA routing | Next.js App Router (server + client) |
| Zustand stores | Admin-specific state | React Server Components + Context |
| Vite | SPA build tool | Next.js built-in |
| Axios | Client-side HTTP | `fetch` API (native) |

### 4.3 Type Definition Strategy

Admin has 15 type files in `apps/admin/src/types/`. These are **duplicated** from backend DTOs. For Web, prefer:

1. **`packages/shared-types/`** — Single source of truth for shared types
2. Web imports from `@visndt/shared-types` directly
3. No type duplication between admin and web

## 7. Next.js Architecture Proposal

### 7.1 Framework Choice: Next.js 14+ (App Router)

| Decision | Rationale |
|---|---|
| **Next.js** | Industry standard for React SSR/SSG. App Router provides server components, streaming, and built-in SEO. |
| **App Router** | File-system based routing, React Server Components, layouts, loading/error states built-in. |
| **Not Pages Router** | Pages Router is legacy. App Router is the future. |
| **Not Vite SPA** | SEO-critical (industrial B2B platform). SPA has poor SEO without SSR. |
| **Not Remix** | Smaller ecosystem, fewer resources, less compatible with existing NestJS backend. |
