## 1. Phase Overview

本阶段实现 DemandParameter 结构化 CRUD API，替代原有的 `parametersJson` 自由格式 JSON。通过 `ParameterDefinition` 引用体系，使 Demand 参数需求与 Product 参数体系对齐，为后续 DemandMatch 匹配算法提供结构化数据基础。

**原则：Schema 不修改，Migration 不创建。**

### 实现的能力

| 端点 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `POST /demands/:id/parameters` | JWT | 为 Demand 添加参数需求 |
| `GET /demands/:id/parameters` | JWT | 获取 Demand 参数列表 |
| `PATCH /demands/:id/parameters/:paramId` | JWT | 更新参数需求 |
| `DELETE /demands/:id/parameters/:paramId` | JWT | 删除参数需求 |

### 3.2 POST /demands/:id/parameters — 添加参数

**认证：** JwtAuthGuard (+ @ApiBearerAuth)

**请求体：**

```typescript
{
  parameterDefinitionId: string;   // 必填，UUID
  value?: string;                  // 精确值
  valueMin?: number;               // 最小值
  valueMax?: number;               // 最大值
  required?: boolean;              // 可选，默认 true
  priority?: number;               // 可选，默认 0
}
```

**禁止客户端提交：** `demandId`（从 URL 路径提取）

**验证规则：**
1. Demand 存在且用户有所有权
2. Demand 状态非终态（CLOSED/CANCELLED）
3. `parameterDefinitionId` 必须引用已有 ParameterDefinition
4. `demandId + parameterDefinitionId` 唯一约束（数据库层）

**成功响应：**

```json
{
  "code": 200,
  "message": "Parameter added",
  "data": {
    "id": "param-uuid",
    "demandId": "demand-uuid",
    "parameterDefinitionId": "def-uuid",
    "value": "2.8mm",
    "required": true,
    "priority": 2,
    "parameterDefinition": {
      "id": "def-uuid",
      "name": "镜头直径",
      "code": "lens_diameter",
      "dataType": "NUMBER",
      "unit": "mm"
    }
  }
}
```

**错误响应：**

| 条件 | 状态码 | 消息 |
|------|--------|------|
| 无组织 | 400 | User must belong to an organization |
| Demand 不存在 | 404 | Demand {id} not found |
| 无权限 | 400 | You do not have permission to modify this demand |
| 终态阻止 | 400 | Cannot add parameters to a demand with status {status} |
| ParamDef 不存在 | 400 | ParameterDefinition {id} not found |
| 重复参数 | 409 | Unique constraint violation |

## 4. Service Architecture

### 4.1 验证辅助方法

为减少代码重复，新增两个私有验证辅助方法：

```typescript
// 验证 Demand 所有权（返回 Demand 对象，失败抛异常）
private async validateDemandOwnership(id, user): Promise<Demand>

// 验证 ParameterDefinition 存在（返回 Definition 对象，失败抛异常）
private async validateParameterDefinition(paramDefId): Promise<ParameterDefinition>
```

### 4.2 方法签名

```typescript
async addParameter(demandId: string, dto: CreateDemandParameterDto, user) → DemandParameter
async getParameters(demandId: string, user) → DemandParameter[]
async updateParameter(demandId: string, paramId: string, dto: UpdateDemandParameterDto, user) → DemandParameter
async deleteParameter(demandId: string, paramId: string, user) → { deleted: true }
```

### 4.3 安全守卫链

```
Request
  │
  ├─ 1. JwtAuthGuard (Controller)
  │     └─ 验证 JWT 有效性
  │
  ├─ 2. validateDemandOwnership()
  │     ├─ user.organizationId 存在
  │     ├─ Demand 存在
  │     └─ isCreator || isSameOrg
  │
  ├─ 3. 状态检查 (write only)
  │     └─ status ∉ TERMINAL_STATUSES
  │
  ├─ 4. validateParameterDefinition() (create only)
  │     └─ ParameterDefinition 存在
  │
  └─ 5. 数据库操作
        └─ @@unique([demandId, parameterDefinitionId])
```

## 5. Security Impact

### 5.1 安全改进

| 改进项 | 说明 | 严重程度 |
|--------|------|----------|
| 身份注入防护 | `demandId` 从 URL 路径提取，不信任客户端提交 | 🔴 Critical |
| 所有权验证 | 所有参数操作均验证 Demand 所有权 | 🟡 High |
| 终态阻止 | CLOSED/CANCELLED 状态禁止参数修改 | 🟡 High |
| 参数定义验证 | ParameterDefinition 必须存在 | 🟡 Medium |
| 同 Demand 唯一约束 | 数据库层防止重复参数 | 🟡 Medium |
| 全端点认证 | 所有参数端点均使用 JwtAuthGuard | 🟡 High |

### 5.2 与 parametersJson 的对比

| 维度 | parametersJson (旧) | DemandParameter (新) |
|------|---------------------|----------------------|
| 类型安全 | ❌ JSON 任意结构 | ✅ Prisma 类型安全 |
| 参数定义引用 | ❌ 无 | ✅ 引用 ParameterDefinition |
| 唯一约束 | ❌ 无 | ✅ (demandId, paramDefId) UNIQUE |
| 范围查询 | ❌ 字符串比较 | ✅ valueMin/valueMax Float |
| 优先级 | ❌ 无 | ✅ priority 字段 |
| 必须/可选 | ❌ 无 | ✅ required 字段 |
| 匹配算法 | ❌ 难以处理 | ✅ 结构化匹配 |
