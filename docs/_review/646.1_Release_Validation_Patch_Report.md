## 3. D1 Fix Verification

### 变更点

`apps/web/src/services/auth.service.ts` — `getMe()` 返回语义明确化：

```ts
export async function getMe(): Promise<AuthUser | null> {
  try {
    const res = await apiClient<{ data: AuthUser }>('/auth/me');
    return res.data;
  } catch (err) {
    if (err instanceof ApiError && err.status === 401) {
      return null; // 未登录 / 会话过期 → 正常态，展示登录入口
    }
    throw err; // 网络异常 / 服务不可用 / 5xx → 由 AuthProvider 呈现错误态
  }
}
```

`apps/web/src/auth/AuthProvider.tsx` — 新增 `authError` 状态与 `retryAuth()`：

- `resolveMe()`：成功 → `setAuthError(false)`；异常 → `setAuthError(true)`；均复位 `isLoading`
- `retryAuth()`：`setIsLoading(true)` + 重新 `resolveMe()`，供错误态「重新连接」按钮调用
- `login / logout / register` 成功后同步复位 `authError = false`

`apps/web/src/app/dashboard/page.tsx` 与 `apps/web/src/app/workspace/page.tsx` — 新增 Case 2 错误态：

- `authError === true` → 红色警示卡片「认证服务暂不可用」+ 说明文案 + 「重新连接」按钮（触发 `retryAuth`）
- 不再将认证异常落入「角色未配置」分支

### 验证结果

| 场景 | 预期 | 结果 |
| --- | --- | --- |
| 正常登录 | `getMe()` → User Context → Workspace Render | 保持，PASS |
| 401（未登录/会话过期） | 返回 null，展示登录入口 | PASS |
| 网络异常 / 服务中断 / 5xx | 进入「认证服务暂不可用」错误态 + 重试 | PASS（不再误判「角色未配置」） |
