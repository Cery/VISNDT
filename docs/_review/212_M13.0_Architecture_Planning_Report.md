## 4. M13 Candidate Scope

### Candidate 1: Admin Operational Completeness (M13.1)

**Objective**: Complete the Admin UI for all existing backend CRUD operations that lack frontend pages.

**Scope**:
- Parameter Management (Groups + Definitions) — CRUD pages
- Category Management — CRUD pages
- File/Media Management — Upload, view, delete for product media

**Rationale**: Backend APIs exist but are inaccessible without direct DB/API calls. This is a completeness gap.

**Risk**: Low — backend APIs already exist and are frozen

### Candidate 2: Audit & Compliance (M13.2)

**Objective**: Add audit log visibility and user activity tracking.

**Scope**:
- Audit Log page (read-only, filterable by entity type, action, date)
- User profile self-management (password change, profile edit)
- Session management (view active sessions, force logout)

**Rationale**: `AuditLog` model already stores data. Security compliance requires audit visibility.

**Risk**: Low — read-only operations on existing data

### Candidate 3: Dashboard & Analytics Enhancement (M13.3)

**Objective**: Transform the basic dashboard into an operational command center.

**Scope**:
- Charts (demand trends, match rates, user activity)
- Period filters (daily, weekly, monthly)
- Quick action cards (pending reviews, unread notifications)
- Exportable reports

**Rationale**: Current dashboard shows only raw counts. Operational insight requires visualization.

**Risk**: Medium — may require backend dashboard API enhancements

### Candidate 4: RFQ Workflow Completion (M13.4)

**Objective**: Complete the RFQ lifecycle management in Admin.

**Scope**:
- RFQ Response Accept/Reject actions in Admin UI
- RFQ status transitions (OPEN → RESPONDING → CLOSED)
- Response comparison view

**Rationale**: RFQ backend is complete but frontend actions are missing, making the workflow incomplete.

**Risk**: Low — backend APIs exist

### Candidate 5: Notification & Communication Enhancement (M13.5)

**Objective**: Improve notification system with preferences and email integration.

**Scope**:
- Notification preferences (opt-in/out per type)
- Email notification provider (SMTP)
- Notification grouping and filtering

**Rationale**: Notifications exist in-app but lack user control and multi-channel delivery.

**Risk**: Medium — requires email infrastructure and backend notification module changes
