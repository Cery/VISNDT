- Bound endpoint to existing `RfqsController`
- Kept legacy `POST /rfqs` unchanged in behavior, but clarified its Swagger summary

### 4.3 Service

- Added `RfqsService.createFromMatch()`
- Validation rules implemented:
  - caller must belong to an organization
  - `DemandMatch` must exist
  - current organization must own the related `Demand`
  - `DemandMatch.matchStatus` must be `ACCEPTED`
  - target supplier organization must be resolvable from `match.offer.organizationId`
  - duplicate RFQ creation for the same `sourceMatchId` is blocked
- RFQ persistence fields:
  - `demandId`
  - `sourceMatchId`
  - `targetOrganizationId`
  - `createdBy`
- Side effects reused from existing infrastructure:
  - notify target supplier organization admins via `notificationsService.createForOrganization()`
  - write `WorkflowEntityType.RFQ + WorkflowAction.CREATED`
